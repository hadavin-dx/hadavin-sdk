## Minor
1. A persistent outage-class refusal of ONE head row blocks everything with no alarm. chain.py:425-428 counts `deferred` only when `not _is_outage(failed)`, and `_is_outage` (chain.py:67-75) is true for any psycopg OperationalError with no SQLSTATE and any OSError. Scenario: a driver or wrapper that raises a SQLSTATE-less OperationalError (or OSError) only for one body (for example a client-side encode failure surfaced as OperationalError) at the oldest row: `reconcile` returns quietly each tick, the step is green, and no later outbox row is ever drained, while inline events keep entering the chain. Before round 5 other rows still drained, so round 5 turned this from "one row stuck" into "all rows stuck". Narrow and needs an unusual driver error, hence Minor. Suggested: count a refusal at the same head row over N consecutive ticks as a failure even when it looks like an outage (or alarm when the pass stops with an outage while a `SELECT 1` succeeds).
2. Paging read is not consistent across processes. chain.py:371-390 reads LIMIT/OFFSET pages with no snapshot (each `run` is its own autocommit statement). In-process there is no race (rows are deleted/renamed only after all pages are read, and under `_flush_lock`). Another process draining, deleting or quarantining the same table between two pages shifts the offset: a row can be SKIPPED this tick (a delete or rename of an earlier row moves the later row into the already-passed offset; picked up next tick) or READ TWICE (a new older-ts row inserted before the offset). A twice-read row is appended once (event_id dedupe, DuplicateEvent -> None at chain.py:420-421) and the second DELETE is a no-op, but `r.done` counts it twice and `r.unreadable` can double count. Skip only delays by a tick; the skip also can let a newer item be written before the skipped older one in that pass (same class as the stated limit, cross-process only). Not stated in A8; add one line.
3. Stale `_transient_stuck`. chain.py:426 sets it from a memory event, but only `_flush_pending` resets it (chain.py:~320-335, the `while ... else`); a pass that drains the memory event, or that stops at an outbox row before reaching `_pending`, leaves it True. Later, an unrelated event parked in `_pending` (for example during an outage) is then reported by `reconcile` as "events not writable in memory" although it was only an outage. Only a false alarm on the step (loud, not silent), cleared by the next successful `_flush_pending`.
4. Naive-`ts` ordering contract differs from `_append`. chain.py:128-131 reads a naive ts as UTC for ORDER; `_append` treats a naive ts as local time when it writes `at` (A-review-4 Minor 3 text). On a non-UTC host a naive event is ordered as UTC but stamped as local, so the chain order may differ from `at` order for that event. The raise is gone (test_audit_drain_transient_2.py:70 holds, but passes only if the CI zone makes the two readings agree in order; it does not pin the non-UTC case). Naive ts only arises from a hand-built event.
