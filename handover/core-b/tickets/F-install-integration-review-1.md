## Major

M1. `_RunMeter.ended` is ignored on the ProviderError branch: IllegalTransition escapes `Runtime.handle`.
- src/hadavin_sdk/runtime/agent_loop.py:688-694 (the `except ProviderError` branch), with `_RunMeter.settle` at :266-273 and `runs.py` (`NEEDS_PERSON` is FINAL).
- Scenario: provider refused before any response (marked, e.g. HTTP 401), so the gate settles at 0 (rule b). That settle fails with a connectivity error (store down / OSError). `_RunMeter.settle` calls `_settle_failed`, which ends the run `NEEDS_PERSON limits.limits_unavailable` and stores it in `run_meter.ended`. The gate re-raises the ProviderError. The loop then calls `_abstain(run, NEEDS_PERSON, "provider_error")`, `_to` reads state NEEDS_PERSON, `check()` raises `IllegalTransition`, and it propagates out of `handle()`. Money is safe (hold stays at worst case, run ended), but the caller gets an exception instead of a Run, and the abstain card is lost. The non-ambiguous (rolled back) case is fine: add_cost(0) returns None.
- Fix: in the ProviderError (and any `except` that follows a chat) branch, `if run_meter.ended is not None: return run_meter.ended` before `_abstain`. Add a test: marked ProviderError plus a settle that raises OSError.

## Minor

m1. An unbound model-calling detector is still constructible and callable. `guard/judge.py:84-87` `JudgeDetector.check` calls `self.llm.chat` on whatever client it holds; `app.build` gives it the raw llm (app.py:266). The runtime only reaches it through `_bound_detector`, but `app.py:264-270` sets `summary_detector = detector` when the caller passes a custom `detector=`; a custom judge in that argument would run unmetered in the approval summary (`approvals/requests.py:38`, `cards.py:79`). Fix: make `JudgeDetector.check` refuse when `self.llm` is not a BoundGate (the eval path passes a bound gate), or have `app.build` strip any detector with `bind` from `summary_detector`.

m2. Judge calls inside a run settle through a plain `limits.for_agent` meter, not `_RunMeter` (agent_loop.py:466-474). A rolled-back settle failure there leaves the hold at worst case (safe) but the rule "book the run cost directly" does not run, so the run cost is under-counted, and an ambiguous failure does not end the run. Fix: use a `_RunMeter` for the detector too (keep its `ended` and check it after `injection_check`).

m3. `Runtime._gate` (agent_loop.py:442-444) returns a pre-built `ModelGate` unchanged and ignores `meter`. A ModelGate passed as `llm` to Runtime then bypasses `_RunMeter` (no settle-failure rule) and uses its own meter. Also nothing stops a raw `Limits` or `Budget` being passed as `ModelGate(meter=...)`: the gate calls `settle(reservation, usd)` without an agent id, `Limits.settle` requires `agent_id=`, the TypeError is caught as `settle_failed`, and every hold stays at worst case forever. Fix: `ModelGate.__init__` should reject `Limits`/`Budget` (require an `AgentMeter` or a Meter whose settle takes no agent), and `_gate` should refuse (or wrap) a pre-built gate in the live runtime.

m4. `_bound_detector` (agent_loop.py:469-476) turns a missing mapping into an empty `RunMap`; the audit row then says `map_enforced_empty` although no run map was supplied. All three current callers pass a map, so this is latent; make `mapping` required there so a forgotten map is a TypeError, like `bind`.

m5. `Reply.cost_usd` unusable-amount check in the loop (agent_loop.py:703) is dead code now that `Reply` validates `cost_usd` on construction (models.py:377-381); a cost that `check_spend_amount` accepts but the gate's `usable_cost` rejects is not caught by it, so the call is booked at worst case with run cost 0 and the run goes on. Acceptable (day counter over-counts), but state it in ii-meter.

m6. defaults.py gets two stray blank lines (comment block) from the merge; cosmetic.
