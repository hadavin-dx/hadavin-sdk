class SpendRefused(RuntimeError):
    """Do not call the model. reason is one of:
    kill_switch | daily_budget | monthly_budget | limits_unavailable | bad_amount | usd_cap"""
    def __init__(self, reason: str) -> None:
        super().__init__(reason); self.reason = reason

    def settle(self, reservation_id: str, actual_usd: Decimal, *, agent_id: str) -> Decimal: ...

Provider errors: `ProviderError.refused_before_response` (class attribute, default False; set True only in llm/retry.py with_retry) marks an error where the provider refused before any response: every attempt was a refused connection or a failed name lookup, or the final answer was HTTP 400, 401, 403, 404, 413 or 422 (openai_compat narrows these never-sent statuses to 401, 403, 404, llm/openai_compat.py:78) with no earlier attempt answered or timed out. What the gate can rely on:
1. reserve returns a reservation id only after the worst case is booked. Any exception from reserve means: do not call the model. SpendRefused.reason is the audit error code. An unknown agent raises KeyError (still no call).
2. worst_usd must be exactly a Decimal, finite, 0 or more and below 1000000000. A float, bool, int, None, NaN, Infinity or negative value raises SpendRefused("bad_amount").
3. settle returns the overshoot, max(0, settled minus reserved), taken from the STORED row: the first settle wins; a repeat with another amount returns the first result and changes nothing.
4. settle with an unknown reservation id raises NotFound (a KeyError subclass) from both meters. `settle` takes a REQUIRED keyword-only `agent_id` (F-store I1: there is no agent-less settle; omitting it is a TypeError, a None or empty one a ValueError). `settle_for(agent_id, reservation_id, actual_usd)` is the same call with the agent first (the gate should call it with the agent it reserved for): a reservation of ANOTHER agent raises the same NotFound and changes nothing. settle with a bad amount raises ValueError.
5. Cost known (also 0 for a request that was refused before sending): settle(rid, cost). Cost unknown (timeout, abandoned thread, crash): either settle(rid, worst_usd) or do not settle; both keep the worst case booked. Never settle lower than the truth.
6. If settle raises (store down after the call), return the reply anyway; the worst case stays booked. Never retry reserve.
7. One reserve covers the whole chat call including the client's own retries; so worst_usd covers the system prompt, messages, tool schemas, documents (counted as the bytes that are actually sent: an invalid byte of a document becomes a 3-byte replacement character), the output schema counted twice, plus a fixed overhead (defaults.WORST_CASE_OVERHEAD_BYTES, 4096 bytes), at the input price (at most one token per byte), plus route.max_tokens at the output price, times the client's max_attempts (doubled when an output schema is passed). If no price can be worked out, the closure raises SpendRefused("bad_amount"): no call. core-b supplies this as the worst_case= callable at each install site (helper worst_case_usd in src/hadavin_sdk/llm/common.py).
8. The settled cost is added to the run's cost by the store (when run_id was given). The gate and the agent loop must not add it again; nothing calls Limits.charge for a gated call.
9. KILL-SWITCH WINDOW (ORDER 020 m1, stated on purpose): the stop-state read and the booking are two steps, not one transaction. A stop committed between them lets ONE more reserve through per caller already past the read; a stop takes effect at the next reserve of every caller. A call already reserved or running is not cancelled by a stop. Operators who need a hard cut also stop the processes. The Budget meter (command-line eval and replay) does not read the stop state.
10. An open reservation older than the expiry age (the larger of 3600 seconds and the stuck-run age) is closed by a tick step at its worst case; a later settle can only raise the booked amount, never lower it.
11. Reply.cost_usd is a Decimal only when the cost of the call is known; None means unknown (the provider reported no usage, or an earlier attempt of the call may have been billed with an unknown cost: a timeout, a reset, a 5xx, a 429). The gate then returns the reply and does not settle: the worst case stays booked (point 5). A call that needed retries carries the sum of the known costs of all its attempts when every earlier attempt was refused before any response (cost 0) or returned a measured usage; otherwise None. Reply.attempts (default 1) is the number of requests the call took; it is audit only and never prices anything.

Stated limits found by the hostile re-read (2026-11-20):
11. Midnight: the day is chosen from the clock after the stop-state read and before the booking; a reserve that waits on a row lock across 00:00 UTC books and checks the previous day's counters.
12. A lost commit acknowledgement: if the database commits a reservation and the connection drops before the caller sees it, reserve fails with limits_unavailable, the booking exists and no id was returned. It closes only by the expiry step, and the counters never go down, so the worst case of a call that never started stays counted for the rest of the day and month. A flapping network can use up a tight daily cap this way. The remedy is the release command (ORDER 020 M1, migration 0008): `hadavin-sdk release-expired AGENT --day D --by WHO` under the dedicated release login lowers only EXPIRED holds of that day to 0 and moves both counters by the same amount, audited first. Invariant 4 now reads: after expiry the booked amount goes down only through that audited command. A settle that arrives after a release returns the stored row (applied False) and books nothing: a call that really was billed after its hold was released is then not counted, which the operator accepts by running the command (release only holds of calls known not to have been billed).
13. Streaming: no adapter streams today. A future streaming adapter needs its own rule for the refused-before-response mark (a late error after a partial answer is billed); until then the mark must not be set for streamed calls.
14. A lock holder that stops (a stopped process, a network partition the server has not noticed) can make a reserve wait; the store connection sets a lock timeout so the wait ends with limits_unavailable (fix round 3); a statement's own run time is not limited.
