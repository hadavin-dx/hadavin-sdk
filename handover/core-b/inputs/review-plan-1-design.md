Alternative: integration branch is the TEST vehicle: merge in dependency order with a tag per step (store contract, money, stop state, text, ledger, door, gate) so one failed run bisects over ~7 points; land on main as sequential ready PRs cut from the same history in the same order; equality test = tree hash (`git rev-parse main^{tree}` equals the tested integration tree), since squash changes SHAs. - D5 Money invariants missing (only T1 named). Required: (1) atomic check-and-reserve (conditional row update `UPDATE ... WHERE usd + est <= cap RETURNING` in the same transaction as the reservation insert, or per-agent advisory lock); (2) T1 must use 50 separate connections/processes on real Postgres (one store object is serialised by a Python lock; memory store proves nothing); (3) crash rule: expired reservation settles at reserved worst case, never zero; a named tick step sweeps expired reservations; (4) settle idempotent by reservation id; overshoot recorded and blocks next reserve; (5) day and month reserved in one transaction; state the midnight rule; (6) zero or missing price refuses the call; store unreadable refuses at every site. Verdict: reservation table (P4b1) is the sounder design; implement the cap check as the conditional update.
- D7 Door guarantees unspecified and one impossible as written: (1) "effect in one transaction" only holds for a row in the same DB: use receipt + work item (transactional outbox), effect later with the receipt key, `unknown` path for timed-out writes; (2) 2xx only after commit; retry returns the STORED verdict; (3) same key different payload = conflict (payload hash), never silent dedupe; (4) replay inside 300 s safe only if the dedupe key is in the signed body and comes from the source event; (5) retry later than 300 s without re-signing would be refused and lost: T5 needs a retry-after-six-minutes case (n8n behaviour UNVERIFIED); (6) secret rotation: two valid secrets, one per sender; (7) ordering: declare unordered or carry a per-key sequence; (8) permanent key + payload hash + verdict, payload itself under ordinary retention (erasure); (9) "no lost message" is "once received: never lost, never doubled"; loss before receipt needs the n8n error workflow in the pack. Design: n8n is the public receiver and verifies vendor signatures; core exposes ONE private endpoint = authenticated ledger claim, reusing hmac_v0 and the handle_slack_action shape (no second signer, no new server).
