## Exact rewordings to paste

R-1: "The trigger worker handles at most `triggers.max_running` runs at a time (default 4; set it to 1 until spend can be reserved before a model call, because parallel runs of one agent can pass a budget, and the worker logs a warning at start when the value is above 1). A further event that arrives while all slots are busy is not queued: the worker holds the request for up to `ack_wait_s` (default 5 seconds) and then answers 503, and nothing is stored for it. A run can last minutes, so the sender must retry a 503 over a span longer than its longest run and sign each retry anew, because a signature is refused 300 seconds after its timestamp."

R-3: "An answer 200 means the run exists and is past RECEIVED (stored, not started) and WORKING (the agent is running); it does not mean the run has ended. The states PLAN_READY (a plan exists), WAITING_FOR_APPROVAL (a person has yet to decide), EXECUTING (the approved write is being made) and VERIFYING (the result is being checked) are also answered 200."

R-4: "If the worker stops or crashes during a run, the run is not continued. The tick later sets it to NEEDS_PERSON (a person must look at it) with reason `interrupted` (`outcome_unknown` if it stopped while executing, `verify_interrupted` if it stopped while verifying). The same key then answers 200 NEEDS_PERSON for good and is never run again automatically; a person decides, and a re-run needs a new key. The tick must run in the same deployment, or such a run never reaches a person."

R-5: "The worker's built-in web server has no connection cap and no TLS, and a slow client holds a thread. It listens on 127.0.0.1 by default. The client's reverse proxy in front of it must buffer whole requests, cap connections and request size, and end TLS. Starting the worker with `--allow-non-loopback` and a non-loopback `--host` exposes it without that protection."

R-7: "The request body limit is `triggers.max_body_bytes` (default and maximum 524288, which is two times `MAX_DOCUMENT_BYTES`; it cannot be set higher). JSON escaping can make a document up to six times larger in the body, so a document under the document limit can still be answered 413."

S-1: "Never use the approvals secret as a trigger secret, or the other way round. Both are checked with the same signing recipe and the header names are not part of the signed text, so whoever holds a trigger secret equal to the approvals secret can forge an approval click. The app start refuses a sender secret that has the same NAME as a secret the approvals channel uses, but the code does not compare the secret VALUES, so one value stored under two names is not caught."

S-7: "The built-in server listens on IPv4 only; an IPv6 address for `--host`, including `::1`, is refused at start. Use 127.0.0.1 or localhost."

C-1: "**Signed trigger endpoint (new).** `python -m hadavin_sdk.triggers.worker` serves `POST /v1/trigger`: a sender signs `{key, document}` with HMAC-SHA256 (the same recipe as the approval callbacks, under the `X-Hadavin` header prefix) and the worker starts at most one run per (tenant, sender, key). Answers: 202 while the run is RECEIVED or WORKING, 200 for any later state (not only ended ones), 409 for the same key with another document, 503 when busy or the store is down. At most `triggers.max_running` runs at a time (default 4; the worker warns at start above 1 while spend is not reserved). Limits are in README.md and SECURITY.md; the n8n files under `n8n/` are an outline that was not run in n8n."
