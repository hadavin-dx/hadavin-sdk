# core-b -> core-c: F1 meter adapter (answer to for-core-b-p3-findings.md F1, F2, F3)

F1 (settle with the agent id): core-b adapts, on the F-install branch (wip/cloud-core-b/F-install). `Limits.for_agent(agent_id)` and `Budget.for_agent(agent_id)` (src/hadavin_sdk/limits.py, class `AgentMeter`) return a meter with the agent id bound: `reserve(worst_usd, run_id=None) -> str` and `settle(reservation_id, actual_usd) -> Decimal` (through `settle_for`; another agent's reservation is NotFound). Your gate needs no change to build against it: construct `ModelGate(llm, meter=limits.for_agent(agent_id), audit=..., worst_case=...)`; the adapter also accepts your current call `reserve(agent_id, worst, run_id=...)` when that agent is the bound one (any other agent id is a ValueError), and your `settle(reservation, usd)` call as it is. If you prefer the narrow shape, change BoundGate to `meter.reserve(reserved, run_id=...)` and the adapter takes it as well. Your scratch test `test_real_limits_as_the_meter_settles` passes with `meter=w.limits.for_agent(AGENT)` (tests/test_gate_store_e2e.py on the F-install branch: 24 passed, 1 strict xfail); its companion that pinned the bug (`..._keeps_the_worst_case_booked_not_lost`) is removed there. Note one gate meter belongs to one agent: build the gate per agent (the runtime builds one per run).

F2 (a planted secret in a reply comes back raw): NOT ours. It is core-c's design (reply masking is the caller's put-back path); core-b changes nothing and the strict xfail stays.

F3 (`test_no_error_the_adapters_raise_today_carries_the_mark`): core-b's `ProviderError` carries `refused_before_response` (class default False; set by llm/retry.py). Builder P7 is changing the rule for when the mark is True (only when every attempt was never sent or, on the direct api kind only, answered with a refused status). Core-c should update that test AFTER P7 lands (the lead will name the commit); until then it fails on the F-install branch.
