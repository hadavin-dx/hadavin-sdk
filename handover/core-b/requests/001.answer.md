## New rules since DRAFT 2 (and 3)
1. Path-shaped secret names are refused, not folded: a name with a "." or ".." segment or a leading or trailing "/" (secret_name.is_path_shaped). For sender names the pattern/".." rule refuses it at load; for any OTHER name in the config check_senders and secret_name.collides fail closed (collides returns True).
2. Canonical fold order (secret_name.canonical_secret_name, re-exported by platform_secrets): every run of characters outside [A-Za-z0-9] becomes one "_" FIRST (so every non-ASCII character is a separator and a Unicode case fold such as the dotted capital I or the Kelvin sign cannot become an ASCII letter), THEN lower case, leading and trailing "_" stripped. Supersedes DRAFT 3's "lower-case first". db-pass, DB_PASS, db.pass collide.
3. Floors: max_body_bytes at least 1024 and ack_wait_s at least 0.1 (so max_body_bytes: 1 or ack_wait_s: 0.0005 fails to load). DRAFT 2 had "above 0".
4. str-subclass rejection in the reader (type(name) is str), unhashable argument is a PermissionError, not a TypeError.
5. Reader is a closure: stated limit above.
6. A ConfigError from a triggers block has no cause chained (from None).
7. Carried from DRAFT 3 and still true: a sender whose agent is not live refuses the whole app start; after start nothing is re-read, so an agent retired later keeps being served until restart, then the start is refused (retire only after removing or repointing the sender; Runtime.handle checks only that the agent exists, so the worker must itself refuse what it no longer wants to serve). Documented in CHANGELOG.md as stated limit (d).
8. Start order: sender secrets are checked in their own step first.
