- message = an e-mail message (top of this file). e-mail address = the address a message goes to. Never "mail" for the e-mail address. web address = what a browser shows in its address bar.
- mail service = the service that sends e-mail messages. stand-in mail server = our own small test program that receives them and can cut the connection on purpose.
- mail step = the step in the n8n flow that sends the lead's e-mail message.
- CRM = the program where a company keeps its customer contacts (the customer list). real CRM service = a real vendor service (HubSpot in the real flows). stand-in CRM = our own small test program that acts as a CRM.
- lead = see 0-words: "the lead" = the Claude session that decides; "a made-up lead" = one made-up person who asked for contact. lead ID (lead key in the table) = the code that names that made-up person; table row = the row of the lead table for one lead ID; the same lead sent twice has the same lead ID.
- re-pin = see 0-words (the lead re-points the demo to the new core commit and checks the take files before the filming).
- archive = the CRM vendor's own word (HubSpot's) for removing a contact. The desk code's comment calls it "delete into the recycle bin" (trace-desk-repo.md, crm_hubspot.py:492-499). Whether a removed contact can be restored, and for how long, no file says: UNKNOWN. This file uses delete for removing a contact and uses archive only when quoting a file or the vendor.
- harness = a test runner program (a program that runs a check from start to end). The old desk harness = run_real_check.py of the desk repository, which deletes the contacts of its run when started with --cleanup. The take does not use it.
- claim and claim row: see the top of this file. A sentence of the video is never called a claim here.
- door = one of the two ways a lead enters: the form entry (path mf-form) and the e-mail-style entry (path mf-hook).
- claim row = n8n reserves something so that no other run does the same thing. The claim row is the row that n8n writes in the lead table when it starts a lead; a second claim row for the same lead ID is refused ("ON CONFLICT DO NOTHING" in the insert). The alert hold (called "claim window" in older files) is the time (720 seconds for an alert) during which no other check may send the same alert.
- lease = how long n8n waits before another run may take over a lead whose run stopped (45 seconds in the shipped flows). The takeover is done by the 30 s check, so a lead is picked up at the first 30 s check after the lease ends. On screen: "setting: lease 45 s".
- window = only a program window on the screen (for example the window that is closed with Ctrl-C in row B-215b); the gap between two steps of a flow is called the gap, and the older words claim window mean the alert hold (above). check = alone, only a test step that a person or the laptop agent runs and the lead reads (P1 to P4c, the positive control, the model-cost check, the psql check); what n8n does is always named in full: the 30 s check (the recovery flow's run every 30 seconds), the step CrmIdOk, the claim-row refusal of a repeat. owner = alone, only the studio owner (section 0-words); the person who receives the alerts is always called that. the lead = alone, only the Claude session; a made-up person is a lead (no the) or a lead ID. Round 12 read M19: these four words keep these meanings everywhere in this file and in CLAIMS-TABLE.md.
- take = one filming run of the video. recording = the finished video of one take; "this recording" means the video being made. screen capture = what the laptop records while the take runs.
- take scripts = n8n_start.sh, n8n_kill.py, run_real_check_n8n.py, n8n_drive.py and the post-twice script (ORDERS.md line 156, Q27 item 1, and line 171, Q30 item 3); the lead copies or writes them at re-pin; not in this checkout. prepared send note = the post-twice script; prepared stop note = n8n_kill.py with n8n_start.sh; prepared screen set = see step 10 of section 0c.
- screenshot = a still picture.
- flow set = one group of four n8n flows (form entry, e-mail-style entry, recovery, CRM and e-mail sending sub-workflow). real-v5 = the flow set in n8n-flows-real-v5 (real mail service and real CRM service), used for scenes 1 to 4, the only set in this video. film-v5 = the flow set in n8n-flows-film-v5 (stand-in CRM, stage service and stand-in mail server), used for scenes 5 to 11 and NOT in this video. The closing card (scene 12) uses no flow.
- stage service = the small program that sorts each lead.
- unknown = the state value written in the lead table when we cannot tell whether the e-mail message went. The reply that n8n gives back to the sender carries the same word in its field verdict. Outcome is an internal word and is not used for viewers.
- two people called "owner": the studio owner (section 0-words) and the person who receives the alerts (the alert recipient; DESK_ALERT_TO in the real flows). In text for viewers and readers I write "the person who receives the alerts". "Owner" alone is used only inside quoted current sentences.
- lead table columns (name on screen): lead key (lead_key), state (state), attempts (attempts), mail sent (mail_sent), alert sent (alert_sent), last change (updated_at). "Mail sent" means the mail step was started, not that the e-mail message arrived. State review = the e-mail address was invalid; it is only a word in the state column. It does not mean anyone has checked or approved the lead.
- RELAYED, UNTRACED, UNCHECKED, UNSUPPORTED: see the top of this file and the line above in section 0-words.

## How to read the tables
- "Paste this" holds ONE clean string in double quotes (the quote marks are not pasted): the words that go in one place in one go (one caption, one spoken passage, one card line, one file line). It has no label, no condition, no placeholder and no alternative. If a cell reads NO PASTE, nothing is pasted; the note says why. If a cell reads DELETE, delete the current sentence. A row with two places or two uses (voice and screen, default and D1 variant, two file lines) is split into rows with a letter (a, b), one string each. Conditions are in the last column; section 0b says what happens while a condition is open.
- A paste string may be only part of a line when the row is FILE EDIT and the "exact current sentence" cell starts or ends with three dots, or shows only part of a sentence: then the string replaces exactly the part shown, and the rest of the line stays.
- "Goes where": SCREEN = text that appears in the video. VOICE = spoken by the narrator. CARD = a line on the closing card. PAGE = a written statement for a reader of the demo page. FILE EDIT = the replacement text for a line of a working file (run sheet, plan, README); never said and never shown.
- Where to paste. SCREEN and CARD strings are typed into the video editing program the lead uses (the program is not named in any file I read: Q-G). VOICE strings are read aloud by the presenter or typed into the narration text (also Q-G). On a CARD row the words Line 1, Line 2 and so on are only the names of the lines in the run sheet; the card prints just the pasted string. A FILE EDIT string replaces the old sentence in the file named in the column "line" (or "file:line"): the files named R: are handover/demo/VIDEO-RUNSHEET.md, P: is handover/demo/n8n-flows/PAGE-STATEMENTS-V4.md; in section 3 a path that starts with flows-audit/ is under handover/ (for example handover/flows-audit/inputs/); every other file is under handover/demo/ (PLAN = PLAN-4-NLITE-FROM-LEAD.md; DOUBTFUL-SCENE.md is handover/demo/DOUBTFUL-SCENE.md; ONS = handover/flows-audit/inputs/OWNER-STEPS-realrun-v3.md, so ONS:131 is line 131 of that file). Only the first line of an edited sentence changes; no program is needed beyond a text editor.
- Section 2 holds PAGE and FILE EDIT rows. Section 3 holds only FILE EDIT rows: it has no viewer sentence. SCREEN, VOICE and CARD rows for this video are in section 1; rows for the later video are in section 7.
- Everything for the lead (sources, conditions, which line of the run sheet it replaces, what to say instead if a rehearsal fails) is in the last column.
