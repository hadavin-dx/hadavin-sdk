## Pin procedure (the one place for the pin file; check 1, GO row 4 and FIX-PLAN steps 4 and 9 point here)
Everything below is read in `flow-check/take_check.sh` and `flow-check/take-warns.pin`. The shell and python3 blocks were run in a scratch folder on made-up data (a scratch pin file and a scratch git repository); `take_check.sh` itself was not run here.
1. **What the pin is.** There is exactly one pin file in use: `flow-check/take-warns.pin`, next to the script. It holds a `# reviewed by:` line, a date line, a line `# flows sha256 ...` (the sha256 of the four flow files the pin was written for) and the WARN lines (a WARN line is a warning the checker prints and a person has read). The script compares the WARN lines and the sha256 of the folder it checks with the pin; a difference exits 4 (`!!! THE WARN SET CHANGED` or `THE FLOW FILES DO NOT MATCH THE SHA-256 WRITTEN IN THE PIN`). No option picks another pin file: setting `TAKE_CHECK_WARN_PIN`, `TAKE_CHECK_FLOWS` or any other `TAKE_CHECK_` variable outside tests is exit 4 ("NOT allowed outside tests"); only `TAKE_CHECK_TEST=1`, set by the test scripts, lifts it, and then a run that would have passed exits 5, which is a test run and never a take check. So the override is never a route to a new pin.
2. **Order of runs (one file, so order matters). Pin first, then the check:** P1a, P1b and P1c (step 3) make and commit pin 1, THEN Block R4 runs. As committed the pin holds the WARN set of the UNFILLED patched copy. So: (a) run check 1 on the unfilled patched copy `$FLOWS` with pin 1 installed and KEEP that log (GO row 4); (b) the first run on the export (Block R4b-1) also uses pin 1 and exits 4 on purpose; (c) only then make and install pin 2, the export pin (step 5, P2a to P2c), and run RUNBOOK step 13 (e) into `$LOG2.final` (counts: Block R4f). After pin 2 is installed, the same command on `$FLOWS` exits 4 (its WARN set and sha256 differ). To repeat a run on the unfilled copy, restore pin 1 first with Block R4r; to go back to the export pin, the first line of Block R4b-2 restores pin 2.
