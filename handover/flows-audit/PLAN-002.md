## 4. Column schema (identical in all lanes; one table per flow file, heading exactly `### <path relative to handover/demo> (<n> nodes)`; every node a row, disabled nodes included; no sticky-note nodes exist in the 52 files)
Machine columns (first 10 cells, produced by the script, never edited): `# | node | type | parameters (masked) | downstream (out,node) | onError | retry/tries/wait | disabled | credential | reachable`.
Judgement columns (13, `TODO` in the skeleton, the lane replaces TODO only): `purpose | trigger or upstream | inputs | outputs | error path | idempotency key | writes (store, table or file) | secrets (names only) | identity it runs as | logs to | what a person sees | stop condition | finding id`.
Vocabulary: reachable = Y | ENTRY | NO-INCOMING | UNREACHED-FROM-TRIGGER (a settings.errorWorkflow value is a workflow id, so it is noted in the lane header, not per node); retry = retryOnFail/maxTries/waitBetweenTries; any other cell = a sentence, `none` (checked, nothing) or `UNVERIFIED: <what needs a runtime>`; evidence cited as `<path>.json:<NodeName>` or `<path>:<line>`. Secret-looking values and personal data are never copied: `<masked>`. Masking rule = tools/mask_patterns.json exactly: parameter keys matching token, secret, password, passwd, apikey, api_key, authorization or bearer; Bearer text and connection strings with credentials anywhere; a string value that is ENTIRELY one 32+ character key-like token; expressions starting with `=` are searched for Bearer text and connection strings only; git shas are allowed; URLs, SQL text and credential NAMES are copied.
FINDINGS.md columns: `id | severity | class | where (file + node, or file:line) | evidence | proposed fix (patch file or OWNER/IMPOSSIBLE reason) | status`. Id = F-001, F-002 ... numbered by the lead after de-duplication. Classes: duplicate, dead, inconsistent, claim-not-backed, store, security, ops, unverified.
Severity: Blocker = a take or client could lose or double-apply a lead or mail, leak a secret or personal data, or a published claim is false. Major = wrong behaviour on a failure path, a second store for one job, a claim with no backing node. Nit = naming, leftovers nothing runs, wording.
LEDGER-ROWS.md (9 columns, per the blocker ledger rule): `id | source | severity | area | summary | status | fixing artifact | verified-by | date`.

## 5. Script interface (built by L0, done; tested)
`python3 handover/flows-audit/tools/dump_nodes.py` with: `table <json>...` (one table per file, header `### <path> (<n> nodes) ...`, machine columns, masked); `skeleton <json>...` (table plus the 13 judgement columns as TODO); `counts <root>` (per-file node counts, TOTAL, parse failures; folder n8n-tests excluded); `diff <a.json> <b.json>` (keyed by node NAME; compares type, typeVersion, parameters, credentials, onError, retryOnFail, maxTries, waitBetweenTries, alwaysOutputData, disabled, edges; prints REMOVED, ADDED, CHANGED and edge lines, then `settings equal: True|False`; position and node id ignored); `check <json>...` (exit 1 on unparsable file, duplicate node name or dangling edge). Entry = an ENABLED node whose type ends webhook, scheduleTrigger, executeWorkflowTrigger or errorTrigger, or contains "trigger" (respondToWebhook is not an entry). Dead-node rule: no incoming edge AND not an entry AND not reached from an entry; a disabled trigger is not an entry.
Tests: `python3 handover/flows-audit/tools/test_dump_nodes.py` = 8 cases (orphan NO-INCOMING; executeWorkflowTrigger ENTRY; errorTrigger ENTRY and next node Y; password and 40-character value masked; value-only secrets (Bearer text, connection string, whole 40-character token, expression Bearer) masked while a URL with a 40-character path part and SQL text are copied; counts exclude n8n-tests; diff reports ADDED and CHANGED and a no-change case; check exits 1 on dangling and unparsable, 0 on clean).
