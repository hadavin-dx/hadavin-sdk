## NEEDS LEAD (planned by the audit, lead to confirm; NOT implemented)
Q1. Protected pin (design M1). Plan: make flow-check/take-warns.pin a protected path: a CODEOWNERS entry naming the person who signs the pin, plus branch protection on the main branch that requires that owner's review for changes to that path, plus a check in take_check.sh that exits 4 "pin is not the approved version" unless the pin is tracked and `git diff --quiet origin/main -- flow-check/take-warns.pin`, failing closed when git or origin/main is not available. Exact cost: one CODEOWNERS file in the repository, one branch-protection rule (a repository setting only the owner can change, and this repo's rules say a cloud session never changes branch protection), about 10 lines in take_check.sh, 4 to 5 tests (pin differs from origin/main, pin untracked, no git, no origin). Side effect: the take can then only run on a machine with the repository and its origin/main fetched. Question: does the owner want this, and who is the named signer?
Q2. Ack hash. Plan: the reviewer line becomes `NAME, DATE, ack <first 8 hex of sha256(WARN-lines hash + flows sha256)>` and the script recomputes it. Exact cost: about 6 lines in take_check.sh, 3 tests, one more thing the signer must copy. What it does: ties the signature to the exact WARN lines and flow files. What it does not do: stop an agent that can read the hash and type it (the design review says the same). Question: worth it without Q1?
