F1 BLOCKER (34, 407, 423, 434, 435) build digest and start-up refusal: the program computes its own digest and runs the check, so a modified build reports the expected digest or skips the check; "stops a builder or an assistant session" (407) false. Digest items: config holds pinned key + client code + notes path so editing config changes digest and key together; evidence on tested artefact can never match per-client config digest; container image digest cannot be computed from inside; digest omits installed dependency files, .pth, sitecustomize, environment. Fix: verifier outside the attested program (deploy admission step / separate verifier not written by builder); registry image digest as build identity + lockfile hashes; split config into security-relevant (signed) and ordinary parameters; reword "binding" to "drift from approved artefact detected by a verifier the builder does not control"; keep "hold is a promise, not a control" until built.
F2 MAJOR (407, 436) approval-key custody: touch protects key, not what was displayed; signing tool on the laptop where agent sessions run can swap the file; revocation list has no version/monotonic counter (replay of older list); expiry uses program's clock; no key loss/succession/rotation. Fix: signer hashes exact bytes it shows (key display or separate-user process); monotonic counter refuse lower; pin key set (current+next), write key-loss procedure.
F3 MAJOR (405) CI conditions: condition (3) says agent-written code never runs where deploy/migration-owner credentials are held, but the migration job runs migrate() (agent-written) as table owner (263, 405); table owner can disable audit triggers/rewrite grants (52). Fix: migration-owner credentials only in a job running a human-reviewed digest-pinned migration artefact, reviewer signs exact migration files; split migration owner into schema role and grant role (neither superuser); reproducible build/image attestation; if deployer is a client person say the hold is advisory there.
F4 MAJOR (243, 264, 409(b)) liveness: tick_state timestamps are writer-supplied (postgres.py:470-471) so a hostile writer can write a future time; a SQL reader cannot verify signatures (264, Decision 29(b)) so it is a program not a query; outbox read must grant event_id and created_at only, no body; alert path outside repo with no owner (295), a stopped reader is silent. Fix: database-side now()/trigger, column not writable by the login; small verifier program with SELECT on named columns + public key; heartbeat to second channel.
F5 MAJOR (214, 380, 421, 432) purge program: agent login holds UPDATE on runs (237) so hostile code can age/re-state a run and the purge deletes tool_calls and plaintext map early; hold_run_ids table writer decides what is held (design not written); purge login has no audit rights (246) so deletions leave no trace. Fix: eligibility from insert-once database-set timestamps not runs.updated_at; hold list through a login the agent lacks; purge writes audit event (count, id range) before deleting via drain path; per-run row cap + alert; negative test agent changes state/updated_at and purge still refuses.
F6 MAJOR (210, 242) checkpoint(): reads only last row and signs (seq, hash) (chain.py:303-309), never recomputes links from last signed head; signer login holds SELECT (seq, hash) only. Fix: recompute chain from last verified checkpoint to head, check previous signed seq row still has signed hash, refuse/alert/red liveness on mismatch; widen signer grant deliberately and test; state checkpoint attests only "this head was seen".
