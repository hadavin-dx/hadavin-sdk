# F6-AUDIT: the mf-hook entry (the e-mail-style webhook door), static audit

Date: 2026-11-16. Static read only. Nothing was run in n8n, Postgres, HubSpot or SMTP, so every n8n behaviour below is UNVERIFIED until a laptop test. Severity rubric: FINDINGS.md line 27 (severity = what happens in the filmed take; not reachable in the take = Nit, and the row says "a Major for a client build" where it would be one). Architecture checklist: ARCHITECTURE-AUDIT-CHECKLIST.md section 2 (workflow walk, single dependency, least privilege, failure paths).

## 1. Area and why chosen

Area: the mf-hook door (`n8n-flows-real-v5/mf-hook.json`, same in `n8n-flows-film-v5`; built by `n8n-mainframe/build_mainframe.py:77-95`, called at :121), meaning its input field names, its reply contract, what a hung or failing sub-workflow does to the caller, and what a repeated key does.

Why chosen: (a) no FINDINGS row, lane or lanes13 file checks the hook door's own field names; rows F-009, F-036, F-017, F-010 and F-002 cover it only as "same as mf-form" (auth, copy, credential, empty key). (b) The run sheet and SCENE-FLOW-MAP name only the form door in scenes; `grep mf-hook` in VIDEO-RUNSHEET.md finds nothing. (c) What the tests cover (corrected after review): `m0()` (mf.py:119-128) loops BOTH doors (mf.py:121-124), posts each key twice and asserts verdict `new` then `done` with `repeat: true`, 1 CRM row, 1 mail, 1 model call. So the hook door's plain case and its repeat case ARE tested, on the test-built flows (not on the take build). NOT tested on the hook door: an invalid or display-name address (the review case, mf.py:125-126, uses mf-form only), a missing or empty `message_id`, a missing key, and the kill and error paths (K1-K5 use mf-form; the 10-at-once burst, mf.py:129-134 in `m1()`, uses mf-form only).

Already covered, not repeated here: no authentication, size or rate limit (F-009, F-036); mf-form and mf-hook are copies (F-017); one shared Postgres and SMTP credential (F-010); empty lead_key and a bare 500 when Claim fails (F-002); placeholder ids (F-029); a review-state lead is never alerted (F-031).
