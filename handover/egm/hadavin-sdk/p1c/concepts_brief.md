## Overview

The library comparison (lead-reading-1.md) found no free redactor that beats ours on our corpus, so the decision is to fix our own gaps, not to adopt a library. The one choke point `runmap.redact_text` (`guard/runmap.py:464`) still lets 6 of 30 hostile inputs through and leaves the last label of two internal host names visible. P1c closes the 3 base64 misses with a decoded view in that same function, masks internal host names whole, writes the bare-number case down as a decided property, and makes the corpus a permanent test so any later improvement or regression shows in CI. It is a redaction and security package: extended review, no round cap.

## Analysis (author's stress test; not Goldfish)

**What is wrong or risky, first.**
1. **The decoded view would be skipped by today's gate.** `redact_text` builds its views only when `scan = not text.isascii() or any(c in text for c in "\\%&")` (`runmap.py:491-492`). A base64 token is plain ASCII with none of those characters, so a view added inside `_views` never runs on the very texts it is for. The view must run outside that gate, on every text. A test must pin that (mutant: view put behind the gate).
2. **Strict UTF-8 is a one-byte bypass.** The order says accept only valid UTF-8. Probe (4): one invalid byte in front of the secret makes the decode fail and the token passes. The alternative (decode with replacement, count U+FFFD as not printable, let the printable share reject binary) closes that but lets ~10 percent junk through and changes the order's mutant list. Real design choice: PENDING LEAD 1. The ticket follows the order (strict) and states the bypass as a named limit with a pinned row.
3. **A length cap is also a bypass.** Any maximum token length lets a longer token through unread. The cap is needed (bounded work per candidate), but it must sit above the common real case: Kubernetes Secret values are base64 of a PEM private key, about 4.4K characters for a 4096-bit key (size UNVERIFIED; the builder measures it). So the cap is 8192 characters, and what happens above it (skip and state, or refuse the text) is PENDING LEAD 2.
4. **Depth 1 leaves base64-of-base64 open.** Stated limit, pinned by a spy test; not fixed. Same for the other views: the decoded text gets the plain pattern redactor only, not NFKC/escape views (that would be recursion).
5. **False masking risk is small but real.** A long ASCII word (a class name) is in the base64 alphabet. It is masked only if it decodes strictly to printable UTF-8 AND the redactor then finds something in that text (for example the HIGHENTROPY backstop on printable junk). Probe (2) shows zero cases on our 14 must-keep and 48 must-mask lines; that is our corpus only (home advantage, lead-reading-1.md caveat 1).
6. **The look-alike xfails are owned by the wrong package in the order.** Order 64 item 2 names P1b. By grep, `tickets/P1.md` (P1b: `scan_keyset`, identity keys, same_person) never mentions `redact_text`; the package that changes `redact()` for a NEW look-alike value is P2d-1 (the fold scan, `tickets/P2d.md` problem paragraph, its probe p2 is a Cyrillic e-mail). Also P1c builds AFTER P1b merges, so "remove the xfail in P1b" cannot happen. PENDING LEAD 3: name the rows P2d-1.
7. **Whole-hostname masking collides with BN-24 later.** Two must-keep lines (`*.svc.cluster.local`, `*.compute.internal`) are kept today by `_KEPT_HOST` (`redact.py:809-811`). P5c BN-24 makes `kept_host_suffixes` empty by default, which will mask them. P1c must not decide that; it relays it to P5c. And `kept_host_suffixes` does not exist on main (git grep), so the order's "keep a test with the setting" can only be a strict xfail named P5c (PENDING LEAD 4).

**Lens notes.** *Contrarian/YAGNI:* stdlib `base64` does the decoding; the glue is a loop of about 30 lines plus 4 constants; no new kind, no new module. A library (Presidio, detect-secrets) has no decoded PII view: Presidio extended still misses 2 of 3 base64 rows (lead-reading-1.md line 4 and caveat 2). *Cost:* one linear regex scan per text, plus one `redact()` pass per accepted token (at most 32); the existing time budget check (`REDACT_BUDGET_S`, `runmap.py:496`, `:509`) also runs inside the new loop. *Ergonomics:* no API change; same placeholders. *Migration:* output changes for texts with base64 secrets or internal host names (more masked); CHANGELOG line; no stored data changes. *Observability:* a refusal is the existing `InputTooLarge`/`RedactionError`. *Debt:* the corpus test pins behaviour of the whole chokepoint; P2d-1 and P5c must update named rows when they land, which is the point.

## Goals vs. Non-Goals

* **In-Scope Goals:** base64/base64url decoded view in `redact_text` (bounded, depth 1, fails closed, masks the WHOLE token); internal host names masked whole; bare-number ACCEPTED PROPERTY written in `guard/redact.py`'s module docstring (the redactor's spec on this tree; `guard/` has no README) and pinned by a test; permanent corpus test (30 + 48 + 14 rows) with the span rule of `score_common.py`; 2 strict xfails for look-alike rows; mutants and hostile-input rows for the new view and the hostname change.
* **Out-of-Scope Non-Goals:** a second-layer detector (order 64 item 6); hex, base32, gzip or nested encodings; the view in bare `guard.redact`/`redact_many` (they have no views today either); `kept_host_suffixes` itself (P5c BN-24); the look-alike fix (P2d-1 per PENDING LEAD 3); any library adoption.

## Alternatives Weighed

- **Adopt Presidio or another library for the encoded case.** Rejected by the lead (order 64, lead-reading-1.md): none reaches our must-mask/must-keep numbers; Presidio extended alters 7 of 14 must-keep lines and misses 2 of 3 base64 rows.
- **Put the decoded view inside `_views` and let the redacted VIEW replace the output (as the NFKC view does).** Rejected by author: the gate at `runmap.py:491` skips it for plain ASCII, and returning the decoded view would show the decoded text that was not sensitive; the order wants the whole token masked.
- **Mask only the decoded span (re-encode the redacted decoded text).** Rejected by author: base64 has no clean span boundaries; the leftover characters carry bits of the secret.
- **A new placeholder kind `ENCODED`.** Rejected by author: needs a new label in the redactor's counters (`redact.py:816`, `:906`); the placeholders the redactor already gives for the decoded findings carry the same safety (secret kinds are never stored, `runmap.py:27-29`).
- **Refuse any text that holds a decodable token with a finding (no masking).** Rejected by author: blocks real tool output that only needs one token masked; masking is the existing contract.
- **Mask a bare 8+ digit number in prose.** Rejected by the lead (order 64 item 4): alters must-keep evidence (`Invoice #...` line); money and account values are typed fields.
- **Keep the `.example` suffix (status quo).** Rejected by author, agreeing with the lead: the suffix after `corp`/`lan` is usually the client's own registered domain, the most identifying part of the name; keeping it on purpose is what `kept_host_suffixes` is for.

## Key Decisions & Staging for Next Steps

1. Decoded view runs in `redact_text` after the existing views, on the current output `out`, outside the `scan` gate, inside the existing `try` (`runmap.py:487-523`), so any unexpected error becomes `RedactionError`. Only `binascii.Error` and `UnicodeDecodeError` are caught, and only to say "not a candidate".
2. Candidate: a run of `[A-Za-z0-9+/]` or `[A-Za-z0-9_-]` (one alphabet per token; both `+`/`/` and `-`/`_` in one token is rejected), not inside a longer run, optional `=` padding, length 16 to 8192; missing padding is added when the length mod 4 is 2 or 3, mod 1 is rejected.
3. Accept if strict UTF-8 and at least 90 percent of characters are printable or `\t\n\r`. Run `redact()` (bare, depth 1) with the run's current map; if it found anything, replace every copy of the token in `out` by the placeholders it produced, in order, and keep the new map entries.
4. At most 32 accepted tokens per text; the 33rd raises `InputTooLarge` (fail closed, like `MAX_DECODED_MASKS`, `runmap.py:423`, `:441-442`).
5. Constants in their own `defaults.py` block (order 20 item 5): `B64_MIN_TOKEN_CHARS = 16`, `B64_MAX_TOKEN_CHARS = 8192`, `B64_MAX_DECODED_PER_TEXT = 32`, `B64_MIN_PRINTABLE_PERCENT = 90`.
6. HOSTNAME: after the private suffix (`corp|lan|intranet|intra|localdomain|home\.arpa`, `redact.py:391`) the match continues through up to 8 further DNS labels, not into a call `(`. `internal|local` keep their existing guard.
7. Corpus as `tests/data/redactor_corpus.json`, values that look like keys stored as lists of parts joined by the loader (the AWS documentation key is the only whole literal); gitleaks run on it before commit.
