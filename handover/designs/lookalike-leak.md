## 1. The question, in plain words
A value V that the redactor already knows is replaced by a placeholder when written plainly. The same V written with look-alike letters, other case, one combining mark, zero-width characters inside, full-width forms, or split over two lines goes to the model unchanged. What is the smallest design that makes such a copy impossible to send?
**What "a folded copy" means in this note (exactly):** a text one of whose keys contains a key of V, where a key is one of three things, each made by an existing P1 function (section 5): the **scan key** (`scan_keyset`, P1b: NFKD and the confusables table, case folded in two readings, ALL whitespace removed, class map `z` to `3`, tag texts T0-T3); the **case key** (`fold` of P1a with case kept, all whitespace and U+FFFD removed, `z`/`Z` to `3`; used for names, addresses and tenants); the **squeeze key** (`squeeze` of P1a: upper case, every character other than `A-Z0-9` removed; used in addition for secret kinds). Anything a reader can see as V only through a transformation outside these functions is NOT covered (section 10).

## 2. What I measured on the snapshot (draft-1 throwaway script; made-up 13-character value; not saved)
"Leaks" = the copy still stands in the returned text. Three ways of knowing V: a map handed in (MAP), an earlier `password=` call on the same run map (PW), `redact_many` (MANY).
| copy of V | `redact_text` MAP / PW | bare `redact` and `redact_many` |
|---|---|---|
| plain | masked | masked |
| Cyrillic look-alikes | LEAK | LEAK |
| Greek look-alikes | LEAK | LEAK |
| full-width forms | masked (canonical view) | LEAK |
| zero-width space inside | masked (canonical view) | LEAK |
| one combining mark | LEAK | LEAK |
| upper case / lower case | LEAK | LEAK |
| split over two lines | LEAK | LEAK |
| every byte percent-encoded (Cyrillic spelling) | LEAK (decoded view not matched) | LEAK |
The choke point already closes full-width and zero-width copies, because stage 2 of `redact_text` scans `canonical(text)` (NFKC and Cf removed, runmap.py 274-280) and adopts it when it holds more placeholders (519-520). Bare `redact` and `redact_many` have no stage 2. Cause: `sweep` (redact.py 1294-1333) is a literal, case-sensitive search on the written text, by the rule of `_sweep` (1485-1500).

## 3. Three designs compared
**(a) Span-mask.** Fold, find V's key, map the hit back to written positions, replace only that span. Needs a position map; `_aligned_fold` (redact.py 1082) gives one only for simple folds and returns None otherwise (COR-R4-4), and then the line is withheld anyway. P2d-1's alias index is a smaller version of this idea and drew findings in rounds 3 to 5 (ADV-R3-2, ADV-R3-3, ADV-R3-8, ADV-R5-5, ADV-R5-6). Best fidelity, largest surface. Rejected for v1 (v1.1 LKV-1).
**(b) Refuse the whole text.** After all masking, if a key of V occurs in a key of the text, refuse. No position map. A person looks. One check, three call sites, no change to what the patterns or the sweep do.
**(c) The round-4 fallback (`deny_hit` over the final output).** Gone: `deny_hit`, `prepare_needles` and `id_keyset` are cut from P1 v1 (P1 round 7 ADV-R7-6, P1 PENDING LEAD 27). Its useful part, the scan key, is `scan_keyset`, which (b) calls directly. The GOLD-1 row ties the check to a plain-`in` oracle over the same keys (section 6).
**Pick: (b).** Why: every table row is closed by an `in`-style check on folded keys; the failure is a refusal, not a leak (fail closed); the span machinery that kept failing review is not needed. What it costs: the whole text is lost when it holds a variant of a known value, and **a refusal ends the whole run**: `agent_loop.py` calls `_redaction_failed(run, cited)` at 377, 470, 496 and 650; `audit/capped.py:71` writes a withheld marker. That price decides sections 5 (kinds and keys) and 7.
Size, honestly (an ESTIMATE): a refactor of about 15 lines in `_build` (shared grouping helper), about 100 new lines in `redact.py` and `runmap.py` (three key types, the check, the second pass of `redact_value`, the exception), 3 constants, and the rows of section 6.

## 4. Why a plain fold is not enough (decides the dependency)
My draft-1 prototype used the snapshot `fold` with case folding and all whitespace removed. All table rows were caught, but the table reads some look-alikes as a different character: Cyrillic Ze (U+0437) reads `3`, so a V holding `z` written with Ze is missed; Cyrillic Be (U+0431) reads `6`; small Greek eta (U+03B7) reads `n`. Confirmed in `_confusables.py`. P1b's class map (`z` to `3`) and two case readings close Ze and capital Eta. **So the check needs `scan_keyset`, and P2d-2 FOLLOWS P1b** (order 11; P1 round 7 ADV-R7-1). P1 round 7 (ADV-R7-13, contested there) keeps no class map for digit-shaped letters: a known value that holds the DIGIT and is written with such a source is found; one that holds the LETTER and is written with a digit-shaped source (Be for `b`) is a leetspeak rewrite, not a look-alike, and stays open (LKV-3, xfail LK-BE, P1 PENDING LEAD 29). Class maps live in P1b only; this design adds none (section 10, mixed Eta reading).

## 5. The design (b), exactly
**New public function** `check_lookalike(texts, mapping, *, _cache=None) -> None` in `guard/redact.py`; it raises **`LookalikeCopy`**, a new public subclass of `runmap.RedactionError` defined in `runmap.py` and raised from `redact.py` through a function-level import (the precedent: `_Redactor._over_budget`, redact.py 986-992, raises `InputTooLarge` the same way, so there is no import cycle). Message = class name only. Bare callers that catch `RedactionError` catch it. The `TextnormError` handler sits in `check_lookalike` itself, the name listed in P1's `REFUSAL_HANDLERS` lint constant (P1 round 7 ADV-R7-5). Internally a private method `_Redactor.lookalike_hit(text)` shares the built state.
1. **Values and keys.** Every original of `mapping` except `"\0seed"` entries, whose kind is in `LOOKALIKE_KINDS` and for which `_sweep(placeholder, original)` is not None. Three key sets, each built once per original and kept in a per-run memo `cache["lookalike_keys"]` (original -> its keys; in the run's cache, never module-level, R371):
   - **K_scan** = the keys of `scan_keyset(original)` for every kind except NAME, ADDRESS, TENANT; minimum length of the FINAL key `defaults.LOOKALIKE_MIN_SECRET_KEY_CHARS = 8` for `redact.SECRET_KINDS` and `defaults.LOOKALIKE_MIN_KEY_CHARS = 12` for the rest.
   - **K_case** = `case_key(original)` for NAME, ADDRESS, TENANT, minimum 12, where `case_key(s)` = P1a `fold(s)` (case kept) with all whitespace and U+FFFD removed and `z`, `Z` mapped to `3`. Why a separate key: these three kinds are pattern-found (TENANT `(?i)`, redact.py 402-407; ADDRESS case-sensitive, 424-430; NAME `(?i)` after a field key, 434-447, case-sensitive after a title or "Dear", 448-454), and ordinary tool results and letter headers carry their all-capitals forms; a case-folded key would refuse those runs. The case key reads Cyrillic, Greek capitals by their own case, combining marks, accents, line splits and full-width forms, and does not read a case-only copy (probe A). Ze: `fold` gives `3` for Ze and capital Ze (probe B), so the `z` to `3` map keeps the case key in step with P1b's class map (pin row LK-NAME-ZE).
   - **K_sq** = `squeeze(original)` (P1a, `loose=False`) for `SECRET_KINDS` only, minimum 12. It reads punctuation fillers (dots, hyphens, underscores, U+FFFD) between the letters of a secret (probe "squeeze"). Not for identifier kinds: squeezing would join host names, IPs and addresses into prose.
   An original that a P1 function refuses (`TextnormError`) is skipped and counted in the evidence step (it is unprotected against variants).
2. **Finder.** The grouping code of `_build` (nesting measure, `_split`, `_slow`, the `RecursionError/re.error/OverflowError` fallback to one-by-one) is factored into ONE helper used by the sweep finder and by one look-alike finder per key set. The look-alike state is cached as `cache["lookalike"] = (map snapshot, finders, slow)` and reused only when the snapshot EQUALS the current map (never keyed by length: a clear-and-update to a different same-size map would reuse a stale finder, a leak). Finders are rebuilt when the map changes, the same rate as the sweep's own rebuild (redact.py 1310); thanks to the memo only new originals are folded. Nothing lives in `re`'s process-wide cache (`_compile_uncached`).
3. **Text.** Each genuine placeholder (a token matching `redact._PLACEHOLDER` AND a key of the map) is replaced by ONE ASCII space; any other `<UPPER_n>` token is ordinary text (today `sweep` skips every such token, so `<ABCD1234EFGH_5>`, an upper-case spelling of an alphanumeric value, survives; this closes it, row LK-FAKEPH). The result goes through `scan_keyset` once, and through `squeeze` and `case_key` once each when K_sq or K_case is non-empty; every key is searched with its finder. All three key functions remove whitespace, so **the pieces either side of a placeholder are joined on purpose**: a copy of V that the attacker splits by writing a maskable value (an e-mail, an IP) in its middle is read (row LK-PH). A space, not deletion, so that the pieces cannot form a new entity or combining sequence across the junction before whitespace is removed. (No sentinel: P1b drops U+FFFD, P1.md 61 and 116, so draft 2's stand-in could not work; RES-1.) A hit returns the placeholder of the matching value (for the log line; never the value). Empty K returns at once.
4. **Fail closed and budget.** `TextTooLong`, `NotText`, any `TextnormError`, or an exception in the finder counts as a hit. `scan_keyset` has no clock (P1 SK-4): the shared budget `started + REDACT_BUDGET_S` (6.0 CPU seconds of the calling thread, `time.thread_time()`, runmap.py 484; the `defaults.py` comment that says "wall-clock" is wrong and P2d-2 corrects it) is checked before every key-function call; the longest uninterrupted step is one call (S_call, measured by the P1b evidence runner; about 2 s by multiplication, UNVERIFIED). Added work per `redact_text`: at most 4 checked texts (final `out` and up to 3 views, runmap.py 399-411) x at most 3 key-function calls; a view whose redacted text equals one already checked is skipped. A hostile text can exceed the budget and is then refused (`InputTooLarge`); a document over P1's size rule is refused when K is non-empty (row FR-16).
**Call sites (the whole change):**
- `runmap.redact_text`: after the view loop and `_clean`, on the final `out` AND on `again.text` of every view stage 2 produced, adopted or not (a copy in percent or `\u` escapes is plain only in the decoded view; that view is what a decoder reads; the cost is row FR-12). Stage 1 and stage 2 `redact()` calls pass `_lookalike=False`, so full-width and zero-width copies are still MASKED by the canonical view and not turned into refusals. The check uses the GROWN map `current`; on a hit the caller's map is updated BEFORE raising, so a value first seen in this text is stored (row LK-LEARN). `LookalikeCopy` is re-raised as itself (added to the `except (InputTooLarge, TooDeep)` tuple).
- bare `redact` (when `_sweep_copies` is true) and `redact_many` (second pass): the check runs at the end and raises `LookalikeCopy`. Behaviour change for bare callers (they got unmasked text; they get an exception): CHANGELOG, loud-failure test; `guard/__init__.py:3` re-exports `redact`, so the CHANGELOG names that import path. Consumers: `redact_many` has no caller under `src/` (grep); demos pin a core sha (list UNVERIFIED, not read).
- **`redact_value` second pass:** when the first pass of `_redact_value` grew the map and the value holds more than one string, `_redact_value` runs again over the FIRST pass's output with the grown map; if that second pass grows the map again, it raises `RedactionError` (fail closed). So a value found in a later leaf masks or refuses its copies in earlier leaves (rows LK-LATER, LATER-PLAIN). This also closes a plain-copy leak that exists today. Cost: up to two `redact_text` calls per leaf, each within its own budget; the total stays capped by `MAX_REDACT_CHARS` (`redact_value`, runmap.py 570-578).
- Not a call site: `sweep`. It works per segment before the views exist; the check must see the final text.
**Who is protected (callers):** the agent loop passes the run map (document 367, tool results, tool inputs 489): known values of the whole run. `judge.py:71`, `tools.py:1005`, `evals.py:63`, `audit/capped.py:71` and `safe_head` with no map (runmap.py 534, 542) pass `{}`: only values found inside the same text are protected. One line in the notes: a refusal is a yes/no oracle for anyone who can see it; negligible for keys of 8+ random characters.
**Constants** (`defaults.py`, added by P2d-2): `LOOKALIKE_MIN_KEY_CHARS = 12`; `LOOKALIKE_MIN_SECRET_KEY_CHARS = 8`; `LOOKALIKE_KINDS` = every secret and identifier kind, **including NAME, ADDRESS, TENANT** (they use the case key). **Merge order:** P1m, P1a, P2a, P2d-1, P1b, P2d-2, P4d-a2-i; `defaults.py` order: P1a, P2a, P2d-1, P1b, P2d-2, then P4d-a2 and P4a-1 (P1 round 7 resolve, ADV-R7-1).

## 7. False-refusal rate: what is and is not known
Not measured on real documents; no figure is guessed. Known: (1) after masking, a PLAIN copy of V is normally a placeholder. The sweep leaves plain copies in four cases (an identifier inside a longer ASCII letter/digit run, words in `_COMMON`, values under 3 characters or all-digit under 6, `_sweep_copies=False`), but only the first produces refusals: `_COMMON` words are at most 10 characters and the short values are under every minimum, and `_sweep_copies=False` is only `redact_many`'s first pass, which the check follows (FR-11). (2) Chance matches are negligible for random secrets and ids: the draft-1 prototype found 0 hits for 8,000 random 12-40-character keys in 262,144 characters; by arithmetic, a random 8-character key matches about 262,144 / 36^8 = 9e-8 per text per value, a 12-digit number about 2.6e-7. (3) The real risks are named: accented spellings of stored names (FR-17), dictionary-word passwords and their case variants (FR-20), long quoted captures (FR-19), split copies around a placeholder (FR-21), Mn-only differences (FR-5). Case-only copies of NAME/ADDRESS/TENANT, the draft-2 worry (letter headers, ERP and database tool results, model arguments), are NOT refused, because their key keeps case. Evidence step (runner): 200 made-up invoices and letters, 100 made-up tool results (ERP/database style, one with ANSI colour), 100 made-up model tool-call arguments, with stored names in plain, capitals and accented spelling and stored passwords of 8 to 12 characters, some dictionary words; the refusal rate per kind and per key type, and the added time on benign near-cap documents, go to `handover/evidence/lookalike-1.md`. **Gate proposal:** more than 1 refusal in 50 documents for a kind removes that kind (or, for secret kinds, raises their minimum back to 12) and opens a v1.1 row.

PHONE (redact.py 478-485) takes 10 to 16 digits (spaces and hyphens allowed inside) that do not follow a letter, digit, `_`, `.` or `-` and are not followed by a letter, digit, `_` or `.`, and are not an ISO date or a 14-digit compact timestamp. ACCOUNTID (360) is `\b\d{12}\b`. BANKACCT (338-356; `_ACCT_WORD` 89 accepts "account no", "acct", "A/C"; 6 to 17 digits, `_ACCT_DIGITS` 93-96) is masked only with bank context: a phrase of `_BANK_CONTEXT` (100-110, e.g. "bank account", a bank code) within `_BANK_WINDOW` = 100 characters (111, `_bank_context` 114-120), or the match starting with "bank", or in `redact_many` and the fold scan a bank word anywhere in the batch/text (`bank_near`, 1056-1059, 1535). "Account No:" and "A/C" are keywords of the pattern but NOT context. HIGHENTROPY needs 40 or more characters with upper case, lower case and a digit (643-650), so a digit string is never caught. IBAN (253-260) is a registry country code, 2 digits and 11-30 letters or digits, with no check-digit validation and no context word. `_redact_value` returns int and float unchanged (runmap.py 590-600): a JSON-number account number is never scanned.
**What P5c as planned adds:** no pattern (plan-v3 81, 110: a redactor kind with a detector-model outline). This design does not close the gap either for numbers the run does not know (the check protects only known values, and only keys of 12+ digits for identifier kinds). **What this design asks P5c to add (PL-LK-7):** (i) PHONE's end changed from `(?![\w.])` to `(?!\w|\.\w)`, so a number at the end of a sentence is masked while `<digits>.5`, `<digits>.txt` and two runs joined by a full stop are not (probe "phone"; the repository suite was NOT run with it: UNVERIFIED); (ii) the strong account keywords ("account no/number/#", "acct", "A/C") count as bank context, so "Account No: <6-17 digits>" is masked with no bank word (false-mask rate UNVERIFIED, measured by P5c's evidence). **Not closed in v1, with the reason:** 8-9 or 17+ digits with no keyword (a context-free pattern of that length masks dates such as 20261105, amounts and invoice numbers); digits glued to letters; JSON numbers.
**Acceptance rows:** ACC-1a 8-9 digits, no keyword (xfail, named record); ACC-1b 17+ digits, no keyword (xfail); **ACC-1c a 10-16 digit number at the end of a sentence (must be masked; fails on `748849c`; P5c)**; **ACC-2 "Account No:" / "acct" / "A/C" + 8 digits, no bank word (must be masked; P5c)**; ACC-3 a JSON number (xfail; LKV-8). Registering the number from the field that holds it protects only LATER texts, since the model must read the first sighting to extract it.
