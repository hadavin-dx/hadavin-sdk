## 1. The question, in plain words
A value V that the redactor already knows (12 or more characters) is replaced by a placeholder when written plainly. The same V written with look-alike letters, other case, one combining mark, zero-width characters inside, full-width forms, or split over two lines goes to the model unchanged. What is the smallest design that makes such a copy impossible to send?
**What "a folded copy" means in this note (exactly):** a text whose key equals, or contains, the key of V, where the key is what P1b's `scan_keyset` gives: NFKD and the confusables table, case folded in two readings, ALL whitespace removed, class map `z` to `3`, tag texts T0-T3. Anything that a reader can see as V only through a transformation outside that function is NOT covered (section 10).

## 2. What I measured on the snapshot (throwaway script; made-up 13-character value; not saved)
"Leaks" = the copy still stands in the returned text. Three ways of knowing V: a map handed in (MAP), an earlier `password=` call on the same run map (PW), `redact_many` (MANY).
| copy of V | `redact_text` MAP / PW | bare `redact` and `redact_many` |
|---|---|---|
| plain | masked | masked |
| Cyrillic look-alikes | LEAK | LEAK |
| Greek look-alikes | LEAK | LEAK |
| full-width forms | masked (canonical view) | LEAK |
| zero-width space inside | masked (canonical view) | LEAK |
| one combining mark | LEAK | LEAK |
| upper case / lower case | LEAK | LEAK |
| split over two lines | LEAK | LEAK |
| every byte percent-encoded (Cyrillic spelling) | LEAK (decoded view not matched) | LEAK |
The choke point already closes full-width and zero-width copies, because stage 2 of `redact_text` scans `canonical(text)` (NFKC and Cf removed, runmap.py 274-280) and adopts it when it holds more placeholders (519-520). Bare `redact` and `redact_many` have no stage 2. Cause: `_sweep` (redact.py 1485-1503) is a literal, case-sensitive search on the written text.

## 3. Three designs compared
**(a) Span-mask.** Fold, find V's key, map the hit back to written positions, replace only that span. Needs a position map; `_aligned_fold` (redact.py 1082) gives one only for simple folds and returns None otherwise (COR-R4-4), and then the line is withheld anyway. P2d-1's alias index is a smaller version of this idea and drew findings in rounds 3 to 5 (ADV-R3-2, ADV-R3-3, ADV-R3-8, ADV-R5-5, ADV-R5-6, COR-R5-3, COR-R5-4). Best fidelity, largest surface. Rejected for v1 (v1.1 LKV-1).
**(b) Refuse the whole text.** After all masking, if any key of V's fold occurs in the folded text, refuse. No position map. A person looks. One check, three call sites, no change to what the patterns or the sweep do.
**(c) `deny_hit` over the final output (the round-4 fallback).** It is (b) built from P1b's generic API. `deny_hit` is capped at 500 needles, fails the whole list on one bad entry (`BadNeedle`), takes an injected clock, and takes 2.3 s of its 2.0 s budget for a hostile 500-needle list (P1.md 58-60). The redactor map holds thousands of values. Rejected as built. `scan_keyset` is the function `deny_hit` uses for its scan view, so (b) and (c) give the same keys by construction; a golden test ties them (row GOLD-1).
**Pick: (b).** Why: every table row is closed by one folded `in`-style check; the failure is a refusal, not a leak (fail closed); the span machinery that kept failing review is not needed. What it costs: the whole text is lost when it holds a variant of a known value, and **a refusal ends the whole run** (callers: `agent_loop.py` 469, 495, 649 call `_redaction_failed(run, cited)`; `audit/capped.py` 72 returns a withheld marker). That price decides section 7.
Size, honestly (an ESTIMATE): a refactor of about 15 lines in `_build` (shared grouping helper), about 60 new lines in `redact.py`, 2 constants, about 6 test files lines of rows. Not "30 lines".

## 4. Why a plain fold is not enough (decides the dependency)
My prototype used the snapshot `fold` with case folding and all whitespace removed. All table rows were caught, but the table reads some look-alikes as a different character: Cyrillic Ze (U+0437) reads `3`, so a V holding `z` written with Ze is missed; Cyrillic Be (U+0431) reads `6`; small Greek eta (U+03B7) reads the letter `n`. Confirmed in `_confusables.py`. P1b's class map (`z` to `3`) and two case readings close Ze and capital Eta. **So the check needs `scan_keyset`, and P2d-2 waits for P1b again** (rev 5 removed that wait when it cut `deny_hit`; order 11 reverses L19). The counted list of look-alikes the table reads as a different character and that have no class map is an evidence item (a script from the P1b builder); until then no count is claimed. P1 round 7 (ADV-R7-13) asks P1 to add class maps for Be and similar: each one added shrinks the open hole LKV-3.

## 5. The design (b), exactly
**New public function** `check_lookalike(texts, mapping, *, _cache=None) -> None` in `guard/redact.py`; it raises `LookalikeCopy` (new public exception, `RuntimeError` subclass, message = class name only). Internally a private method `_Redactor.lookalike_hit(text)` shares the built state. `runmap` imports the public function.
1. **Values.** Every original of `mapping` except `"\0seed"` entries, whose kind is in `LOOKALIKE_KINDS` and for which `_sweep(placeholder, original)` is not None. K = union of `scan_keyset(original)`, keeping only keys of at least `defaults.LOOKALIKE_MIN_KEY_CHARS` characters (proposal 12, measured on the FINAL key) and dropping any key that contains U+FFFD. An original that `scan_keyset` refuses is skipped (and counted in the evidence step: it is unprotected against variants).
2. **Finder.** The grouping code of `_build` (nesting measure, `_split`, `_slow`, the `RecursionError/re.error/OverflowError` fallback to one-by-one) is factored into ONE helper used by both the sweep finder and this one. The look-alike state is cached as `cache["lookalike"] = (map snapshot, finders, slow)` and reused only when the snapshot EQUALS the current map (never keyed by length: a clear-and-update to a different same-size map would reuse a stale finder, a leak). It never lives in `re`'s process-wide cache.
3. **Text.** Each genuine placeholder (a token matching `redact._PLACEHOLDER` AND a key of the map) is replaced by U+FFFD; any other `<UPPER_n>` token is ordinary text (today `sweep` skips every such token, so `<ABCD1234EFGH_5>`, an upper-case spelling of an alphanumeric value, survives; this closes it, row LK-FAKEPH). The result goes through `scan_keyset` ONCE and every key is searched with the finder. A hit returns the placeholder of the matching value (for the log line; never the value). Empty K returns at once.
4. **Fail closed.** `TextTooLong`, `NotText`, any `TextnormError`, or an exception in the finder counts as a hit. `scan_keyset` has no clock (P1 round 7 ADV-R7-2): the shared budget `started + REDACT_BUDGET_S` is checked between calls (text, then each view), and the one uninterrupted step is one `scan_keyset` call at the size rule. A document over that rule is refused when K is non-empty (stated; row FR-16).
**Call sites (the whole change):**
- `runmap.redact_text`: after the view loop and `_clean`, on the final `out` AND on `again.text` of every view stage 2 produced, adopted or not (a copy in percent or `\u` escapes is plain only in the decoded view; that view is what a decoder reads; the cost is row FR-12). Stage 1 and stage 2 `redact()` calls pass `_lookalike=False`, so full-width and zero-width copies are still MASKED by the canonical view and not turned into refusals. The check uses the GROWN map `current`; on a hit the map is updated BEFORE raising, so a value first seen in this text is stored (row LK-LEARN). A hit raises; the existing `except Exception` turns it into `RedactionError("LookalikeCopy")`.
- bare `redact` (when `_sweep_copies` is true) and `redact_many` (second pass): the check runs at the end and raises `LookalikeCopy`. Behaviour change for bare callers (they got unmasked text; they get an exception): CHANGELOG, loud-failure test. Consumers: `redact_many` has no caller under `src/` (grep); demos pin a core sha (list UNVERIFIED, not read). One line in the notes: a refusal is a yes/no oracle for anyone who can see it; negligible for 12+ characters.
- Not a call site: `sweep`. It works per segment before the views exist; the check must see the final text.
**Constants** (`defaults.py`): `LOOKALIKE_MIN_KEY_CHARS = 12`; `LOOKALIKE_KINDS` = secret and identifier kinds, **excluding NAME, ADDRESS, TENANT** (section 7). **Merge order:** P1a, P2a, P2d-1, P1b, P2d-2, P4d-a2-i (P1.md:70, P4d.md:17).

## 7. False-refusal rate: what is and is not known
Not measured on real documents; no figure is guessed. Known: (1) after masking, a PLAIN copy of V is normally a placeholder, but the sweep leaves plain copies in four cases (an identifier inside a longer ASCII letter/digit run, words in `_COMMON`, values under 3 characters or all-digit under 6, `_sweep_copies=False`); the check cannot tell a plain copy from a variant, so those are refused too (FR-11); (2) chance matches are negligible for secrets and ids of 12+ mixed characters: the prototype found 0 hits for 8,000 random 12-40-character keys in 262,144 characters, and the arithmetic for a 12-digit number is about 2.6e-7 per text per value; (3) the real risk is **names, addresses and tenants**: all-capitals copies appear in letter headers, ERP and database tool results, and model arguments; a refusal there ends the run. Pattern-found kinds (e-mail, host, IP) already mask case variants, so only hand-registered NAME/ADDRESS/TENANT values would be hit. **Decision (PENDING LEAD LK-4): they are out of the default `LOOKALIKE_KINDS`**; an all-capitals copy of a stored name is a stated limit (xfail LK-NAMECAP), v1.1 LKV-1. This partly cuts the owner's table for those kinds and the lead must say if that is acceptable. Evidence step (runner): 200 made-up invoices and letters, 100 made-up tool results (ERP/database style) and 100 made-up model tool-call arguments, with stored names in plain, capitals and accented spelling; write the refusal rate to `handover/evidence/lookalike-1.md`. Gate proposal: more than 1 refusal in 50 documents for any kind in the set removes that kind and opens a v1.1 row.

## 9. Order 11(5): Intake's plain account number without a context word
Read in the snapshot: BANKACCT is masked only with bank context: a bank word within `_BANK_WINDOW` = 100 characters (`_BANK_CONTEXT` 100-110, `_bank_context` 114-120), or the match itself starting with "bank", or, in `redact_many` and the fold scan, a bank word ANYWHERE in the batch/text (`bank_near`, redact.py 1056-1059, 1535). The phrases are English; "Account No:" and "A/C" are not in the list. HIGHENTROPY needs upper case, lower case and a digit, so a digit string is not caught. IBAN has its own pattern (253-260) with a country prefix and checksum and needs no context word. **So the core detector set as planned for P5c adds no pattern and does NOT close the plain-account-number gap; this design does not either** (it protects only numbers the run already knows). `_redact_value` returns int and float unchanged (runmap.py 596-600): a JSON-number account number is never scanned. A context-free digit-string pattern would mask invoice numbers and amounts. Recommendation (PENDING LEAD): not closed in v1; acceptance rows ACC-1 (plain digits, no context word), ACC-2 ("Account No:" / "A/C" wording), ACC-3 (a JSON number) pin today's leak as xfail with named records. Registering the number from the field that holds it protects only LATER texts, since the model must read the first sighting to extract it. Lead question LK-10: should `redact_value` stringify numbers (LKV-8; recommended: no, rows only). UNVERIFIED: Intake code, and whether Intake already registers account numbers.

## 10. What the design does not cover (stated; one CHANGELOG line)
A value not yet known when the variant text passes (no design can); values whose final key is under 12 characters (LKV-2); NAME/ADDRESS/TENANT in another case (LKV-1); inert fillers between letters: dots, hyphens, markup (LKV-7, xfail LK-INERT); letters the table reads as another character without a class map (LKV-3, xfail LK-BE); other encodings such as base64, hex, rot13, reversed (LKV-9, cannot be closed); a copy split across separate strings (the redactor sees one string at a time); a value learned only by a later leaf of the same `redact_value` call (LKV-6); numbers (LKV-8); hidden channels that are not copies of a known value (P1 tiers and the P2d-2 hook; note P1 round 7 ADV-R7-4: "no limit there protects a short secret from an encoded copy"). Text that `scan_keyset` refuses is refused, not passed.
