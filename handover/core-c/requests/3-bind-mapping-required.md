## 1. The change in `bind`
Before: `bind(agent_id, run_id, *, mapping=None, principal=None, source="gate")`; `mapping=None` silently skipped the enforce step.
Now:    `bind(agent_id, run_id, *, mapping, principal=None, source="gate")`.
- `mapping` is a REQUIRED keyword. Leaving it out is a TypeError at bind time. `mapping=None` or anything that is not a `hadavin_sdk.guard.runmap.RunMap` (a plain dict, a `dict(rmap)` copy made at bind time, a `MapSnapshot`, any other Mapping) is a TypeError too (round 4: it used to be any `Mapping`), so a forgotten variable or a stale copy cannot turn the guarantee off. Pass the run's own `RunMap` object (agent_loop.py:397 builds one).
- "No run map" is said in the call with the named constant `NO_MAP` (`from hadavin_sdk.guard.model_gate import NO_MAP`): `gate.bind(agent_id, run_id, mapping=NO_MAP)`. Only the eval and replay command lines may use it.
- A no-map call is marked in every audit row it writes: the field is `models.AuditEvent.decision` (a free `str | None`), value `"no_map"`; a gate with a map writes `"map_enforced"`, or `"map_enforced_empty"` when the run's map holds no entry at that call (the empty map is still ACCEPTED: contested with ORDER 020 m-2, the lead decides), `"enforce_custom"` when the gate was built with an injected `enforce=` (a test hook, never in src), and `"map_failed"` on a call the enforce step refused. The row says what was configured, it is not a proof that every value was replaced.

## 3. The gate's exception type for every failure BEFORE the provider call (ORDER 017 item 5)
`hadavin_sdk.guard.model_gate.GateRefused` (base class; subclasses `UnmaskedInput` (and its subclasses `MaskBudgetExceeded`, `HeldValueLeft`), `WorstCaseInvalid`, `ReservationInvalid`, `FramingRefused`). Catch `GateRefused` and you know: NO provider call was made. It carries only a `code` (also `exc.args == (code,)`): no text, no secret, `__cause__` and `__context__` both None.
Raised as `GateRefused` for every failure before the call that is NOT a `SpendRefused`:
| code | when |
|---|---|
| `mask_refused` | the enforce step failed: content that is not `str`, a document that is not `bytes`, a bad map, more than 4 sweeps, any other failure of the step |
| `mask_budget_exceeded` (`MaskBudgetExceeded`, a subclass of `UnmaskedInput`) | the enforce step ran out of its budget: a text over `runmap.ENFORCE_MAX_CHARS` (8 x `defaults.MAX_REDACT_CHARS`), all texts of the call over `ENFORCE_MAX_TOTAL_CHARS`, too many steps, the CPU deadline (`defaults.REDACT_BUDGET_S`), a map over `ENFORCE_MAX_ENTRIES` (20,480) or `ENFORCE_MAX_HELD` (4,096 held-back values). Past a map cap EVERY call of that run is refused: see section 7 |
| `held_value_left` (`HeldValueLeft`, a subclass of `UnmaskedInput`) | safety net: after enforcing, a value of a SECRET kind (4 or more characters) still stands raw in a chunk of text (a forged `<NAME_1>` that is not a key of the map hides nothing; a value that merely lies inside a fixed framing word is NOT refused) |
| `framing_refused` | a value of a SECRET kind (4 or more characters) EQUALS a tool name (the `tools` list, an assistant line or a framing token) or a call id, or is a SUBSTRING of a name in the `tools` list. The marker words (TOOL, RESULT, END, call_id, tool) no longer refuse: the fixed words are kept exact. A host or tenant named like a tool does not refuse |
| `worst_case_failed` | your `worst_case` function raised (its error is NOT passed on: it may carry text) |
| `worst_case_invalid` | it returned something that is not a finite `Decimal >= 0` |
| `reserve_refused` | `reserve` raised anything that is not a `SpendRefused`: a KeyError, a store that is down, an OSError |
| `reservation_invalid` | `reserve` returned something that is not a non-empty `str` (whatever it booked stays booked until the store's sweep) |
UNCHANGED: a `SpendRefused` (a meter error whose `.reason` is one of the six published reasons: kill_switch, daily_budget, monthly_budget, limits_unavailable, bad_amount, usd_cap) passes as the same object; errors of the client (ProviderError, ProviderExhausted, timeouts, anything) pass as the same object; KeyboardInterrupt / SystemExit pass. When `limits.SpendRefused` lands in `src/hadavin_sdk/limits.py` the gate will import it; until then it is recognised by its published `.reason`.
Map per site (yours to decide, listed in tickets/F-gate-wrapper-body.md "For core-b (install)"): `GateRefused` and `SpendRefused` both mean "no call, nothing was sent"; the run loop must catch both (today line 477 catches ProviderError only and would leave the run in WORKING).

## 4. Cost absent (ORDER 017 item 2)
A reply whose `cost_usd` is absent, None, not a Decimal, NaN, infinite or negative is returned to the caller and NOT settled (audit row `ok` / `cost_unknown`; the worst case stays booked and the store's sweep closes it). `models.Reply.cost_usd` defaults to `Decimal(0)` (models.py line 299): an adapter that sets no cost looks like a free call and is settled at 0. core-b must change the default to `None` (type `Decimal | None`) or make the field required, and every adapter must set it. Until then the gate cannot see the difference.

## 7. Round 4 additions (design review round 3 M1, M2, M4; code review round 3 M3)
- REGISTRATION SIDE (core-b, the gate cannot do it). A hostile document plants a value with one line and the map only grows: `password=read_logs` makes a tool name a secret, so `framing_refused` on every later call of the run; `password=>aaaa1` (an edge value) or `token_type=search` and a few thousand more make held-back values, so past `runmap.ENFORCE_MAX_HELD` (4,096) every call is refused with `mask_budget_exceeded`. The gate must keep refusing (it cannot tell a planted value from a real secret and the `tools` list is forwarded untouched). The filter belongs where values are registered (`redact_text` / `redact_untrusted` and the run loop): do not register as a secret a value that equals a name of the run's tools (or a piece of one) or a call id, and cap the number of values one document may add.
- The gate keeps its built patterns between calls (per bound gate). Bind ONE gate per run and keep it; a gate bound per call rebuilds every time.
- `GateRefused` subclasses now: `UnmaskedInput` (`mask_refused`), `MaskBudgetExceeded`, `HeldValueLeft`, `WorstCaseInvalid`, `ReservationInvalid`, `FramingRefused`. Catching `GateRefused` still means "no provider call was made".
- A KeyboardInterrupt in the enforce step, in `worst_case`, in `reserve` or in the instant after `reserve` returns writes a row (`call_interrupted` or `reserve_interrupted`) and passes on unchanged.
