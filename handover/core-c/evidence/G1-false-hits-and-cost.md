# G1 evidence: false hits (review M5) and cost (review M4) of the text fold

Evidence runner for core-c (role TEXT), 2026-11-20. Measurements only; no design verdict. Run from a clean `git archive cloud/core-c` export in /tmp/core-c-ev (module path printed: /tmp/core-c-ev/src/hadavin_sdk/guard/textnorm.py), removed afterwards. Scripts: `g1_false_hits.py`, `g1_cost.py` in this folder (`uv run python ev/<script>` from the export).

## Environment
Python 3.13.18, `unicodedata.unidata_version` 15.1.0 (equals TEXTNORM_PINNED_UNIDATA), 4 cores, load 0.4 to 10 (other agents ran at the same time, so seconds are noisy upward). CPU seconds = `time.process_time()`.

## A. False hits on ordinary text

### Corpus (no protected value in any of it)
| corpus | chars | origin |
|---|---|---|
| repo(prose+code) | 5,053,368 | 468 files of the export: README, CHANGELOG, docs, src, tests, tools, demos (.py .md .toml .yml .txt .json; textnorm_corpus.json left out) |
| stdlib-docstrings | 10,069,421 | docstrings (ast) of the Python 3.13 stdlib, tests and idlelib left out |
| generated-markov | 3,000,005 | word-level order-2 Markov text from stdlib docstrings + /usr/share/doc copyright/README/NEWS/changelog files (13.0 M chars) |
| han-zipf, han-uniform, cyrillic-freq, arabic-freq, devanagari-freq | 400,000 each | SYNTHETIC (see below) |

**Non-Latin text could not be taken from the box**: a search (grep for a 20-character run of Han, Cyrillic, Arabic or Devanagari in /usr, /opt, /root, /home, the venv and the export; .txt .md .po .rst .json .py .html .xml) found none. So the five non-Latin corpora are generated by the script from tables written in it: Han = 3,500 characters of U+4E00.. in a shuffled order, drawn Zipf(1) (zipf) or uniformly (uniform), sentences of 4 to 14 characters joined by U+3002; Cyrillic, Arabic = words of 2 to 9 letters from hand-written letter-frequency tables; Devanagari = consonant + optional vowel sign syllables. They are NOT real language: the Zipf and frequency tables are guesses, letters are independent, so real Chinese/Russian/Arabic/Hindi rates may be higher or lower. Treat the non-Latin rows as a model, not a measurement of real text.

### Method
`scan_holds(text=chunk, value=v)` inside `with scan_cache()` (chunk outer, values inner), chunks of 10,000 characters at random non-overlapping offsets, seed 20261120. `register_value` not used (scan_holds raises by itself for a value that is too short: counted as "refused", not as a miss or a hit). Values are drawn at random, so a hit is not a real protected value; BUT a value that is a literal word of the text (e.g. "black", "Omar" in code) counts as a hit: whole-word hits were NOT separated from inside-a-word hits (a split run was started and stopped on the lead's load rule: NOT RUN). The examples show only the matching needle (the substring of the view that matched).
Run 1 (`g1_false_hits.py 1000 200 10000`): 1,000 values per class; Latin classes over 199 chunks (67 repo, 66 stdlib, 66 markov; 199,000 scans); non-Latin classes over 40 chunks (corpora are 400,000 chars, so 40 not 200). Run 1 was stopped after han-2 (uniform) because Han classes cost about 9 minutes CPU each (load rule). Run 2 (`g1_false_hits.py 300 40 10000 han-3,han-4,cyrillic,arabic,devanagari`): 300 values x 40 chunks = 12,000 scans per class (the same script with the 4th argument added after run 1; the 4 earlier edits of the script otherwise unchanged).

## B. Cost (g1_cost.py; best of 3 where stated, else one run; CPU seconds)
`scan_holds` checks no deadline: grep of textnorm.py and injection.py for monotonic, perf_counter, deadline, time., timeout finds none (textnorm.py line 1212 says "there is no clock or deadline"); the only clocks are in guard/runmap.py (REDACT_BUDGET_S = 6.0, checked in redact_text and one more loop), not in `scan_holds`, `scan_cache` or `RegexDetector`.

Size rule: the cap is a WEIGHT (TEXTNORM_MAX_CHARS = 262,144, the sum of each character's folded length). A 262,144-character text with 1 % non-ASCII letters is REFUSED (`TextTooLong`: 263,308 of 262,144 and 263,476 of 262,144), and so is a 262,144-distinct-character text (287,409). Those texts were therefore cut to the longest prefix the rule accepts (bisection with `textnorm._checked`): 260,989 chars (1 % non-ASCII incl. sharp s), 260,818 chars (1 % without expanding letters), 236,879 chars (distinct). The distinct text had to include 112,426 private-use characters (fewer than 262,144 assigned non-private characters exist); the first 236,879 code points from U+0081 (surrogates, Cc, Cn skipped) are all distinct.

## NOT RUN / NOT BUILT, with reasons
- Real non-Latin prose (Chinese, Russian, Arabic, Hindi): none on the box, no network corpus allowed; synthetic models used (above). Real rates unknown.
- Whole-word versus inside-a-word versus across-spaces split of the Latin hits: a script was written and started, stopped on the lead's load rule; the hit counts above mix all three.
- Han and other non-Latin classes with 1,000 values x 200 chunks: Han costs about 9 CPU minutes per class at 1,000 x 40; reduced as stated (40 chunks; 300 values x 40 for Han 3, Han 4, Cyrillic, Arabic, Devanagari).
- Chunks of 10,000 characters only; no other chunk size; no Greek, Thai, Hangul, Kana, Hebrew classes.
- 2,000-value runs without the cache, and with the cache over the distinct text: extrapolated or killed as marked.
- A text of 262,144 distinct non-ASCII characters is refused by the size rule (weight 287,409); the 236,879-character prefix was timed instead.
- Mutant/test suite not run (not asked). Values drawn at random are not real redactor values: names are random pronounceable strings plus a 70-name hand list (about 30 %).
