## Drifts ranked by risk

Rank 1 is a drift that makes a security promise false.

1. **A security promise in the code docstrings is false (A39, A40).** `guard/redact.py:15-17` says the outbound gate's G5 re-runs the patterns "independently, on everything that leaves"; `approvals/gate.py:42-44` says a final text that still holds anything the redactor classes as secret is blocked (G5), and `gate.py:59-63` names `enforce`, `for_terminal`, `outbound_data` and a BLOCK verdict. None of this exists in src. G6 (the wording fix) is still not applied at HEAD. A reader of the code is told there is a second leak check; there is none (the gate's `enforce_map` replaces known values only, runs no pattern; README 2.1 says so correctly).
2. **`runmap.is_masked` is promised in three places and is gone (A10, A11, A12, A35, A37, B25).** G-text-deltas offers it "to step F and SPINE", G3-I5 says the fold scan sits inside it so it sees look-alike spellings, and the G6 proposed text says model input is "checked once more by the model gate's mask check (`runmap.is_masked`)". At HEAD the model gate uses `enforce_map`, which runs no pattern and so cannot see a NEW look-alike-spelled value. If the G6 text is applied as proposed it would state a check that does not exist. The tests that pinned it (tests/test_runmap_is_masked.py) are also gone, and G7's property file and ticket still cite them.
3. **What the redactor leaves unmasked is wider than the README and the G7 ticket say (B22, B26, C7).** A SECRET value made only of own-label tokens is left: any kind (`password=‹EMAIL_1› host`), tokens separated by space/tab/`;`/`,`, and cut-off openings (`password=<SEC`). README K43 and decision 7 name only `‹SECRET_n›`; the ticket names a different, looser regex (`_ESCAPED_LOOKALIKE`, which does not exist). The accepted-limit list a customer would read is incomplete. Low exploitability (the value must itself look like our own placeholder), but it is a stated-limit drift.
4. **README K39/K40/K41 and the 'working copy' lines describe a state that is no longer true (C1-C6, B6, B11).** The README says the finder does two rounds, K39 and K40 are OPEN with strict expected failures, the repeat is uncommitted, and the time check is between rounds only. At HEAD the capped loop is committed (as an unverified WIP commit), K39 and K40 inputs are masked, the xfail markers are gone and a K40 test id the README cites no longer exists. The drift is in the safe direction, but a reader would act on the wrong owner and status, and the true state ("committed, NOT verified, full batch NOT RUN") is itself unproven.
5. **Counts and names in the G7 ticket and G-text-deltas are stale (A4, A5, A21, A23, B14-B16, B18, B19).** Test counts (49 vs 48 non-perf, 3 vs 6 non-param tests), the round-1 invariant "at most 2 passes and 2 sweeps" left in place beside the round-2 design, tests +8,505/17 files vs +10,583/38, data +14,683 vs +12,671, app.py +4 vs +5, textnorm test functions 306-326 vs 351. No security effect; they cost a reviewer trust in the numbers.
6. **Line numbers moved (A2, A15, A42, A53).** app.py:134 is 132; the tests/test_textnorm.py assertion is at 3026, not 3023; main-relative lines in G-text-deltas no longer match HEAD.

Findings that make a ticket claim BETTER than stated (no action beyond editing the text): Amendment 6's 3.12 behaviour is now measured on a real Python 3.12.3 (A41, A52, A53); the README's "NOT RUN on 3.12" statements understate what has been run (C19, C20).
