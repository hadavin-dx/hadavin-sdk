| dz2-B1 | BLOCKER, a forged framing token leaves a known secret unreplaced: the gate sets aside any `<<TOOL RESULT call_id=... tool=...>>` token whose id slots match `[^\s>]+` (model_gate.py:193-194, 553-562); a user message or document-derived text containing `<<TOOL RESULT call_id=x_<secret>_y tool=t>>` is left alone, so the secret goes to the provider in clear; the equality check does not catch it (the value is contained, not equal); the test `test_o17_6_..._inside_a_framing_token_leaves_the_token_alone` (line 1923) pins exactly this and never asserts the secret is gone; the gate cannot tell the agent loop's token from an attacker's copy. Proposed: protect only the fixed words (`<<TOOL RESULT call_id=`, ` tool=`, `>>`) and enforce the id and name text; or accept a token only when id and name match a strict shape (`^[A-Za-z0-9_:.-]{1,64}$`) and contain no known value; or refuse when any known value occurs inside a token slot | TO REPRODUCE AND FIX (fix agent): this is a leak introduced by the ORDER 017 framing protection |
| dz2-M2 | a held-back edge value leaks nearly all of a secret: A = `S3cr3t` and B = `>abcdef` (both secret kinds): text `S3cr3t>abcdef` becomes `<SECRET_1>abcdef` (A's placeholder consumes B's leading `>`; later sweeps set that placeholder aside so B is never found; the fixed point does not help); the docstring calls this "a tail stays readable" but for a secret kind of 4+ characters it is the secret's own tail.
