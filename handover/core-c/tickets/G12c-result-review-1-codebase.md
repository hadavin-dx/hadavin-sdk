# G12c result review 1 (fresh, codebase, read only, NOT RUN). 0 Blocker, 2 Major, several minor
Major
1. `_LABEL_TEXT` declines a core of the form `<any _LABELS entry>_<digits>`, not only an issued placeholder: a real password `TOKEN_2024.` or `SECRET_123,` (label in _LABELS) gets no core, so a later bare copy leaks (redact ~1014-1033, 1900-1907; test at :289-296 documents it for EMAIL_1). Fix: decline only when the text is already in self.mapping or the number is within the label counter; else register and let the sweep skip escaped look-alikes.
2. A value over 4096 chars whose core is at most 16 shorter gets no core (~995-996, 1905): `password=<5000 chars>, <same 5000 chars>` leaves the bare copy readable; pinned as a feature by a `qwxz*2000` test. Threshold far too low (doubling 4097 chars cannot threaten MAX_MAP_CHARS 524,288). Fix: base the rule on the real budget (skip only when len(full)+map chars would pass ~half of MAX_MAP_CHARS, or ~128k). Related: 17+ edge chars on a 300k value registers the core again and doubles the map (fail closed, InputTooLarge).
Minor leaks
3. `_cut_a_lookalike_bracket` (~1004-1011) drops the core for a single leading ‹ plus all-caps core (`password=‹HUNTER2,`), for both brackets (`‹hunter2zz›`: no core, no piece entry) and via `_LOOKALIKE.search(full)` (~1903) when a password contains user-typed `<X_1>` rewritten to `‹X_1›`: bare copy leaks. Tests pin all three. Fix: register the core unless it collides with a real label token; handle the collision in the sweep.
4. A core that is the tail of a real label token (`MAIL_1`, `AIL_1`) is not caught; the sweep skips real `<..>` placeholders but not `‹EMAIL_1›`, giving `‹E<SECRET_3>›` (integrity, not secrecy; untested).
5. `f"<{core}" in full` (~1019) matches `<core` anywhere; `full.find(core)` takes the first occurrence: looser than documented.
Perf: new `_bare` forms are bounded (tag 16, spaces 3, entity 10, 64-char close window) and linear, but constant factor rose: ~64 start positions x ~7 alternatives per strip step; a 500k run of `!` or `-` costs seconds with no deadline check in `_bare` (~974-989). Suggest trying the close search only when text[end-1] is in `;>%` or alphanumeric; the linear test checks correctness, not time.
Tests: EQUIVALENT note (g12_mutants.py:9-10) wrong in general (`PW<em/>` end-of-value unlisted tag is stripped only by the whole-form branch; M30 tests only the start): add a case and mutant. Test name `...takes_at_most_two_entries` stale vs docstring; comment at redact ~963 and `_place` docstring (~1869-1870) list fewer reasons than the code.
Later-copy sweep `password=X, X`: no input found where a previously swept copy stops being swept; regressions only in the core-less cases 1-3.
