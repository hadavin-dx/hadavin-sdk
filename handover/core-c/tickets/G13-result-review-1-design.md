Snapshot g13r1. No Blocker. 2 Majors (availability / false refusal), 2 Minors, blind spots, nits. Leak-side logic reads correct.
- M-1: the head/tail rule refuses ordinary text beside a placeholder, and one planted value makes it permanent for the run: runmap.py:1336-1366 `_touching_piece`, :1425: any key preceded by a string that is a prefix of ANY secret value (symmetrically a suffix after it) is refused; nothing checks whether the key's own original continues the value. Case: a WEBHOOK secret is the whole URL starting `https://hooks.slack.com/...` (redact.py:250-256, SECRET_KINDS :2763): `https://` before any key (`https://<HOSTNAME_1>/health`) is an 8-char prefix piece: refused `held_value_left`; tool results are producer output so they contain it too; a model message with it stays in history and is re-enforced on every call: every later call of the run is refused. Hostile: one fake webhook URL in a document makes it permanent. ENCODED/SECRET values (arbitrary strings, a `password=https` value) same. The 1,978-input corpus (0 refused on producer output) cannot show it (a fully masked value leaves no piece beside a key); the 699 raw-input refusals are not a false-refusal measurement of the new rule; D7 "0 in the corpus" accepted: wrong for URL-scheme heads. Fix: require the piece longer than a floor (8+) or half the value, OR require that the key's original's start continues the value (`value[len(piece):]` starts with that original; reverse for a suffix), OR exempt pieces made only of scheme/separator characters; gate test: webhook value + `https://<HOST_1>/x` must be SENT.
- M-2: `_windows` refuses every large non-ASCII/escape-bearing text once one long secret is in the map (runmap.py:1380 `max(map(len, snap.secret_values))`, :1399-1403): overlap = 10 x longest + 16; InputTooLarge when 2 x overlap >= VIEW_WINDOW (65,536): a longest secret >= 3,262 chars (RSA-4096 PEM, large JWT, or an ENCODED original a hostile document plants up to B64_MAX_UNIT_CHARS 65,536): any chunk over 64 KB with a non-ASCII char or any `\`, `%`, `&` returns mask_budget_exceeded (logs, HTML, URL-heavy tool results); a ~4 KB planted blob suffices. Fix: window from the cap (`MAX_REDACT_CHARS` / 4 or more, or `max(VIEW_WINDOW, 4 x overlap)`), or cap the overlap used (a view-only secret needs ~10 x its length around the match); test: a 4,000-char secret and a 100 KB non-ASCII chunk.
- m-1: overlap assumption (10 chars per char) fails for stacked encodings: decoder runs up to SCRUB_MAX_LAYERS = 8 (defaults.py:185), `%26%23...` multiplies (~30x for two layers): a secret in 2+ layers across a window edge of a chunk > 64 KB is missed (producers see it too: fails only where the producer was bypassed): state the limit or overlap 10 x 3^layers up to the cap. m-2: piece lookups can spend the call budget on hostile text (runmap.py:1355-1358: each head hit spends `len(left) - i`: ~27K keys in a 2 MB message exceed the 8M budget): charge the bisect once per distinct head or cap hits per gap.
- Blind spots (stated or acceptable): base64 of the secret NOT in the views (model_gate.py:68, D4); unlisted: UTF-7, quoted-printable `=41`, hex dump/ROT13/reversed, homoglyphs not folded by NFKC, a secret wrapped across lines; pieces under 4 chars on both sides, interior pieces between two keys (D5: `abc<K>defghi<K>jkl` leaks the 6-char interior), case change (stated).
