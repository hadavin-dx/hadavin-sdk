## Findings

Scenario: (1) line 1 `password=hunter22` becomes `<SECRET_1>`; (2) eight strings, each `password=<SECRET_1>` followed by about 260,000 secret-class characters; a forged token the map already holds makes `original != full` so each string is registered; about 300 MB of trie nodes in one call; `_place_union` adds more in every sweep; nothing refuses it; the 6 s CPU budget does not stop it (about 0.05 s per 200,000 characters suffices). Fix: count the registered characters per call (charge `_spell` and `_place_union`); past a limit (e.g. 1,000,000 characters) raise `InputTooLarge`; do NOT skip the registration (fail open); or do not trie-register a value over some length N and refuse it (the lead chooses N); state the limit as a number in defaults.py.
