## Findings
- MAJOR Registry memory has no limit and no refusal and the stated bound understates the real worst case (redact.py:1721-1730 `_spell` called from `_place` in `find`; comment 1153-1158; defaults.py:108-110): about 185 bytes per character of every registered written form (37 MB per 200,000 characters measured by the builder), no cap on count or length; registration happens in `find`, outside the work counter and the deadline check; the comments say "bounded by the call's input cap"; for `redact_many` it is the sum of the strings up to `MAX_BUNDLE_CHARS` (8 x 262,144, if that is the bundle cap). Scenario: (1) line 1 `password=hunter22` becomes `<SECRET_1>`; (2) eight strings, each `password=<SECRET_1>` followed by about 260,000 secret-class characters; a forged token the map already holds makes `original != full` so each string is registered; about 300 MB of trie nodes in one call; `_place_union` adds more in every sweep; nothing refuses it; the 6 s CPU budget does not stop it (about 0.05 s per 200,000 characters suffices). Fix: count the registered characters per call (charge `_spell` and `_place_union`); past a limit (e.g. 1,000,000 characters) raise `InputTooLarge`; do NOT skip the registration (fail open); or do not trie-register a value over some length N and refuse it (the lead chooses N); state the limit as a number in defaults.py.
- Nit: the second read in `redact()` is redundant and double-counts `actions` (redact.py:963-969): `r.actions` is not reset, so a flipped text reports about twice the real changes (`RedactionResult.actions` is documented as "how many times the redactor changed the text of this call"); the flip also costs a full extra pass; a hostile author can force it with one full-width `ＢＳＢ`. Fix: save `r.actions` before the first `find` and restore it before the second, or drop the read; if kept say it is redundant by construction. `redact_many` has the same redundancy at 2285: `range(flipped_at + 1)` re-reads string n itself (read with the flag set); `range(flipped_at)` is enough.
- Nit: the growth trigger is a round-1 patch, not a structural invariant (redact.py:1232-1241): a union registered in the sweep stage of round 2 or later is still not growth for that round (no leak found: see Verified 3); the invariant is argued, not enforced. Fix (cheap): record `len(mapping)` before the sweep loop of every round and if it grew put every string in `todo`; `NotSettled` stays the cap.
- Nit: figures and wording that differ from the code or the raw evidence: hostile refusal time 0.53 s (defaults.py:104 and the ticket) vs raw 0.489 s twice; per-unit cost on the hostile text 0.115 us vs raw 0.134 and 0.133; "13 times the largest honest shape" is measured against the 330-line jar at 304,221 units whose registered text is 320,924 characters (over the 262,144 cap, so not an accepted input); the largest in-cap shape is the 275 x 128 jar at 254,629 units = 15.7x (the claim is conservative; name the in-cap jar); the 13x is measured on four enumerated shapes: a both-ends-growing grid (variants at the front and the end, many forms of all combinations) is not among them (estimate 20 x 20 about 3 units per character: add it to g7r6_units.py); redact.py:1798 and the docstring say the limit "can be passed by up to `_SPELL_CHECK_EVERY` units" but the terminal cost (`cost = min(M, T)`) is added after the lookup so the overshoot is up to one terminal lookup (up to `len(matched)`, not 1,024): trivial, but the sentence is false; redact.py:1158 and the ticket say `_spelled_at` holds "substrings" but the stored prefix is a reversed copy and the suffix a slice copy: a second copy of each written form (memory finding); redact.py:2059 says "the distribution is printed by the test" while the ticket says it now uses `record_property`.
- Dead code: none found in the changed area (`if tries is None: continue` and the defence-in-depth `self.mapping.get(term[0]) == term[1]` check are live and the latter is test-pinned per the ticket).
