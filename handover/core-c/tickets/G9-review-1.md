## Design critic (read only; inputs constructed by reading, nothing run): NOT ready to build; 5 Majors, 2 Nits
The read-back idea is sound for the raw case measured; four things must change first: the `_written` allow-list, the "never 3 passes" argument, the union kind, the gate default.
- M1 `_written` is an allow-list kept by hand, so omissions leak (ticket 4.2, D-4, Goal 1; redact.py:1517, :1679-1688, :1465): `_mask_in_place` (:1517) writes `self.reverse[full] if full in self.reverse else self._place(...)` (the fold scan and `_withhold` write through it): when the placeholder exists it is written without `_place` and without `_mask`; `_mask_ex` has the same reuse path. Failure: map `<SECRET_1>` = `abcdefgh`, `<SECRET_2>` = `efghijkl`; text: a full-width or look-alike spelling of `abcdefgh` followed by `ijkl`: the fold scan writes the existing `<SECRET_1>` from the `reverse` hit; `_written` never gains the token: NUL separator, no overlap seen: `<SECRET_1>ijkl`: the E10 (a) leak reached through the fold path. GATE (worse): `enforce_map`'s `first` is a fresh `_Redactor` so `_written` starts empty: model-bound history that already holds `<SECRET_1>ijkl` is never read back (the map may have learned `efghijkl` after the text was produced): "Trap 3 closed" (L-D1 default's consequence, 11) is true only for raw-raw overlaps; the gate's input is mostly already-placeholdered text; `_written` is shared by every text of one snapshot: detection of `<SECRET_1>ijkl` in text 2 depends on whether text 1 wrote that name: order-dependent behaviour in a security check. Fix: define "read back" as "a token that is an exact key of `self.mapping`", not "a token this redactor wrote" (the forged-token inflation case 9.5 is answered by the per-piece work count; the 13 hits in 9.6 are entity-encoded views = L-D5); if `_written` stays, derive it at one chokepoint; add a test per writer (fold, `_withhold`, `_sub_glued`, a `reverse` reuse).
- M2 "A union does not change the read-back text, so passes 3 and 4 are unreachable" is FALSE (4.4, 9.2, 11, 7 stub tests; redact.py:1690-1710): `_place_union` calls `_place(kind, full, union)`: for a secret kind `_place` registers every readable piece of the union's written text (`_PIECE` 8+ characters, `_secret_shaped` upper+lower+digit, not already in `reverse`) and the union's written form via `_spell`: the map grows by new every-copy rules and the next pass rebuilds with them: derived registration, contradicting D-5 and the lead's design; the fuzz alphabet was `abc` with 4-7 letters so no piece can reach 8 or be secret-shaped: the 20,000-input "max 2 passes" says nothing about this path. Chain (abstract): S1 ends with `G9`, S2 starts with `G9`, S2's tail after the overlap is a 12-character mixed run `hIjK1mNoPq2R`; pass 1 unions the pair; the readable tail piece is registered as P1; elsewhere readable `hIjK1mNo` glued to a placeholder X whose value starts with `Pq2R`: P1 straddles it: pass 2 unions that; the new union's readable piece `hIjK1mNo` (8 characters) registered as P2; and so on: each pass costs a union, a full `_build` and a finder rebuild: a hostile document needs 3, 4 or 5 passes and ends in `SpelledNotSettled` (fail closed but REACHABLE; a time-multiplied DoS: 5 settle sweeps x 4 passes x `_build`). Fix: delete the "unreachable" claim; measure with mixed-case-plus-digit values of length 8+ or register NO pieces for G9 unions (a `_place` variant with pieces off); tests that build a 3-pass input and one that needs a 5th pass; add `_build` cost to the bound arithmetic in 4.4 (paid per map growth per pass, not in the work count).
- M3 Union kind (D-3) unimplemented and the signature is wrong (5 D-3, L-D4; redact.py:1916-1922): `_place_union(union, first)` takes the kind from `first`; a read-back span can start with an identifier placeholder (IPV4, TENANT): a union that holds a secret is then stored under the identifier kind: swept only standalone; `_place` skips the `SECRET_KINDS` branch (no `_spell`, no pieces); `storable` and `restore_text` treat it as restorable: a secret value handed back by `restore_text`/`undo` (violates "a secret kind never restored"); `_place_union` returns `self.reverse[full]` when the span's value already exists: that value may sit under an identifier placeholder. "Strongest kind" needs the kinds of values found by the finder in E, not the tokens in the span (they come from `reverse[value]` or the alias map): the lookup and which secret kind wins among several are not specified; the test is "NOT run" and the prototype lacks the rule; this is exactly the case the redesign introduces (`_spelled_sweep` unions are secret-first by construction; E-based ones are not). Fix: specify the kind lookup; change the `_place_union` signature to take a kind; on a `reverse` hit with a weaker kind register a second placeholder of the strong kind (or refuse); run the D-3 test before approval.
- M4 L-D1 gate default (refuse) vs fallback (skip): leak size if skipped: at most len(B)-1 characters of a real secret B (the later-swept overlapping value): for a 40-character key overlapping a 4-character value 36 characters of the key; DoS if refused: the run map is written by untrusted text (`password=inter` and `token=terna` in a tool output; each 4+ characters = a secret kind swept in every copy): any gate-bound text not already redacted upstream that contains `interna` is refused (a prompt, a system message, anything bypassing `redact`); texts that passed `redact` already hold the union placeholder after G9; one planted pair kills every model call of the run that carries such a string, cost to the attacker two short values; `snapshot` refuses over `ENFORCE_MAX_ENTRIES` for the whole run (G9 adds the union entry plus its pieces per overlapping region).
