## Findings
- MAJOR 1 The caps are not justified by any honest-run measurement and the defaults.py rationale is false for cookie lines (defaults.py:83-91, redact.py:1677-1690). The caps count per call and per FIRST placeholder token of a compound secret's written form; "offset" is `first.start()` = the number of characters of unrelated text before the first placeholder inside the value; defaults.py says "0 to 2 in practice": wrong for the cookie patterns (redact.py:516-531): `Cookie: _ga=GA1.2.333.444; theme=dark; sid=<JWT_1>` has an arbitrary offset (0 to 200+). Scenario A: a 200 KB access log of ONE session, the same JWT `<JWT_1>` throughout, each request's Cookie header preceded by different cookies: each distinct header is a new `full` and a new form under `<JWT_1>`: the 33rd distinct prefix length or the 257th distinct line raises `InputTooLarge("SpelledFormsTooMany")`: the whole tool result or document is refused where it was masked correctly before round 4. Scenario B: `password=<UUID_1>.<hmac_n>` or `sid=<UUID_1>.<sig_n>` on 300 lines with distinct suffixes, offset 0: forms cap fires at 257. Evidence gap: G7-1.md and test_redact_settle_loop.py:328-407 cover only a hostile text; the 5,000-form scale test uses a distinct first token per form so it never touches the caps; 32 and 256 are chosen, not derived; the at-cap cost test shows 32 offsets cost under 2 s on a 130 KB hostile text so the cap could be much higher at the same cost. Refusal consistency is sound (the check precedes the counter, the map write, the reverse map, the journal and `_spell`; the redactor is thrown away on the exception; `redact_text` runs `mapping.update(current)` only on success); side effect: a refused call teaches the run map nothing (old behaviour for any InputTooLarge, now reachable by honest input). Fix: measure on a real corpus (cookie, Set-Cookie, signed-id logs) and report max offsets and forms per token; drop or raise the caps (the per-1,024-unit deadline bounds hostile time already) or bound total trie work (tokens x offsets x depth); or bucket forms on the first K characters after the token instead of the offset; correct the "0 to 2" sentence.
- MAJOR 2 The leftmost-longest rule fixes one order of an overlap and leaves a secret tail in clear in the other; order-dependent across settle rounds (redact.py:1739-1792, test_redact_settle_loop.py:410-424). Within one sweep: F1 = `<SECRET_1>ab` (secret V+ab) and F2 = `xyz<SECRET_1>` (secret xyz+V): `xyz<SECRET_1>ab` becomes `<F2>ab`: F1 starts inside F2 and is skipped so `ab` stays readable (pinned by the test); with a long tail (20 characters of F1's tail) the tail of a value the map holds as a secret is left in clear; nothing rereads it; no docstring, defaults.py comment or ticket line states this as a limit (the ticket says "now `<BEARER_2>ab`" as though it were a fix). Across rounds: a form registered in a later round cannot recover text an earlier sweep already consumed (round 2 registers F1 and sweeps `xyz<S1>ab` to `xyz<F1>`; round 3 registers F2 through a chain; `xyz` stays readable = the M-B leak reached through a chain); numbering unaffected; not an idempotence problem. Fix: on an overlap fail closed (withhold the line, or register the union form `xyz<S1>ab` as its own entry on the spot) or state it as a limit with the leak size and drop "THE RULE, exactly" as a safety property.
- MAJOR 3 The stated time bound is not true for `redact_many` on a bank flip, and it is CPU time of one thread with unchecked stretches around the `redact_text` budget (redact.py:2139-2144, 1179-1186; runmap.py:555-604; defaults.py:55-82): on a `bank_near` flip the first `find` pass over every item runs twice (2139, 2143), both unchecked, then `sweep(text, deadline)`, and only then does `settle` check: overshoot about 2 x pass 1 + a sweep (curl -u shape: about 3 s over 6 s before the first check); the flip needs a non-ASCII bank word in a folded view (rare, but non-ASCII is the hostile case the budget exists for). `redact_text` is a series of calls: `started` is taken before `_clean`, `fits_after_nfkc`, `neutralise`; each view runs a full `redact` against the same absolute deadline; worst case = budget + one view's pass + sweep + an uninterruptible regex + `_clean(out)`: about 6 s plus up to 2 to 5 s unchecked tail on the test machine (the fixed 25 percent statement in defaults.py is about the refusal point, not this tail). `thread_time` does not advance while the thread waits on the GIL, a lock or I/O; `redact_text` has no wall guard (the tool-result path calls it); `EnforceBudget` has a wall deadline (runmap.py:651-657) only for the gate. Fix: a check between the two reads in `redact_many` or re-read only strings read before the flip; a wall deadline in `redact_text` beside the CPU one; state the worst case as budget + pass + sweep + 0.5 s per view.
- Nits: 1 segment check `i % 64 == 0` (redact.py:1892-1899) and an empty first segment skipped before it: text starting with a placeholder or with fewer than 32 free segments reads no clock in the segment loop; "a sweep with nothing to look for reads no clock" is accurate (`not (self._finders or self._slow)` plus `_spelled` empty); everything `find` registered in the round is in the map and triggers `_build`; the stale-state risk is the length-only `_built_for != len(self.mapping)` (1879): an in-place value change at the same length would not rebuild; the redactor only appends. 2 Settle and module docstrings omit the flip (12-18, 1159-1170: after a flip a round runs over every string). 3 Misleading refusal on a last-round flip (1210-1217): a `bank_near` flip in round 4 with no text change leaves `todo` = all strings so NotSettled is raised (right result); the docstring should say "or a flip no round has read since". 4 The `_PLACEHOLDER` first-token key is not restricted to real map keys but `original != full` makes forged tokens harmless: add a test that many forged tokens do not consume the cap. 5 No dead code found; `mapping.get(term[0]) == term[1]` at 1773 is a deliberate safety net; `redact(..., _sweep_copies=...)` (945, 958): not checked that any caller still passes False. 6 The depth evidence is 2,000 generated compositions of 4 to 8 lines; the reference loop shows 78 compositions needing 4 passes and 5 needing 5; the settle loop converges in fewer rounds; the cap of 4 is a margin, not derived; consider reporting one honest 5-pass composition as a test.
