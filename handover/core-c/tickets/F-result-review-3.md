## Design critic: 0 Blocker, 4 Major, 5 Nit
Verified closed: forged framing token leak (call id and tool name slots enforced); held-value net and cap exist; money paths: one settle per path, no double settle, GateRefused raised outside any except (no cause leak); no per-call state, so threads can share one gate.

- M1 Untrusted text can brick a run. (a) a line `password=<real tool name>` in an untrusted document makes the tool name a secret-kind value, then every chat is `framing_refused` (model_gate.py:311-314, runmap.py:818-820). (b) 257 planted edge values (`password=>aaaa1`...) make `snapshot` raise InputTooLarge, every chat `mask_refused`; the map only grows. Also step budget 102,400 vs about 2+2n enforce calls per tool message: an honest long history can be refused. Fix proposed: do not store a tool name as a secret at registration; no refusal past the cap, use a real deadline and a cheaper path; count steps per text.
- M2 The per-call budget is not hard. The sweep (redact.py `sweep`, `_replace_standalone`) has no deadline: 256 KB of `a` with 500 planted identifier values is about 128 million loop steps in one sweep. `snapshot` does `original in tokens` per value (quadratic) before the budget starts; one planted held value defeats the run's redact cache. Fix: deadline argument in `sweep` (asked of the G7 agent), cap K at snapshot with a code, one-pass `late`, pass the cache for `first` even when `late` is non-empty.
- M3 `held_value_left` checks held values only. Other known secrets can stay raw without a refusal: a secret straddling a fixed framing word or chunk boundary; a secret hidden inside a placeholder-shaped token `<AKIAEXAMPLE123_1>` (the net and the sweep both accept any `<[A-Z][A-Z0-9]*_\d+>`); overlap tails (stated limits, but the row says `map_enforced`). Fix: widen the net to all secret values; collapse only tokens that are exact keys of the map.
- M4 A stale or wrong map still reads `map_enforced` (a copy taken at bind time, another run's map); `enforce=` custom is accepted in production; nothing refuses. Fix: `isinstance(mapping, RunMap)` unless NO_MAP; refuse custom enforce outside tests; empty map only with an explicit caller flag (this touches the contested ORDER 020 m-2).
- N1 comment on CODE_WORST_CASE_FAILED says "error re-raised"; code raises GateRefused with a code only; ticket repeats it. N2 `spend_reason` spoofable by a class NAMED SpendRefused (use isinstance when limits.SpendRefused exists). N3 `getattr(reply, "cost_usd")` with a raising property escapes after the paid call (no row, no settle); `Decimal('-0')`, `Decimal('1E+999999')` count as usable. N4 KeyboardInterrupt in `_enforced` writes no row; gap between `reserve` and the `try`. N5 per-token amplification is not capped (2-4 enforce calls per token): cap tokens per message.
- Not found defective: case handling, value containing a marker word, allowlist codes reachable (`gate_refused` only through the `_note` bug guard; `provider_refused` only with doubles today), settle rule.
