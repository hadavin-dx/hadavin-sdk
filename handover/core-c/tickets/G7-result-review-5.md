## Findings (design)
- M-A The honest margin (16x) holds for one shape; a plausible honest log nears the limit (redact.py:1783-1819, defaults.py:93-101): the suffix walk runs once per matched prefix node (each prefix node has its own forward trie), so work per token is about P (matched prefix forms) x S (suffix length), not P + S. Example: a growing cookie-jar log of about 330 lines at the 262,144-character cap, one 4-character cookie added per line, every line ending in the same signed suffix of about 64 characters: line j matches j prefix forms and walks 64 characters for each: about 65 x 330^2 / 2 = 3.5M units against a limit of 4M; a slightly longer suffix or one more line gives SpelledWorkTooMuch on an honest log (the failure round 5 set out to remove). The measured honest worst cases (243k units with a short suffix of about 5 units per pair; 77k signed-id case with one prefix) do not cover P x S. This is arithmetic, not a measurement. Fix: walk the suffix once per token (one forward trie per first token, the set of prefix keys at each terminal, prefix verified by back-trie membership: O(P + S)); or test the P x S shape and set the limit from it.
- M-B Overlap that leaves a tail readable is wider than E10 states and the union rule does not touch it (redact.py:1948-1982 sweep order, 1822-1841 union): F1 = `<S1>ab` (full V+ab) and F2 = `xyz<S1>` (full xyz+V) registered; a raw copy `xyzVab` in another string: the literal sweep runs longest-first, replaces `xyzV` with `<F2>`, the `Vab` rule is then no longer in the segment: result `<F2>ab` with `ab` (F1's literal tail) in clear: inside ONE sweep, no later round needed (the union covers only overlaps between written forms, tokens in the text). Order dependence: a string swept after a union exists gets the union placeholder, so the same value gets different placeholders by string order. Caveat: derived by reading sweep order and rule length order; may be an old property of overlapping literal secrets, but G7 now claims "no part of it stays readable" (docstring 1752, ticket line 17). Fix: detect overlap of raw values in the literal sweep too, or state it as a limit in E10: "overlap of two compound values, written or raw".
- M-C E10 (cross-round overlap): what is leaked, who controls it, how to fail closed: the literal prefix or tail of the later form (secret material, e.g. a password's own characters before an embedded earlier secret; the embedded secret itself stays masked); the attacker needs no secret knowledge, only control of order and rounds: two strings suffice (one makes F1 register early, a later one registers F2 after the sweep wrote `<S1>`); a log author controls both. A cheap fail-closed fix: when `_spell` registers F2 under first token T, look at the other forms under T; if any string of the call contains an earlier form's placeholder immediately after the text of F2's prefix (`out.endswith(prefix, 0, idx)` before `<E>`) or immediately before the text of F2's suffix, raise NotSettled or register a union (cost: the count of E placeholders in the text, not a quadratic registry; E10 designs 1 and 2 are not needed for fail closed). Is the limit honest? Partly: pinned by a test, but it omits M-B and "Leak size: literal prefix or tail" is accurate only for the written-form case.
- M-D `redact()` (single string) does not re-read after a `bank_near` flip (redact.py:959-964, fold scan 1355-1374): one hostile text: line 1 an account number under a look-alike keyword (full-width `ａｃｃｏｕｎｔ: 12345678`) visible only in view A; line 2 a bank word hidden by a zero-width split visible only in view B; view A's hits are computed while `bank_near` is False and the flag is set only after view B: no suspect appears and `find` returns the text unchanged; `settle` builds `todo` only from changed strings, so nothing re-reads: the account stays readable. `redact_many` re-reads 0..n after the flip and pre-scans its items for bank words; `redact()` does neither. Fix: in `redact()`, after `find`, if `bank_near` changed run `find` once more (as `redact_many` does), or have the fold scan set the flag before computing hits (two passes over the views). Caveat: the rest of `_fold_scan` not read; a hypothesis to be run.
- M-E `settle` growth trigger no longer matches where the map can grow (redact.py:1208-1216, `_place_union` 1849): `known = len(self.mapping)` is read at the start of each round; a union registered during the FIRST sweep (which now registers entries) is invisible to it; strings swept earlier in that first sweep are re-swept only if the table changes them; the old invariant that the map grows only in `find` is gone. Fix: read `known` before the first sweep (in `redact` and `redact_many`) and pass it in, or have `_place_union` set a flag forcing an all-strings sweep. Related: union registration and its `_spell` and `_place` work (`_PIECE.findall`, restoring the union text) are not covered by the deadline or the work counter.
- Registry growth and memory (no caps): `_spelled` is per `_Redactor` (per call, not per run); nodes are bounded by the total length of registered originals plus unions (about one more text length per round); a single 200k-character compound value with a leading placeholder (the generic SECRET value class has no length cap, line 636) puts about 200k nested dicts in the trie: tens of MB per registration; `_spelled_at` keeps a second copy of each original; no memory figure is stated anywhere: state it.
- The limit and its cost: 4,000,000 is chosen (16x the single honest shape), not "measured" (defaults.py:95): say chosen. The stated 0.09-0.1 microseconds per unit (0.4 s at the limit) looks 3-5 times too fast for this loop body in CPython (several dict gets, comparisons and a walrus per step): the reviewer expects 0.3-0.7 microseconds per unit, so 1.2-3 s at the limit on a 130-262 KB text; ask for the raw timing; the deadline bounds it when passed; with no deadline it is 4M units per sweep per string per round with no total bound (stated); a hostile author can force a refusal of the whole document (fail-closed denial of service): worth a line in the SECURITY text.
- Union mechanics (verified): union looked up by `full` in `reverse`, one placeholder per value; restore works in one step; the union registers its own written form so the same overlap in a later string is covered by one longest candidate; unions are registered in `sweep` with no journal open, so never rolled back; `_unspell` pruning correct as traced; the overwrite case (same original gets a second placeholder after a rollback) leaves the first form unpruned: harmless (term check at 1729); a value gets different placeholders depending on whether a copy is swept before or after a union exists (M-B); no way found for a union to change the placeholder of a value already in `reverse`.
- Time statement: defaults.py:69-70 says the flip "adds one string pass at most, never a second pass over every string": wrong when the flip is at the last string (it IS a second pass over every string, each preceded by a check); what holds is that the overrun past the budget is at most one string pass. Segment cadence matches the code (`(free-1) % 32 == 0`); per-form caps gone as stated.
- Nits: `_spell` (1691) `first is None` return unreachable from `_place`; `_unspell`'s defensive returns (1706, 1716, 1726) unreachable; the comment at 1141 about a "safety net" reads like dead code (the check at 1799 is the net); `_spelled_at` keeps duplicate full strings (memory); the defaults.py list omits the back-step unit.
