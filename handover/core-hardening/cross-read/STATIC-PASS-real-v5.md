## Extra things seen
- `CrmIdOk` (`:159`) reads `CrmUpsert` output, but `SetCrmId` ran first and `alwaysOutputData` is on; if the UPDATE affected no row (claim lost) the flow still goes on to `OwnsClaim1`, which stops it correctly (`OutLost`).
- Reply wording for a second send during the first run is `processing` (not `done`); the narrow claim "processed once" holds by construction in the SQL, but the on-screen reply for a repeat depends on the timing.
- A lead whose email is invalid is stored as `review` and never reaches HubSpot or mail; resending it gives `review`.
