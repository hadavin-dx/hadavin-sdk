- **tty**: the keyboard-and-screen window a person types in. A program can check that a person, not a script, is typing; the release note's check on that is G35 (what the owner is asked to type).
- **loopback**: the network address 127.0.0.1, which only reaches the same computer; a call "over loopback" does not leave the laptop.
- **lease**: the time n8n keeps a lead claimed while it works on it; if the work stops, after the lease runs out another attempt may start. The release note (G12) says only "a gap longer than the lease is not claimed". I found no more exact definition.

## What the script does to the machine (exact)
`sh lead-repin-verify.sh [TAKE_DIR]` (TAKE_DIR defaults to the current folder). It needs GNU sed (or a sed that knows the `s///I` flag), grep, awk and find.
- It reads files (grep, sed, awk, wc, find, sha256sum), reads git (`rev-parse`, `log`, `status`, all with `--no-optional-locks` and the file-system monitor switched off, so git does not rewrite its index), and reads the list of listening ports.
- **git can still start a program:** `git status` may run a program named in the folder's own git settings (a filter, for example for large files). If you do not trust the folder, run with `LEAD_REPIN_NO_STATUS=1`; the script then skips `git status`. The script also prints the top folder of the git work tree, because a take folder inside a bigger repository would print that bigger repository's commit id.
- It writes **only** into one private work folder made by `mktemp` (folder mode 700, files mode 600). **On a Windows-mounted drive under WSL those modes may not be enforced**, so set `TMPDIR` to a Linux folder. The work folder holds: the output copy (already masked), lists of file names (paths only), the two masking rule files, and small masked helper files. **No unmasked line of a searched file is written to disk**: every search sends grep's output straight into the masking filter. The only file with made-up secrets is the canary test input, and the script deletes it again right after the test.
- It deletes: (a) the two canary test files; (b) in the modes `--self-test` and `--mask`, and when the canary test fails, the work folder it made itself (it checks the path is of the form `.../lead-repin.XXXXXX` first). **A normal run keeps its work folder** (it holds the masked output copy); delete it yourself. The script lists the folder's files at the end of the output.
- It makes no network call and no model call, and starts no program of the take and never the model program.
- It judges nothing.
- **Masking is a safety net, not a guarantee.** One masking filter is used on every search result. Before a normal run opens any take file, the script runs a **canary test** (the masking filter is tried on about 60 made-up secret lines and about 40 lines that must stay readable); if any case fails, or the filter cannot work with this sed, the script stops with exit code 3 and has read nothing. The lead still reads the output before sharing it. A secret whose **name the filter does not know** (not key, token, secret, password, passwd, passphrase, pass, pwd, pw, psw, pswd, pat, credential, auth, authorization, bearer, private, and words ending in key/token/secret/password) and whose value has no known shape (sk-, ghp_, AKIA and so on) is NOT hidden. The filter errs on the side of hiding: names like `key_file` or `monkey` hide their value, so you open that file yourself to see the path.
- At the end of the output the script prints how many lines had a value hidden and how many were hidden whole by the "next line" rule, so you can see what the filter did.

Other modes: `sh lead-repin-verify.sh --self-test` runs the canary test and prints PASS or FAIL per case (it never prints a secret, only the case name). `<command> | sh lead-repin-verify.sh --mask` passes any text through the same masking. Test aid: `SELFTEST_FILTER="sh other.sh --mask" sh lead-repin-verify.sh --self-test` runs the same cases against another filter (I used it to run v2's filter).

Settings (environment variables, all optional): `TAKE_PY CRM_PY DRIVE_PY N8N_PY` (when not set, the script finds each file by name up to 4 folders below TAKE_DIR, prefers a `scripts/` folder, prints which file it used and any other file with the same name), `FLOWS_DIR`, `MODEL_DIR`, `MODEL_SETTINGS`, `ONE_STORE`, `LEAD_REPIN_NO_STATUS`, and the search words `END_RE`, `MODEL_RE`, `DELETE_RE`.
