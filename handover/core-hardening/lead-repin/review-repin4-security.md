# Re-pin v4 security/redaction design review (condensed copy of inline report), 2026-11-16
Read only, nothing run. Verdict: not yet reliable on a real tree. No confirmed Blocker; Majors 1, 3, 4, 5 could leak real values.
## Majors
1. Filename injection into sed (script L953 `sed "s#^#$lf_f:#"`): a file name with `#` breaks the expression; GNU sed `e` could run a command (UNVERIFIED, from sed docs). Fix: build the prefix with awk -v / ENVIRON.
2. Guide L91 hand command `git --no-optional-locks status --porcelain` lacks `-c core.fsmonitor=false`; hand commands lack LC_ALL=C and `grep -a`, so binary-looking files are skipped silently. L77 "a secret cannot print" says nothing about what is skipped.
3. YAML block scalars leak (L135, L224-225): `secret: | # note`, `secret: |2`, `secret: !!binary |`, `secret: &a |` hide only the header; body lines print (short bodies under 24 chars not caught). Multi-line quoted/plain scalar continuation also leaks. Canary covers only plain `|`.
4. Names with the secret word not last leak (L122): secretValue, tokenString, passwordHash, authTokenValue, keyValue, secretdata. Canary tests only accessToken, apiKey.
5. Canary can pass while half a secret prints (L631-775): checks only the full made-up lowercase string. URL password with `@` leaves tail (`user:pa@ss@host` shows `ss@host`); mid-line "Password: correct horse staple" hides one word; "the password is a b c" same. Fix: canary line per character class, check a 6-char prefix.
