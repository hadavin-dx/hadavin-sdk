## Plain words first (read this if you have never seen the project)
Every label below is used later in this file. One word keeps one meaning.
- **script**: the file `lead-repin-verify.sh`. You start it by typing `sh lead-repin-verify.sh` in a terminal (the text window where you type commands). It only reads and prints; it judges nothing.
- **masking filter** (also **filter**): the part of the script that looks at every line before it is printed and replaces a value that looks like a password, key, token or e-mail address with `<masked>` (or `<email-masked>`). Two other replacement words exist: `<masked-blob>` for a long string of letters and digits that no name explains, and `<masked-token>` for a mixed-letter word of 12 or more characters.
- **canary test** (also **self-test**): before the script opens any file of the take, it feeds the filter a list of made-up secrets and a list of harmless lines. If one made-up secret still shows, or a harmless line is hidden, the script stops with exit code 3 and has opened no file of the take and no input. It is named after the bird taken into a mine to warn of bad air. `sh lead-repin-verify.sh --self-test` runs the same test and prints every case.
- **work folder**: the private folder the script makes for itself with the `mktemp` command. Only its owner can open it (see **umask**).
- **umask**: a setting that decides who may open the files a program makes. The script sets it so that only your own user can read them.
- **exit code**: the number a program leaves when it ends. 0 means it ran to its end; any other number is a specific kind of stop (the list is below).
- **sed, awk, grep, find**: ordinary text tools on Linux. **GNU sed** is the usual Linux version of sed; some other systems (macOS, busybox) ship a different one, which the canary test then rejects.
- **WSL**: Windows Subsystem for Linux, a Linux terminal inside Windows.
- **sha256**: a 64-character fingerprint of a file; the same file always gives the same fingerprint and any change gives a different one.
- **porcelain**: the machine-readable output form of the `git status` command.
- **qs_37**: the name of the test that shows a refusal after the window end (item Q27 b).
- **stage**: one step of the masking filter. The first stage uses rules about names and shapes (a `sed` program); the second stage (an `awk` program) hides long opaque strings and whole lists, and cuts long lines.
- **BL-wp6-G1**: a row number in the studio's own list of open problems; this file only quotes it.
- **take**, **head** and the other words of the project are explained in the section "Words used in this file".

## What the script does to the machine (exact)
`sh lead-repin-verify.sh [TAKE_DIR]` (TAKE_DIR defaults to the current folder). It needs GNU sed (or a sed that knows the `s///I` flag), grep, awk, tr and find. All text tools run with `LC_ALL=C` (byte-wise matching) and `grep -a` (a file with a byte that is not valid text is still searched, never skipped as "binary").
- It reads files (grep, sed, awk, tr, wc, find, sha256sum), reads git (`rev-parse`, `log`, `status`), and reads the list of listening ports.
- **What the git switches do and do not do.** All git calls use `--no-optional-locks` (git does not rewrite its index file to refresh it) and `-c core.fsmonitor=false` (the folder's file-system-monitor program is not started). Checked on a made-up git folder (evidence-repin4/09-git-index.txt): the index file had the same sha256 and the same modification time before and after a normal run. These two switches do **not** stop every program the folder's own git settings can name: `git status` may still run a filter program (for example one for large files). If you do not trust the folder, run with `LEAD_REPIN_NO_STATUS=1`; the script then does not run `git status`. The script prints the top folder of the git work tree, because a take folder inside a bigger repository would print that bigger repository's commit id.
- It writes **only** into one private work folder made by `mktemp` (folder mode 700, files mode 600). **On a Windows-mounted drive under WSL those modes may not be enforced**, so set `TMPDIR` to a Linux folder. During a run the work folder holds: the output copy (already masked), lists of file names (paths only, no file content), the three masking rule files (no secret in them), and small masked helper files. **No unmasked line of a searched file is written to disk**: every search sends grep's output straight into the masking filter. The only file with made-up secrets is the canary test input; it is deleted at once and on every exit path, including a stop by signal.
- **When the run ends normally, the script deletes every file in the work folder except the masked output copy and the three masking rule files** (4 files). The lists of file names are deleted because a file name can itself hold private text (an e-mail address, for example). Checked: evidence-repin4/08-main-run-dash.out and the self-test case "the kept folder holds only the output copy and the rule files".
- It deletes only inside the work folder it made (the path must have the form `.../lead-repin.XXXXXX`, checked before `rm -rf`). It removes the whole work folder: in `--self-test` and `--mask`; when the canary test fails or the setup fails; and when the run is stopped by INT, TERM, HUP or PIPE (Ctrl-C, kill, closed terminal, closed pipe). A normal run that reaches its end keeps the work folder with the masked output copy; delete it yourself. If the output pipeline fails (for example you closed the reading end with `| head`), the exit code is 4 and the work folder is kept with the partial output.
- It makes no network call and no model call, starts no program of the take and never the model program.
- It judges nothing.
- **Exit codes.** 0: the checklist ran to its end (this does not mean the answers are good). 2: setup problem (no work folder, take folder missing). 3: the filter is not usable or failed its own test; no take file and no input was opened. 4: the output pipeline failed. 129, 130, 141, 143: stopped by HUP, INT, PIPE or TERM. For `--self-test`: 0 all cases passed, 1 at least one failed.
- **Masking is a safety net, not a guarantee.** One masking filter is used on every search result, and a second pass over the whole output text runs at the end ("final pass"); the script prints how many extra values that second pass hid. Before a normal run opens any take file (and before `--mask` reads any input), the script runs the **canary test**. The filter now hides: values after secret names (key, token, secret, password, passwd, passphrase, pass, pwd, pw, psw, pswd, pat, credential, auth, authorization, bearer, private, and words ending in key, token, secret, password; also in the plural: API_KEYS, PASSWORDS, AUTH_TOKENS); every word of 24 or more letters and digits that holds a letter and a digit (so a bare base64 string is hidden even when no name explains it); mixed-letter words of 12 or more characters; JWT-shaped values; `curl -H "X-Auth-Token: v"`, `-H 'Authorization: token v'`, `curl -u`; `ENV TOKEN v` (no equals sign); `passwd "v"`; a `name: value` in the middle of a line; JSON and YAML values that sit on the next line, inside arrays, nested objects and pretty-printed blocks; escaped quotes and adjacent strings; PEM private-key blocks; `sk_live_` keys; and, for a line that grep printed, the `path:12:` prefix does not stop the rules. Token counters (`max_tokens`, `prompt_tokens`, `total_tokens` and similar) are kept. A secret whose name is unknown, whose value is short (under 24 characters) and has no known shape is still NOT hidden. The filter errs on the side of hiding: names like `key_file` or `monkey` hide their value, and a long path component made of letters and digits (a scratch folder with a 36-character id, for example) prints as `<masked-blob>`.
- At the end of the output the script prints how many lines had a value hidden, how many searches printed fewer lines than grep counted (`PRINT MISMATCH`), and on how many matching lines the searched word itself was hidden (`MATCH WORD HIDDEN`: open the file at the line numbers printed).

Other modes: `sh lead-repin-verify.sh --self-test` runs the canary test and prints PASS or FAIL per case (it never prints a made-up secret, only the case name); it then also runs 11 machinery checks (see below). `<command> | sh lead-repin-verify.sh --mask` runs the canary test, then passes any text through the same masking. Test aid, `--self-test` only: `SELFTEST_FILTER="sh other.sh --mask" sh lead-repin-verify.sh --self-test` runs the same cases against another filter; in every other mode the script removes `SELFTEST_FILTER` from its environment. `LEAD_REPIN_TEST_BREAK_FILTER=weak|empty` damages the filter on purpose so the stop can be seen; never set it in real use.

**Test counts (from the run in evidence-repin4/03-selftest-dash.txt and 03-selftest-bash.txt):** the canary test makes 288 checks (each made-up line is checked through up to four views of the filter: the whole filter, the final pass, the first stage alone and the second stage alone, so that a damaged rule cannot hide behind the other stage); `--self-test` adds 11 machinery checks: 299 passed, 0 failed, under dash and under bash. A 1 MB single line takes about 0.5 seconds (evidence-repin4/04-timing-1mb.txt).

Settings (environment variables, all optional): `TAKE_PY CRM_PY DRIVE_PY N8N_PY` (when not set, the script finds each file by name among the files whose path has at most 3 sub-folders below TAKE_DIR, prefers one in a `scripts/` folder directly below TAKE_DIR, prints which file it used and any other file with the same name), `FLOWS_DIR`, `MODEL_DIR`, `MODEL_SETTINGS`, `ONE_STORE`, `LEAD_REPIN_NO_STATUS`, and the search words `END_RE`, `MODEL_RE`, `DELETE_RE`.

**How deep the search goes.** `find -maxdepth 4` looks at files whose path has at most 4 parts below the folder: `a/b/c/file` (3 sub-folders) is searched; `a/b/c/d/file` (4 sub-folders, 5 parts) is NOT. The script counts the left-out files and prints the number.
