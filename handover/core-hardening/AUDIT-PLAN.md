# AUDIT PLAN v3 (ORDER 002 part 1): static architecture audit of the hadavin-sdk core
"Session" below means the core-hardening cloud session (the author of REPORT.md). "Lead" means the laptop lead.
Ladder line: rung 1 (reuse). Reading, grep and one stdlib analysis script (analysis tooling, not product code). No edit outside handover/core-hardening/. Static only: no n8n, no network, no model calls, made-up data only. Anything needing a runtime is tagged UNVERIFIED.
Audited head sha: recorded in REPORT.md and at the top of every output file (git rev-parse HEAD).

## Goal and deliverables (checklist section 4 mapped to files; all in handover/core-hardening/)
(a) MASTER-MAP.md: master map. (b) AUDIT-FINDINGS.md: findings table, plus sections for (c) ordered fix plan, (d) CUT LIST (merge/remove/archive; owner yes before any removal; archive, never delete), (e) exceptions with reason, owner, removal trigger, (f) claims check (claim, source file:line, evidence, status), (g) lessons for checklist/preamble. Fix proposals are patch files in patches/<finding-id>.patch (git diff format, never applied by us) or patches/<finding-id>.md when prose. patches/ledger-rows.md holds Blocker and Major rows in the header format of handover/ledger.md (read it first). Cross-repo items (desk, n8n, portal, CRM, other repos) cannot be seen here: listed in AUDIT-FINDINGS.md section "Questions for the lead" as UNVERIFIED.

## Formats (every lane uses exactly these)
Map row (one per module, kind, store, log, script, job, test group, doc, hook, CI job, folder, credential path, port/host, external system; repos/branches and agents/sessions get one row each in lane D3): id M-<lane>-<nn> | kind-of-thing | path | purpose (one line) | owner of the job | inputs | outputs | failure path | retry/timeout | idempotency | where it logs | identity it runs as | where tested | who uses it (importers) | notes. Unknown cell = UNVERIFIED (not blank). Full 15 columns only for rows with state, egress or credentials; leaf utilities, docs and tests use 5 columns (id | kind | path | purpose | used-by). The evidence script emits the skeleton (id, path, importers, test files, logger/store/credential hits); builders fill the judgement columns.
Finding row: id <lane>-<nn> (A-01, B-02, C-.., D1-.., D2-.., D3-.., X-.. for cross-lane) | severity | class (DUPLICATE, DEAD, INCONSISTENT, UNVERIFIED-CLAIM, STORE, SECURITY, OPS, WALK) | evidence file:line (raw quoted line, no secret values) | what is wrong | proposed fix | verdict | thing's own verdict | duplicate-of / single source | guarantee text (doc file:line), code file:line, test file:line or the literal "no test found by grep for <names>" (required for Blocker and for every claims row) | patch file. Verdicts are proposals; the lead decides.
Severity: Blocker = secret, money, redaction, approval or audit guarantee can fail, or a stated guarantee has no code or test behind it. Major = duplicate store/log/engine, working code that contradicts a doc or other code, or dead code that looks live. Nit = naming, stale text, harmless idle file.
Verdict: NEEDED (one place for a job, in use or required as an alternative kind under no-single-dependency with wiring complete); DUPLICATE (second place for a job; name the single source); NOT-NEEDED (no importer, no registration, no test, no doc or rule needs it); CRM-COULD-DO (used only if a function here overlaps something a CRM or n8n flow outside this repo does; then state the outside tool as UNVERIFIED). For findings that are not about a whole module or job (INCONSISTENT, SECURITY, OPS, WALK, UNVERIFIED-CLAIM) the verdict cell is FIX-NEEDED, and the "thing's own verdict" cell holds NEEDED/DUPLICATE/NOT-NEEDED for the module involved. CRM-COULD-DO is allowed only when a function here has a clear outside counterpart; when unclear use NEEDED or UNVERIFIED. A finding with no judgement possible without a runtime keeps its class and gets the tag UNVERIFIED in the verdict cell (exact spelling UNVERIFIED). Never flag n8n or other no-code tools as wrong (owner reminder).
Alternative kinds (secrets_*, signer_*, anchor_*, llm backends): NEEDED unless wiring is missing; missing wiring is Major, a missing test is Nit.
Legend: AUDIT-FINDINGS.md starts with a plain-words legend of every class, severity and verdict word (wording rule).

## Timeline (wall clock from GO of part 1 build; at T+135 the session stops, writes FINAL and lists open items by severity)

T+15..75 six builders in parallel (60 min box; at minute 60 a builder stops, marks the unfinished modules UNVERIFIED in its findings file, reports; lane order: security-relevant and stateful modules first, leaf utilities last). Plan review exit: if round 3 still has Blocker or Major, the session fixes them, records them in plan-review-3.md and proceeds, listing them in REPORT.md for the lead.

## Steps
1. Plan review rounds (this file), max 3, done with 0 Blocker and 0 Major. Reports saved by the session: plan-review-<n>.md, plan-resolve-<n>.md.
2. Evidence runner (EVIDENCE RUNNER, sonnet). Writes parts/evidence-1.py (stdlib only: ast, pathlib, re, difflib, hashlib) and runs it; raw output to parts/evidence-1.md with command and head sha. No pytest, no mutation or plant script, no file rewrite. It lists, never judges. Sections: (1) import graph module -> importers; (2) modules with zero importers, EXCLUDING and listing separately: __init__ re-exports, names found as strings in registry.py, backends/factory.py, backends/builtin.py, sources/kinds.py, pyproject entry points, tests; (2b) every dynamic-import hit (importlib.import_module, __import__, getattr on module objects, lazy loaders in deferred.py) and every string literal that equals a module dotted path, with the line where it is built; (3) public functions/classes with zero references by name across src, tests, demos; (4) test file to module map by import; (5) pattern hits per file:line for state and logs (sqlite3, open( with write modes, write_text, write_bytes, .jsonl, psycopg, DSN, logging.getLogger); (6) pattern hits for credentials and egress (environ, getenv, secret, token names only, urllib, http.client, requests, httpx, boto3, socket); (7) claims: exact claim types and sources: number of tests (claim in docs vs count of `def test_` by ast, always UNVERIFIED-against-pytest), number of modules and kinds (claim vs count of files), versions (claim vs pyproject), ports and file names (claim vs literal in code); (8) declared dependencies (pyproject, uv.lock names) vs imported top-level names; (9) duplicate candidates: AST-normalised function-body hash and difflib ratio for function pairs across modules, same-named public functions and classes in different modules, duplicate regex and string literals (redaction patterns, header names), file diff ratio of each demos/ask-your-data/askdata module against the same-role core module, and a parity table of methods across the secrets_*, signer_* and anchor_* kinds with the test files that name each; (10) skeleton map rows. The runner writes the commands it ran and exit codes into evidence-1.md.
3. Builders (6 general-purpose sonnet, parallel: A, B, C, D1, D2, D3; 60 min box; read-only except the allowlist). Each reads evidence-1.md first, opens the code for every finding, writes parts/map-<lane>.md, parts/findings-<lane>.md, parts/checkpoint-<lane>.md (every 30 min). Each map file ends with a mandatory section listing every store, log, credential name, egress call, redaction point, retry and timeout in the lane. Walks (headings: trigger, branches, error paths, retries and timeouts, kill/restart/duplicate/out-of-order/empty/huge input, what is written where, what a person sees, what is logged, which identity acts, approval points, loop stop conditions; needs-a-runtime steps are UNVERIFIED), each in parts/walk-<lane>.md: approval path (approvals -> actions executor -> audit) owner A reading runtime/ read-only; agent loop (runtime/agent_loop, plan, tick) owner B; k1b diagnosis and replay loop owner C (reading k1b/ read-only); llm call path owner C. Two walks in one file go in the order written here.
4. Cross-lane pass (1 builder, sonnet): reads all parts/, writes parts/cross.md with these tables, columns fixed: (T1 stores and logs) engine | path | writer | reader | retention | exception reason | owner | removal trigger; (T2 credentials and identities, names only) name | where read | who uses | scope | lane; (T3 egress) call site | host config name | guard applied (egress.py) | lane; (T4 redaction implementations) file | what it masks | callers | overlap with other redaction files; (T5 retry and recovery) file | policy | callers; (T6 hashing and secrets backends) file | purpose | callers; (T7 approvals: slack.py vs slack_channel.py and any other pair) file A | file B | same job? | evidence; (T8 demo vs core) demo file | core file | diff ratio | verdict; (T9 OPS sheet) start | stop | restart | kill | cleanup | limits. A pair is a DUPLICATE candidate when evidence section 9 shows the same function body or the same patterns, or two files perform the same stated job. Findings use prefix X-. Then the session merges into MASTER-MAP.md (map rows plus cross.md tables), AUDIT-FINDINGS.md (legend, findings by lane, X- rows, (c) fix plan sorted Blocker then Major then Nit, within a class by dependency; (d) cut list built from NOT-NEEDED and DUPLICATE verdicts, marked owner yes needed, archive not delete; (e) exceptions from T1 exception columns; (f) claims table from parts/claims-D3.md and evidence section 7; (g) lessons; questions for the lead). Merge: no renumbering, check ids unique, check every X- row cites evidence.
5. Result review (fresh egm agents; every Agent call sets model sonnet; the session saves their reports as result-review-<n>.md): inputs MASTER-MAP.md, AUDIT-FINDINGS.md, parts/, evidence-1.md, the repo at the audited sha. Lenses: egm-codebase-details (spot-check 10 random findings and 10 random map rows at file:line; any mismatch is a Major), egm-zoom-out (given evidence section 9: what duplicates or dead things were missed), egm-design (store rule, one source per job), egm-comprehension (can the lead read the table; wording). Then egm:egm-resolve through the Skill tool (it runs on opus). Max 2 result rounds, with the security/money/redaction exception above.
6. Fix patches and ledger rows (session only): patches/<finding-id>.patch only for Blocker and Major whose fix is under 20 lines; produced with git diff in a scratch worktree outside the repo working tree, and checked with git apply --check on a clean checkout; all other fixes are the one-line "proposed fix" cell, or patches/<id>.md when a decision is needed. patches/ledger-rows.md: Blocker and Major rows in the 7-column format of handover/ledger.md: id (CH-<finding id>) | package (core-hardening) | severity (BLOCKER or MAJOR) | summary | status OPEN | verifying artifact (the evidence file:line) | reviewed commit (audited head sha). REPORT.md duties: agent register row before each agent starts; status block every 10 minutes (UTC and IST) with agents running and what each does; push to branch cloud/core-hardening after each block; FINAL block at the end.
Part 2 (r7u/r7v hygiene restart) starts only after the FINAL block of part 1 and only if time remains; it gets its own plan and EGM review.

## Write allowlist for builders (anything else is forbidden)
parts/map-<lane>.md, parts/findings-<lane>.md, parts/checkpoint-<lane>.md, parts/walk-<lane>.md (owners only), parts/claims-D3.md (D3 only), parts/cross.md (cross-lane builder only), parts/evidence-1.py and parts/evidence-1.md (evidence runner only). <lane> is one of A, B, C, D1, D2, D3. The session creates parts/ and patches/ before step 2. Only the session writes MASTER-MAP.md, AUDIT-FINDINGS.md, patches/, REPORT.md.

## Brief template (every general-purpose brief)
First block: full contents of handover/BRIEF-PREAMBLE.md pasted unchanged (starts STUDIO-PREAMBLE v1, contains EGM-GATE v1). Then: lane, read list, deliverables with the Formats section pasted, the write allowlist, the 60-minute box and checkpoint rule. MUST-NOT: edit outside the allowlist; git commit or push; call any model or network; run pytest, mutation or plant scripts; open .env or key files; print any secret or config value (names only); write "known limitation" instead of a finding; flag n8n or no-code tools as wrong; spawn sub-agents. Report: what failed first, what was not checked, files written, head sha.

## Stop rule
Done when a fresh result-review pass has no open Blocker or Major, or the round cap is reached and the remaining items are listed with severity (security/money/redaction items keep going). Then FINAL block in REPORT.md, push, stop and wait.
