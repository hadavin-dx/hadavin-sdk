# AUDIT PLAN v2 (ORDER 002 part 1): static architecture audit of the hadavin-sdk core
"Session" below means the core-hardening cloud session (the author of REPORT.md). "Lead" means the laptop lead.
Ladder line: rung 1 (reuse). Reading, grep and one stdlib analysis script (analysis tooling, not product code). No edit outside handover/core-hardening/. Static only: no n8n, no network, no model calls, made-up data only. Anything needing a runtime is tagged UNVERIFIED.
Audited head sha: recorded in REPORT.md and at the top of every output file (git rev-parse HEAD).

## Goal and deliverables (checklist section 4 mapped to files; all in handover/core-hardening/)
(a) MASTER-MAP.md: master map. (b) AUDIT-FINDINGS.md: findings table, plus sections for (c) ordered fix plan, (d) CUT LIST (merge/remove/archive; owner yes before any removal; archive, never delete), (e) exceptions with reason, owner, removal trigger, (f) claims check (claim, source file:line, evidence, status), (g) lessons for checklist/preamble. Fix proposals are patch files in patches/<finding-id>.patch (git diff format, never applied by us) or patches/<finding-id>.md when prose. patches/ledger-rows.md holds Blocker and Major rows in the header format of handover/ledger.md (read it first). Cross-repo items (desk, n8n, portal, CRM, other repos) cannot be seen here: listed in AUDIT-FINDINGS.md section "Questions for the lead" as UNVERIFIED.

## Formats (every lane uses exactly these)
Map row (one per module, kind, store, log, script, job, test group, doc, hook, credential path, port/host, external system): id M-<lane>-<nn> | kind-of-thing | path | purpose (one line) | owner of the job | inputs | outputs | failure path | retry/timeout | idempotency | where it logs | identity it runs as | where tested | who uses it (importers) | notes. Unknown cell = UNVERIFIED (not blank).
Finding row: id <lane>-<nn> (A-01, B-02, C-.., D1-.., D2-.., D3-.., X-.. for cross-lane) | severity | class (DUPLICATE, DEAD, INCONSISTENT, UNVERIFIED-CLAIM, STORE, SECURITY, OPS, WALK) | evidence file:line (raw quoted line, no secret values) | what is wrong | proposed fix | verdict | duplicate-of / single source | patch file.
Severity: Blocker = secret, money, redaction, approval or audit guarantee can fail, or a stated guarantee has no code or test behind it. Major = duplicate store/log/engine, working code that contradicts a doc or other code, or dead code that looks live. Nit = naming, stale text, harmless idle file.
Verdict: NEEDED (one place for a job, in use or required as an alternative kind under no-single-dependency with wiring complete); DUPLICATE (second place for a job; name the single source); NOT-NEEDED (no importer, no registration, no test, no doc or rule needs it); CRM-COULD-DO (used only if a function here overlaps something a CRM or n8n flow outside this repo does; then state the outside tool as UNVERIFIED). A finding with no judgement possible without a runtime keeps its class and gets the tag UNVERIFIED in the verdict cell (exact spelling UNVERIFIED). Never flag n8n or other no-code tools as wrong (owner reminder).
Alternative kinds (secrets_*, signer_*, anchor_*, llm backends): NEEDED unless wiring is missing; missing wiring or no test is a finding.

- A security: src/hadavin_sdk/{actions,approvals,audit,guard}/
- B state and runtime: src/hadavin_sdk/{store,backends,runtime,k1b,sources}/, src/hadavin_sdk/registry.py, src/hadavin_sdk/deferred.py. Lane B owns the complete inventory of every store and every log in the whole repo (core and demos read-only).
- C models and top level: src/hadavin_sdk/{llm}/, src/hadavin_sdk/{__init__,app,cli,config,defaults,evals,extract,hashing,identity,limits,models,replay_records,scrub_settings,stats,tools,errors}.py
- D1 tests: tests/ (all, except tests/demo_askdata), test-to-module map, tests for removed code, vendor-import guard test vs real imports
- D2 demos: demos/ask-your-data/, tests/demo_askdata/; compares each demo module shaped like a core module (audit, ledger, meter, policy, config, pgsource) with the core module, per rules/core-modules-one-source-of-truth.md
- D3 around code: docs/, .github/, .claude/ (rules, hooks, settings.json), pyproject.toml, uv.lock (dependency list only), README.md, SECURITY.md, CHANGELOG.md, LICENSE, CLAUDE.md, root dotfiles (.gitignore, .gitattributes, .coderabbit.yaml, .gitleaks*, .sonarcloud.properties), and handover/ in scope only: README.md, STATUS.md, MANIFEST-SUMMARY.md, ledger.md, MODEL-ROUTING.md, BRIEF-PREAMBLE*.md, CLOUD-*.md, directory listing of handover/. Everything else under handover/ is out of scope and said so. D3 extracts doc claims (counts, versions, ports, file names, test counts) into the claims table.
Builders never open .env-style or key files and never print values of config or secret settings: credential paths are listed by name only.

## Steps and time budget (wall clock, real; target about 120 min total)
1. Plan review rounds (this file): done when a fresh pass has 0 Blocker and 0 Major (max 3 rounds). Reports saved by the session in plan-review-<n>.md and plan-resolve-<n>.md.
2. Evidence runner (EVIDENCE RUNNER, sonnet, 15 min). Writes parts/evidence-1.py (Python stdlib only: ast, pathlib, re) and runs it; raw output to parts/evidence-1.md with command and head sha. No pytest, no mutation or plant script, no file rewrite. Sections: (1) import graph (module -> importers) from ast; (2) modules with zero importers, EXCLUDING and listing separately: __init__ re-exports, names found as strings in registry.py, backends/factory.py, backends/builtin.py, sources/kinds.py, pyproject entry points, tests; (3) public functions/classes with zero references by name across src, tests, demos (string grep, listed as candidates, not verdicts); (4) test file to module map by import; (5) pattern hits for state and logs: sqlite3, open(, write_text, write_bytes, .jsonl, psycopg, DSN, Path( with write modes, logging.getLogger, per file:line; (6) pattern hits for credentials and egress: environ, getenv, secret, token (names only), urllib, http.client, requests, httpx, boto3, socket; (7) numbers extracted from README, CHANGELOG, SECURITY, docs, CLAUDE.md (counts, versions, ports) next to the matching values in code or pyproject. It lists, it never judges.
3. Builders (5 general-purpose sonnet, parallel, 60 min box, read-only except their allowlist): lanes A, B, C, D1, D2 plus D3 = 6 builders. Each reads evidence-1.md first but opens the code for every finding. Each writes: parts/map-<lane>.md, parts/findings-<lane>.md, parts/checkpoint-<lane>.md (every 30 min: done, next, blockers). Each map file must contain a mandatory section listing every store, log, credential name, egress call, redaction point, retry and timeout in its lane (inputs for step 4).
   Walks (one owner each, output parts/walk-<lane>.md; headings: trigger, branches, error paths, retries and timeouts, kill/restart/duplicate/out-of-order/empty/huge input, what is written where, what a person sees, what is logged, which identity acts, approval points, loop stop conditions; steps needing a runtime are UNVERIFIED): approval path (approvals -> actions executor -> audit) owner A, reading runtime/ read-only; agent loop (runtime/agent_loop, plan, tick) owner B; k1b diagnosis and replay loop owner B; llm call path owner C.
4. Cross-lane pass (1 builder sonnet, 30 min, after step 3): reads all parts/ files, writes parts/cross.md with fixed tables: stores and logs (engine, path, writer, reader, retention, exception reason/owner/removal trigger), credentials and identities (names only), egress points, redaction implementations (guard/redact.py, k1b/redaction.py, scrub_settings.py and others), retry and recovery engines, hashing, secrets backends, approvals (slack.py vs slack_channel.py), demo vs core duplicates, OPS sheet (start, stop, restart, kill, cleanup, limits). Findings use prefix X-. Then the session merges everything into MASTER-MAP.md and AUDIT-FINDINGS.md (concatenate by lane; renumber nothing; check no id collides; check every X- row cites evidence).
5. Result review (fresh egm agents, model sonnet set on every call; the session saves their reports as result-review-<n>.md): inputs = MASTER-MAP.md, AUDIT-FINDINGS.md, parts/, evidence-1.md, the repo at the audited sha. Lenses: egm-codebase-details (spot-check at least 10 random findings and 10 random map rows against file:line; any mismatch is a Major), egm-zoom-out (duplicates and dead things: what was missed; are verdicts consistent), egm-design (store rule, one source per job), egm-comprehension (can the lead read the table without help; wording rule). Then egm:egm-resolve. Max 2 result rounds; Blocker/Major findings on security, money or redaction are uncapped (they override the cap).
6. Ledger rows and fix patches as above. REPORT.md duties: agent register row before each agent starts; status block every 10 minutes (UTC and IST) with agents running and what each does; push after each block; FINAL block at the end.
Part 2 (r7u/r7v hygiene restart) starts only after the FINAL block of part 1 and only if time remains; it gets its own plan and EGM review.

## Write allowlist for builders (anything else is forbidden)
parts/map-<lane>.md, parts/findings-<lane>.md, parts/checkpoint-<lane>.md, parts/walk-<lane>.md (owners only), parts/cross.md (cross-lane builder only), parts/evidence-1.py and parts/evidence-1.md (evidence runner only). <lane> is one of A, B, C, D1, D2, D3. The session creates parts/ and patches/ before step 2. Only the session writes MASTER-MAP.md, AUDIT-FINDINGS.md, patches/, REPORT.md.

## Brief template (every general-purpose brief)
First block: full contents of handover/BRIEF-PREAMBLE.md pasted unchanged (starts STUDIO-PREAMBLE v1, contains EGM-GATE v1). Then: lane, read list, deliverables with the Formats section pasted, the write allowlist, the 60-minute box and checkpoint rule. MUST-NOT: edit outside the allowlist; git commit or push; call any model or network; run pytest, mutation or plant scripts; open .env or key files; print any secret or config value (names only); write "known limitation" instead of a finding; flag n8n or no-code tools as wrong; spawn sub-agents. Report: what failed first, what was not checked, files written, head sha.

## Stop rule
Done when a fresh result-review pass has no open Blocker or Major, or the round cap is reached and the remaining items are listed with severity (security/money/redaction items keep going). Then FINAL block in REPORT.md, push, stop and wait.
