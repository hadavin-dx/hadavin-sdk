## The money rule (the only one; A, the day card and I.0 point back here)

**Words, once.** **Usage page**: the model account's page (type its address by hand from the card; check the account name on it) showing **balance** (credit left) and **money used so far**. **Worst-case price per call** = (tokens in x input price + tokens out x output price) / 1,000,000, worked out by you (A.2). **Call ceiling**: the most model calls the studio lead states one run can cause (3 expected; if the flows can call again for a person, THE STUDIO LEAD FILLS THIS IN, blank B10, with whether the backstop refuses call 4). **Run total** = call ceiling times the worst-case price per call. **Ledger**: the model program's own spending record; it adds all spending since it was created and does not reset between a trial and the real run (lead verifies at re-pin). **Ledger total**: its sum; you print it with the command on the card as a cross-check. **Backstop**: the highest dollar total written in the model settings file. The program prints neither the backstop nor the ledger total: you compare the figures in the settings file and the printout by eye. Ledger and backstop sit under the studio lead's shared Linux user, so they are not independent: **the usage page is the one independent figure.**

**Worked example (all numbers invented).** Input price US$3, output price US$15 per million tokens; worst case 40,000 tokens in and 10,000 out. Per call: (40,000 x 3 + 10,000 x 15) / 1,000,000 = 0.27. Run total with a ceiling of 3 calls: 3 x 0.27 = **US$0.81**. Balance US$25.00 (at least 0.81: ok). Ledger total printed: US$12.40, so the backstop may be at most 12.40 + 0.81 = **US$13.21** (the file says 13.00: ok; 13.50: answer no). Money used so far at the E reading: US$3.10. After the run: 3.90, an increase of 0.80 (not over 0.81: ok). If it read 4.00, the increase 0.90 is over: emergency cancel.
