### THE CARD (print this page; no printer: copy it by hand; fill the blanks before you press create of the run key)
**The five steps (do them at once, in this order, whenever this sheet says "do the card"):**
1. If Recording is ON: switch it OFF yourself at once with the tool the numbers message names; then proceed and describe to the lead that the raw recording must be checked.
2. In your normal profile open the key list at the address in the blanks. Write on the card how many rows it shows now (own key or older key blank) and K = how many keys you cancel now (your keys of L1, normally 1, 2 if you pressed create twice; 1 for the older key).
3. For each of your keys: press the cancel button; if a box asks, press the confirmation word. A button or box word that differs from the blank but plainly cancels only this one key (not the account, not other keys): describe it, press it, and let step 4 be the proof. Any other difference: press nothing, go to "If it fails". Right after the press run `date -u` in the read terminal and jot the time.
4. Proof: reload the page. Each of your keys shows the cancelled word, and shows it again after one more reload (yes ___ no ___); or its row is gone and the list shows exactly the rows you wrote minus K (yes ___ no ___; leave the page's filters as they were). Anything else: press cancel again and reload; after two tries: "If it fails".
5. Send exactly: model key cancelled (not for a look key). Only now may you do anything else.
The look key (5.9) is the only key whose words are not on this card yet: you do its steps 2 to 4 as 5.9 says, and write the three words in the blanks.

**The only danger signs (any one, at once; W1 to W8 only while a key is alive):** W1 you typed `end`; W2 the run is stopped, refused or called off by anyone, or you typed `n`; W3 you do not know what to do, or a number, name, count, account, time or key state differs from this sheet or the numbers message; W4 the second or third phone alarm rings (after you proved the cancel: dismiss it, do nothing else); W5 the first phone alarm rings or the latest start has passed and you have not pressed Enter on the start line (if you had pressed it: dismiss alarm 1, do nothing); W6 the test terminal shows a shell prompt before you typed `end`; W7 the text of a model key appeared on your screen, except the key's own one-time display at 5.9 and 6.3 and the paste at 6.4 (a long text elsewhere counts); W8 a step says "do the card"; W9 the text of the older key appeared on your screen, key alive or not (do the card for your own key first if one is alive, then steps 2 to 4 for the older key, list L2). No word of the lead resumes a run whose key was alive: a new try needs a new numbers message, run name, key file, key and yes.
**Not danger signs (no card, no FREEZE):** a lead message "wait" or a slow lead (6.6: keep waiting, the latest start still holds); the y question; the wait for the film cue; the film pause; the wait for `end`; a button or menu wording that differs but means the same.

**What you may cancel or revoke (the only list):** L1 the keys you made with the create button (normally 1, plus the look key of 5.9): named `run-<run name>`, `look-<run name>` or the misspelled name you typed, created at or after the key-list time of my key (not yet jotted: the create time), or the look key. Another key created at or after that time: describe its name, cancel nothing. L2 the older key named in the numbers message, only if its name and creation date equal the blanks; this cancel cannot be undone. If its text appeared on your screen: cancel it at once (the 7-day condition below never applies to that). The planned cancel: only at 6.7, after 6.6 passed (new key saved, size checked), and only if its last-used time is "never" or more than 7 days before the run day (the 7-day condition belongs to this planned cancel only; else describe it: no run). A run that ended before 6.7: 7.11 says what happens. L3 an app password or HubSpot app secret whose text appeared on your screen: revoke it at once (8.3, 8.4); the entry is the one with the exact name the numbers or clean-up message gives; no name known: describe, revoke nothing. L4 After you sent "model key cancelled" or "no key was made": only the app passwords, HubSpot apps and contacts the clean-up message names, in the throwaway accounts the numbers message names (8.2 to 8.6). L5 The last-resort step in the blanks, only as "If it fails" says. Any other key or password, or a key you did not make: describe its name (a long random text: describe only that); cancel nothing. The cancel button is UNVERIFIED: treat it as final and prove it.

**Blanks, filled before you press create of the run key (the three words at 5.9, the rest from the numbers message):** key list address ______ | run name ______ | cancel button word ______ | confirmation box word (the button that really cancels, not one that only closes the box) ______ | cancelled word ______ | other channel ______ | backup person ______ | last-resort step and whether it can be undone ______ | older key name, creation date and last-used time ______ | key list time zone ______. **Filled after you press create of the run key (6.3), not before:** create time (UTC) ______ | key-list time of my key (the key list's own zone) ______. **Filled during the card, just before each cancel (step 2):** rows now, own key ______ | rows now, older key ______.

**If it fails.** The key list does not load: retry for 2 minutes, then use your phone (UNVERIFIED; 5.3 tried it), send "cancel failed", keep trying. The cancelled word differs after two tries: send "cancel failed". The latest start passes before you press Enter on the start line: do not start, send "time passed", and do the card if you made a key. **Last resort:** 10 minutes after "cancel failed" with no proof, send it again on the other channel and call the backup person; if nobody answers within 10 more minutes, do the last-resort step yourself, only in the model account. For the older key, steps 2 to 4 apply and you send no "model key cancelled"; proof failing after two tries: send "cancel failed", do the card for your own key, no run; the last resort applies (the older key may still spend).

**After the card (not part of it):** if 7.4 never happened, send "none" for the time in 8.1. If you had typed `end`, proceed at 7.9. If not, type nothing in the test terminal, describe that the run is over without `end`, and proceed once the lead has answered or the give-up minutes have passed. If you never pressed create of the run key and the run is over (decline, time passed, a check failed after "go"), send "no key was made". **Every way the run ends (finished, "I decline", "time passed", "key save failed, cancelled, new run name <name>", "cancel failed", FREEZE, no `end`) passes 7.11 before 8.1**; when no key is alive and the run is over, put the Privacy switches back to the values on your paper (the first sentence of 8.7).

**Words on this card, each meaning only this.** **Lead** and **send** as in the sheet. **Key list** = the model account page that lists keys with name, creation time, last-used time and a state word. **Alive** = from the moment you press the create button of the key list until step 5 is done (a look key of 5.9: until step 4 is done). **Latest start** = the time after which you must not press Enter on the start line. **Phone alarm** = one of the three alarms of 6.2. **Other channel** and **backup person**: as in the sheet. **Read terminal** = a second Ubuntu window where you only type `date -u`, `ls -l`, `clear` and the grep of 5.7. **Test terminal** = the Ubuntu window where the test program runs. **Normal profile** = the Chrome profile you always use. **Recording** = any screen recording or sharing.
