# Owner sheet v32 security review (egm-design, condensed copy of the inline report), 2026-11-16
Read-only, ran nothing, no vendor page. Verdict: 0 blockers, 4 majors, 8 minors. The three v31 majors are closed on the pages. Abbreviations: SA/SB sheet, CA/CB card, AA/AB appendix, LN LEAD-RELEASE-NOTE-v16, OL v32-OPEN-FOR-LEAD, HP OWNER-HELPER-v32.
## MAJOR
- M1 A failed cancel on the deadline path can leave a key spending after 18:29 UTC = 23:59 IST and the pages allow it (CA/CB "If it fails" line 17; AA/AB part 10 line 115/111; part 8 the yes). Chain: retry 2 min, "cancel failed", wait 10 min, call the backup person, wait 10 more, last-resort step. From the 18:09 UTC = 23:39 IST reminder the last-resort step comes at 18:31 UTC = 00:01 IST (2 minutes after the deadline); from the 18:19 UTC = 23:49 IST backstop it comes at 18:41 UTC = 00:11 IST. Part 10 quotes only 18:41. The yes discloses 18:41 only; the card never shortens the wait near the deadline; a key can spend up to the whole balance (sample USD 189.00) for 12 to 22 minutes past the approval. Fix: at a deadline reminder or after the deadline, do the last-resort step at once after the first "cancel failed"; state the 18:31 case. Lower impact: HP 3(d) lets the helper cancel only after 18:19 UTC and the helper has no last-resort authority (HP item 6), so with the owner unreachable the helper path also ends at the owner's last-resort step.
- M2 Command line 7.2 (SA/SB line 80): the `cd` line from the message is typed while a paid key is alive; R6's shape check (AA/AB part 3) covers the start line, paths, folders and file names only; "cd line" is never defined as `cd ` plus the Take folder; `cd /x && <anything>` is not excluded by name. Fix: the cd line must be exactly `cd ` plus the shape-checked Take folder, nothing else.
- M3 LN and OL misdescribe sheet A's money exposure (same class as v31 M2): LN lines 11, 208, 234 and OL line 88 (row 82) say "A has one live key at a time and only the owner's own run key can spend". On the sheets the older key stays valid from the run key's create press (6.3) until 6.7 (SA R4, line 25) and through the look key (5.9); if any 6.7 check fails it stays valid through the whole run until 7.11, which is B's exposure (SA line 76). "B is worse than A for money" is overstated. Fix: state the windows: A from 6.3 to 6.7 on the happy path, to 7.11 on any failure path; B always to 7.11.
- M4 "No default pick" not applied consistently: OL rows 92 (line 98), 95 (line 101), 97 (line 103) still end "Default: A"; OL row 71 says no default pick; LN 0.6 says "you do not choose for him" yet gives a money judgement favouring A. Sheets consistent (SA 5.1a sends the owner to B if the 7-day rule fails; SB 5.1a lets the owner choose A if the rule holds). Strike or reword as conditions.

The helper's scope excludes the "misspelled name you typed" key that L1 allows the owner.
- m3 Sunday run windows not excluded: check 2 only requires the cancel-by time to be at least 10 minutes before the Mon 23 Nov deadline; a Sunday 22 Nov run can overlap the 18:09 UTC Sunday reminder (safe for money, run wasted). AA/AB part 10 muddles it: "on Sun 22 Nov if you can (... latest start of 18:04 UTC = 23:34 IST ...)", but 18:04 is a Monday plan fact (LN 195, OL row 103); "backstop time" is defined only as Mon 23 Nov 18:19 UTC, yet the Sunday reminder says "by the backstop time (18:19 UTC)".

- m5 The older key is cancelled irreversibly at 7.11 on the run day even when use was seen after the 6.7 check (stated design, AA part 6, v31 minor 3); money safety needs the cancel only by the backstop time, so 7.11 on a Wed run is earlier than the deadline needs (Open 79 owns this).
- m6 5.1a "at or before Sun 15 Nov 10:30 UTC = 16:00 IST" is true only if the earliest key time on Sun 22 Nov is 10:30; the sheet says "at least 168 hours before" while the sample says "before Wed 11 Nov 10:30" (boundary mismatch).
- m7 Demo-mail deleting (R7 / 8.5): the Gmail filter matches words anywhere in the subject and the subject start may be shared with an earlier run; the count check is the only guard. Add the run name to the subject start or compare creation time.
- m8 R9 (a) says no address other than the three made-up ones, but the From column always shows the throwaway sender (SA/SB line 105), so (a) fails for the raw video by design; say 8.8 checks the edited video.
