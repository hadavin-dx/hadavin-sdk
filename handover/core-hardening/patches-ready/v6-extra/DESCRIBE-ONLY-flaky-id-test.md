# Describe-only item (lead answer Q16.1, 10:42Z): random id matches a redaction pattern
Class: a random id collides with a redaction pattern. The cmdlet-shape rule in the write-command withholding list reads ids of the form prefix + 32 hex digits as a cloud command when they start with ec2 and the next character is a-f.
Effect: test_s4_llm_guard.py::test_ids_and_plan_hashes_survive_redaction fails about 1 run in 2,731. How that is counted: the sweep tried 4 id prefixes x 65,536 first-four-digit values = 262,144 ids through `clean()` and 24 were wrongly withheld on the unpatched base (4 prefixes x 6 values; `v3/raw-c7b-fix1/sibling-clean-allids-OLD.log`), which is 1 id in 10,923. The test builds 4 ids per run, so one run fails with chance 4 x 24 / 262,144 = 1 in 2,731 (calculated, `v3/REPORT-c7b-fix1.md:17-18`). A 200,000-run loop on the unpatched base saw 81 of 800,000 ids missing (`flake-loop-OLD-200k.log`), the same order of size. Not in the take path.
Where the fix belongs: at the redaction rule (one lookahead). A ready patch and 23 tests exist in FIX-id-vs-command-withheld.patch; it is a security path and not yet independently reviewed. Nothing under src/ or tests/ was edited on this branch. Decision for a later core branch is the lead's.
Guard failures on this branch are BRANCH ARTEFACTs (Q16.2): the vendor-string and non-UTF-8 file under handover/, and the non-proprietary LICENSE copies in promotion-inputs (decision 11).
