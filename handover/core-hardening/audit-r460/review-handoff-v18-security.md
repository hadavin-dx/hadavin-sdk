## MAJOR
- MA1 The guard is not deny-by-default (secdef_guard_v18.py:3-6 docstring; HANDOFF:311 item 1(j) says only a short list of shapes is allowed and a bare SELECT, DROP or LOCK is refused). check_sql_text (207-283) has deny branches for ALTER, OWNER TO, SET ROLE, RESET, DO, GRANT and denied CREATE kinds; anything matching none passes; only CREATE FUNCTION is positively checked. Bypasses: (a) REVOKE ALL ON FUNCTION f(...) FROM PUBLIC; DROP FUNCTION f(...); CREATE OR REPLACE FUNCTION f(...): DROP has no branch, `revoked` (line 209) is an unordered set, so the later CREATE gets default PUBLIC EXECUTE (mitigation in design only: apply_function_grants re-revokes at every migrate() and the start-up query reports PUBLIC, both unwritten product code). (b) SELECT set_config('role', ..., false) passes (lead word SELECT); SET "role" TO ... passes (_lead stops at a quoted name, line 92); SET session_authorization as one underscore word; RESET "role". (c) file-level SET search_path, CALL, PREPARE, REASSIGN OWNED, CREATE VIEW, CREATE POLICY, ALTER TABLE ... DISABLE TRIGGER / DROP CONSTRAINT pass. (d) body rules (174-202) police only EXECUTE and relation words: a definer body can call query_to_xml(<caller text>, ...) which runs a caller-chosen SELECT as owner. Mutants (secdef_mutants_v18.py:44-80) test bare SELECT, DROP, LOCK only inside function bodies (F6-F8), none at top level. Fix: allow-list of statement lead words (SET LOCAL lock_timeout, ALTER TABLE ADD ..., CREATE TABLE/INDEX/TRIGGER, COMMENT, DROP TRIGGER IF EXISTS, listed function shapes, REVOKE); refuse quoted and underscore forms of role and session_authorization; require the REVOKE after the last CREATE or DROP of that signature; ban set_config, query_to_xml, dblink*, pg_read_* in definer bodies; one mutant for each.
- MA2 Allow-list and REVOKE matching ignore the schema and fold quoted-name case: _name_and_args (127-142) keeps only the last name part; sigkey (124-126) lower-cases; _type_of (112-123) lower-cases quoted types. So other_schema.spend_reserve(text,date,numeric) or "Spend_Reserve"(...) is read as the listed function; the one REVOKE for the real function satisfies it; a BEGIN ATOMIC body is never scanned (line 274), so the lookalike body can be anything: a definer function with default PUBLIC EXECUTE called clean. Same for quoted type "Date". No mutant uses a listed name with another schema or quoted case (S04 uses public.evil, not on the list). The start-up query would report it but exists only as a prototype. Fix: compare the schema part (reject any qualification or require the one schema); keep quoted case as written; mutants for both.
- MA3 "Check detects it" and "tested" claims for the audit-reader secret are overstated (HANDOFF:310; run_secrets_v18.sh:23,28,32): M3g, M3i, M3l PASS because the agent user READS the secret; nothing detects. Detectors are the unwritten S-2b start-up probe (row T) and the mode & 0o077 rule, which exists only in agent_probe_v18.py (file-strict, M3j, M3k); CHANGES 3(4) says the product accepts 0440 "by design". Real protection is the operator separating OS users and setting modes by hand: state it as that. The probe design has the agent process request the secret once and discard it (310 (3)): where readable, the fetch puts it in agent memory and leaves an access log for cloud managers; prefer a stat/permission check for the file kind, probe from the operator side for the others. v17 m5 only partly fixed.
