MAJORS
1 (lines 250, 253, 643, 650) Old `spend` and `spend_month` tables stay writable by the runtime (migrate.py:53-54) with no sign check; totals = frozen spend row + sum of spend_op, so a large negative usd wipes every cap until M2d. Fix: read old spend only before a cutover date held in a migration-role-only table, or CHECK (usd >= 0), or ship M2d in the same train.
2 (256, 284, 323, 406) A failed finish (lock_timeout 55P03 swallowed as spend_finish_failed) is not retried: the reservation stays at the reserve amount, excess over reserve never booked, runs.cost_usd never written. Finish is idempotent, so bounded in-process retry is safe, or spool to a local retry queue and count only reservations older than the retry window as orphans.
3 (256) lock_timeout does not bound the Python lock: one connection, one threading.Lock, N queued threads wait up to N x 2 s, and every other store method (Limits.blocked, kill switch, approvals) waits behind it. Add a total deadline per spend call, fast-fail when the Python lock is held past a bound, and a separate connection for spend; the "second connection only if E0-3 measures more than 1 s" trigger is too late for a money path.
4 (255-256, 288, 650) (a) add_spend now writes a direct row; nothing says it sets lock_timeout or READ COMMITTED, which reopens M-G or wrongly refuses. (b) Any database role can call pg_advisory_lock(spend_lock_key(...)) and hold it, blocking reserve, finish and relief; section 5 omits this lock attack. Add to the limits; two-int advisory form does not stop deliberate holding; provider limit and statement/idle timeouts on the runtime role are the bound (UNVERIFIED).
5 (113, 193, 256) D29 per-agent roles cannot work with the current store: one PostgresStore connection means one session_user; the trigger requires session_user to equal the agent's role, so all agents but one are refused. Say so or design a per-agent connection or store.
6 (110, 319, 325) Tier fix M-B depends on a human noticing the vendor tier (a flat route that is tiered at the vendor is booked low, 5x in the rule file's Haiku case); nothing in code detects it. Fix: required price_basis: flat | tiered with explicit confirmation, refuse routes whose model id matches a known-tiered list; cached tokens outside the input count would under-book (UNVERIFIED, doc assumes the opposite).
