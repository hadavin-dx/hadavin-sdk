# Hand-off v7 security/money review (egm-design, read-only, ran nothing), condensed copy, 2026-11-16
Verdict: no Blocker, 9 Majors, 8 Nits. Fix M-A before M2a is built. Not checked: any Postgres behaviour (triggers, ON CONFLICT with trigger, advisory locks, FOR UPDATE privilege, isolation), migrate.py 210-360, postgres.py beyond greps, Gemini/Anthropic/Bedrock kind bodies, all vendor billing facts (UNVERIFIED).
## Major
- M-A finish vs relief race: the final-guard trigger and the adjust trigger take no lock on the reservation; at READ COMMITTED both commit, reservation nets to -R (day/month/run totals below true spend). finish_spend not said to take the lock. Fix: both triggers take pg_advisory_xact_lock keyed by res_id (or agent), finish_spend takes it, two-connection test.
- M-B flat prices: Route has one input and one output price; owner's rule file records Haiku tiered price (0.10/0.50 up to 100k prompt tokens, 0.50/2.50 above) plus cache-read price; v7 ignores both; 150k prompt booked 5x low, floor uses same price. Fix: tier threshold or refuse over-threshold prompts; state cache/batch handling.
- M-C bookkeeping inside the retry classifier: settle/keep/release run inside the closure wrapped by with_retry; an OSError/ConnectionError from the store counts as transient and re-sends an already-billed request. Fix: settle outside the retried function or catch everything except SpendRefused; test with a store raising ConnectionResetError, assert one HTTP request.
- M-D demo stage gets the weak rules (MeteredLLM over any object, floor 0) though demo is where real test money is spent; subclass overriding chat accepted. Fix: key on "can spend money", MeteredLLM only over FakeLLM/named doubles; assert type(llm).chat is NetworkLLM.chat in live and demo.
- M-E over-claims about a hostile runtime (lines 30, 570): "visible" only via monthly invoice; runtime has INSERT on spend_op and agent_id is a free column, so it can fill another agent's caps (denial of service); "never exceeds a cap" is a lock property not a constraint. Fix: state it; consider per-agent roles or row security; negative test.
- M-F floor overstates by design (3 chars/token, 429/5xx booked at full worst case), so the 5% invoice rule fires every month and hides the real signal (total below invoice). Fix: true lower-bound floor or split reported-usage total from kept/estimated total.
- M-G advisory lock without timeout, taken inside the store-wide Python lock: a stuck session hangs every store call in the process. Fix: SET LOCAL lock_timeout mapped to meter_unavailable; do not hold the Python lock across the wait; explicit READ COMMITTED; test with second connection.
- M-H self-hostable kinds unusable in pilot/prod (price 0 refused; local route has unknown usage every call): breaks no-single-dependency. Fix: ship self-hosted flag now (price 0 only for loopback base_url, no keep-on-unknown) or name trigger and state the loss.
- M-I clock is the host's (replica with skewed clock doubles the cap or passes window end). Fix: compare caller ts with transaction_timestamp(), refuse skew over a bound.
