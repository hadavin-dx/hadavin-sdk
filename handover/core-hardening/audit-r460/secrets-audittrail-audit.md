## 3 Audit trail
Detected (per code and tests): edited row, changed prev, mid-chain removal or reorder (chain.py:386-403), seq gap (391), checkpoint over another history or bad signature (413-437), rewrite plus re-sign or deleted tail plus checkpoints WHEN an anchor exists (440-450), tail cut that leaves its checkpoint (test :173), concurrent writers (advisory lock, BEGIN IMMEDIATE, tests).
- 3.1 MAJOR the CLI says "intact" when nothing protects the tail or the chain (cli.py:349-364, chain.py:143-145): no signer (allowed outside prod) lets anyone with database write recompute every hash and still pass (test :520 asserts it); a signer without an anchor, or 99 unsigned rows, prints intact "(99 not signed yet)". Breaks the honest tamper-evidence rule. Fix: print "NOT tamper-evident: no signer or anchor" and the unsigned-tail range; make intact depend on it.
- 3.2 MAJOR rollback to an older consistent prefix (rows and checkpoints removed) is invisible without an anchor; anchor "none" allowed in demo and pilot (table.py:604); deleted intermediate checkpoint also silent; no test (the :173 test keeps the checkpoint).
- 3.3 MAJOR alias-named anchor object can mask a rewrite: S3Anchor.all (anchor_s3.py:70-81), GcsAnchor.all (anchor_gcs.py:50-55), AzureBlobAnchor.all (anchor_azure.py:62-67) key by the body seq and ignore the object name; anchors.parse (anchors.py:35-37) does not compare name to key(seq). A holder of the signing key plus database write plants anchors/...999.json whose body says seq=2 with the forged head; listing is lexicographic so the forged pair wins and verify passes. A junk object makes parse raise (verify blocked, exit 3). Name check exists only offline (verify_anchor_bodies). Fix: shared anchors.collect requiring name == key(seq) and rejecting duplicates; planted-alias test.
- 3.4 MAJOR signer and anchor writer are one runtime identity (chain.py:309,325) though the docstring (line 16) says anchors are written by another principal; only S3 IfNoneMatch plus Object Lock limits it; S3 has no start-up probe for Object Lock (GCS and Azure probe); retain_days defaults to 1 with no floor (table.py:155).
- 3.5 MAJOR a checkpoint whose anchor put failed is never re-anchored after restart (_unanchored is in-process, chain.py:176): verify then reports it never anchored forever; no anchor freshness check.
- 3.6 MAJOR outcome events can vanish: write_outcome falls back to audit_outbox (not chained, runtime role has SELECT, INSERT, DELETE, migrate.py:59) then to memory (chain.py:215-230); drain order differs from real order. Fix: alert on outbox age, state the limit in verify output.
- Nits: event time is writer-chosen and never checked for order (backdated events pass; checkpoints carry no time); principal is the unauthenticated OS user (k1b/audit_sink.py:29,52); signed message hadavin-audit:{seq}:{head} has no chain id; local_dir sink has no chain or signature (dev only), verify_object raises on a missing object, torn index lines silently skipped, index.jsonl default umask 0644.
