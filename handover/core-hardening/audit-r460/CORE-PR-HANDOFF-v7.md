## 4. Designs

### 4.1 Spend: reserve, settle, release, relieve (resolves v6 security majors 1, 2, 4 and nits 1 to 4, 6; readiness blocker 2, majors 1, 5, 10, 11)

**Words used here, explained once.** A *reservation* is money set aside before a model request is sent, so the daily, monthly and per-run caps count it at once. An *attempt* is one request sent to the model provider. A *call* is one `chat(...)` from our code; it holds one or more attempts (retries, and the OpenAI-compatible kind's second request). *Settle* = replace the reservation by what the answer really cost. *Release* = give the reservation back. *Keep* = leave the full reservation booked as spent. *Relieve* = an operator later gives back part or all of a kept or stuck reservation (audited). A *nano-dollar* is one billionth of a US dollar (0.000000001 USD); the new tables store whole numbers of nano-dollars, so adding rows never loses a fraction (D5).

**Admission rule (honest bound).** The sum of admitted reservations never exceeds a cap, because the compare and the insert happen in one store transaction taken under one per-agent lock (below). That is a statement about reserved amounts. The money actually billed can pass a cap by the estimator error: at most, over the attempts that were sent, the sum of (booked cost minus reserved amount) where positive; with N attempts in flight at once, N times the per-attempt error. A request already sent cannot be recalled. "Exact cap" is not claimed.

**What a reservation covers: one attempt (readiness blocker 2).** `with_retry` can send up to `max_attempts` requests for one `chat` call (`retry.py:92-107`, default 3, `backends/table.py:40`), and the OpenAI-compatible kind can run **two** `_retry` loops inside one `chat` (`llm/openai_compat.py:117-129`: the second runs when the forced answer is missing), so one call can hold up to `2 x max_attempts` attempts. Each attempt has its own reservation, its own outcome, its own booking. Attempt numbers come from **one counter inside the call's `CallBook`** (4.2), not from `with_retry`, so the second loop continues at the next number: the reservation ids of one call are `<call_id>:1`, `<call_id>:2`, ... with no collision. `call_id` is `models.new_id("res")` (`models.py:23`), fresh per call.

**Money unit (D5, lead decision, default applied).** Every amount in the new tables and the new store methods is a whole number of nano-dollars (`int`, Postgres `BIGINT`). `Reply.cost_usd`, `Route` prices and `Budget` stay `Decimal` US dollars (they exist today); one module, `store/amounts.py` (standard library only), converts at the edge: `to_nano(usd: Decimal) -> int` (calls `usd.is_finite()` **before any comparison**, because a signalling NaN raises on `<`; refuses negative and above `MAX_SPEND_NANO`; rounds **up** with `ROUND_CEILING`, so rounding can only over-count) and `from_nano(n: int) -> Decimal` (exact). `MAX_SPEND_NANO = 10**15` (1,000,000 USD, **chosen by me** as a sanity ceiling far above one call; it exists only so an arithmetic bug cannot write a huge number; the table `CHECK` repeats it and a test pins the two equal). `llm/spend.py` holds the same ceiling in dollars, `MAX_SPEND_OP_USD = Decimal(1_000_000)` (so `llm` never imports `store`); a test pins `to_nano(MAX_SPEND_OP_USD) == MAX_SPEND_NANO`. A price per million tokens with at most three decimals gives a whole number of nano-dollars per token (3.00 USD per million = 3,000 nano-dollars per token), so for today's routes no rounding happens at all.

**Store: both stores, new migration** `src/hadavin_sdk/store/migrations/0006_spend_op.sql` (name fits `_FILE`, `store/migrate.py:71`; `0001`-`0005` exist, no gap). Two new tables; both are append-only.

(`BIGINT` cannot hold NaN or infinity, so the v6 NaN comment is gone; the Python edge refuses them first.)

**The trigger text (readiness major 1).** Plain functions, not `SECURITY DEFINER` (they read `spend_op` with the caller's own SELECT right). `RAISE ... USING ERRCODE` uses condition names Postgres defines (`check_violation` = 23514, `foreign_key_violation` = 23503); the store maps both to `ValueError` with a fixed message and no values.
```
CREATE OR REPLACE FUNCTION spend_op_guard() RETURNS trigger LANGUAGE plpgsql AS $$
DECLARE r spend_op%ROWTYPE;
BEGIN
  IF NEW.kind = 'reserve' THEN
    IF NEW.op_id <> NEW.res_id || ':reserve' THEN
      RAISE EXCEPTION 'spend_op: reserve op_id' USING ERRCODE = 'check_violation'; END IF;
  ELSIF NEW.kind = 'direct' THEN
    IF NEW.op_id <> 'direct:' || NEW.res_id THEN
      RAISE EXCEPTION 'spend_op: direct op_id' USING ERRCODE = 'check_violation'; END IF;
  ELSE  -- final
    IF NEW.op_id <> NEW.res_id || ':final' THEN
      RAISE EXCEPTION 'spend_op: final op_id' USING ERRCODE = 'check_violation'; END IF;
    SELECT * INTO r FROM spend_op WHERE op_id = NEW.res_id || ':reserve';
    IF NOT FOUND THEN
      RAISE EXCEPTION 'spend_op: no reserve for this final' USING ERRCODE = 'foreign_key_violation'; END IF;
    IF NEW.agent_id <> r.agent_id OR NEW.day <> r.day OR NEW.run_id IS DISTINCT FROM r.run_id THEN
      RAISE EXCEPTION 'spend_op: final differs from its reserve' USING ERRCODE = 'check_violation'; END IF;
    IF EXISTS (SELECT 1 FROM spend_adjust WHERE res_id = NEW.res_id) THEN
      RAISE EXCEPTION 'spend_op: reserve already relieved' USING ERRCODE = 'check_violation'; END IF;
    IF NEW.how = 'release' AND NEW.usd_nano <> -r.usd_nano THEN
      RAISE EXCEPTION 'spend_op: release amount' USING ERRCODE = 'check_violation'; END IF;
    IF NEW.how = 'keep' AND NEW.usd_nano <> 0 THEN
      RAISE EXCEPTION 'spend_op: keep amount' USING ERRCODE = 'check_violation'; END IF;
    IF NEW.how = 'settle' AND (NEW.actual_nano IS NULL OR NEW.usd_nano <> NEW.actual_nano - r.usd_nano) THEN
      RAISE EXCEPTION 'spend_op: settle amount' USING ERRCODE = 'check_violation'; END IF;
    IF NEW.how <> 'settle' AND NEW.actual_nano IS NOT NULL THEN
      RAISE EXCEPTION 'spend_op: actual only on settle' USING ERRCODE = 'check_violation'; END IF;
  END IF;
  RETURN NEW;
END $$;
CREATE TRIGGER spend_op_guard BEFORE INSERT ON spend_op FOR EACH ROW EXECUTE FUNCTION spend_op_guard();

CREATE OR REPLACE FUNCTION spend_adjust_guard() RETURNS trigger LANGUAGE plpgsql AS $$
DECLARE r spend_op%ROWTYPE; f spend_op%ROWTYPE;
BEGIN
  SELECT * INTO r FROM spend_op WHERE op_id = NEW.res_id || ':reserve';
  IF NOT FOUND THEN
    RAISE EXCEPTION 'spend_adjust: no reserve' USING ERRCODE = 'foreign_key_violation'; END IF;
  IF NEW.agent_id <> r.agent_id OR NEW.day <> r.day OR NEW.run_id IS DISTINCT FROM r.run_id THEN
    RAISE EXCEPTION 'spend_adjust: differs from its reserve' USING ERRCODE = 'check_violation'; END IF;
  IF NEW.reduce_nano > r.usd_nano THEN
    RAISE EXCEPTION 'spend_adjust: more than the reserve' USING ERRCODE = 'check_violation'; END IF;
  SELECT * INTO f FROM spend_op WHERE op_id = NEW.res_id || ':final';
  IF FOUND AND f.how <> 'keep' THEN
    RAISE EXCEPTION 'spend_adjust: only open or kept reservations' USING ERRCODE = 'check_violation'; END IF;
  RETURN NEW;
END $$;
CREATE TRIGGER spend_adjust_guard BEFORE INSERT ON spend_adjust FOR EACH ROW EXECUTE FUNCTION spend_adjust_guard();
```
Decision table (what each row may be; everything else is refused, and the unique indexes allow one reserve, one final and one adjustment per reservation):
| Insert | Allowed when | `usd_nano` / amount | Refused with |
|---|---|---|---|
| `reserve` | `op_id = res_id:reserve`, `usd_nano >= 0` | the reserved amount | `check_violation` |
| `final` + `settle` | its reserve exists, same agent, day, run; no adjustment exists | `actual_nano - reserved` (can be positive: overrun) | `foreign_key_violation` (no reserve) or `check_violation` |
| `final` + `release` | same | `-reserved` | same |
| `final` + `keep` | same | `0` | same |
| second `final` for one reservation | never | | unique index violation (23505) |
| `direct` | `op_id = direct:<res_id>`, `usd_nano >= 0` | the amount | `check_violation` |
| `spend_adjust` | reserve exists, same agent, day, run; amount at most the reserve; the reservation is open or its final is `keep` | `reduce_nano` | `foreign_key_violation` or `check_violation` |
The trigger **cannot** force a `settle` to carry a realistic cost: a hostile runtime can write a `settle` with `actual_nano = 0`, which equals a release. That is the stated limit (section 5), not a hidden one. Nothing here was run: **specified, unverified; E0-3 runs it on two database roles.** Not known without running Postgres: whether `ON CONFLICT ... DO NOTHING` on the partial unique index lets the `BEFORE INSERT` trigger fire first (the design relies on that: a duplicate final passes the trigger and then conflicts); E0-3 has a test for exactly this.

**Grants** (`store/migrate.py:46-67`, the one map; `check_grants` refuses the migration without the entries): add `"spend_op": Grant("table", _APPEND)` (= `SELECT, INSERT`) and `"spend_adjust": Grant("table", "SELECT", adjust="INSERT")`; **shrink** `"spend"` and `"spend_month"` to `Grant("table", "SELECT")` (frozen history; `_apply_grants` does `REVOKE ALL` then `GRANT`, so the next `migrate --runtime-role` removes UPDATE from an existing runtime role, F21). **The operator role** mirrors the existing purge role: a new field `adjust: str = ""` on `Grant` (like `purge`, `migrate.py:32-34`), a new option `--adjust-role` on `migrate()` (like `purge_role`, `migrate.py:287-303`) and on the CLI `migrate` parser (`cli.py:99-103`), and an optional store setting `adjust_dsn_secret_name` (like `purge_dsn_secret_name`; `app.py:131-139` builds the second connection for purge the same way). **Totals come from the tables, not from counters.** `spend_totals(agent, day)` = the frozen `spend` / `spend_month` rows (history before 0006; in US dollars, `NUMERIC`) + (the sum of `spend_op.usd_nano` over the agent's day, and over the calendar month, minus the sum of `spend_adjust.reduce_nano` over the same rows) / 10^9, returned as exact `Decimal`. No code writes `spend` or `spend_month` after 0006; the old `add_spend` writes a `direct` row. The run total is the same sum over `run_id`. The runtime role holds no UPDATE on any total.

**Serialising reservers, and the isolation level (security nit 2 and 3).** `reserve_spend` takes the lock **as its first statement**: `SELECT pg_advisory_xact_lock(%s)`, key `key64(agent_id)` computed in Python as `int.from_bytes(hashlib.blake2b(b"hadavin.spend:" + agent_id.encode(), digest_size=8).digest(), "big", signed=True)` (a documented standard-library function; v6's `hashtextextended` is an undocumented internal and is gone). Two agents that hash alike only wait for each other, never over-admit. One lock covers the day, month and run checks because every run belongs to one agent. The lock needs **READ COMMITTED**: each statement then takes a fresh snapshot after the lock is granted and sees the earlier reserver's committed row. The connection is opened `autocommit=True` (`store/postgres.py:146`) and `self._db.transaction()` (`:419` shows the pattern) starts a transaction at the server default, READ COMMITTED; under REPEATABLE READ the snapshot would predate the lock and over-admit. So E0-3 asserts `SHOW transaction_isolation` equals `read committed` inside the reserve transaction, and a test with 8 threads fails if the level is changed. A Python `self._lock` already serialises threads inside one process (`postgres.py:419`); the advisory lock serialises processes. Memory store: the same steps under `self._lock`.

**Store methods** (protocol home `store/protocol.py`; result types `Reserved`, `Finished`, `Adjusted`, `OpenReservation` as frozen dataclasses next to `Store`; `UnknownReservation(NotFound)` also in `store/protocol.py`, where `NotFound` is defined (`:45`), not in `errors.py`; both stores):

```
`ts` is passed by the caller (the meter's injected clock), never read by the store, so tests with a fixed clock are deterministic and `list_unsettled(older_than)` is testable; a naive `ts` raises `ValueError`.
- `reserve_spend`: one transaction: take the lock; if `<res_id>:reserve` already exists, **compare** its agent, run, day and amount with the arguments: equal returns the recorded grant (`admitted=True`) and adds nothing; different raises `ValueError("res_id reused with different values")`. Compute the day, month and run totals as above (the run total counts this run's open reservations and its settled calls together); refuse in this order: `daily_budget` if day total + `usd_nano` is greater than `daily_nano`, then `monthly_budget`, then `run_budget` if `run_cap_nano` is given and run total + `usd_nano` is greater than it; **only if admitted** insert `<res_id>:reserve`. A refusal writes nothing. A zero amount never trips a zero cap (`0 > 0` is false), so zero-price fake routes keep working. The comparison is `>` (would exceed); `Limits.blocked` keeps `>=` (already at the cap); both are pinned by a test side by side.
- `finish_spend` (order fixed by security nit 4): in one transaction: (1) read the reserve (unknown id raises `UnknownReservation`; agent, run, day and reserved amount come from that row, never from the caller); (2) if a `spend_adjust` row exists for the reservation: write nothing, return `applied=False, late=True`; (3) insert `<res_id>:final` with `ON CONFLICT (res_id) WHERE kind = 'final' DO NOTHING RETURNING op_id`; no row returned means a final already existed: return `applied=False, late=True` and **do not touch `runs`**; (4) only if the insert happened and `run_id` is not NULL: `UPDATE runs SET cost_usd = cost_usd + <booked or reserved USD> WHERE run_id = ?` (the runtime already holds UPDATE on `runs`, `migrate.py:47`): `settle` adds the booked amount, `keep` the reserved amount, `release` nothing. A missing run row raises `NotFound` and rolls the whole finish back (the reservation stays open and counted). **`run_id` NULL (eval scope, direct booking): step 4 is skipped** (readiness major 11). The caller logs `spend_finish_late` when `late` is true (the call was already finished or relieved). `settle` amounts: the day-total change written is `booked_nano - reserved_nano`; `release` writes `-reserved_nano`; `keep` writes 0. The per-run cap reads `spend_op` and `spend_adjust`, not `runs.cost_usd`, so editing the `runs` row cannot lower the cap's view; `runs.cost_usd` is a display copy that is **not** reduced by a later relief (the operator role has no UPDATE on `runs`); the run page therefore shows spend as booked at the time.
- `adjust_spend` (operator only, 4.3): in one transaction under the same lock: read the reserve; if its final exists and is not `keep`, return `applied=False`; reduce by `reduce_nano` (None means the whole reserved amount); insert the row. The unique index allows one adjustment per reservation.
- `list_unsettled`: reserves older than `older_than` with no final and no adjustment (`state="open"`), plus, when `include_kept`, reserves whose final is `keep` and which have no adjustment (`state="kept"`); oldest first, at most `limit`; optional agent filter.

**Booking rule for one attempt (D23).**
| What happened to the attempt | Booking | Why |
|---|---|---|
| a usable answer (parsed) with known usage | `settle` at `max(cost, floor)`, clamped at `MAX_SPEND_NANO` | normal; includes a reply that later fails the caller's own checks |
| a usable answer with **unknown** usage (rule below) | `keep` (the whole reserve stays booked), logged `spend_cost_unknown`; the final `Reply` gets `usage_estimated=True` | the real cost cannot be read, so book the largest sound number |
| a **definite client error**: HTTP 400, 401, 403, 404 or 422 (a kind hook `refused(exc)`, below) | `release` | the provider refused before generating |
| anything else: timeout, connection error, 408, 429, any 5xx, an unparseable 200 (F6), a certificate error, any other `Exception`, `KeyboardInterrupt` or another non-`Exception` exit | `keep` | the attempt may have been billed (D23); a missing status is also `keep` |
| the gate refuses the **next** attempt (window, daily, monthly, run cap, call too large) | no new reservation; **earlier attempts of this call keep what they were booked as** | the refused attempt sent nothing |
| the process dies or the store write fails | the reservation stays open and counted | fail closed; `limits orphans` lists it |
**N answered attempts in one call** (the OpenAI-compatible second request): each answered attempt is settled at the moment its own answer is parsed, from that answer's own token counts, so a call with two answered requests writes two `reserve` rows and two `final(settle)` rows and the call's booked total is their sum. Nothing is "left over" to keep. The call's `Reply.cost_usd` is the existing combined price (`llm/openai_compat.py:122,131`) and equals the sum of the two settles when no floor binds (the test checks it).

**The status hook (lock-in watch point).** `NetworkLLM` gets a class attribute `refused: Callable[[BaseException], bool | None] | None = None`, the same shape as `retryable` (`common.py:244`). The generic rule is `retry.status(exc)` in {400, 401, 403, 404, 422}. `llm/bedrock.py` sets its own hook that reads `response["ResponseMetadata"]["HTTPStatusCode"]` (where `detail()` at `bedrock.py:93-101` and `retryable()` at `:104-110` already read it) because `retry.status()` does not see it. A hook that returns `None`, or an exception with no status, gives "not refused": the attempt is `keep` (over-counts, never under-counts).

**Unknown usage, the floor, and the output bound (security major 4).** `answer_usage(ans)` in `llm/common.py` returns the token pair of one answer or `None` (unknown): unknown when the input count is missing or 0, or when the output count is missing or 0 **and** the answer carries text or tool calls (an answer with no content and no output count, such as a blocked prompt, is priced at its input only). This is the same condition under which `reply()` falls back to its estimator (`common.py:164-165`), so `Reply.usage_estimated` (new field, default False, in `models.py`) is true exactly when the booking was unknown. For a known answer: `floor_usd` = (input tokens estimated by `estimate_tokens` over what was sent) x input price / 10^6 + (output tokens estimated by `estimate_tokens` over the answer's text and the JSON of its tool calls) x output price / 10^6; the booked cost is `max(reported cost, floor_usd)`. The estimator overstates English by about a third (3 characters per token against about 4 real), so the floor errs high for ordinary text; for text with fewer characters per token (Chinese, base64) it can sit below the truth, so **the floor protects against zero, missing or absurdly small usage; it does not detect a provider that reports a plausible wrong number**. The hard stop for that is the provider-side limit (section 0 item 5a). The floor and "unknown means keep" apply only to **network** kinds; a non-network object wrapped by `MeteredLLM` (demo stage only) books its own `reply.cost_usd` with floor 0 (this keeps `tests/test_k5_tools.py:723-731` passing; section 4.2). Output bound: the output of one request is bounded by `max_tokens` for the Anthropic and Bedrock kinds (request bodies read, `anthropic.py:107-120`, `bedrock.py:132-154`); for Gemini the body sets `maxOutputTokens` and no thinking setting (`gemini.py:54-83`, read) and `_parse` adds `thoughtsTokenCount` to the output (`gemini.py:97-100`); for the OpenAI-compatible kind the body sets `max_tokens` or `max_completion_tokens` and no reasoning setting (`openai_compat.py:94-116`, read). **Not known:** whether a vendor counts hidden reasoning tokens inside those caps for a reasoning model the client chooses; so for Gemini and OpenAI-compatible no output bound is claimed: the reserve is a good estimate, `settle` books the reported usage whatever it is, an excess over the reserve is booked and logged `spend_overrun`, and the provider-side limit is the backstop.

**Settle details.** `settle(res, booked_usd)`: (1) a booked cost that is not finite or is negative books as `keep` and logs `spend_bad_cost`; (2) a booked cost above `MAX_SPEND_NANO` is booked **as** `MAX_SPEND_NANO` and logged `spend_actual_capped`; (3) a cost above the reserve is booked and logged `spend_overrun`; it never refuses after the provider billed. `settle`, `release` and `keep` call `finish_spend`. If the store raises (`StoreUnavailable`, `NotFound` for the run, `UnknownReservation`, or `ValueError` for a bad amount) they catch it, log `spend_finish_failed` (class name only) and leave the reservation open and counted; **those four are the only exceptions caught**, anything else propagates, so "never raises" means "never raises these four" (the list is in the code and its test).

**Worst case, full input.** `llm/common.py:reserve_estimate(route, system, turns, specs, margin) -> Estimate(reserve_usd, floor_in_usd)` (named so it does not share a name with `k1b/loop.py:115`, `worst_case_usd`; `llm` never imports `k1b`). The input text counted is `system` + the JSON of `turns` (which already holds the documents decoded by `turns()`, `common.py:86-100`) + the JSON of `specs` (`tools_for`, `common.py:65-83`, which also turns an `output_schema` into the forced answer tool); the OpenAI-compatible kind also repeats the schema inside the system text (`schema_hint`, `common.py:~135`), which the estimate counts once, and the margin covers the rest (E0-5 compares). `floor_in_usd` = those input tokens x input price / 10^6. `reserve_usd` = ((input tokens x `margin`) x input price + `route.max_tokens` x output price) / 10^6. The margin applies to the input part only (D20). The estimator is not defined for PDF or image bytes (`extract` refuses them, D22; the runtime sends text only).

**Orphans and relief (security major 2, readiness M7 of v5).** A reservation can stay *open* (process died) or *kept* (a 429, a 5xx, a timeout: booked in full). Both can now be relieved:
- `Limits.orphans(older_than, ...)` (a read; `list_unsettled`) feeds `hadavin-sdk limits orphans` (4.3); the tick logs a warning when any open reservation is older than `spend.orphan_alert_after_s` (default `defaults.SPEND_ORPHAN_ALERT_AFTER_S` = 3600 seconds; the socket timeout is 60 s per operation and `max_attempts` is 3, `backends/table.py:34-40`, so an hour is far above any real call).
- `Limits.correct(res_id, by, reason)` mirrors `Limits.reset` (`limits.py:48-51`): `audit.write_intent(...)` first (if the audit write fails, nothing changes), then `store.adjust_spend(...)` through the **adjust connection**. - What this enforces: the runtime role cannot insert into `spend_adjust` (grants), so a compromised runtime cannot relieve anything; only a connection under the adjust role can. What it does not enforce: nothing stops an operator from relieving money that the provider really billed; the invoice comparison (section 0 item 5b) is the check. A census test allows `adjust_spend` only in `cli.py` and `limits.py`. A late genuine finish for a relieved reservation is refused (`late=True`), so a relieved amount stays relieved.
- **Why not a floor estimate instead (the other option the review named):** booking a 429 or 5xx at the input-only floor would under-count whenever the provider generated output before failing; this design keeps "errs high" and gives the operator the way back.

**Retention and cost of the table (D24).** 2 rows per attempt; the indexes above cover the day sum, the run sum and the orphan query; no deletion; rollup trigger in D24.

    def __init__(self, window_end: date | None, clock: Callable[[], datetime], margin: Decimal): ...
    def check_window(self) -> None:          # SpendRefused("window_ended") when utc_day(clock()) > window_end
    def open(self, scope: SpendScope | None, est: Estimate, route) -> "CallBook":

class CallBook:
    n: int = 0                       # ONE counter for the whole call, shared by every _retry loop of the call
    unknown_seen: bool = False
    _open: dict[int, Attempt]
    def begin(self) -> Attempt:
        self.gate.check_window()                      # (1) window, every attempt, window-only scope included
        self.n += 1
        if self.scope.window_only: return Attempt(self.n, None, None)    # nothing reserved
        res_id = f"{self.call_id}:{self.n}"
        res = self.scope.meter.reserve(self.scope, self.est.reserve_usd, res_id)     # (2) may raise SpendRefused
        att = Attempt(self.n, res_id, res); self._open[self.n] = att; return att
    def settle(self, att, booked_usd, *, unknown): ...  # meter.settle(att.res, booked) or meter.keep(att.res) when unknown
    def release(self, att): ...
    def keep(self, att): ...
    def close(self): for att in list(self._open.values()): self.keep(att)
```
Each of `settle`, `release` and `keep` removes the attempt from `_open` first (a second call on the same attempt does nothing), then calls the meter. A window-only attempt (`res is None`) books nothing. `CallGate.open` with a scope whose `meter` is `None` and `window_only` false is a programming error and raises `SpendRefused("unmetered")`.

**The `_retry` closure (settle per answered attempt, security major 1).** `NetworkLLM._retry(call)` reads the book from `_CALL.get()` (none -> `SpendRefused("unmetered")`) and gives `with_retry` this function:
```
def one_attempt():
    att = book.begin()                                  # may raise SpendRefused: passes with_retry untouched (below)
    try:
        ans = call()                                    # the kind's request + its _parse
    except Exception as exc:
        (book.release if self.refused is not None and self.refused(exc) else book.keep)(att); raise
    except BaseException:
        book.keep(att); raise
    usage = answer_usage(ans)                           # None = unknown (4.1)
    if usage is None:
        book.unknown_seen = True; book.settle(att, None, unknown=True)       # = keep the whole reserve
    else:
        cost = max(cost_of(book.route, *usage), floor_usd(book, ans))       # the answer's OWN tokens
        book.settle(att, min(cost, MAX_SPEND_OP_USD), unknown=False)
    return ans
```

- `restore_kinds` non-empty: the holder exists; it refuses to be copied out. `_Mapping.__repr__` returns `"<mapping withheld>"`; `__reduce__` and `__reduce_ex__` raise `TypeError` (so `pickle` fails loudly); `__copy__` and `__deepcopy__` return an **empty** holder, so `dataclasses.asdict(valid)` (which deep-copies fields) neither leaks nor raises and holds no original; there is no `__iter__`, `__getitem__` or `__dict__`.
- The only way to use it is the method `Valid.restore(kinds: frozenset[str]) -> BaseModel`: `kinds` must be a subset of the `restore_kinds` given to `extract` (else `ValueError`), then it does `restored = runmap.restore_value(self.data.model_dump(mode="json"), self._map._m, kinds)` and returns `type(self.data).model_validate(restored)` (`restore_value` takes only `str`, `dict`, `list`, F16). `kinds` is always passed explicitly (with `None` it would restore `NAME`, `ADDRESS`, `PHONE`, `EMAIL`). `IBAN` is not a stored kind and **is not added**: the IBAN test asserts the value stays a placeholder after restore. Default scope: extract is for fields that are not personal data.
