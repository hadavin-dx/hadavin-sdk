## MAJOR
1. Negative-total protection in Postgres depends on DB-1, which is OFF by default (5.4 items 3-4, 5.6 item 6(a), pg_v15.py:73-89). The prototype maps CheckViolation to ValueError and never inspects returned usd; wedge/rollback tests ran only with the default file applied; the "code refuses a total below zero" claim holds for the memory store only. A double give-back would push a Postgres total negative and `Limits.blocked` (limits.py:26) would never block. Fix: in the UPDATE branch raise ValueError if returned usd < 0 (rolls back), plus a test with no held file that fails on the old shape.
2. Read side with a NaN or Infinity row unspecified: default file lets NaN/Infinity in; `Decimal('NaN') >= x` raises InvalidOperation in `Limits.blocked` (limits.py:24-29), escaping `_limits_stop` and `Runtime.handle`; give-back on NaN stays NaN so the agent is bricked silently. Fix: finite checks in `spend_totals`, `blocked`, `limits status`; test with planted NaN and Infinity rows under the default file.
3. v15 new evidence is author-run only (93 of 93 from builder script pg_v15.py, run2 same author); independent runner re-ran only v14's; cluster used `initdb -A trust` so auth never exercised; audit-reader role has no product code (G1-G8 test existing _apply_grants/effective_problems, not future Grant(audit_read=)). Need EVIDENCE RUNNER re-run on a fresh cluster with password auth, on PG 14 and 17.10.
4. Audit reader credential unspecified and conflicts with policy: `startup_checks` runs inside `make()` in the agent process (5.5b item 1) and does `to_regclass` through the audit-reader connection, so the agent holds `decrease_log_dsn_secret` (mixes two identities, breaks one identity per function); no credential lifecycle (made, stored, rotated, short-lived); no config home for `audit_reader_role`; reader TEMP privilege not checked (`effective_problems` migrate.py:193-262 ignores TEMP and database CREATE; G4 holds only after the operator's REVOKE). Fix: log detection and `limits status` only from the operator CLI; agent holds no reader secret; credential policy text; TEMP check; negative test without the REVOKE.
5. The runtime-role "limitation" stays: runtime can UPDATE spend totals to 0 and UPDATE kill_switch off (migrate.py:53-55); DB-2 logs the first only after the fact; "POST-DEMO" is a schedule not an allowed exception; L-2 has no design or date. Add kill-switch transition logging to DB-2 (needs only L9's yes) and a dated L-2 design.
6. No class-level guard for SECURITY DEFINER: B1 closed for one function; `_SAFE_CREATE` (migrate.py:80-85) accepts any CREATE OR REPLACE FUNCTION. Add a guard test over migrations/ and migrations_held/: every SECURITY DEFINER needs SET search_path = pg_catalog, pg_temp (pg_temp last), EXECUTE format uses %I and a schema, REVOKE ALL FROM PUBLIC; ship in DB-1 or DB-2 with a mutant.
