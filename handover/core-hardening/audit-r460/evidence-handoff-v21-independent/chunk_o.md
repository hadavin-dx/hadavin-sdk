Four `SECURITY DEFINER` functions are written with `BEGIN ATOMIC` bodies (Postgres parses and binds the table names when the function is created, so there is no search-path or temporary-table lookup at call time and no schema name in the file):
   - `spend_reserve(agent, day, worst)` computes the month row from the day inside the function and adds the worst case to the total and to `open_usd` of the day and month rows; an amount of 0 or less writes nothing and returns no row;
   - `spend_settle(agent, day, worst, actual)` replaces one earlier reserve of `worst` by `actual`; it **fails `23514` when `worst` is larger than the open reservation**, changes nothing when the day row or the month row is missing, and **returns no row when its checks reject the amounts** (negative, `NULL`; 5.6c item 2(d)); so the total can fall by at most what is still open and never below the money already settled (settled = total minus open, which only grows);
