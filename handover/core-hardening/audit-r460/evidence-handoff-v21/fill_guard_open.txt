the guard reads SQL files and the text of statements; it cannot read what a function does at run time, so a body that builds SQL from data inside the database is covered only by the call rules and by rule m8 (an `EXECUTE` string after a `;`), not by a proof; function bodies are pinned by a fingerprint of the SQL text in the file, not by a hash of the stored catalog text (section 0 item 9(g)). The next step is the start-up catalog check (item 4) plus an independent review of every function body; the guard stays a tripwire, not a proof.
