# Hand-off v17 security review, round 4 (egm-design, condensed copy of the inline report), 2026-11-16
Target: CORE-PR-HANDOFF-v17.md (H), evidence-handoff-v17/ (E), secdef_guard_v17.py (guard). Read-only; nothing run. Verdict: 0 blockers, 4 majors, 8 minors. M1 closed in the test model only (grants no product code makes); M2 only partly; M3 closed in design, not in code.

## MAJOR
- MA1 The guard still misses spellings, and the mutant set has none of them. A: `strip_comments` (guard:13-41) has no branch for double-quoted names, `statements()` does: a name like "a--b" or "x/*" hides SECURITY DEFINER from the scan. B: `ALTER FUNCTION ... SET search_path = public`, RESET, OWNER TO carry no token; S05 tests only the spelling with it; migrate `_SAFE_CREATE`/`_ANY_CREATE` (migrate.py:80-86, :133) react to CREATE only. C: overloads: HEAD (guard:75) keeps only the name; one REVOKE for the real signature covers a second CREATE OR REPLACE FUNCTION spend_settle(<other args>) left with PUBLIC EXECUTE. D: GRANT regex (guard:112) misses a second function in a list, ON ALL FUNCTIONS IN SCHEMA, ALTER DEFAULT PRIVILEGES ... GRANT EXECUTE ON FUNCTIONS to the runtime role (sharpest: survives the later REVOKE FROM PUBLIC), and grants of kill_switch_release to any non-operator role (G0 tests PUBLIC only). E: SET ROLE / SET SESSION AUTHORIZATION changes the owner; guard never checks ownership. F: one union allow-list for all files (DB-2 file could define a DB-3 name); search_path accepts any schema the runtime can write; EXECUTE format() with %s/%L from a caller value accepted; bare SELECT/DROP/LOCK not in the DML list (guard:77); CASE ... END inside BEGIN ATOMIC clears the atomic flag (guard:66). Fix: deny by default (any ALTER FUNCTION, ALTER DEFAULT PRIVILEGES, GRANT ... FUNCTION, SET ROLE outside an allow-list is a problem); signature from the head with one REVOKE per signature; a "..." branch in strip_comments; per-file allow-list; a mutant for each of A to F.
- MA2 The only control for hand-made functions is specified nowhere: H:309 says "the start-up check of 5.5b item 3 also lists SECURITY DEFINER functions not on the list", but 5.5b item 3 (H:293) is the temporary-table check; migrate.py has no prosecdef query; effective_problems (migrate.py:210-262) audits tables only; v17-CHANGES.md does not list it as text-only. Fix: specify the query (prosecdef, proowner, proconfig, aclexplode on EXECUTE against an allow-list of grantees incl. release), give it an owner and a test, or delete the sentence.
- MA3 M1 holds only in a hand-granted test: migrate(runtime_role=...) re-applies GRANTS at every call (migrate.py:340-345) and spend, spend_month, kill_switch are _RW (SELECT, INSERT, UPDATE; migrate.py:40, :53-55); pg_v17.py apply_grants (:106-112) grants by hand after one build() and never calls migrate() again. H:314 admits the GRANTS change and function-grant kind are not written. Fix: make it a start gate for DB-3; test: apply DB-3, run migrate(runtime_role=...) a second time, repeat G1, G4, G9; function-EXECUTE audit in effective_problems; also test DELETE and TRUNCATE of spend and spend_month by the runtime role (G1 omits them).
- MA4 L22 wording would let the owner approve what M1 forbids: v17-OPEN-FOR-LEAD L22 and H:545 say the runtime role gets "execute on four functions"; H:314, H:394 and the SQL header (spend_guarded_writes.sql:11-12) say three (spend_reserve, spend_settle, kill_switch_engage) and only the operator gets kill_switch_release. Fix: state per role: "runtime role: SELECT on three tables and EXECUTE on three functions; operator role: EXECUTE on kill_switch_release; nobody else".

## MINOR
- m1 H:314 "under-report by at most the amount it reserved, bounded by the call cap in our code" is no bound for a hostile runtime (spend_reserve takes any non-negative amount; settle takes it to 0); p_agent is caller-chosen so one agent can settle another's reservation (H:319). Say: settled history cannot be lowered; spend can be under-reported up to any reservation; the invoice comparison is the control; consider a per-call maximum from a config table.
- m2 kill_switch_engage (spend_guarded_writes.sql:49-53): while already ON by an operator it rewrites by and ts to the runtime login with no log row (add AND "on" = false); if row id = 1 is missing the UPDATE changes nothing and returns silently (add RETURNING check or raise).
- m3 lock_timeout 55P03 at 5.0 s is real on all five held files (raw-pg-v17-new-run2.txt:2-12; v16 control waits to the 12 s cap), but "leaves nothing applied" (H:313) is checked only by counting information_schema.tables rows named spend_decrease_log (pg_v17.py:66-67), vacuous for 4 of 5 files; dead code at pg_v17.py:51 (`if False else None`); "L text" (:74) only checks presence, not position; lock_timeout bounds the wait, not the CHECK scan; no statement_timeout in the files.
- m4 DB-2 m5: handler `EXCEPTION WHEN OTHERS` (spend_decrease_log.sql:93) does not catch query_canceled (57014); with lock_timeout and statement_timeout both T, the switch ON can still fail. Test it or catch 57014.
- m5 Secrets (M3): run_secrets_v17.sh M3a-M3g real (operator root, agent nobody); M3g shows a group-readable file READ by the agent; the file kind refuses only S_IROTH; refuse mode & 0o077; the start-up probe (S-2b) is unwritten (row T); test makes the folder mode 755 although the text says "a folder the agent's user cannot list"; same-OS-user case only a warning in demo; add a negative test for same user and a folder-mode test.
- m6 Operator role (L23 open): nothing for a runtime login that is a member of the operator role (migrate.py:333-339 checks only the three named roles); `by` is session_user (login, not human): use per-person logins in a NOLOGIN group role holding EXECUTE on release; the test grants the operator more (kill_switch_engage and SELECT on three tables, pg_v17.py:110-111) than the text (EXECUTE on kill_switch_release, H:314); say which is intended.
- m7 DB-3 binds names with the creating session's search_path (BEGIN ATOMIC); all runs used public only; test with a non-default schema (DB-2 uses TG_TABLE_SCHEMA).
- m8 H:315 (p)(2) "each new check with a control that fails on v16": controls exist only for L (1), K (1), G1/G4 and G9 (2); none for G0, G2-G8, G10, G11, H1; H1 does not test the m4 fix (the code check is unwritten); v17-CHANGES.md row m4 lists H1 as the Test, overstated.
