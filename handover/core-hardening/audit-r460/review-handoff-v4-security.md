# Review of CORE-PR-HANDOFF-v4.md: money / redaction / secret / audit angle (egm design, condensed copy), 2026-11-16
Verdict: NOT ready for build on PR-2, M2, A1 as written. 5 blockers, 10 majors. Mostly one-line spec fixes plus one design question (guard in the store, not only in SpendMeter). Read only; nothing run.
## Blockers
B-1 Nothing validates amounts reaching add_spend (memory.py:196-204, postgres.py:416-431, protocol.py:107): NaN poisons day and month rows (Postgres NUMERIC takes NaN; memory day_total > daily raises InvalidOperation after the add, undo never reached); Infinity plus undo gives NaN. Fix at the choke point: reject non-finite in Store.add_spend on both stores; usd >= 0 and finite in reserve; reply.cost_usd >= 0 and finite in settle; day must be today UTC +/- reservation day; fuzz NaN/Infinity/huge/negative (E0-7 covers only Money, Budget, Route).
B-2 "Can never be admitted wrongly (over-refusal only)" (4.1 limit a) and "exact cap, no overspend" (line 39) are false: estimator leaves out tools and output_schema (agent_loop.py:425-431, extract.py:52), 3 chars/token wrong for CJK/base64 (common.py:59-62), bytes are not tokens for PDF/images; the clamp is two writes (a race that admits parallel reservers) and hides double-release; Reservation is a frozen dataclass with no id/state so settle twice or keep then release is legal. Decide before M2: a minimal append-only reservation table, or a state check inside add_spend.
B-3 Fail-open by omission: metering opt-in at evals.gate, extract(), CLI; census test counts .chat( sites, not that the llm is metered; Runtime takes llm directly; k1b keeps an in-process Budget (k1b/loop.py:40-52). Deny by default: anything not fake-kind and not metered must refuse. Also ordering hazard: M1 uses "demo"/"pilot" names but the dev-to-demo rename (H-0) comes later; config.py:366 tests != "dev".
B-4 Valid.mapping (extract.py:18-25, plain dataclass) holds secret originals; repr/traceback/asdict leaks; runmap.py:218-226 storable() drops them anyway. Hold only storable(mapping), repr=False, compare=False, masked wrapper; test repr and JSON for a canary.
B-5 v4 4.7 says runmap.redact_text for the document; untrusted text must use redact_untrusted (runmap.py:298-303, escape_placeholders :275-280): placeholder injection class. Test: document contains <EMAIL_1> next to a real e-mail.
## Majors
M-1 Orphans/refuse-leaks: D15 "at most one worst case per crash" is no bound (crash loops, provider outage keeps a full worst case per failed call, failed undo leaves refused amount counted); need reservation age + operator view of orphans; cap worst case per call with a distinct code.
M-2 limits.blocked uses >=, reserve uses >; silent refusal cards (:669, :702) mean nobody learns the agent is dead.
M-3 prod may set spend_window_end none (D1): add alert and named owner; Budget has no sign/order check (registry.py:33-36); CLI gate with memory store resets the cap each run: refuse memory store for non-fake llm (not a documented limitation).
M-4 adapter cost_usd (common.py:176, fake.py:54) could be negative: validate in settle; failed retry attempts unbooked, reconcile has no owner/date.
M-5 One identity reserves and refunds: the section 5 negative test (no refund path to call) cannot pass; "agents hold no store credentials" unverified; D15 "audited" DBA write has no mechanism (audit/chain.py _append only writer). Use append-only table or positive-only add_spend plus a separate "returned" row.
M-6 fileguard skips permission checks on Windows (secrets_file.py:54, :38); say so and give a Windows rule.
M-7 restore recipe does not work: valid.data is a pydantic model, restore_value handles str/dict/list only (runmap.py:560-567); IBAN is not a stored kind so the IBAN restore test cannot pass (do not add it to STORED_KINDS); restore_text kinds=None restores NAME/ADDRESS/PHONE/EMAIL: make kinds required.
M-8 Non-UTF-8 dead letter: DeadLetter.errors is required (models.py:218-221) so the spec'd call raises; PDFs/images always refused (say what text step masks them; no errors="replace"); say which encodings are accepted.
M-9 Masking can corrupt the fields extract reads (PHONE/IBAN/CREDITCARD/HIGHENTROPY vs invoice numbers): measure false-abstain and dead-letter rate by reason on a golden set before PR-2 ships (risk from pattern names, not measured).
M-10 tamper_evident = ok and signed and anchored and tail <= max overstates what chain.py:363-450 detects (last K rows rewritable; signing key in a file; S3 anchor GOVERNANCE 1 day, anchor_s3.py:36-37, H-1 not gating; outbox/_pending not covered; vacuous anchored); max_unsigned_tail from current checkpoint_every needs a code ceiling and a defaults.py literal. Publish named bounded claims (rows_verified_through, unprotected_tail, signing_key_location, anchor_retention_proven) or rename chain_checked with the bound next to it.
