## 0b. Before you get any file (do this first, once, in Git Bash)
Git for Windows may turn line ends into CRLF while it copies a file (the setting `core.autocrlf`). A CR in a patch, in `acc5.sh`, in `P-4b.sh` or in the plan changes the checksums and breaks the checks. Use ONE of two ways BEFORE you clone, pull or copy. The narrow way changes no setting: add `-c core.autocrlf=false` to the one command (`git -c core.autocrlf=false clone <address>`, `git -c core.autocrlf=false pull`). The broad way (the block below) sets the global setting for all your repositories, which is your choice; the block prints the old value and the command that puts it back:
```bash
old=$(git config --global --get core.autocrlf); if [ -n "$old" ]; then echo "old global core.autocrlf: $old. To put it back later: git config --global core.autocrlf $old"; else echo "old global core.autocrlf: not set. To put it back later: git config --global --unset core.autocrlf"; fi; git config --global core.autocrlf false; echo "core.autocrlf now: $(git config --global --get core.autocrlf) (must be false)"; echo "system setting (a later 'true' here is overridden by the global one): $(git config --system --get core.autocrlf 2>/dev/null)"
```
**How the files reach the laptop (two ways, both after the setting above or with the narrow `-c` form):** (1) `git clone` or `git pull` of the repository branch, then use the folder `handover/core-hardening`; (2) a zip download of the same branch from the repository page, unpacked as a folder (do not open and save the files in Notepad or another editor). `CH` below is that folder `core-hardening` (it holds `inputs/` and `paste-check/`). Step A2 checks every file for CR. If a file has CR: set the config above, then `git -C "$PC" checkout -- <file name>` (cloned; this throws away your own changes to that one file) or unpack the zip again (zip); never remove CR by hand from a patch, the checksum is the check.
