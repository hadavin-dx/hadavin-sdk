## PROPOSAL for item 1: body of `pastes\P-4b.sh` (NOT part of the plan; the lead may use, change or discard it)
Read-only scan of /proc. Definition used (my guess, to be replaced by the lead's from the final-head `n8n_kill.py`): "this user" = the real user id on the `Uid:` line of `/proc/<pid>/status` equals the user id that runs the script; "unreadable" = opening `/proc/<pid>/environ` for reading fails; "n8n-shaped" = the command line contains `n8n` (case-insensitive). It prints `P-4b-HIT pid=<n>` per process, nothing else, and exits 0 also when it finds nothing. It uses no run variables. The file must not contain the words `kill` or `env.sh` anywhere (P-3b searches for them, comments included), so the text below avoids them.
**Why `status` and not `stat` for the user id (M-1 of the round-2 review; the v5 proposal used `stat -c %u /proc/<pid>`).** The risk: for a process that has marked itself "not dumpable" (which is what makes its `environ` unreadable to its own user), the kernel makes the FILES inside `/proc/<pid>` belong to root. If it did the same to the folder `/proc/<pid>` itself, a filter on `stat -c %u /proc/<pid>` would skip exactly the processes this check must find. Tested here (Linux 6.18 container, user 65534, stand-in below): the folder `/proc/<pid>` stays owned by the user (`stat` printed 65534) and only `/proc/<pid>/environ` belongs to root (printed 0), so the v5 filter would have worked here. NOT tested: WSL Ubuntu (its kernel is a different build) and a real unreadable n8n. The `Uid:` line of `/proc/<pid>/status` does not depend on that kernel detail (the file is world-readable and names the real user id), so v6 uses it; it is the safer filter. Whatever filter the lead finally uses must be proven against the real stand-in with the one-line test below.
```bash
#!/bin/bash
# P-4b (PROPOSAL, lead to replace): read-only scan of /proc.
# Prints one line per process of THIS user whose /proc/<pid>/environ cannot be read
# and whose command line mentions n8n. Changes nothing. Needs no run variables. Always exits 0.
me=$(id -u)
for d in /proc/[0-9]*; do
  p=${d#/proc/}
  [ "$p" = "$$" ] && continue
  u=$(awk '/^Uid:/{print $2; exit}' "$d/status" 2>/dev/null) || continue
  [ "$u" = "$me" ] || continue
  if ! { : < "$d/environ"; } 2>/dev/null; then
    if tr '\0' ' ' 2>/dev/null < "$d/cmdline" | grep -qiF n8n; then echo "P-4b-HIT pid=$p"; fi
  fi
done
exit 0
```
**Concrete stand-in (recipe for the lead; run it in the WSL Ubuntu shell as the same WSL user that runs the plan, NOT as root: root reads every `environ`, so a root test proves nothing).** The stand-in is a throwaway python process that marks itself not dumpable and whose command line starts with `n8n-stand-in`; it holds no data and ends by itself after 10 minutes:
```bash
bash -c 'exec -a n8n-stand-in python3 -c "import ctypes,time; ctypes.CDLL(None).prctl(4,0,0,0,0); time.sleep(600)"' & echo "stand-in pid=$!"
```
**One-line test that the user-id filter sees the stand-in (the lead runs it right after the recipe; replace `<pid>` by the printed pid; the expected output is below):**
```bash
p=<pid>; echo "me=$(id -u)"; stat -c '%u %n' /proc/$p /proc/$p/environ; awk '/^Uid:/{print "status-uid=" $2}' /proc/$p/status; { : < /proc/$p/environ; } 2>&1 | head -n 1
```
Expected: `me=<your uid>`; `<your uid> /proc/<pid>`; `0 /proc/<pid>/environ` (root-owned: that is the "not dumpable" signature); `status-uid=<your uid>`; `...environ: Permission denied`. If the folder line shows `0` instead of your uid, a `stat` filter would be wrong on that kernel; the `status` filter above still works. If `status-uid` is not your uid, STOP and tell me: the filter is wrong for this machine and the plan cannot rely on it.
Positive-control instructions for the lead (to make `pastes\P-4b.control.txt`): (1) save the final `P-4b.sh`; (2) start the stand-in with the recipe above and leave it running; (3) run `bash pastes/P-4b.sh > /tmp/p4b-run.txt; echo "exit=$?"`: at least one `P-4b-HIT` line and `exit=0`; (4) write the control file: first line `P-4b.sh sha256 ` plus the output of `sha256sum pastes/P-4b.sh | cut -d' ' -f1`, then the lines of `/tmp/p4b-run.txt` (plain ASCII, LF line ends, no CR); (5) end the stand-in by its exact pid (you started it; `kill <pid>` typed by you in the shell, never inside `P-4b.sh`); (6) any later edit of `P-4b.sh` needs steps 1 to 4 again (P-3b compares the hash); (7) note in PROGRESS (append at the end) how the stand-in was made.
