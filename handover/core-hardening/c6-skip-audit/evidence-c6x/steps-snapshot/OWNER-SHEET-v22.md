## 2. The card, then the ten rules
### The card: cancel the key and prove it (the only place that says how; follow it top to bottom, no jumping)
**Part 1, when you do the card (the one list).** Only while a key is alive, and at once, if any of these happens: (a) you typed `end` (7.8); (b) the run is aborted, refused or called off, or you typed `n`; (c) a FREEZE starts (R10); (d) either phone alarm rings; (e) the latest start passes before you press Enter on the start line; (f) the take terminal shows a prompt again before you typed `end`; (g) a secret text of a model key appeared on your screen (R1); (h) 6.5 sends you here. The STOP RULE at the top applies here too. No word of the lead resumes a run whose key was alive: a new try needs a new numbers message, run name, key file, key and yes. No timer of the lead exists: nobody cancels the key for you.
**Part 2, what you may cancel or revoke (the only list).** (a) Every model key you created from 6.3 on, whatever its name (a typo counts: report in words the name you see); an account-name mismatch never blocks cancelling it: cancel it, tell the lead. (b) The older key named in the numbers message, once, in 6.2 (or at once if its text appeared on your screen), only if its name and creation date in the key list equal the message, the message says no file the lead read uses it, and you first wrote to the lead the phrase of 6.2 yourself (the lead never asks for it). (c) An app password of a throwaway Gmail that appeared on your screen: revoke it. A key with any other name or creation time, or any other key or password: report its name in words; cancel nothing. Cancelling may not be undoable (what the button does is UNVERIFIED): treat it as final. It should end further model calls with that key (vendor behaviour, UNVERIFIED), which is why you prove it and why the balance stays the real limit (R4). The card is always allowed, also while frozen.
**Part 3, the steps in order.**
1. If Recording is ON: say "stop" and wait until Recording is OFF, at most 60 seconds; then go on anyway and tell the editor the raw recording must be checked (the recording box does not include your normal-profile key page: UNVERIFIED, the editor confirms in the rehearsal).
2. In your normal browser profile open the key list. Write the number of keys it shows (call it N) and how many keys you are about to cancel (K, normally 1; two if you pressed create twice).
3. Cancel each key of Part 2 (a), one by one. Right after you press cancel, in the read terminal run `date -u` and write the time it shows.
4. Proof: reload the page. Each cancelled key shows the cancelled word, and still shows it after one more reload; or it is no longer listed and, with all filters off, the number of keys now shown is N minus K (one lower for each key cancelled). Anything else: cancel again (Part 4).
5. Send the lead "model key cancelled". Only now are you free to do anything else.
6. The run is over, however far it got. Go on at 7.9 if you typed `end`; otherwise at 8.1.
**Part 4, if something fails.** The key list page does not load: retry for 2 minutes, then try the same page on your phone (UNVERIFIED), send "cancel failed", keep trying; the key stays alive until proven. The state word differs after two tries: send "cancel failed". The latest start passes before you press Enter on the start line: do not start, send "time passed", and cancel the key if you made one. The cancel-by alarm rings and the key is not proven cancelled: nothing else matters until it is. For the older key (6.2) steps 2 to 4 apply, you send no "model key cancelled", and the proof counts only if the word equals the cancelled word of the message; a failure there is a FREEZE and no key exists yet.
