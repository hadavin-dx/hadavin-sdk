## MAJOR
- M1 `--restore --sha COMMIT --discard-marker` can exit 0 while a mutant sits in another folder (run.py 1422-1456, 2385-2388). It compares only the tree now at --root; the marker's root_dev/root_ino are never read. Scenario (T84): planted root renamed away, a full git-archive copy takes its path; comparison passes, marker and backup deleted, exit 0, planted file left behind without backup. The text on stdout says a renamed-away folder is not checked; the docstring exit-0 row and the exit code do not. Second case: an unreadable or non-dict marker sets "its test group was not looked for", settled=True, marker deleted, though docstring line 117 promises exit 3 when a test group still runs. Fix: differing root_dev/root_ino gives exit 3 unless an explicit extra flag; unreadable marker is unsettled (exit 3) or the docstring says what 0 does not cover; add a renamed-away test.
- M2 An empty `--sha` silently drops the git authority on `--restore` (run.py 2335, 2376, 2329): `if a.sha:` treats `--sha ""` (unset variable) as absent, so a forged marker plus backup is accepted (T95d1) with no git comparison. Fix: compare with `is not None`, refuse empty or invalid --sha with exit 2; add a test.
