## MAJOR
- MAJ-1 Plain `--restore` now writes setuid, setgid and sticky bits from the marker, and the docstring says the opposite (r10 worse than r9). Code run.py 1562-1568 accepts mode up to 0o7777; restore_target applies it with fchmod at 773, 777, 793-796. r9 turned a mode above 0o777 into 0644; r10 restores 4755 exactly (T97e, safety-tests.sh 1558-1563, requires it). Docstring 142-143 "cut to at most 0777, never more" is false and contradicts 134-135. T98e2 (1739-1741) titled "mode masked to 0777 at most" only asserts exit 0 and last = return1; no test sends a forged 04777 to plain `--restore`. With limit (d) a same-user forger can plant marker + matching backup + 04777 and plain `--restore` creates a setuid file with chosen content (only `--sha` refuses, 1547-1555). Not an escalation by itself (forger already holds the user's rights; source files under test never need special bits). Nothing checks the mode after the write (a setgid bit the user may not set is dropped silently; `ok` at 1578 compares content only). Fix: for plain `--restore` refuse or clamp to 0o777 when mode & 0o7000 is set; adjust T97e; add a forged 04777 test; check mode after write.
- MAJ-2 "New tests fail on old code" does not hold for T98d, T98e, T98e2, and T98 cannot run alone: dev3-r9code-T98only.txt shows `forge97: command not found`, `setmarker97: command not found` (helpers defined inside the T97 block, 1487-1502). On r9 those three failed because nothing was forged, not on behaviour; real r9 behaviour equals r10 (plain restore trusts the forged marker, `--sha` refuses). "T98 7 of 7 fail on r9" is really 4 of 7 (T98a, b, c, f; c and f only grep text). Fix: make helpers global, rerun T98 alone against r9, label T98d/e/e2 as guards.
