- K1b: per-case timeout and per-call wall clock (loop.py:151, 158-165), USD cap (loop.py:154).

### Start, stop, restart, kill, cleanup, what stays running
- Start: `hadavin-sdk tick` is one-shot (tick.py:1-25); Postgres connection opens at `build` and stays open for the life of the process (postgres.py:195-197).
- Stop: kill switch row (limits.py:43-46, store kill_switch). Runtime checks it before every model call and tool call (agent_loop.py:240-243, 421, 460). K1b replay does not check it (B-07).
- Restart/kill mid-run: tick moves runs quiet for longer than `stuck_after_s` to NEEDS_PERSON; an EXECUTING run is never re-executed (tick.py:111-118).
- Cleanup: purge job in tick (tick.py:184-218); `.tmp` and temp CA files are not cleaned (B-14, B-15).
- What stays running: the process that embeds the runtime; abandoned `k1b-llm-call` threads until the provider answers (loop.py:104-109); nothing else started by this lane.
- Resource limits: tool bytes per run, tool calls per run, map entries, document bytes from config evidence block (agent_loop.py:354, 382, 463, 481); K1b `MAX_RESULT_BYTES` 20000 (k1b/tools.py:22); no limit on bundle size (B-17).

### Personal data fields and retention
- `redaction_maps.mapping`: placeholder to ORIGINAL identifier (e-mail, name, phone, address, IP, ARN per README.md:32); retention 30 days, ceiling 400 days (config.py:182-192, tick.py:184-218).
- `tool_calls.inputs/output`: stored redacted; 30 / 400 days.
- `runs.principal_id`, `approval_requests.requested_by/summary`, `approval_decisions.approver_id/reason`: person or service ids and free text; retention: none found (no purge for these tables: UNVERIFIED, grep for DELETE FROM found only tool_calls and redaction_maps).
- Audit rows hold hashes and codes only (models.py:188-190); retention by audit kind (lane A).

### What a new person must know
- Everything about run state goes through `runs.advance` and `Store.transition` (compare-and-set). Do not write `runs.state` any other way.
- The runtime role in Postgres also holds approval and kill-switch write rights (README.md:33 waiver; B-06).
- Tick is a separate process; anything it sets in memory is lost when it exits (B-05).
- Evidence tools and docs say "dev"; the studio rule says DEMO, PILOT, PROD (B-11).
