## MAJOR
M1 (0008:34-40, 0011:20 header): release has no age check and runs as owner. Sequence: reserve 10; the tick (or any runtime login) expires it; the operator runs release for that agent and day: the row becomes settled at 0 and the counters fall by 10; the real settle then returns claimed=false (0011:179-192): the real cost is never booked: money lost (0011:16-21 admits this; it is the loss the C1 reversal was meant to prevent). Fix: release only expired rows with closed_at < now() - a floor (max call time + margin).
M2 (migrate.py:78-80): step 4 of option B is not shipped: the runtime still has SELECT, INSERT, UPDATE on spend, spend_month, spend_reservations: the H1/H2 bypasses of 0010:11-20 are live: `reserve; settle; UPDATE spend SET usd = usd - x` repeated in one transaction erases charges. Fix: flip the grants (runtime SELECT only), then delete the claim 'only release lowers'.
M3 (0011:62-69, :328): `hadavin_reserve_spend` takes p_day_cap/p_month_cap from the CALLER; `hadavin_caps` exists, nothing reads it: a runtime login calls reserve(..., 1e30, 1e30, ...) and the cap is void. Fix: read the caps from hadavin_caps inside reserve, drop the arguments.
M4 (migrate.py:78): the purge role has table-level DELETE on spend_reservations though the store purges through the definer function (0011:256): `DELETE FROM spend_reservations WHERE status='open'` as the purge login makes the hold vanish; a late settle gets HD002 and the real cost is lost; nothing guards DELETE (0010 is BEFORE UPDATE only). Fix: drop purge="DELETE" from the GRANTS row.
M5 (0011:114, postgres.py:393): reserve is not idempotent: reserve('r1') commits, the connection dies before the reply, the retry ('r1', same arguments) gets StaleState and cannot tell its own success from a collision: the hold stays open, expires, stays booked at the full amount until an operator releases it (race M1). Settle is retry-safe (claimed=false). Fix: on 23505 with identical agent, day, amount and run_id return success; StaleState only on a mismatch.
M6 memory vs Postgres: memory.py:219-225 `add_spend` skips check_spend_day, check_store_id and any day/agent validation; Postgres (0011:299-305) refuses a day before 1970-01-01, an empty agent id and agent ids with control characters: `add_spend("", date(1969,12,31), 1)` books in memory and raises ValueError on Postgres; the same day window applies to reserve (protocol.py:101 check_spend_day checks the type only, the database refuses day < 1970 at 0011:96); memory has no release (Postgres-only). Fix: put the 1970-9999 day window and the agent check into protocol.py and call them in memory add_spend.
