## MAJOR 2: cap changes are not audited at the database
0011:423-463 `hadavin_set_cap` writes only `set_by` from the caller-supplied `p_by`; it records no session_user and writes no audit row. Audit lives in the CLI (cli.py:834-861: an intent line and an outcome line). The caps role holds INSERT on audit_entries, so with the DSN alone it can call `SELECT hadavin_set_cap('a', 1e9, 1e9, 'anything')` with NO audit row, and can forge audit rows. Same weakness as the old reset role: M4 is a split of roles, not an audit guarantee; the help text 'write the change to the audit' (cli.py:185) overstates it. Fix: record session_user and write the audit row inside the definer function (or state the limit in the help text/SECURITY wording).
