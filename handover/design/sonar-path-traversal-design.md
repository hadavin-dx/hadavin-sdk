# Design: one path-containment choke point (ORDER 260, SonarCloud path traversal in k1b/atomic.py L16 and k1b/score.py L167)

Status: plan for ONE EGM review-loop round before building. Security path (no round cap). EGM draft step skipped: the lead's order fixes the design; this note is the plan. Ladder line: rung 1 (reuse) and rung 2/stdlib `pathlib`/`os`; own code only for what stdlib cannot do (Windows device names, NUL, symlink or junction leaving the base, one safe-component rule).

## Problem in plain words
Two functions open a file whose name arrived on the command line (`atomic_write(path, text)` writes then renames; `_read_json(path, what)` reads). SonarCloud calls this path traversal. The core already has THREE private containment checks that each answer a slightly different question and none is shared: `config.confined(base, relative)` (resolves, `is_relative_to`; no NUL, no device-name rules; a NUL in `relative` raises ValueError, not ConfigError), `k1b/causelist._inside(directory, fname)` (strict resolve, must be a file), `audit/signer.key_path` (key folder, symlink refused, own error type). Class: containment checks copied per caller, so a rule fixed in one is missing from the others.

## Design
1. New stdlib-only leaf module `src/hadavin_sdk/pathguard.py` (no vendor imports; the lock-in guard test applies). Public names:
   - `confined(base, relative, *, must_exist=False, kind=None)` -> resolved `Path`. `base` is given by the caller (the operator's own `--outputs`, `--cases`, config or key folder). Refuses: NUL or other control characters; an absolute `relative` (and, on Windows, drive-relative `C:x`, rooted `\x`, UNC, `\\?\`, `\\.\`); `..` escape after resolve; a symlink or junction whose real target leaves the base; Windows device names (CON, PRN, AUX, NUL, COM1-9, LPT1-9, with or without extension or trailing dot or space); an over-long path (checked at resolve, `OSError` becomes a refusal). `must_exist=True` uses `resolve(strict=True)`; `kind="file"` or `"dir"` also checks the type. Returns the resolved path; callers use ONLY the returned path (no check-then-use on the original).
   - `component(name)` -> the same string if it is one safe path component (no separator of either flavour, not `.`/`..`, no NUL or control character, no device name, no trailing dot or space, not empty, length cap); else refusal. Used for data-derived names: case ids, ordinals, names listed in a folder, run folder names.
   - Refusal type: `ConfigError` subclass `PathRefused` (message names the rule and the argument NAME, never echoes the raw path value beyond what the caller already shows; control characters are not printed).
2. `atomic_write(path, text, *, base)`: `base` required (a keyword with no default so no caller can forget). Final path = `confined(base, path)`; temp path = the final path's folder plus a name made by the helper (`.<final-name>.<random>.tmp`, created with `O_CREAT|O_EXCL`), never taken from outside; both stay inside the base; a leftover temp from a crash is not trusted. fsync, `os.replace`. Callers: `cli.py:266` (base = `--outputs`), `k1b/replay.py:75, 261, 262, 276` (base = the run's out folder).
3. `score._read_json(path, what, *, base)` and `_recorded_digest(sha_file, *, base)`: path through `confined(..., must_exist=True, kind="file")`; `load_answers` (operator-typed `--answers`): see step 5 of the order, an operator-chosen file: containment against a base is not meaningful, so it gets the control-character/NUL/device-name checks (`pathguard.operator_file(path)`: resolved, must be a file, no base) and the PR body states why; the finding is then for the lead to mark accepted in SonarQube Cloud only if Sonar still flags it (never a code suppression).
4. Delegate the three existing copies to the helper in the same change: `config.confined` and `causelist._inside` become thin callers (same messages kept where tests pin them); `audit/signer.key_path` keeps its own rule (key files never through a symlink, folder created 0700) but calls `pathguard.confined` for the containment part. No behaviour change except new refusals; each old test must still pass.
5. Remove every `NOSONAR` in `k1b/`, `cli.py` and `src/` that this makes unnecessary (found: score.py 101, 158, 160; cli.py 264, 265). No new suppression.
6. Sibling list (builder step 1, written into the PR body table with each path's ORIGIN: operator-typed, data-derived, fixed): every `open(`, `Path(`, `.read_bytes`, `.read_text`, `.write_*`, `os.replace`, `shutil`, `mkdir`, `unlink`, `glob`, `iterdir` in `src/` that touches a path from argv, a model reply, a name read from a folder, or case data. Every data-derived one goes through `component` or `confined`.

## Tests (each must FAIL on the old code; new tests run against `main` to prove it)
`..` escape; absolute path; symlink out of the base (skip with a reason if the OS refuses to create it: try/except OSError then pytest.skip, on Windows without privilege); junction (Windows only, skip elsewhere); Windows device names and trailing dot/space (pure-string rules, tested on every OS because the check is on the text); NUL and control characters; case id with a separator; very long path; a normal path inside the base still works (no false refusal; Linux and Windows spellings, nested, unicode, spaces); seeded property test over random segments against an independent oracle built from `os.path.commonpath` on the resolved path; temp file name not controllable and not left behind after a refusal; `atomic_write` without `base` is a TypeError; one mutant per refusal rule in a new `tests/pathguard_mutants.py` run by the mutation runner and wired like `bind_mutants` (blocking CI step; CI change needs the lead's yes: the builder adds the file and the step text, the lead decides). Guard test: no `NOSONAR` remains in the touched files; no module under `src/` calls `open`/`read_*`/`write_*` on a path built from `sys.argv`/args without going through `pathguard` (AST test, a tripwire, limits stated).

## Not in scope (stated, owner or third party)
SonarCloud's own status changes (accepting a finding) are an owner click. Windows behaviour is tested by the string rules only here; real junction and `\\?\` behaviour cannot run on this Linux box (impossible now; the CI Windows job, if any, is the check).

## Risks and open points for the reviewer
(1) Making `base` required changes a public function signature (callers inside the repo only: 5 call sites). (2) `resolve()` then `open` is not race-free against a swap after the check; mitigation is to use the resolved path only and open with `O_NOFOLLOW` where the OS has it; say it plainly in the docstring. (3) Overlap with part 5 (`config.confined` NUL fix on `wip/cloud-pd-reset`): this branch is from main and will conflict there; the lead sequences the merges, I will rebase whichever merges second.
