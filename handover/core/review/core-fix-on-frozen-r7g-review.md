## Findings

### m1. The mailbox host check accepts a non-ASCII host (Kelvin sign) and the docs sentence "same rule as the mail sender's host" is not exactly true
`src/lead_desk/imap_count.py` (`ImapSettings.__post_init__`, line ~94): `_HOST_NAME.fullmatch(self.host.lower())`. `"K".lower()` is the ASCII letter `k`, so `ImapSettings("Kexample.invalid", ...)` is ACCEPTED (I ran it). The name the check saw (`kexample.invalid`) is not the text that is later looked up and given to TLS (`server_hostname`), so "validated text equals used text" fails. The SMTP check does not lower-case at all (it demands lower case), so "the same rule" in docs/limits.md and docs/settings.md is wrong in two ways (upper case allowed; non-ASCII slip). Real-world risk is small (the owner types the host), but it breaks the defect rule's spirit (bad input should be one refusal line before anything real). Fix: add `self.host.isascii()` to the refusal condition (or match against `self.host` with `re.IGNORECASE | re.ASCII`), a test with `"Kexample.test"` (fails now), and say "upper case is allowed, non-ASCII is refused" in the docs. Everything else I tried is refused with the fixed line: 64-char label, `a..b`, empty, trailing dot, `[::1]`, zone id, space, NUL, trailing newline, lone surrogate, None, bytes, fullwidth letters, leading hyphen. (`1.2.3.4` is accepted, same as SMTP.)

### m2. A host with many silent addresses: the last address is never tried
`connect_bounded` hands min(5 s, time left) to each non-last address. With a 12 s limit and silent addresses: times given were 5.0, 5.0, 2.0 and then the limit was gone, so the 4th (good) address was never tried; with 8 silent plus a good one, only 3 were tried. Total time is respected (12.0 s measured in every case), the first-address starvation of r7f m1 is closed (one hung address uses 5 s, the next is tried), and the docs say "an address that never answers does not stop the next one from being tried", which is true for one silent address but not for three or more at a short limit. By design bound, not a crash, but the docs sentence overclaims. Fix: either state the bound ("at most limit / 5 silent addresses are tried before the time is gone") in docs/limits.md, or divide the time left over the addresses still to try (with a floor), as r7f m1 suggested. A test with 3 silent addresses and a good one at a 12 s limit pins whichever rule is chosen. This only matters for a host with 3 or more addresses; I know of no such mail host, so I rate it minor.

### n1. Helper threads are not capped
Each timed-out look-up leaves one daemon thread until the system look-up ends (I measured 20 leaked threads for 20 hung look-ups, all `daemon=True`, so the process still exits). Under a dead name server and many retries the count is bounded only by the number of calls times the system resolver time-out. The leak is in docs/limits.md only as "left to finish by itself"; the pile-up is not stated. Add one sentence or a small cap (refuse a new look-up with the fixed TimeoutError while N are running). Nit because every caller has a total deadline, so the call rate is low.
