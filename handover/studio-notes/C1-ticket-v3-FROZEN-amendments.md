## F1 Session ownership (replaces v3 D2/D3 text on per-run wrappers)
`MaskedLLM(inner, redactor, audit)` is built ONCE by `app.build_llm` and is stateless: it holds no session. The run context is `RunCtx(run_id, principal, session)` held in a `contextvars.ContextVar` and entered with `with masked.run(run_id, principal) as ctx:`. `Runtime.handle` enters it for the WHOLE body (including `_abstain`, `_shadow`, `_submit`, because the shadow card screens the diagnosis with the judge). `chat` reads the ctx; outside any ctx (extract, gate, judge golden) `chat` opens a fresh one-call ctx with run_id `adhoc:<uuid>` and principal `system`. The judge (built once, shared) receives already-masked text under the SAME ctx, so its marks are session-issued. Threads do not inherit a ContextVar: `k1b/loop.py:_chat_bounded` and any other thread hop use `contextvars.copy_context().run`; inner LLMs must be thread-safe (state this in README). `chat` signature is identical to `LLM.chat` (`messages, *, system, route, tools=None, documents=None, output_schema=None`). `MaskedLLM.__init__(self, inner, redactor, audit, *, _token)` raises `TypeError` on a wrong token; `MaskedLLM.of(inner, redactor, audit)` is the public helper and returns `inner` unchanged if it is already a `MaskedLLM`. `app.build(llm=raw)` wraps with `MaskedLLM.of`. Test `test_two_threads_two_runs_no_crosstalk`.

## F2 No pass-through exemption
No text is exempt from masking: `mask()` scans the whole body every time and leaves ISSUED marks as they are (as `redact._mask` already does). A mark-shaped token not issued by the current session is `forged_mark`. Tests: `test_mark_next_to_raw_value_still_masked` (`"<EMAIL_1> and carol@example.com"` with `<EMAIL_1>` issued: `carol` absent from the recorded body), an idempotence test over the fuzz corpus (`mask(mask(x)) == mask(x)`; where it fails the second-pass output is what is sent).

## F3 Which fields are masked
`MaskedLLM.chat` masks, as ONE text through `redact_many` (so a value in one place is masked everywhere): every `str` leaf of `messages[*].content` (and content blocks) plus `documents`. `system`, `tools` and `output_schema` are TRUSTED CONFIG: not masked, but scanned with `check` against the session (a session original in them gives `self_check_failed`). Dict keys and tool names are never masked; a mark-shaped dict key is `forged_mark`. At registry load, refuse any prompt, contract description or schema in which `redact.find` would mask something (lint). README: "prompts and contract text are trusted configuration; the client must not put PII in them".

## F3 lint table (lead, 2026-11-05)
The registry-load lint of F3 ("refuse any prompt, contract description or schema in which `redact.find` would mask something") is narrowed to a fixed kind table, because `find` also masks keyword-and-prose shapes (`Customer name: as printed`, `Dear Customer,`, `up to 999999999999`) and bare numbers, which refused ordinary prompts. Decided from round-1 and round-2 reviews; implemented in `RegexRedactor.lint` (guard/redactor.py) and `registry._trusted_text_problems`.
- Linted always: PRIVKEY JWT APIKEY GCPTOKEN AZURESAS WEBHOOK URLCRED BEARER BASIC HIGHENTROPY (secrets); EMAIL IBAN CREDITCARD SSN AADHAAR PAN BANKCODE BANKACCT (personal and financial identifiers; BANKCODE and BANKACCT need their bank-word context, so the whole joined text is linted too).
- Linted only when the matched value looks real: SECRET and TENANT (6+ characters with a digit and a letter, or 12+ letters after a keyword such as `password:`), ADDRESS (a digit and 6+ characters), PHONE (a plus sign or separator inside the number, or a phone word such as tel/phone/mobile/fax within 40 characters before it on the same line).
- Not linted (a keyword or shape alone says nothing about a real value): NAME ACCOUNTID UUID IPV4 IPV6 MAC HOSTNAME ARN GCPRESOURCE AZURERESOURCE. Consequence: a real person's name or an account id in a prompt is not caught.
- A number written in a schema (an enum member, a length) is a number: only a card number (13-19 digits passing the Luhn check) is refused.
- Read: prompts of every agent that is not retired (draft prompts go through the gate, evals.py:48) and, for the contracts in their `scope_allowed`, `id`, `description`, `expected_outcome` (reaches the approval card) and every string, key and scalar of `input_schema` (a `pattern` value inside a schema node is a regex rule and is skipped). Not read because they never reach a model: executor operation/lookup_operation/secret_name, target_system, idempotency_header, verify_check, rollback, rollback_test, undo_test, manual command templates (refused at load until K8).
- The prompt bytes read by the lint are hashed; `Registry.prompt()` refuses a file that changed after load.
- Dict keys (`refuse_unsafe_keys`) use the same table: mark-shaped keys are `forged_mark`, keys holding PII or secrets are `unsupported_input`; UUID, IP, host and MAC keys are allowed.
