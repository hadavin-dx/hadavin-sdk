## C. Item 7: where `check_core_copies` lives, the exact command, and which demos lack it
* Search done: `find projects _local/scratch/wt -iname "check_core_copies*"` (excluding venvs).
* Demo repos that HAVE `tools/check_core_copies.py` (two): `projects/hadavin-demo-apexc/tools/check_core_copies.py` and `projects/hadavin-demo-intake/tools/check_core_copies.py` (Intake also has copies in `intake-wp4-cut/` and `intake-wp4-mut/` subfolders and in ~35 worktrees under `_local/scratch/wt/`, all scratch). Also in the stale monorepo copy `projects/hadavin-demos-apexc/demos/apexc/tools/` and in `_local/scratch/wt/handover/handover/promotion-inputs/*/tools/` (the cloud handover input).
* Demo repos that LACK it: **`projects/hadavin-demo-dealdesk` and `projects/hadavin-demo-refunds`** (neither has a `tools/` folder; `ls` fails). **Plan-v3 P8a says "copy `check_core_copies` into a demo that lacks it (apexc, refunds)" and the glossary says "today only inside demo repos, e.g. `tools/check_core_copies.py`": that is wrong for apexc (it has one) and omits dealdesk.** Correct list: dealdesk, refunds.
* Exact command (from the script docstring, both versions): `python tools/check_core_copies.py <path to a hadavin-sdk checkout>` run from the demo repo root (it uses `ROOT = Path(__file__).resolve().parent.parent` and reads `core_copies.json`); exit 0 only if, for every file in `core_copies.json["files"]`, `git -C <core> show <commit>:<core_path>` hashes (LF-normalised) to `core_sha256`; the commit per file is its `pr_snapshot`, else the table `core_commit`. Output: `ok      <path>` / `DIFFERS <path>` / `MISSING <path>`. The apexc version prints the missing commit and path; the Intake version prints only the path. Neither version applies `import_rewrite` (the Intake docstring says it does, but its code compares the core file with `core_sha256` only, and the JSON hash is described in the refunds/dealdesk notes as "after reversing import_rewrite on the copy", so the check works because the stored hash is of the core file, not of the copy: it checks that the pin matches core, not that the demo copy matches the pin; I did not find a step that hashes the demo's own file in these two scripts). **That means the script as written does not detect an edited demo copy**; the studio-level script does.
* The other check, which exists for ALL four demos: **`<studio>/tools\core_sync_check.py`** (studio-level, stdlib only, with tests under `tools\tests\test_core_sync_check*.py`). Command: `python tools\core_sync_check.py --core <core checkout> --demo <demo dir> [--demo ...] [--json] [--strict-pin] [--core-ref REF]` (argparse at lines 525-533); it reads each demo's `core_copies.json`, compares the demo files with their pinned core file, enforces the pin policy (pin must be in core main history) and `allowed_local` expiries. Exit 0 = no errors, 1 = errors, 2 = incomplete. `projects/hadavin-demo-refunds/CORE_COPIES.md` line 7 points at this tool (`--core ... --demo demos/refunds`; the path `demos/refunds` there looks stale, the repo is `hadavin-demo-refunds`).
* All four demos have a `core_copies.json` (keys per file: `core_path`, `core_sha256`, `import_rewrite`, `core_pr`, `pr_snapshot`). Pins: apexc, intake, refunds `660814674ece8ad578293e5412633d796eddb96f` (= the "6608146" of plan-v3); dealdesk `6608146`. Files copied: apexc 7, dealdesk 4, intake 3, refunds 2 (listed in memo 4 section 5).
* Recommendation for P8a/plan-v3 section 9 "Demos re-pinned" row: replace `python tools/check_core_copies.py` by `python tools\core_sync_check.py --core projects\hadavin-sdk --demo projects\hadavin-demo-<x> --strict-pin` run from the studio root for all four demos (one tool, already tested, no copying), and drop "copy check_core_copies into apexc, refunds" (or keep the per-demo script only where the demo's CI needs a standalone check).
