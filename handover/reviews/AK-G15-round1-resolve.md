## PENDING LEAD (continues the ticket's numbering after 14; 1-14 as in the ticket, PL13 unchanged)
15. **NEEDS LEAD (money, least privilege): who may write the re-run of a message.** Today both the worker AND the runtime role can re-run any waiting message by a direct UPDATE (fact 1; R1-RES-1, R1-ADV-2).
    - **(a) Recommended:** one migrator-owned `SECURITY DEFINER` function `hadavin_queue_close_rerun(tenant, item_id, assignee, expect_version, binding, now, acknowledge_outcome_unknown)`. In one transaction it checks the holder, version, binding, item/receipt match, `generation = item.generation`, no open run, `outcome_unknown` with its acknowledgement and the PL16 cap. It then closes the item and performs `reopen_inbound`'s update. The worker gets EXECUTE on it and SELECT only on `inbound_receipts`. AK-G2's trigger allows `needs_person -> received` only when `current_user` is the function's owner, which also removes the runtime role's path. The memory store mirrors this in code. Cost: one function, one AK-G2 build note, about 4 negative rows and mutants.
    - (b) Keep the worker's column UPDATE, and add an AK-G15-owned trigger on `inbound_receipts`: `needs_person -> received` only for the worker role, and only when a `queue_items` row of that receipt and generation was closed `rerun` in the same transaction. The runtime role's path must still be closed by an AK-G2 build note. Smaller, but the money check spans two tables' triggers.
    - (c) Move every person action into SECURITY DEFINER functions; the worker has no table UPDATE or INSERT at all. This is the strongest option and the largest change; the lease would then also need a database-side clock decision.
    - Refused: state it as a limit. The runtime role is the agent's role, and "agents never hold approver or executor credentials" is an owner hard rule.
16. **NEEDS LEAD (money): a cap on re-runs of one message** (R1-ADV-4).
    - **(a) Recommended:** `queue.max_reruns`, default 3, from 0 to 10. When the cap is reached, the re-run is refused with `rerun_limit`, and the item can only be closed `answered` or `no_action`.
    - (b) No cap below AK-G2's 65535; every re-run is audited and acknowledged, nothing more.
