- **Close guard gaps by rule, and prove each rule by ablation (ADV-3, ADV-5, ADV-6, RES-1, RES-2).** Round 2's guard Majors share one cause: the guard's rule list was prose, so a reviewer could always find one sink or source the prose left out, and no test proved each rule earned its place. That is less text than listing more lines, and a future reviewer's "rule X has no test" is answered by a failing build, not by a new round.

## Draft text for `handover/owner-visible-limits.md` (plain words, for the revision 3 author)
> **Configuration error messages (package P5b3).** When a configuration file is wrong, the program prints a short message that our own code writes. Most of these messages name a file, a setting or a secret's name so that the person running the program can fix it. If someone types a password, a web address that contains a login, or a person's name into a place where the program expects a name or a path, that value can appear in the message on the screen. The program checks only that the message is one line of plain letters, digits and punctuation; it cannot tell a password or a person's name from an ordinary name. Before the first pilot with real client data, a person re-reads every such message in the code.
