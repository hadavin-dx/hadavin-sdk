## Minors
1. A dead role stays forever if it owns objects in a database other than the one sweeping (migration_role.py:115-121, exit hook :134-148). DROP OWNED works per database; DROP ROLE then fails and the whole transaction rolls back. Fix: on failure, query pg_shdepend for the role oid grouped by dbid and name the databases (or retry there); in the exit hook drop owned objects in every used database first, then DROP ROLE once (no false "not dropped" line). Real-server test: stale role owning a schema in database X, swept from Y, reported with X named.
2. application_name is a free client setting: any session can keep a stale role alive (clutter only); it cannot make a live role look stale. A human-made role named hadavin_test_migrator_<8 hex> with no session gets DROP OWNED ... CASCADE in the current database. Fix: in sweep_stale_roles skip a role unless every schema it owns in the current database starts with the scratch prefix (`AND NOT EXISTS (SELECT 1 FROM pg_namespace n WHERE n.nspowner = r.oid AND n.nspname NOT LIKE 'hadavin\_test\_%')`); docstring: "a session that sets application_name can only keep a role, never drop one".
3. Sweep error path (migration_role.py:122-123): the finally runs pg_advisory_unlock on a possibly broken connection and can raise out of test setup. Wrap in try/except psycopg.Error.
4. The "alive" check needs a superuser or pg_read_all_stats (non-members see NULL application_name/usename). tests/fixtures/role_child.py:13 calls ensure_plain_role with any DSN. Fix: at the top of sweep_stale_roles check `rolsuper OR pg_has_role(current_user,'pg_read_all_stats','MEMBER')`; if false sweep nothing and return [].
Wording (not blocking): add one plain sentence at the top of _hold_the_role ("A test run keeps one connection open, named after its role, so other runs can tell the role is still in use."); split the long refusal message at migrate.py:746-759 into what is wrong / that nothing changed / what the administrator does.
