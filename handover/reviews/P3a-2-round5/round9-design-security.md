# PR73 (P3a-2) round 9, design and least-privilege lens, head d41a0c0 (code as ce3ade7, tree a039b1c)

Reviewer: fresh egm design reviewer, read-only, snapshot /tmp/snap/core_P3a-2-d41a0c0. Saved by the cloud session.
Verdict: 0 Blocker, 3 Major, 6 Minor, 1 Nit. The grant read-back is a real improvement: a GRANT on a managed relation, column, sequence or function to a third role or PUBLIC, the default PUBLIC EXECUTE on functions, and a SECURITY DEFINER function in the run's schema (also by dynamic SQL) are now refused. The Majors are grant paths that still escape it.
NOT CHECKED: nothing run; builder NOTES.txt for r9 not read (my pointer was wrong: the builder evidence lives on branch core/P3a-2, not in the cloud-handover checkout the reviewer could read, so no r9 claims were checked); the CLI wiring of migrate is not in the snapshot (unknown whether lock_wait_seconds can be passed from the command line); PostgreSQL 15+ public default not checked on a live server; pg_shdepend readability by a non-superuser; mutant files, long CHANGELOG lines and test_migration_rules.py not read in full.

1. MAJOR. A SECURITY DEFINER function in another schema escapes the refusal. migrate.py:151-154 (_SAFE_CREATE allows any CREATE OR REPLACE FUNCTION, no name check); :728-732 (_managed_names drops a function whose written schema is not the run's schema); :823-826 (_function_ids reads current_schema() only); :799-820 (both ACL queries filter n.nspname = run schema). Scenario: file 0006 holds CREATE OR REPLACE FUNCTION public.f() ... LANGUAGE sql SECURITY DEFINER AS $$...$$; works where the migration role has CREATE on that schema (any PostgreSQL before 15, or an administrator grant); not in the managed list, not new in the run's schema, keeps the default EXECUTE for everyone and runs with the migration role's rights. Fix at the choke point: refuse a function name written with another schema, or compare the set of function ids in the whole database before and after the files and read prosecdef and proacl for all of them. Test: a qualified SECURITY DEFINER function in a second schema.
2. MAJOR. ALTER DEFAULT PRIVILEGES is neither refused nor read back. migration_numbers.py:665-669 (_BLIND has no ALTER DEFAULT); migrate.py:799-820 (nothing reads pg_default_acl). Scenario: ALTER DEFAULT PRIVILEGES IN SCHEMA s GRANT SELECT ON TABLES TO PUBLIC; no new managed relation appears in that run, so the read-back finds nothing; the entry stays; every later table the migration role creates in that schema is readable by everyone, including tables made outside migrate. Also an administrator-set default privilege is reported at migrate.py:870-877 as "Remove the statement from the migration file", wrong advice when no file holds a statement. Fix: add ALTER DEFAULT PRIVILEGES to the static refusal; read pg_default_acl for the migration role and the run's schema; say in the message the cause may be a default privilege on the database.
3. MAJOR. Rights on the schema itself are never read back, and only the three named roles are checked. migrate.py:799-820 and effective_problems (about :292, has_schema_privilege(role, schema, 'CREATE') only for named roles). Scenario: GRANT CREATE ON SCHEMA s TO PUBLIC; (has an ON so the static rule passes); run migrate with no role arguments; nothing refuses; any login can create objects in the package schema (for example a function that shadows a name on the runtime role's search path). Same hole for GRANT ... ON DATABASE, TYPE, DOMAIN, LANGUAGE, LARGE OBJECT n, FOREIGN SERVER, ON ALL TABLES IN SCHEMA <other>, ALTER PUBLICATION p ADD TABLE audit_entries (if the migration role owns the publication). Fix: read nspacl of the run's schema and refuse any grantee other than the owner and the named roles; narrow the static rule so a file may GRANT or REVOKE only on TABLE, SEQUENCE or FUNCTION; everything else becomes a reviewed exception.
4. MINOR. The owner exemption can be moved by a file. migrate.py:853 and :866 (is_owner: grantee = relowner). ALTER TABLE audit_entries OWNER TO other_role where the migration role is a plain member of other_role: other_role is now owner with every right and the read-back treats that as normal; effective_problems catches an owner change only for the three named roles; _refuse_foreign_owned passes because the migration role is a member. Fix: treat an object as "owner" only when its owner is current_user; refuse any other owner.
5. MINOR. Relations made by dynamic SQL are not diffed (functions are). migrate.py:1194 and :1249-1254 (made_here carries function ids only). A function body builds 'CRE'||'ATE TABLE x ...; GRANT ALL ON x TO PUBLIC' and a file calls it; table x is not in managed so its ACL is never read. Fix: before and after set of pg_class ids in the schema.
6. MINOR. Every migrate run must name every role that already holds grants, and the refusal text blames the file. migrate.py:853 and :870-877. Run 1 uses runtime_role=app; a later CI run uses portal_role=ro only (or no roles); app still holds its rights and is not in named, so the run is refused with "Remove the statement from the migration file" though no file is at fault. Fix: say "or this role was granted in an earlier run, name it", or exempt roles that hold exactly what GRANTS gives. Side effect: REVOKE ALL ON ROUTINE ... FROM PUBLIC (:878) breaks any function the runtime role must call directly; today only a trigger function; nothing guards a future one.
7. MINOR. Lock wait ceiling gaps. migrate.py:894 and :1145-1149: no upper bound on lock_wait_seconds; above 2147483 seconds PostgreSQL rejects the lock_timeout value and the user gets a raw driver error, not a ConfigError. :903-909 queries backend_start, state, application_name for another user's session; PostgreSQL returns NULL for activity fields the login cannot see (not run); message would read "connected since None, state None"; print "not visible to this login" for NULL fields. Stale docstring: migrate.py:1124-1128 still says a second migrate "is not limited while it waits" (now false; it waits at most lock_wait_seconds) and contradicts :890-893. The error tells the user to rerun "with a larger lock_wait_seconds"; unknown whether the command line accepts it.
8. MINOR. Marking connection and sweep guard (tests/fixtures/migration_role.py). Reopen is sound for a clean death. The reopen does a blocking pg_advisory_lock on the same key (:109): if the old session is half-open (firewall drop, network cut) the server may still hold the old lock and test setup hangs forever; use pg_try_advisory_lock with a short loop and a clear message. A window remains between the death of the marking connection and the next plain_role_connect where a parallel sweep can still drop the role; test only proves reopen and a later sweep; at minimum state the window. :183 runs a pg_shdepend query inside the except handler; if the login is in pg_read_all_stats but not superuser the query may be refused and the error escapes the handler and fails setup: wrap it. Sweep guard for tables, functions, types in non-scratch schemas matches the r8 request (:157-161; current database only; other-database objects fall to the reported DROP ROLE failure path: fine).
9. MINOR. Wording for a non-technical reader. migrate.py:23-34 step 4 is one long sentence listing about 12 items; :413, :1136-1143 "closure", "tripwire" (migration_numbers.py:14), "read-back" used before explained (explained only in a bracket at :23); migration_role.py:12 "scratch schema" used before defined (comment at :40); "hold" still used for the advisory lock in the sweep text (second meaning); migrate.py:870-877 refusal is one long paragraph: split into what was found, what changed (nothing), what to do.
10. NIT. REVOKE ALL ON ROUTINE <name> is matched by function name only (migrate.py:815-819), so an unrelated same-name function owned by the migration role in the schema also loses PUBLIC EXECUTE (very unlikely).
Sound: attacl, relacl, proacl reads, PUBLIC mapping (grantee 0), SECURITY DEFINER refusal, default EXECUTE revoke when proacl IS NULL for objects in the run's schema; membership grants of the three named roles caught (m.roleid IN own in _READBACK_MEMBERS_SQL; a grant of some other role the migration role belongs to is not compared: falls under finding 3); static CREATE of schema, type, publication, extension refused by the _SAFE_CREATE allowlist (only dynamic builds escape: finding 5); lock wait logic sound apart from finding 7 (SET LOCAL lock_timeout before the lock, savepoint, holder lookup after rollback, later RECIPE_TIMEOUTS overwrite); extension-owned exemption (deptype 'e') correct.
REPLICATION flag (lead decision, not counted): reviewer's view is to add the check: a REPLICATION role can create replication slots from SQL, a slot is not rolled back with the transaction and keeps WAL on disk (can fill the disk), and the role can stream table content around table grants; PLAIN_MIGRATION_ROLE_SQL already says NOREPLICATION, so refusing the flag enforces the runbook; one flag in _ROLE_FLAGS and one test; docstring lines migrate.py:16-17 and :1131-1132 change from "not checked" to a fifth refused flag; leaving it out is defensible only if the lead records the reason.
