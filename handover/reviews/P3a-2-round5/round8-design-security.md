## Findings
1. MAJOR, migrate.py:1065-1097 and migration_numbers.py:661-670. Grants to any role other than the three named ones are never checked. A migration file may contain `GRANT ... ON ...`; only `GRANT r TO s` without `ON` is refused. `effective_problems` runs only for the runtime, portal and purge roles. Scenario: a future file says `GRANT ALL ON audit_entries TO some_other_login`, or grants to PUBLIC when migrate runs with no role arguments; nothing refuses it. The read-back never covers the ACLs (`relacl`, `proacl`). A new function gets EXECUTE for PUBLIC by default and `effective_problems` ignores functions; a `SECURITY DEFINER` function would give the runtime role everything its owner can do. Fix at the choke point: after the grants, for every relation in GRANTS and every function the files create, list the grantees; refuse any grantee that is not the owner or a named role allowed that privilege; refuse SECURITY DEFINER unless on a reviewed list. Negative tests: grant to a third role, grant to PUBLIC with no role arguments, a SECURITY DEFINER function.
2. MINOR, migration_role.py:78-90 and :270. The sweep can drop a live role if its hold connection dies (database dropped WITH FORCE, idle_session_timeout, firewall, restart): no named session and no lock remain, a parallel sweep drops its schemas. Fix: in `plain_role_connect` test `hold.closed` or `SELECT 1` and reopen; test with `pg_terminate_backend` then sweep.
3. MINOR, migration_role.py:125-135. The scratch-schema guard covers only schemas; `DROP OWNED BY ... CASCADE` also drops tables, functions, types the role owns in a non-scratch schema such as public. Fix: extend NOT EXISTS to pg_class, pg_proc, pg_type in non-scratch namespaces.
4. MINOR, migrate.py:1023-1027. The advisory lock is taken before any time limit; any role with CONNECT can hold the lock number and hang migrate forever (documented as deliberate, :978-981). Fix: overall wait ceiling with `pg_try_advisory_xact_lock` and a deadline; message names the holding session.
5. MINOR (lead decision open): REPLICATION flag not checked (migrate.py:388-395, CHANGELOG 14). Recommend adding the check (one flag, one test). The pg_database_owner exemption (migrate.py:571) is fine; keep it with a test.
6. MINOR, wording: module docstring migrate.py:7-19 is one sentence of about 200 words with terms used before explanation ("read-back", "closure", "tripwire"); refusal at migrate.py:757-769 is a run-on paragraph; "hold", "mark", "marker", "liveness" name one idea; CHANGELOG 240-241 should say in one plain sentence why a test run keeps a connection open; explain "scratch schema" at first use.
7. NIT, test_migration_rules.py:793-801: the password-less-login guard skips `**` calls, ignores `user=` inside a DSN string, and `# pw-env` turns it off. tests/demo_askdata/conftest.py:78 uses the `**` form and :102-105 puts a clear password into CREATE ROLE (made-up data). Resolve dict literals in `**`, use `create_login_role` or a hash in the demo conftest, or narrow the CHANGELOG sentence "every login role".
8. NIT, migration_role.py:121-123 returns [] silently when the sweep cannot see other sessions; print one line. `role_child.py:13` should call a helper that states this.

Spoofing, advisory lock, sweep safety: application_name or an advisory lock key set by another session can only keep a role (checked sweep SQL :125-135 and order hold, sweep, CREATE ROLE :270-272); token parsing strict (8 lower-case hex, escaped LIKE prefix); exit hook sound.
