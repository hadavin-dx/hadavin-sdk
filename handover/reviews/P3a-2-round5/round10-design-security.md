## Design (lead decisions)
The read-back selects objects by four rules (managed names, owned by me, new, changed); M1 and M2 come from the union. One before/after comparison of (owner, ACL, SECURITY DEFINER flag, body hash) over every object kind, with new objects checked in full, gives the same guarantee, removes _managed_names (migrate.py:725-739), the proowner clause and most `kept` logic; keep an absolute check only for the managed tables, schema_migrations and the trigger function. The "no-args run after a named run is refused" behaviour (test :3141) means every later run must name every role holding rights: runbook note for the lead. Static GRANT/REVOKE allowlist is needed (read-back cannot cover schema, database, type rights); simpler: refuse all GRANT/REVOKE in files (needs the real .sql files to confirm). REVOKE ALL ON ROUTINE FROM PUBLIC would break a non-trigger function the runtime role must call directly. On PostgreSQL 14 and earlier the public schema's explicit PUBLIC CREATE always refuses until an administrator revokes it (not verified on a server).
REPLICATION (open lead decision, not counted): reviewer view: add the check; a REPLICATION role can create replication slots from SQL inside a function body, a slot survives rollback and keeps WAL on disk. Change touches rolreplication in _ROLE_FLAGS and _ROLE_FLAGS_SQL (migrate.py:411-416), the borrowed-role query (:590-600), docstrings (:16-17, :1283-1284, CHANGELOG:14), plus two tests.
