## Pending-lead positions the reviewer judges wrong or unsafe
- **Wiring (item 1, recommended owner P4c): wrong.** The single write path is `actions/executor.py`, which has no reference to limits or the kill switch (grep: no matches). P4c edits `agent_loop.py` and comes after P4b, so after P2a merges the stop gate stays unwired for several packages, while the switch is advertised as a safety control. Recommended owner: P2a itself, inside the executor (a gate call around every outbound effect), or a named v1 package that must close before P8c. Add to "Done" that the "unwired" label blocks Core v1.
- **Five-PR split (item 2): unsafe as ordered (see A4).** 1a and 1b must merge together. P2a-2 and P2a-3 first is fine (no core caller, no state change).
- **Hot files:** `limits.py` P2a-1b, then P4b1, then P4c is consistent with F6. No other conflict found. `store/*` ordering P4d, P2a-1a, P6b2 is consistent with A11.

## Considered and found sound (reviewer's list, abridged)
- The trigger tests `session_user` (not `current_user`), uses `SECURITY DEFINER` with a pinned `search_path`, and `ENABLE ALWAYS TRIGGER` covers `session_replication_role = replica`; `kill_switch` has `id` PK with `CHECK (id = 1)` and `"on"` NOT NULL, so no id-move or NULL-on bypass; deny-all when no reset role is given is correctly specified; `42501` and the `RuntimeError` derivation are right; the `clear_kill_switch_if` compare-and-set holds under READ COMMITTED; the runtime role has no INSERT, DELETE or TRUNCATE and `effective_problems` already rejects TRIGGER and CREATE rights; the mutation arithmetic and the weak-row analysis are internally consistent; barrier scope is stated honestly.
