## A. Attacks tried, and why each fails or where it bites
- A1 smallest count `e`: undercount only adds refusals (safe). Overcount would need c <= e with a whole copy L visible; `str.count` is a greedy count of non-overlapping occurrences, the put-back original's own occurrences and a visible copy are disjoint, so c >= count_in_O + 1 >= e + 1: refused. A junction occurrence overlapping one inside O only describes a partial copy (the stated INSERT leak). Per-reading soundness holds if `scan_keyset` is local per character (traced from P1 text; P1b code does not exist, UNVERIFIED). It bites in M1 (self-refusal) and M3.
- A2 as-written put-back with needle forms from `undo(O)`: tokens only in the decoded form raise c and e equally; cross-value cases refused as expected; V with its `_place` pieces (redact.py 1247-1253): piece keys are substrings of V's key so c equals e for a V token alone; a decoded copy of V beside V's own token gives e = 0 (B-1 stays closed). An original may literally hold token-shaped text (snapshot redact.py 1229); the put-back must be ONE pass (one `re.sub`); no row or mutant for single-pass (N5). Seed placeholders not put back and excluded as needles (FR-13): sound.
- A3 length bound: evasion by splitting is not meaningful (denial-of-service guard; splitting moves to the stated "split across two texts" limit); false refusal only for texts holding tokens of long values; `len(form)` against `TEXTNORM_MAX_CHARS` is weaker than P1's `W(text)` (P1.md line 44) so some non-ASCII texts pass the bound and are refused later by `scan_keyset` with `TextTooLong` (fail-closed); `undo` is capped via `fits_after_nfkc` (runmap.py 101-107).
- A4 FR-43 is not a leak (refusal only adds). Wider than the draft says: any stored O whose `undo(O)` splits into two or more separately known values W1, W2 triggers it. The same adjacency class exists without encoding in outcome IN: stored `Anna Schmidt` plus `Anna` and `Schmidt` stored separately; text `Anna\nSchmidt` or `Anna,  Schmidt` masks the two parts individually giving `<NAME_1>\n<NAME_2>`; the put-back has key `annaschmidt` equal to the full-name needle with e = 0: refused although the model sees only tokens. Fail-closed and stated, but P-1 must count it (N2).

## MAJOR
**M1. False refusal of the redactor's OWN correct masking for every value whose two case readings differ; much wider than FR-42 states, and P-1 cannot see it.** Hit rule (section 5 item 3): for each text key s and EVERY needle k, c = s.count(k); e = sum over put-back O of count x min over keys(O) of count(k). The needles include the original's own keys. For a stored X with two keys kA, kB (SK-2: capital Eta, pass A and pass B differ), X's own plain, correctly masked token gives pair (sA, kA): c = 1; e = 1 x min(count(kA in kA) = 1, count(kA in kB) = 0) = 0; so c > e, refused. X alone is refused; PL-LK-49 words the cost as only when X holds another value's key; FR-42 pins "X's token alone refused" only for a value built to hold V twice. Any such value that is a checked needle (raw 12 or more, key 8 or more) and appears in a text; also a value found in the same text (`current`). FR-2 (self-explained) is asserted only for an ASCII V. Which values: letters that P1's table reads differently by case: capital Eta (h or n) named; by table logic other Greek capitals (Nu, Upsilon) UNVERIFIED. Real examples: Greek all-caps names, addresses, identifiers. In outcome IN (NAME and ADDRESS checked) any document with such a stored name ends the run, including on a plain, fully masked copy. P-1's corpus (English, German, French, plus Korean, Vietnamese and Arabic near-cap texts) has no Greek, Turkish or Cyrillic stored values, so P-1 reports IN while the failure sits unmeasured; GOLD-1 cannot see over-refusal (a raise counts as a pass).
Recommendation (smallest first): (1) add stored Greek-capital (and Turkish/Cyrillic) names, addresses, identifiers, written plainly, to P-1's corpus; state in section 7 and PL-LK-49 that FR-42's cost includes the value's own token; add a named FR row "X plain, alone, Greek capital Eta: refused (stated cost)". (2) Or exempt a needle that is itself a key of the put-back original, counted as 1 per token (UNVERIFIED sound; needs a character whose reading B equals what another reading A gives for a different character, none found, P1 data must confirm). (3) Or ask P1 for labelled keys (PL-LK-49(b)): more surface. Under order 8 option 1 is a text change and the rule stays.

**M2 (honesty). A PARTIAL copy of a known value is not listed as "not caught", and FR-3 pins it as passing.** The needle is V's whole key. A copy missing its last characters, or with one wrong character, reaches the model; in look-alike spelling never masked; in plain spelling the snapshot sweep matches only the whole literal for identifier kinds (redact.py 1498-1524) and the whole original for secrets (`_EVERY_COPY`, 1490-1497), so it is sent today too. Example: V of 13 characters, copy = first 12 with one Cyrillic letter: nothing refuses it (`key(copy)` does not hold `key(V)`). Section 10 and the CHANGELOG sentence do not list it; section 1(c) says every value of 12 or more is "covered on every path in the table": whole copies only. The owner summary must not read as "impossible to send". Recommendation: one plain sentence in sections 1 and 10 ("a copy of only part of a value, or with a character changed or dropped, is not caught; FR-3, FR-4"), the CHANGELOG and the lead's later-fixes list; a strict xfail row or merge into LK-SHORT/LK-INERT. No new code.

**M3 (spec gap on a redaction path). `e`'s "smallest count over the keys of `scan_keyset(O)`" does not say whether the key list is the memo's filtered list; the two readings give a refusal storm or an overcount.** Item 1 stores in the memo "its keys", each key under 8 dropped. (a) With the filtered memo list, for any put-back original O of a short value (a 5-character NAME is typical) the filtered list is EMPTY; `min()` over empty raises `ValueError`, which `redact_text` converts to a `RedactionError` (item 4; runmap.py 524-525): every text with a needle occurrence and a token of a short value is refused. With `default=0` the refusals are right but the code is unspecified. (b) If keys of different lengths exist for one original (tag characters: T0 drops them, key under 8; T1 decodes them, key 8 or more), the filter changes the minimum: `e` counts only the T1 key and over-explains in the T0 reading, so a copy visible only in T0 passes. Preconditions: attacker needs O (stored value partly in tag characters) in the map and its token in the text; exotic; UNVERIFIED that tag-text lengths differ (SK-2 and A2 gap 3 suggest they do). Recommendation: write "`e` uses the UNFILTERED `scan_keyset(O)` keys (length filter applies to needles only), `min` over the full list, an empty list counts 0"; FR row (needle present + token of a 5-character stored value: not refused); a row with a tag-character stored value; mutant "e over the filtered keys" (killer: the tag-character row). Counts: LK +1 or 2, mutants +1.
