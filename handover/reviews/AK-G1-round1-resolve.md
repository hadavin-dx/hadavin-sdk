## Facts I checked myself (they decide rows)

1. **The state machine.** `runtime/runs.py:10-23`: `NEEDS_PERSON`, `NO_ACTION`, `DENIED` and `STOPPED` have no row, so they are FINAL. `check` (`:29-34`) raises on a final state, and always allows `-> STOPPED` from a non-final state. `handle` moves RECEIVED to WORKING at `agent_loop.py:350` before any work. Both reviewers are right on the double transition: `_limits_stop` (`:239-250`) already ends the run, and its `run_budget` branch goes through `_abstain`, which posts a card (`:569-597`).
2. **The tool block.** In `agent_loop.py:455-538`, every stop calls `_abstain`, either directly or through `_redaction_failed` / `_evidence_unavailable` (`:540-548`). So a "verbatim" `_tool_step` posts abstain cards and returns a FINAL run.
3. **Principals and the gate.** `_principal` (`:724-728`) returns the registered principal, or one with `rights=[]`. `Principal` (`identity.py:10-15`) has `id`, `kind`, `rights` and `approver_of`. `approvals/requests.py:158-159` holds `requester_cannot_approve`. `_submit` can end in DENIED, `NO_ACTION shadow`, or NEEDS_PERSON (`invalid_proposal`, `approvals_not_configured`, `card_not_delivered`, `audit_unavailable`, `limits_unavailable`) (`:632-722`). `_shadow` posts a card (`:599-630`).
4. **Tools carry no person.** `ToolBox.invoke(name, args, mapping)` (`tools.py:1162`) builds `ToolContext(spec, timeout, resolver, bindings, ...)` (`:1166-1174`, class at `:459-480`). That context has no tenant, user or caller field. The plain-callable path `hooks.tools[name](args)` (`agent_loop.py:292-295`) has none either. This answers the adversarial reviewer's open question: today nothing can carry a fixed per-person argument.
5. **Redaction functions.** `redact_untrusted` = `redact_text(..., neutralise=neutralise_untrusted)`, and its own docstring says model-written text uses `redact_text` (`guard/runmap.py:298-303`). `escape_placeholders` rewrites `<X_n>` to `‹X_n›` (`:275-280`), so `PLACEHOLDER` no longer matches. The correctness reviewer's point is confirmed.
6. **Counters and stored kinds.** Placeholder counters start after the highest number in the map KEYS (`guard/redact.py:893-908`). `EMAIL` is a STORED kind (`defaults.py:108-113`), so the D4 example "counters for an e-mail start again at 1" is wrong in its detail. The collision is real only for kinds that are not stored, or for originals that fail `storable_original` (`runmap.py:218-226`).
7. **Map purge.** Both memory (`store/memory.py:260-262`) and Postgres (`store/postgres.py:496-503`) refresh the map time on every `put_redaction_map`. Both age a map with an unknown key by that time (`memory.py:269-282`, `postgres.py:512-533`). So D5 holds while a conversation is active, and ADV-12's mismatch still holds for an idle one.
8. **Restored key and errors.** `app.py:202-206`: pilot/prod refuses a missing `restored_hash_key_secret_name`. `_restored_digest` is an HMAC under it (`agent_loop.py:256-265`), so a keyed digest for chat hashes already exists. `ConfigError` exists (`errors.py:4`). `config.py:3`: cross-file checks live in `registry`. `deferred.py:48` and `registry.py:321` already branch on `environment in LIVE`.
9. **Lease against stuck time.** `stuck_after_s = max_steps x call_timeout_s x max_attempts + 60`, with `call_timeout_s` 60 when the backend sets none (`runtime/tick.py:100-109`). `python3 -I` gives: for `max_steps` 2, 5 and 10 it is 180, 360 and 660 s. All are above the default `lease_s = 120`, so a HEALTHY exchange can lose its lease (resolver finding R1-RES-1).
