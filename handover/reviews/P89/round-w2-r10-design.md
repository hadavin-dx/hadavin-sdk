Short-secret floor leaves a real gap and a safe fix exists. tools/mutation_runner.py:438-439 (None return of _skeleton_pattern), docstring :63 and :76-78, test pinning the leak at tests/test_mutation_runner_keywords.py:2015-2025. Failing input: pass_env value "pw=ab'c" (bare password a'bc) printed as repr(repr(repr("a'bc"))) is not fully masked; also "a\b1" printed three times (backslashes 2, 4, 8; exact forms stop at 4); also a short secret with a non-ASCII character in the middle. The builder's description is wrong both ways: a short secret of plain printable ASCII without backslash, quote or control character is NOT at risk (repr never changes those characters; layer 0 hides every plain occurrence at any depth); only short secrets containing a backslash, quote, control character or non-ASCII character leak at depth 3+. The stated reason "a shorter skeleton would hide ordinary text" does not hold. Fix: for a secret whose skeleton is under 6 characters, do not drop the removed characters: build the pattern from the secret as written, making each character the skeleton would drop (backslash or quote) a mandatory run of one or more of [\\'"]; keep per-character escape choices for the others (a'bc becomes roughly a[\\'"]+bc). Needs real quote or backslash characters in the line, so no over-masking of ordinary text; depth-independent; reuse the widening step. Secrets with no dropped character need nothing extra. Short non-ASCII-only secrets: accept the escape looks or add the same anchoring. Then remove the "printed three or more times" sentence (:77), replace the "!=" pin (test lines 2023-2025) with a no-leak test over depth 3 to 5, add a mutant for the new branch, fix CHANGELOG line 8 (floor stated there).
