# P5a: ticket errors and builder notes (BN.md)

Found while building. Each item: what the ticket says, what is true, what the build does.

1. **BN-24 ("P5a is not released to build start").** Lead order 83 and the brief override it; the whole ticket was built. `codes.py` is pure data (stdlib enums and tables); `validation_text` is thin glue in `guard/diagnostic.py`.
2. **`StepToken.of(step)` for corpus steps.** The ticket's `test_active_rows_hold_on_new_code` says an exception row runs `diagnose(..., step=StepToken.of(step))`. `StepToken.of("extract")` is `Where.other`, because `extract` is a `Where` member and not a tick step (`TICK_STEPS` has six other names). A golden line with `step=extract` can therefore not come from that call. The tests convert: a `Where` member name becomes the `Where` member; anything else stays a raw string (so `jane_doe` and `Sweep` correctly give `step=other`).
3. **Oracle gap found by `test_every_active_row_has_teeth`.** The ticket's oracle decodes entities, percent, backslash and quoted-printable views but has no ANSI/C1 view, so an e-mail broken by `ESC [ 1;31 m` or U+009B was NOT seen as a leak (rows ansi_c1-03 and -05). A view with the control sequences removed was added to `views()`.
4. **Row with no canary in any leaky subject.** `builtin_text` row 3 (UnicodeEncodeError over a name): a real `UnicodeEncodeError` prints only the offending character, never the text, so no writer could leak it and the row had no teeth. The factory now sets `reason` to carry the name. Same for `json_decode` row 2: `str(JSONDecodeError)` holds no document; the teeth test therefore also reads `.doc` and `.msg` of the leaky subject.
5. **`_MetaName` with a `__qualname__` property.** `type()` refuses a metaclass whose `__qualname__` is a property (TypeError at class creation), so the row "a class whose `__name__` and `__qualname__` raise" is built with `__name__` only.
6. **P1m runner and params.** `only_test` must be an identifier, so a parametrised killer cannot be pinned; `test_pinned_code_per_class` is one loop test and the frame-rule killers are named tests instead of corpus-row ids.
7. **T6 via `Config`.** A real `Config` with a stray key through the model gives a `ValidationError` as the ticket predicts; the unit test uses `Config.model_validate({"zzz_typo": ...})` (also reports `missing` for required fields, so `type` is the first reported type, not necessarily `extra_forbidden`).
8. **bandit** is not installed in the uv test group (`uv run bandit` fails to spawn); it was run as `uv run --with bandit bandit -ll -q -r src` (exit 0).
