(a) The runtime stop cannot be written. `PostgresStore.set_kill_switch` is `INSERT ... ON CONFLICT (id) DO UPDATE`. Postgres needs INSERT privilege for any INSERT statement. The ticket says the runtime keeps "UPDATE" and does not mention INSERT or changing the store to a plain UPDATE. (b) The reset role gets "UPDATE" only. `clear_kill_switch_if` has a WHERE on `id`, `"on"`, `by` and `ts`, so it also needs SELECT. `Limits.reset` also writes audit rows through a sink built on the same store connection, so that role needs the audit INSERT rights too, or the reset needs a second connection. The ticket gives the reset role neither. (c) There is no path for the reset credential. No reset DSN secret name, no change to `backends/table.py` (a hot file in amendment F6) or `backends/builtin.py`, and no second store in `app.py` or `cli.py` is listed. So "connecting with the reset database role" has no implementation. (d) The trigger cannot learn the reset role name from a migration file. `migrate()` applies static SQL files (`migrate.py:327-332`) and only afterwards takes the role arguments.
