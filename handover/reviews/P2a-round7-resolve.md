## Positions
1. **The reset names a set by (version, count).** A count alone is not an identity across resets; the pair is, because requests only grow within a version. This is a small change (one more parameter, one more comparison) and it closes the only major that can clear a stop the operator never saw.
2. **The cap goes into the stop function and is not a denial.** At `N` open requests the switch is already ON; skipping the INSERT keeps the state and bounds the read cost. The livelock cannot be removed by code without letting the runtime clear things, so it is a runbook step.
3. **A stop can wait behind migration DDL.** I withdraw "no lock another caller can wait on". The delay is bounded by the DDL's `lock_timeout` (new config). The probe never tests behaviour by running an UPDATE any more; it reads the catalog.
4. **Cuts (order 8).** Config table + HD002, typed name, breakglass login, the dry run. Each has a v1.1 row. None is a defect fix; the first three removed features that nobody needs to be safe; the fourth removed a check that cannot be made reliable.
5. **Kept:** the ON-then-OFF pre-step (the common path, not an edge) and `kill_switch."on"` as a second ON source (decided path A14).
