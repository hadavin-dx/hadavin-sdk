## Proposed ticket-facing text (ledger row BL-hadavin-sdk-p3a2-003, refusal-list erratum)

**BN-P3a-2-f (the refusal list is wider than the ticket's list).** The P3a-1 refusal list (`refused_statements`) refuses `GRANT r TO s` and `REVOKE r FROM s` with no `ON` (role membership) in a `.sql` migration file, which the ticket's list did not name. This is intended and stays. Role membership is changed by `migrate()`'s own Python step with the role as an argument (the ticket design), never by a migration file: a role is chosen by the person who runs `migrate`, so a static file cannot name it. `migrate()` makes no membership change today; the plans that need one (AK-G15-b, AK-G2 BN-28) write it in `migrate.py` Python, not in a `.sql` file. Written into the `migrate()` docstring (`migrate.py`) and checked by `tests/test_migration_rules.py::test_the_migrate_docstring_says_where_role_membership_is_changed`. Tripwire: `tests/test_migration_rules.py` compares the refusal with the PostgreSQL parser (pglast 8.7 = the PostgreSQL 17 grammar, test-only) over 5 role names x 7 grant options and 4 revoke heads x 5 role names x 5 tails, each with six comment/noise wrappers; every one must parse as a role grant AND be refused, and no role-grant form may hold an `ON` token (so a pglast upgrade that adds one fails first). Object grants (`GRANT ... ON ...`) must not be refused by this rule.
