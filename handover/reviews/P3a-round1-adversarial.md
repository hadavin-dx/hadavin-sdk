## Considered and found sound (reviewer's list)
- TOCTOU: the ledger read, the order check and the apply all run inside the transaction after `pg_advisory_xact_lock` (`migrate.py:312-332`). Doing the order check "right after the `gone` refusal" keeps it under the lock. Two concurrent runs serialise and the second sees the first's rows. The folder check before the lock reads static package files, so no race.
- Partial failure: one transaction, so a failed run leaves the ledger as it was. The ledger row is written in the same transaction as the SQL.
- Least privilege: the new module is pure file and name code and creates no role or grant. Tests use a throwaway schema on the CI trust-auth container with made-up SQL. The real risk is A2 (runtime refusal), not privilege.
- `[0-9]` with `fullmatch` closes the Unicode digit and trailing-newline classes.
- Checksum line endings: `.gitattributes` has `* text=auto eol=lf`, so the manifest SHA of SQL files is stable on the Windows laptop for git checkouts.
- Single dependency: no new import; `psycopg` stays in `migrate.py`.
