# AK2a round 1, adversarial review

Status: REPORTED (saved from the reviewer hand-back, which is model output, not user authority).

TICKET REVIEW ROUND 1 (adversarial), AK2a revision 1, commit b1f180d. Read-only. I did not read handover/reviews/ or handover/evidence/. Ticket line numbers are from the file as read. No code was run; every claim below comes from reading the ticket and the cited source.

Verdict: NOT BUILDABLE AS WRITTEN. 0 Blockers by my labels, but 12 Majors. Several are bugs in the ticket's own rules (CRLF files, K1 against the heading rule, the child's I/O protocol). Several mutants cannot be killed by the rows assigned to them.

| R1-ADV-1 | Major | 121 (e), 157 R5, 99 c1 | The `high_nontext` count includes "control characters other than \t and \n", measured on the RAW pages, before c1. `\r` is a C0 control, so every CRLF line ending counts as non-text. A Windows text file with short lines (a list of 15-character lines is about 6%) exceeds the 5% limit and goes to a person. R5 never tests `\r`. The denominator of `nontext_share_ppm` (all characters or non-space only) is also undefined. | Exclude `\r` and `\f` from the count, or measure after c1/c2. Define the denominator. Add an R5 case with a CRLF file of 15-character lines that must be `ok`. |
| R1-ADV-2 | Major | 121 (e) `low_text` | Median non-space characters per page below 100 gives `low_text`, with no exemption for `has_images=False`. The same applies to short `\f`-split text files. | Apply `low_text` only where `has_images` is True or None, or use a separate, lower text-file minimum. Add rows for a 60-character `.txt` and for a 9-page text file with a short last page. |
| R1-ADV-3 | Major | 110 vs 175 (K1) | Headings are detected as ONE-line blocks between blank lines. | R1-ADV-4 | Major | 130 "stops after KIT_MAX_PAGES pages or KIT_MAX_DOC_CHARS characters", 246 (M-40) | The spec does not say what the worker returns when it stops. | R1-ADV-5 | Major | 129 | The parent writes the whole input to the child's stdin before any timeout applies (the timeout is described on `wait()` only). | R1-ADV-6 | Major | 129, 130 | The 4*chars+1 MiB cap is wrong for JSON. The parent also trusts the child's JSON: a compromised child can claim `code:"ok"`, any `reader` string (goes into the report), or lone surrogates (later `.encode` raises). The trust boundary is not stated. | Fix the worker encoding (`ensure_ascii=False`, UTF-8) and recompute the cap, or cap on parsed characters. Parent validation: exact keys; `code` must be in {ok, unreadable codes}; `reader` must match a pattern; every page `[str, bool|None]`; no surrogates; page count and character count re-checked. Add a P-row where `_worker_code` returns a hostile result line. |
| R1-ADV-7 | Major | 192 P6, 244 M-38, 193 P7 | (a) The bomb is 64 MiB of spaces, far below the 1,024 MiB `RLIMIT_AS`. (b) `RUSAGE_SELF` does not measure the child, so the "less than 64 MiB growth" assertion passes with no child at all, and it is a peak figure. (c) `_worker_code` replaces the worker module, but the rlimit is set inside that module, so the substituted `-c` code gets no limit. The ticket says it keeps "every limit". | (a) A memory-kill row that sets a small `KIT_PDF_MEMORY_MB` (say 128) and runs code that allocates beyond it, expecting `memory`. - Scans to needs-person: consistent with order 27 item 54 (AK0 PL2). OK. Note the weakness in R1-ADV-2 (short text goes to a person) and the `None` handling for `has_images`: one short page in ten gives 10%, so two give `suspected_scan` for any PDF library that cannot report images. Text PDFs with short last pages will mass-route to a person. Consider requiring a minimum page count for the percentage rule or using only the median plus a pure-scan test.
