Verified by reading the code. This is not a run result.
- `proc.wait` is wrapped as claimed: `TimeoutExpired` first, then `except BaseException: _kill_tree(proc); raise`, then `_kill_tree` after a normal exit (lines 171-182). `_kill_tree` always reaches `proc.kill()` and `proc.wait()` in its `finally`.
- Nothing in `root` is ever mutated. The snapshot is taken once, and each mutant goes into a fresh copy. `_locate` never joins the caller's string to a path and checks the real path. `_relative` rejects `..`, absolute paths, a drive, UNC paths and `:`. `_inside` resolves symlinks. I found no path or symlink escape from the mutation target. The environment is an allowlist, `PYTHONNOUSERSITE` is set, and `PYTEST_ADDOPTS` and `PYTEST_PLUGINS` are not passed.
- For each of the 37 mutants I checked four things: `old` occurs once, `expect` is a fragment of its own assertion message, no other assertion in the pinned test carries that fragment (except the Windows case in R2-ADV-3), and a `test_file` and `only_test` are named. I did not find an expect that matches the wrong failure on Linux. I also did not find an equivalent mutant except the duplicate in R2-ADV-6.
- `Path(tmp)` makes the "joined as a path" mutant behave the same as "not checked again" (R2-ADV-6).
- The "timeout reported as exit code" mutant keeps the `_kill_tree` above it, so it does not hang the inner run.
- The Windows `_pid_alive` logic is sound as written. Details:
  - It calls `OpenProcess(0x1000)`, then `GetExitCodeProcess == 259`, then `CloseHandle` in a `finally`.
  - `use_last_error=True` is set, error 5 counts as alive, and a failed exit-code read falls back to `tasklist` under System32.
  - The helper tests exercise those branches with a fake kernel32 on Linux.
  - Real ctypes calls are not exercised.
- The four sha256 values in the manifest and in the CHANGELOG match as text. I did not compute the real hashes of the files.
- The `ci.yml` lint and format steps do include `tools`.
