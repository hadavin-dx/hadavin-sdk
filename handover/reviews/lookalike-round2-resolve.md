## Positions
1. Design (b) stands: refuse the whole text when a key of a known value occurs in the folded text after masking. Draft 3 widens what it reads (three key types instead of one) without a position map.
2. **Three keys, each from an existing P1 function:** `scan_keyset` (P1b) for every kind except NAME/ADDRESS/TENANT; `case_key` (P1a `fold`, case kept) for NAME/ADDRESS/TENANT; `squeeze` (P1a) additionally for secret kinds. No new P1 function, no `id_keyset`, no `deny_hit`.
3. **Placeholders are joined, not segmented** (PL-LK-12). This departs from RES-1's recommendation for a stated reason; the lead sees it.
4. **What draft 3 still does not close (stated, each with a row and a v1.1 trigger):** case-only copies of NAME/ADDRESS/TENANT; values whose key is under the minimum (8 secret, 12 other); markup or letters between the letters of V, and fillers in identifier kinds; the mixed Eta reading; letters the table reads as another character with no class map (leetspeak, P1 PENDING LEAD 29); deliberate encodings other than percent/entity/escape; copies split across separate strings; numbers held as JSON numbers; values not known when the text passes. Order 11(1) says "closed in Core v1": the honest reading is that every row of the lead's table is closed for secret and identifier kinds of 12+ characters (8+ for secrets), and for NAME/ADDRESS/TENANT every row except "upper case / lower case". PL-LK-4 asks the lead to accept that.
