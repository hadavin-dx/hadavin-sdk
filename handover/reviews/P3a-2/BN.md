# Proposed build-note text for P3a.md (for the lead to place; handover not edited by the builder)

**BN-P3a-2-a (read-back values; replaces "seven values" wherever the ticket says it).** The read-back saves and compares NINE values in one query before the first file and after each file: `current_user`, `session_user`, `session_replication_role`, `search_path`, `standard_conforming_strings`, `backslash_quote`, `client_encoding`, `transaction_timestamp()` and `txid_current()`. The last two are the backstop for a `COMMIT` that the text rules did not see: a COMMIT starts a new transaction, so the clock and the id change. Source: LEAD-ORDERS order 74 item 10. In the ticket, build note 12 stays true for the two read-back constants (`_READBACK_VALUES_SQL` now has nine columns). Names in the refusal text are the nine item names above, then `trigger <schema>.<table>.<name>`.

**BN-P3a-2-b (downgrade-read test; replaces the cite "plan section 198").** The cite is `studio-notes/plan-v3.md` line 193: "Migrations are forward-only; each includes the downgrade-read test of P3a." The test built in P3a-2 is `test_the_previous_release_columns_survive_the_newest_migrations` in `tests/test_migration_postgres.py`: build the schema of the files up to `PREVIOUS_RELEASE_LAST`, record every column (type, nullability), apply the rest with `migrate()`, require that no old column is gone, retyped or made NOT NULL (unless named in `ACCEPTED_CHANGES` with a real `test_` function), and run the old column list as a read on every old table. `PREVIOUS_RELEASE_LAST` is provisionally `0004_audit_checkpoint_meta`; the lead sets it when the first tag exists. The pg_dump structure comparer (layer 1) stays P3a-3.

**BN-P3a-2-c (one release manifest).** The forward-only manifest is `tests/fixtures/migrations_released.json` (stem to SHA-256) checked by `released_problems` in `store/migration_numbers.py` and `tests/test_migration_numbers_fix1.py`. P3a-2 had built a second one (`tests/migration_manifest.json`) and deleted it as a duplicate (same checks; fix1's also reads Windows line endings as Unix ones). When a release is cut, the lead adds that release's new stems to the one file.

**BN-P3a-2-d (mutant count).** The ticket figure of 124 distinct mutants is stale for this split. P3a-1 holds the lexer, number, recipe and refusal mutants (`tests/migration_numbers_mutants.py` and the ticket's M-ids); P3a-2 holds 36 mutants (read-back and scan M61, M62, M64-M71, M87-M95 as built, plus new MB1, MB2 for the clock and id, MW1-MW9 for the wiring, MM1-MM3 for the manifest). M63 stays cut. Table with a named killing test per mutant: `P3a-2-evidence/evidence.md`, section "Mutants and killers".

**BN-P3a-2-e (test server).** The dblink attack in `tests/demo_askdata/test_validate_harm.py` makes the SERVER connect to itself, so the test server must listen on the default socket directory and port 5432 (CI's service container does). A builder's throwaway server on another port makes `[dblink-connect]` fail; start it with `-p 5432 -k /var/run/postgresql`.
