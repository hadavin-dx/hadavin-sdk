## Majors
M1 Role check looks only at `current_user` (`_ROLE_FLAGS_SQL` migrate.py:390, `_BORROWED_ROLES_SQL` 538-541). The fixture `plain_role_connect` (tests/fixtures/migration_role.py:75) connects as a superuser and runs `SET ROLE plain`; the session user stays superuser; a file can undo the switch inside a function body (e.g. `set_config('role','none',true)`) and the read-back sees equal current_user at the end. Same for a DSN with `options=-c role=...`. Fix: line 390 `WHERE rolname IN (current_user, session_user)`; line 540 also `pg_has_role(session_user, r.oid, 'MEMBER')`; change the autouse fixture to connect as a LOGIN plain role (`owner_dsn`, `_create_roles(login_password=...)` already build one); update pin test `test_the_membership_check_reads_the_current_user_and_all_four_flags` (wiring:830); real-server test: a superuser login with SET ROLE plain is refused. Cost: CI test role needs password or trust login; one extra login per Postgres test. Order 186 G73-5 says "current_user is a superuser": code matches the words, not the purpose.
M2 Printed plain-role SQL (`PLAIN_MIGRATION_ROLE_SQL`, migrate.py:529-532) gives `GRANT USAGE, CREATE ON SCHEMA` without grant option or ownership; `_apply_grants` (220) then runs `GRANT USAGE ON SCHEMA ... TO runtime_role`, which from a role without grant option only warns ("no privileges were granted") and does nothing. `effective_problems` checks only too much access, never too little. Tests hide it (autouse fixture makes the plain role schema owner, migration_role.py:72-74; `plain_role` fixture uses GRANT ALL ON SCHEMA and GRANT CREATE ON DATABASE, test_migration_postgres.py:1296-1306; the only real-connect run, line 1385, passes no runtime/portal/purge role). Fix: printed SQL `GRANT USAGE, CREATE ON SCHEMA <schema> TO migration_role WITH GRANT OPTION` (or ALTER SCHEMA ... OWNER TO); after `_apply_grants` check `has_schema_privilege(role, schema, 'USAGE')` and refuse if false; real-connect test with the role made by the printed SQL only and `migrate(dsn, runtime_role=..., portal_role=...)`; mutant: delete `WITH GRANT OPTION`.
M3 Least-privilege check incomplete: never looks at predefined roles pg_execute_server_program, pg_read_server_files, pg_write_server_files, pg_write_all_data, pg_signal_backend, nor parameter grants (PostgreSQL 15+ `pg_parameter_acl`). Text tripwires (`COPY ... PROGRAM`, `ALTER SYSTEM`, `SET`) only at statement start; a function body called by SELECT can `EXECUTE 'COPY x TO PROGRAM ...'` or `set_config('session_replication_role','replica',true)`; test helper `_plain_role_may_set` (test_migration_postgres.py:212-227) shows such a grant is possible. Fix: clause in `_BORROWED_ROLES_SQL` for membership in those five (or refuse any `pg_*` membership except pg_database_owner); `SELECT parname FROM pg_parameter_acl WHERE has_parameter_privilege(current_user, parname, 'SET') OR has_parameter_privilege(current_user, parname, 'ALTER SYSTEM')` guarded by `to_regclass('pg_parameter_acl')`; real-server tests for one predefined role and one parameter grant.
