Checked and holding (attacks that failed):
- Grant matrix against P4d's sweep SQL (`P4d.md:178`). The claim sets exactly status, settled_usd, closed_at, expired_at. The trigger's `settled_usd = OLD.reserved_usd` plus both timestamps non-NULL matches it.
- P4d's BEFORE INSERT trigger (line 167) forces new rows to `open`. So a runtime login holding INSERT cannot insert an `expired` row, and the actor trigger being BEFORE UPDATE only is sufficient.
- `PostgresStore` start-up reads no table (`postgres.py:125-175` runs only a connect and `SET TIME ZONE`). So the maintenance login needs no extra right at start-up; the ticket's own UNVERIFIED hedge (line 202) is probably unnecessary.
- The iam_auth path (`build` refuses a password DSN) fits the maintenance DSN.
- Fail-closed paths hold. No maintenance role named gives deny-all. A maintenance store missing in pilot or prod raises `ConfigError`. In dev and test it logs one WARNING. There is no runtime fallback in any environment. The tick records a failed step and the others still run.
- The `_ROLE` regex (`migrate.py:70`) accepts `public`, `none`, `current_user`, `pg_monitor` and `postgres`, so the H1 fail-before is real. Uppercase and quoted forms are already refused.
- Mutants b12 to b26 each have a killer in S1 to S6. Counts add up: 26 `a` mutants, 32 `b` mutants.
- G rows: 12 and 13 are cut and not reused. T/L/G/K ids are consistent with their mutant references.
