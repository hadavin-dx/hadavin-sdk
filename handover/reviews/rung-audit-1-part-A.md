**The answer in one paragraph.** Both first suspects are mostly NOT cuts.
- **AK-G16.** Most of its code is the core change that lets each process read only its own secrets (D1, `:101-116`) and the audit-row checks. No deployment tool touches either. The renderer and the lint mostly hold our own least-privilege rules (per-part secret lists, the metadata-address set arithmetic, DNS and egress ports, the file-mode mask, the closed allow-list, the gate on `migrate.GRANTS`). kube-linter, kubeconform, Trivy and Kyverno do not ship those rules (kube-linter's check list, read today).
- **AK-G2.** It already climbed the ladder. E-mail, folders, queues and schedules were cut to a forwarder, which is the client's tool or n8n (`:94`, `:207-211`). What is left is the R368 brain: write-ahead receipt, run once per message, terminal states, backpressure. Neither an n8n webhook nor a database queue library gives those.
- **The real cuts are small:** AK-G16-b2 as a document, three or four duplicate lint rules, a static container file, AK-G2's own dev server, and the load generator moved to k6.
- **One real gap I found is not a cut.** AK-G2 has no multi-hour soak and no "3x peak" statement for R370 (grep `soak` in `tickets/AK-G2.md`: 0 matches).
