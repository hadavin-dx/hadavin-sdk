## Positions (where I disagree with a reviewer's proposed fix, and why)
- **R2-ADV-1's first option, "a named group AFTER the digits":** rejected. Any extra group changes `groups()` for a pattern that the fold scan and `redact_many` also read. And "after the digits" cannot hold a keyword that comes before them. Reading the slice before group 1 needs no group at all.
- **R2-COR-17's narrowing to exclude `A-Z`:** rejected. On the redaction path an over-mask fails safe, and all-caps names are real names on invoices (row NAME-CAPS).
- **R2-ADV-3's option "refuse, since fail-closed":** rejected. The text that would be refused is text the masker deliberately leaves alone, so refusing adds no safety and only adds false abstains. The sweep rule is reused, so there is no new matching rule to review.
- **R2-ADV-8's "write an outcome after the call":** not taken. Main already has intent-only rows (Facts), and the meter owns the call's outcome.
- **R2-COR-2's first option, "add constructor, `redact_value`, `len` and a hook-facing map to the session API":** rejected as surface. Seeding the session with the run loop's own map deletes every such caller instead.
- **R2-COR-16's `TooDeep` part:** contested by `git show` (Facts).
- **No finding was contested in full.** Both reports are accurate on the code I re-checked. The Blocker is real and reproduced.
