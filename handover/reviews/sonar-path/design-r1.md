## Blocker
- **B1** `confined(base, relative)` refuses an absolute `relative`, but every real caller passes an absolute path already joined to the base (cli.py:266, replay.py:75/261/262/276, score.py:228/242). Choose: (a) callers pass base plus relative name and the design lists each call site's new form; or (b) accept an absolute path that resolves inside the base. State the order: join, resolve, then check containment.
- **B2** The stated purpose (clear SonarCloud) is not shown to be met. `base` itself comes from argv; containment inside a tainted base does not remove taint in a taint tracker; a user-named function is likely not a recognised sanitiser. Needs an acceptance gate: one scratch-branch SonarCloud scan of a minimal helper, result recorded, BEFORE NOSONAR lines are deleted; fallback = honest owner accept in the Sonar UI. (Reviewer's Sonar statements are from memory, uncertain; the rule key `S8707` in repo comments not confirmed.)

## Major
- **M1** `config.confined` is not one of three private copies: 12+ callers (app.py:274, registry.py:76/85/96/345, evals.py:43/60/106, hashing.py:23, actions/secrets_file.py:36, runtime/agent_loop.py:138, k1b/bundle.py:211). Applying Windows device-name and trailing-dot rules on every OS is a behaviour change on Linux (a file `aux.md` becomes refused). Decide: every OS (argue it) or gate on os.name with the text rule tested on every OS via a parameter. Add a callers table with origins; run the whole suite. Note ConfigError is a ValueError, key_path raises plain ValueError, so a PathRefused(ConfigError) stays compatible.
- **M2** Sinks not routed through the helper: cli.py:256-257 (exists, iterdir), :265 mkdir; replay.py:81, 125, 133, 145, 275; score.py:193-205, 226; bundle.py:112, 137, 199, 214, 335, 344; causelist.py:39. Either a sink table, or one validated `Folder` root object (mkdir, glob, iterdir, join as methods) as the real single choke point.
- **M3** Race mitigation wrong/incomplete: `O_NOFOLLOW` covers only the last component and not on Windows; `os.replace` re-resolves by name. Either use `dir_fd` on POSIX (open base once; os.open(name, ..., dir_fd=fd); os.replace with src_dir_fd/dst_dir_fd) or state the threat model plainly (attacker = operator's CLI input, not a concurrent local writer). Pick one; add a test or state none.
- **M4** Rules under-specified: which control characters (C0, DEL, C1, Cf/bidi); numeric length limits and unit; incomplete device list (CONIN$, CONOUT$, CLOCK$, superscript COM/LPT, `NUL:`, extension forms); `:` / alternate data streams not mentioned (refuse in component on every OS; in confined after the drive prefix); 8.3 names; trailing dot/space also in confined; case-insensitive FS and Unicode normalisation (refuse, never repair); hard links and mount points scope. Python floor 3.12 so `ntpath.isreserved` unusable; inline list.
- **M5** Errors: resolve can raise OSError, RuntimeError (symlink loop on 3.12) and ValueError (NUL); causelist already catches (OSError, RuntimeError). List all three; add a symlink-loop test.
- **M6** `operator_file` is dangling (not in the public names list; "step 5 of the order" points at nothing) and gives no containment so cannot clear Sonar, while step 5 deletes the NOSONAR at score.py:101 anyway. State: that finding stays open until the owner accepts it; PR body says so.
- **M7** Rung table missing (preamble rule 20): component | need | rung tried | evidence | what only our code gives | verdict. Try: werkzeug safe_join (only if already a dependency), pathvalidate, os.path.commonpath, ntpath.isreserved (3.13).

N4 AST tripwire needs exact node patterns and a seeded bad fixture. N5 tests/test_k1b_cli.py:207 monkeypatches atomic.atomic_write and needs the new signature; list all tests calling atomic_write/_read_json.
