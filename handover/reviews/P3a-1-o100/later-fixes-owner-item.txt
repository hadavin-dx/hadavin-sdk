OWNER item (GitHub setting, only the repository owner can change it; builders must not): two branches that each add a migration with the same next number (for example both add 0006) are each green alone, and the duplicate appears only after the second one merges. To stop this, turn on the branch protection setting "Require branches to be up to date before merging" for main, or use a merge queue. Until then, the lead checks the migration numbers by hand before each merge of a PR that adds a file under store/migrations/ (check_migration_numbers runs in the test suite on the merge result only if the branch is current).
