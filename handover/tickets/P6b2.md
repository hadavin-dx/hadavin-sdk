## Words used in this ticket (one meaning each)
- **environment read**: code that reads, writes, lists or tests for the process environment variables, or that starts a process or native call that can do so. The closed list is item L1 of field "Interface".
- **secrets kind**: the `secrets` capability in `TABLE` (`backends/table.py:387`), and the modules its factories name.
- **secret holder**: a module that holds a secret provider or the executor. Today that is the set `SECRET_HOLDERS` in `tests/test_repo_rules.py:131-142`.
- **wiring**: code that builds backends from a config and hands each factory a bound `resolve`. Today: `app.py`, `backends/factory.py`, `backends/platform_secrets.py`, `backends/builtin.py`, `cli.py` and `k1b/audit_sink.py` (fact 3).
- **ambient identity** (also called "workload identity"): a cloud SDK signs in with whatever its default chain finds, and our code passes it no credential. The chain looks at environment variables first, then files, then the machine's attached role (this order is from memory: UNVERIFIED). Examples: the AWS default chain, Azure `DefaultAzureCredential` and Google Application Default Credentials.
- **ambient-credential variable**: one of the six environment variables in N2. Each one can make a cloud SDK sign in as someone other than the machine's attached role.
- **identity** of a kind: the kind of principal it acts as toward an outside system. It is one or more words from a closed list of six (field "Interface", item K). **Rights** (the operations a kind needs) are not declared in v1; they are v1.1 row V3 (order 22 item 25).
- **operator folder**: a config folder used only by the operator's commands (`migrate`, `limits reset`, `limits check`). In pilot and prod it is separate from the runtime config folder (N11).

## Decisions taken in this ticket
- **D1 Ambient identity is pinned, and refused in pilot and prod when a credential variable is present** (N2, order 22 item 25). The lint checks three things:
  - every explicit-key SDK constructor passes `api_key=` that is not the literal `None`;
  - every ambient-identity constructor sits at one of the 13 pinned sites, each tied to its (capability, kind) with a reason;
  - a new, moved or stale site fails.
  It does NOT rewrite the 13 sites to a narrower credential class (V1).
  - N2 refuses pilot and prod start-up when any of the six variables is present, **whatever kinds the config names**.
  - Still open, in plain words: **credential FILES (a shared AWS credentials file, a developer's cloud login) are not checked.** So a pilot or prod machine with such a file can still sign a cloud SDK in as that person. That is V1.
