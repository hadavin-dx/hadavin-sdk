## Words used in this ticket (defined once)
- **provider**: the company whose model Hadavin calls (Claude API, Amazon Bedrock, an OpenAI-shaped server, Gemini). **Provider text**: any string a provider (or a library reading its reply) produced: an error message, an error body, a status line phrase, a header value, an error code string. It can quote the request, so it can hold personal data, a document line or part of a key.
- **fact**: one small checked value about a failure: a number in a fixed range, a word from a fixed list, or a short token of a fixed shape. A fact is never free text.
- **closed list**: a list fixed in our source code; a value outside the list is replaced by `other` or dropped, never copied. **Shape check**: a whole-string pattern check (`re.fullmatch`) that rejects anything else, including a trailing newline.
- **adapter** (the plan calls it a "per-kind hook"): a small function that reads one failed call's exception object and returns the facts. One per kind that has its own error library (Claude library, Amazon library); every other kind uses the neutral one that knows only the Python standard library.
- **attempt**: one request sent to the provider. `max_attempts` is the setting (1 to 10, `backends/table.py:40`).
- **hostile**: chosen by someone who wants to put text, numbers or size where our code does not expect them: a provider, a server in the middle, or a misconfigured gateway.

## Problem in plain words
When a call to a model provider fails, our retry code builds an error message that includes text taken from the provider's side: for Amazon Bedrock the error code string (`llm/bedrock.py:88-101`), for every kind the class name of whatever the library raised. Today the error also carries no machine-readable facts, so a person looking at a failed run cannot tell "wrong key" from "rate limited" from "provider down" without the message text, and the redesign (design-v3 section 1) forbids printing provider text at all because an error body can quote the request (a document line, a name, part of a key). R1P gives the error object a few checked facts (HTTP status, a word from a fixed list for the kind of error, a request id of a fixed shape, whether it was retried, and which attempt failed) and builds the message only from those. The diagnostic module from P5a (R1) already exists when this package starts; without these facts it can only say "the provider failed". After this package the message and the stored text of every provider failure hold nothing a provider typed, and a hostile reply (injected text, a wrong-sized number, a huge body, an object that raises) cannot put text or numbers into them.

### From facts to the closed code (the "which code" table; D4)
The code is chosen when the error is diagnosed (P5a `diagnose`); who writes the function is PENDING P5a (item 10). This is the table this ticket pins end to end; the code names are P5a's (`provider_http, provider_timeout, provider_rate_limit, provider_invalid_request, provider_auth, provider_exhausted`).
1. Class `ProviderExhausted` -> `provider_exhausted` always. The facts (`http_status`, `provider_error_type`, `request_id`, `retry_count`) still show.
2. Plain `ProviderError`: by status first: 429 -> `provider_rate_limit`; 401, 403 -> `provider_auth`; 400, 404, 422 -> `provider_invalid_request`. Status absent or not in that list -> by error_type: `rate_limit`, `throttled`, `quota` -> `provider_rate_limit`; `authentication`, `permission` -> `provider_auth`; `invalid_request`, `not_found` -> `provider_invalid_request`; `timeout` -> `provider_timeout`; `overloaded`, `server_error`, `connection`, `other` -> `provider_http`. Nothing known -> `provider_http`.
3. A failure to understand a 200 reply (missing key, bad JSON, `ValueError` from the Gemini parser) is a plain `ProviderError` with no status and no error_type -> `provider_http`.

## Retry interplay
- The retry decision (`transient`), the wait (jitter, `retry_after`), the number of requests, and which class is raised are IDENTICAL to ce70eb5 for every input. Pinned by a table of (kind, status or failure) -> request count that PASSES on ce70eb5 (regression pins).
- Facts are read once per RAISED error (the last failing exception), not per attempt, so a retried failure costs nothing extra. `retry_count` is the attempt number at which the error was raised: 1 for an immediate refusal, `max_attempts` for exhaustion, 2 when attempt 1 was retried and attempt 2 was refused. `retryable` is the answer of `transient()` for that last exception (True for exhaustion, False otherwise).
- A hostile status (outside 100 to 599, not an `int`, a `bool`) is NOT copied as a fact and NOT printed, but the retry rule is not changed: ce70eb5 retries any `int` status of 500 or more (`retry.py:39-40`; the stdlib experiment shows a real server can make `urllib` produce status 777). I did not make it "no retry" because that would turn a today-"exhausted" (billed at the worst case by `askdata/pipeline.py:163`) into a "refused, free" error: a money change that belongs to P4b2 (PENDING LEAD item 9).
- `with_retry` still re-raises `ProviderError` from `call` untouched (P4a's "refuse an estimate" error and any later billing marks pass through with their own attributes).
- Money interplay (for P4a and P4b2): `retry_count` and `retryable` describe the retry layer only. PR #48's `attempts` (requests sent) is a different, billing-grade number that P4b2 will define; when it arrives `retry_count` should be derived from it or the two checked for agreement (one source). This ticket makes no claim that a failed call was or was not billed.

## Fail-closed behaviour (each item has a test row)
1. A fact that fails its check is dropped (`None`); a string that is not in a closed list is `other` or dropped. Nothing provider-typed is ever copied, truncated and kept.
2. The adapter can raise nothing: `safe_attr`, `safe_facts` and exact-type checks (`type(x) is dict`, `type(x) is str`) mean a subclass of `dict` or `str` that overrides `get`, `__eq__`, `__hash__`, `__len__` or `__iter__` cannot choose the error type or make us loop.
3. If the adapter itself fails, the error is STILL raised as before (`ProviderError` or `ProviderExhausted`) with no facts; the diagnosis then says `provider_http` (or `provider_exhausted`) with no extra facts. Never silence, never a generic crash.
4. `KeyboardInterrupt` and `SystemExit` from an adapter propagate (they are not `Exception`).
5. A missing optional library (Google auth for Vertex) never raises `ImportError` inside `facts` (same lazy import pattern as `anthropic.retryable`).
6. The message of our error is built from a fixed grammar (tested), so even a future adapter bug cannot put text into it.
7. A kind that forgets to set `facts` gets the neutral adapter, not "no facts and a raw message".

## Security and least-privilege notes (identity, rights, secrets, personal data, dev-only flag)
- No new identity, role, grant, secret, kind or setting. The adapters read only the exception object; they receive no key, no prompt, no document. No `dev_only` flag (no kind added).
- Personal data: provider text is zone T2 of design section 1 (never printed). The allow-list table above is the enforcement; the attribute tripwire (R4) and the message grammar (R6) prove it; the source guard (R7) keeps it from regressing inside `llm/` until P5b3's full taint guard exists.
- Hostile values: numbers are bounded; tokens have a shape; words come from closed lists; types are exact; objects are read through `safe_attr`; the work per failure is constant (no loop over body, headers or message text; the only loop is `_chain`, 8 deep, existing).
- Request ids are logged-grade identifiers (a provider support reference), not secrets; they are shape-checked because a hostile provider could otherwise put chosen text there.
- Wording rule: no new operator-facing text beyond the existing message grammar; labels stay the existing kind names.
- State and races: no database, no multi-row SQL, no lock order. Adapters and the checks are pure functions of one exception object; `NetworkLLM` keeps no new state, so there is no race test (the retry loop is per call, as today).
