## Words used in this ticket (defined once)
- **provider**: the company whose model Hadavin calls (Claude API, Amazon Bedrock, an OpenAI-shaped server, Gemini). **Provider text**: any string a provider, or a library reading its reply, produced: an error message, an error body, a status-line phrase, a header value, an error code string. It can quote the request, so it can hold personal data, a document line or part of a key.
- **fact**: one small checked value about a failure: a number in a fixed range, a word from a fixed list, or a short token of a fixed shape. A fact is never free text.
- **closed list**: a list fixed in our source code. A value outside it becomes `other` or is dropped, never copied. **Shape check**: a whole-string pattern check (`re.fullmatch`) that rejects anything else, including a trailing newline.
- **adapter** (the plan calls it a "per-kind hook"): a small function that reads one failed call's exception object and returns the facts. There is one per kind that has its own error library (the Claude library, the Amazon library); every other kind uses the neutral adapter, which knows only the Python standard library.
- **attempt**: one request sent to the provider. `max_attempts` is the setting (1 to 10, `backends/table.py:40`).
- **retry decision**: the code that says whether a failed attempt is tried again (`transient` and the kind's `retryable` hook). A **decision failure** is an exception raised inside that code.
- **hostile**: chosen by someone who wants to put text, numbers or size where our code does not expect them: a provider, a server in the middle, or a misconfigured gateway.
- **step R1P**: the second step of the diagnostics redesign. P5a is step R1 (the closed codes and the safe text). This package is step R1P, the provider part: it writes the facts AND the code that reads them in `diagnose`.
- **read-recorder test**: a test where a stand-in error object writes down the name of every attribute our adapter reads, and the test compares that list with the allowed list.
- **mutant**: a deliberate small break of the new code (for example, delete one check). The tests must fail on it. **Stand-in**: an object built by the test instead of one produced by a real library or wire. Every stand-in is named in the tables.
- **strict expected failure** (`xfail(strict=True, raises=AssertionError)`): a test known to fail today for a named reason. It must fail with an `AssertionError`; it turns into a build failure the day it passes, or when it fails for any other reason.
- **billed class**: `ProviderExhausted`. `askdata/pipeline.py:163` books the reserved worst case for it; a plain `ProviderError` is released there ("refused, free").

- **Problem in plain words:** When a call to a model provider fails, our retry code builds the error message from text on the provider's side: the Amazon error code string (`llm/bedrock.py:101`) and the class name of whatever the library raised (`retry.py:79`). An Amazon error's class name IS the provider's error code. The error also carries no machine-readable facts, so nobody can tell "wrong key" from "rate limited" from "provider down" without reading that text, and the redesign forbids printing it, because an error body can quote the request (a document line, a name, part of a key). This package gives the error a few checked facts (HTTP status, a word from a fixed list, a request id of a fixed shape, whether it was retried, which attempt failed) and builds the message only from those and from P5a's sanctioned class text. It also teaches P5a's `diagnose` to read those facts and choose the provider codes, so a hostile reply cannot put text or numbers into the message, the stored text or the diagnosis.

## Retry interplay
- The retry decision, the wait (jitter, `retry_after`), the number of requests and which class is raised are IDENTICAL to ce70eb5 for every input that does not make the decision raise. Pinned by R2, which passes on ce70eb5.
- **Inputs whose outcome changes (stated plainly).** On ce70eb5 each of the following lets a raw Python exception escape `with_retry` after the request was sent. The callers catch only `ProviderError`, and the pipeline keeps the reservation booked.
  - (1) A `status_code` or `code` property that raises.
  - (2) A `reason`, `__cause__` or `__context__` property that raises, or an `__eq__` that raises, inside `_chain` (line 49 `in`).
  - (3) A kind `retryable` hook that raises.
  - (4) A Bedrock `ClientError` whose `response` is not a dict (`retryable` at :108), whose `Error` is not a dict (`_code` at :90), or whose `ResponseMetadata` is not a dict.
  
  After this package, (1)-(4) are decision failures. They raise `ProviderExhausted`, not retried, with `retryable=None`, `retry_count` = the attempt, and a message ending ` after <attempt> attempts`. Booking: ce70eb5 kept the reservation through the raw escape; the new code keeps it through `run.cost += worst` (`pipeline.py:165`). The upper bound is booked both before and after (R20).
  
  (5) A `headers` lookup that raises something other than the three caught errors (`retry_after`): the wait is 0 seconds and the class is unchanged.
- **Adapter failures change nothing.** If `facts` raises or returns the wrong type, `safe_facts` gives `NO_FACTS`; the decision was already made, so the class is the one the decision chose.
- **The decision and the facts read `status_code` separately** (finding R2-ADV-9). For an attribute whose value changes between reads (a property returning 503, then 401), they may disagree. The guarantee is only this: the grammar holds, nothing escapes raw, and the attributes are checked values (R5 case). Reading once is not designed here (cut).
- Facts are read once per RAISED error (the last failing exception), so a retried failure costs nothing extra. `retry_count` is the attempt number at which the error was raised: 1 for an immediate refusal, `max_attempts` for exhaustion, 2 for row 29, and the current attempt for a decision failure. `retryable` is `transient`'s answer for that exception (True, False, or None for a decision failure).
- **A hostile status** (outside 100 to 599, not an `int`, a `bool`) is NOT copied as a fact and NOT printed, and the retry rule is not changed: ce70eb5 retries any `int` status of 500 or more, so 777 is retried and ends as `ProviderExhausted` (rows 30 and R11(a)). P4b2 revision 4 classifies 777 as "unknown, kept" (`P4b2.md:52`, `:127`), so the 777 half of the old PENDING LEAD 10 is closed. What is still open is a success-body size cap: P4b2 has none (`grep` for a cap, `N+1` or `_MAX_RESPONSE` in `P4b2.md` finds nothing; PENDING LEAD 10).
- `with_retry` still re-raises a `ProviderError` from `call` untouched: P4a's `UsageMissing`, `UnpricedUsage` and any later billing marks pass through with their own attributes.

## Fail-closed behaviour (each item has a test row)
1. A fact that fails its check is dropped; a string not in a closed list becomes `other` or is dropped. Nothing provider-typed is copied, truncated and kept (R3, R5, R18, R19).
2. Nothing in the failure path raises out of `with_retry` except `ProviderError` and `ProviderExhausted` (and `KeyboardInterrupt`/`SystemExit`). That includes the decision (one guard, R5), the adapters (`safe_facts`, R5) and the wait (`retry_after`, R10). Exact-type checks in the adapters (`type(x) is dict`, `type(x) is str`) mean a subclass of `dict` or `str` cannot choose a FACT. It can still steer a ce70eb5 RETRY decision exactly as it does today; that decision is not changed by design.
3. If an adapter fails, the error is STILL raised, with no facts; the diagnosis says `provider_http` or `provider_exhausted` (R5).
4. `KeyboardInterrupt` and `SystemExit` from an adapter, a hook or a property propagate (they are not `Exception`).
5. A missing optional library (Google auth for Vertex) never raises `ImportError` inside `facts` (the same lazy import as `anthropic.retryable`).
6. The message comes from a fixed grammar (R6), so a later adapter bug cannot put text into it.
7. A kind that forgets to set `facts` gets the neutral adapter.
8. The reader in `diagnose` re-validates every attribute on its own (R18), because unpickling and plain assignment both bypass the constructor.

## Security and least-privilege notes (identity, rights, secrets, personal data, dev-only flag)
- No new identity, role, grant, secret, kind or setting. The adapters read only the exception object; they receive no key, no prompt and no document. No `dev_only` flag.
- Personal data: provider text is never printed. The allow-list table is the enforcement. R4 (read recorder) and R6 (grammar) prove it, and R7 keeps it from regressing inside `llm/` until P5b3's full guard exists.
- Hostile values: numbers are bounded (`FACT_BOUNDS`); tokens have closed shapes; words come from closed lists; types are exact; the work per failure is constant (no loop over body, headers or message; the only loop is `_chain`, 8 deep, existing).
- Request ids are support references, not secrets; they are shape-checked because a hostile provider could otherwise put chosen text there.
- State and races: no database, no lock order. The adapters and checks are pure functions of one exception object; `NetworkLLM` keeps no new state, so there is no race test.
