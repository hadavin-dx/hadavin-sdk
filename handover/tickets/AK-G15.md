## Words used (plain meaning, one meaning each)

- **item**: one row in the queue that says "a person must look at this". It holds ids, a closed reason code, the people who may see it, its state and times. It NEVER holds message text, a body, a user id or an exception text.
- **subject**: the thing an item points to. Two kinds in v1: a **chat** subject (a conversation and the run of the exchange that was handed off, AK-G1) and an **inbound** subject (one received message at one generation, AK-G2).
- **queue reader**: a person (a principal of kind `person` in `principals.yaml`) listed in config as allowed to see the items of one tenant. Not the same as AK1's `readers` of a document; the item's `readers` field holds queue readers.
- **claim**: a person takes an item for a limited time (the **lease**). While the lease is live, nobody else can claim it. **Assign**: a person with the `assign` role claims an item on behalf of another queue reader. **Release**: the holder hands the item back unfinished.
- **close**: the holder ends the item with one **outcome** from a closed set. `closed` is the item's ONLY final state. A closed item never changes again.
- **reopen an item**: make a NEW item, round + 1, for the same subject, linked to the closed one. The closed item stays closed. This is NOT AK-G2's "reopen" of a receipt; to avoid one word with two meanings, this ticket calls AK-G2's action **re-run a message** (outcome `rerun`, which calls AK-G2's `reopen_inbound`).
- **binding (content binding)**: a SHA-256 digest of the item's ids (never of text). A person who acts must send the binding of the item they saw, so an action can never land on another item or another round.
- **version**: a counter on the item that every write raises by exactly 1. Every write is a compare-and-set on it (the lease token rule of order 38 item 85 and order 39).
- **age**: now minus the time the item was opened. **Service time**: the time from opened to closed. The **service-time limit** (`queue.service_time_days`) is the number the client contract sets; it must be shorter than `retention.conversations_days` (`contract-terms-notes.md` item 1; order 39 item 2).
- **queue worker identity**: a NEW database role and connection used only by the code that acts for persons (claim, release, close, reopen, re-run). The agent runtime never holds it.
- **erased**: the subject's content was deleted by retention or by `forget_user` (owner rule R98). The item stays, holding ids only, and shows `subject_erased`.
- **pilot/prod**: a config whose `environment` is `pilot` or `prod`.
- Row ids: Q = queue core (AK-G15-a), N = inbound side (AK-G15-b), W = wiring (AK-G15-c), V = later rows; mutants M-a, M-b, M-c by sub-PR. INFORM decisions are I1-I11 (no test row uses the letter I).

## The decision that shapes this ticket (INFORM I1, recommended; read before the fields)

Options for "durable queue of needs-a-person items" (options first, BRIEF-PREAMBLE rule 16):
- (a) **Recommended: our own store-backed queue** behind a small interface (`NeedsPersonQueue`), one table in the existing store (Postgres in pilot and prod, memory in tests), ids only, compare-and-set on every write, one final state, a lease, audit on every person action. It is the neutral, self-hostable default (it runs wherever the store runs). Tool ladder rung 7 (our own code): it decides who may act, binds the action to what the person saw, and can start a second paid run, so it is "the brain" (approval binding, audit, money) and stays in our tested code.
- (b) **The client's own ticketing or help-desk tool** (rung 2). Written outline, NOT built (row V1): a mirror adapter that copies each item to the client's tool as an ids-only ticket with a link, and copies "closed" back through AK-G2's signed door. Our table stays the record of state, because the client's tool cannot give our guarantees by itself: compare-and-set on a version, one final state that never changes, dedupe on the idempotency key, no text in the item, and erasure of the content without losing the item. **Trigger:** "a client already runs a ticketing or help-desk tool and chooses it in writing, after the options were shown in the quote". Cost and risk in plain words: the tool sees ids and links (not text); if the tool breaks or changes price, items still exist in our table; the quote and the contract's tool schedule say who carries that risk (options-first rule).
- (c) A workflow engine or a vendor queue service as the queue itself: rejected for the core (a new dependency for what one table and the tick already do; the same guarantee gap as (b)). Kept as the written alternative under the trigger of (b).

Why (a): it closes the BLOCKER (GAPS G15) for both consumers that exist on paper (AK-G1 hand-offs, AK-G2 waiting messages) with one table, adds no vendor, and is what the mirror of (b) would sit on. Confidence 80 percent; reversible (the interface lets a mirror be added without touching callers).

- **Interface (names, argument and return types, errors):**
  1. **Item record (-a, `models.py`).** `NeedsPersonItem(Shape)`:
     - `tenant: str` (AK1 `TENANT_PATTERN`); `item_id: str = new_id("itm")` (`itm-` plus 32 hex); `kind: Literal["chat", "inbound"]`; `idempotency_key: str` (1-600 characters; rules below); `round: int = 0` (0 to `defaults.QUEUE_MAX_ROUNDS` = 20); `reopens: str | None` (the closed item this one reopens).
     - Subject ids: `conversation_id: str | None` (chat: `conv-[0-9a-f]{32}`); `run_id: str | None` (chat: the exchange's run; inbound: the receipt's `run_id` at this generation; pattern `run-[0-9a-f]{32}`); `source: str | None`, `delivery_key: str | None` (64 hex), `generation: int | None` (inbound only). A CHECK and the record's validator require exactly the fields of its kind and `None` for the other kind's fields.
     - `reason: str`: chat: `CHAT_REASONS` = AK-G1's `HANDOFF_STOPS` plus `interrupted`; inbound: `INBOUND_ITEM_REASONS` = AK-G2's `needs_person` reasons (`low_quality`, `unreadable`, `over_budget`, `meter_unavailable`, `masking_refused`, `outbound_refused`, `policy`, `attempts_exhausted`, `body_missing`, `run_interrupted`, `run_limits`, `run_mismatch`, `run_needs_person`); a reopened item: `reopened`. Constants in `queue/items.py`, copied from the frozen tickets; a test pins each set against the built constant of the other package once it exists (rows Q3, N1).
     - `readers: frozenset[str]` (AK1 `Readers`; queue readers of the tenant at open time); `binding: str` (64 hex).
     - `state: Literal["open", "claimed", "closed"]`; `assignee: str | None`; `lease_until: datetime | None`; `version: int = 0`.
     - `outcome: Literal["answered", "no_action", "rerun"] | None` (set only on close); `closed_by: str | None`.
     - Times, all from the injected clock, never the database clock: `opened_at`, `first_claimed_at: datetime | None`, `closed_at: datetime | None`, `updated_at`.
     - Allowed outcomes per kind: chat `{"answered", "no_action"}`; inbound `{"answered", "no_action", "rerun"}`. `answered` = "a person dealt with it outside the agent"; `no_action` = "looked, nothing to do"; `rerun` = "start the message again" (inbound only, money).
     - **Idempotency keys.** chat: exactly `HandoffRequest.idempotency_key`, which must equal its `run_id` (AK-G1 contract). inbound: `tenant_key(tenant, source, delivery_key, str(generation))`. reopened: `tenant_key(tenant, "reopen", <closed item_id>)`. A chat key starts with `run-` and the others with `t` (the `tenant_key` format, `tickets/AK1.md:110`), so the three kinds can never collide. Unique on `(tenant, idempotency_key)`.
  2. **Binding (-a, `queue/items.py`).** `binding(item) = models.sha256_hex({"v": 1, "tenant": ..., "kind": ..., "idempotency_key": ..., "round": ..., "conversation_id": ..., "run_id": ..., "source": ..., "delivery_key": ..., "generation": ...})`. Ids only; no text, no reader list, no person. Computed once at open and stored; the trigger refuses a change. Every person action passes `binding` and `expect_version`; a mismatch of either is refused before any write.
  3. **Queue roles on people (-a, `identity.py`, `registry.py`).** `Principal.queue: frozenset[Literal["work", "assign", "rerun"]] = frozenset()`. Load rules (`ConfigError` naming the principal): only `kind == "person"` may have any queue role; a principal id starting with `chat:` or `trigger:` may have none (those are the runtime's own principals, AK-G1 `:213`, AK-G2 BN-1); `assign` and `rerun` require `work`. Rights for actions (`rights`) are untouched.
  4. **Store methods (-a: 1-9; -b: 10-11; protocol, memory, Postgres).**
     1. `open_queue_item(item: NeedsPersonItem) -> tuple[str, bool]`: one transaction; insert, or on a conflict on `(tenant, idempotency_key)` insert nothing; return `(item_id of the row that holds the key, created)`. Postgres: `SET LOCAL statement_timeout = defaults.QUEUE_OPEN_TIMEOUT_MS` (10000) first, so the hook stays inside AK-G1's 30 s. Runtime role.
     2. `get_queue_item(tenant, item_id) -> NeedsPersonItem | None`.
     3. `list_queue_items(tenant, *, reader: str, states: frozenset[str], limit: int, after: tuple[datetime, str] | None) -> list[NeedsPersonItem]`: only rows whose `readers` contain `reader` (in the SQL `WHERE`), oldest `opened_at` first, then `item_id`; `limit` 1 to 500; `after` is the keyset cursor.
     4. `claim_queue_item(tenant, item_id, *, assignee, expect_version, binding, now, lease_s) -> NeedsPersonItem`: compare-and-set `WHERE version = expect_version AND binding = %s AND (state = 'open' OR (state = 'claimed' AND (lease_until < now OR assignee = %s)))`; sets `state = 'claimed'`, `assignee`, `lease_until = now + lease_s`, `first_claimed_at` if null, `version + 1`. The same person claiming again renews the lease. 0 rows: `StaleState`.
     5. `release_queue_item(tenant, item_id, *, assignee, expect_version, now) -> NeedsPersonItem`: `claimed` by that assignee with `lease_until >= now` -> `open`; clears `assignee` and `lease_until`; `version + 1`.
     6. `close_queue_item(tenant, item_id, *, assignee, expect_version, binding, outcome, now, rerun: bool = False) -> NeedsPersonItem`: `claimed` by that assignee with a live lease (`lease_until >= now`), version and binding equal; sets `closed`, `outcome`, `closed_by = assignee`, `closed_at`, `version + 1`. With `rerun` (only from -b; -a refuses `rerun=True` with `ValueError`), the SAME transaction also runs AK-G2's `reopen_inbound` update for the item's receipt, with the extra condition `generation = item.generation`; if that update changes 0 rows, the whole transaction rolls back and `StaleState` is raised (nothing changed).
     7. `reopen_queue_item(tenant, closed_item_id, *, new: NeedsPersonItem) -> tuple[str, bool]`: the closed item must exist and be `closed`, `new.round == closed.round + 1 <= QUEUE_MAX_ROUNDS`, `new.reopens == closed_item_id`, the same subject ids; insert with the reopen key; a second reopen of the same closed item returns the existing new item (`created = False`). Worker role.
     8. `queue_stats(tenant, now, service_time: timedelta) -> QueueStats`: `QueueStats(open: int, claimed: int, oldest_age_s: float | None, over_service_time: int, closed_30d: int, closed_30d_over_service_time: int)`. "Over" means `opened_at < now - service_time` and not closed; a closed item is over when `closed_at - opened_at > service_time`. Exactly the limit is NOT over. Runtime role (it reads only `tenant`, `state`, `opened_at`, `closed_at`).
     9. `queue_subject_present(tenant, item) -> bool`: chat: the `conversations` row with that `tenant` and `conversation_id` exists (reads those two columns only); inbound (-b): the `inbound_bodies` row with that key exists (reads key columns only, never `body`).
     10. (-b) `list_inbound(tenant, source, states: frozenset[str], since: datetime, limit: int) -> list[InboundReceipt]`: receipts with `received_at >= since`, oldest first, `limit` 1 to 1000. Backs `compare_ids` (moved from AK-G2 BN-14).
     11. (-b) `collect_inbound_items(now, readers_by_tenant: Mapping[str, frozenset[str]], limit: int) -> tuple[int, int]`: in one statement per batch, for every receipt in `needs_person` that is not an id-reuse row (`reuse_of IS NULL`) and has no item with its inbound key, insert an item (`reason` = the receipt's reason, `readers` = that tenant's queue readers, binding computed in the statement's caller from the selected ids); returns `(created, uncollected)`, where `uncollected` counts waiting receipts whose tenant has no queue readers in config (they get no item and the tick fails loudly, Interface 7). This and `list_inbound_sources` (AK-G2) are the only cross-tenant reads; it writes each item with its receipt's own tenant. Runtime role.
     Postgres shape: explicit SQL, not `_row`; `readers` as a sorted `list[str]` into `text[]`, rebuilt as a `frozenset` on read (AK-G2 BN-20 lesson); a `schema_version` column (`Shape`).

     - `NeedsPersonQueue(Protocol)`: `open_handoff`, `open_item`, `get`, `list`, `claim`, `release`, `close`, `reopen`, `stats`. Default implementation `StoreQueue`.
     - `StoreQueue(runtime_store, worker_store, audit, clock, registry, readers_by_tenant: Mapping[str, frozenset[str]], lease_s: int)`. `runtime_store` is used ONLY by `open_handoff`, `open_item` and `stats`; every person action uses `worker_store` (the queue worker identity). In tests both may be the same memory store.
     - `open_handoff(req: HandoffRequest) -> str` (AK-G1's hook, exact signature): validates `req` (tenant pattern; `conversation_id` `conv-[0-9a-f]{32}`; `run_id` `run-[0-9a-f]{32}`; `idempotency_key == run_id`; `reason in CHAT_REASONS`; every field `type(x) is str`), else `ValueError` naming the field, not the value; no queue readers for the tenant raises `QueueRefused("not_configured")` (AK-G1 then ends the run `handoff_unavailable` and the sweep retries, which also fails the sweep step loudly, design `:321`); builds the item, `open_queue_item`; when `created`, one `write_outcome` audit event `domain="queue"`, `operation="opened"`, `principal="queue"`, `source="queue"`, `object_ref=tenant_key(tenant, item_id)`, `inputs_hash=binding`, `result=reason`, `run_id=req.run_id`; returns the item id (the existing one on a repeat). It logs nothing at INFO or above except on an error (ids and class name).
     - Person actions, each `(..., person: str, ...)` where `person` is the authenticated person the CALLER (the screen, G14) names; AK-G15 does not log anyone in (owner-visible limit 16): `claim(tenant, item_id, person, *, expect_version, binding, on_behalf_of: str | None = None)`, `release(tenant, item_id, person, *, expect_version)`, `close(tenant, item_id, person, *, expect_version, binding, outcome, acknowledge_outcome_unknown: bool = False)`, `reopen(tenant, item_id, person, *, reason_code: Literal["more_work", "closed_by_mistake"])`, `list(tenant, person, *, states, limit, after)`, `get(tenant, item_id, person)`.
     - Checks, in this order, before any write: (1) `person` is a registry principal of kind `person` with queue role `work` (else `no_right`); (2) the item exists in that tenant AND `person` is in its `readers` (else `not_found`: one answer for both, so a person cannot learn that another tenant's item exists); (3) for `on_behalf_of`: `person` has `assign`, and the assignee has `work` and is in `readers` (else `no_right`); (4) for `close(..., outcome="rerun")`: `person` has `rerun`, the item's kind is `inbound` (else `bad_outcome`), `queue_subject_present` is true (else `subject_erased`), and when the receipt's current run is `NEEDS_PERSON` with reason `outcome_unknown` the call must pass `acknowledge_outcome_unknown=True` (else `outcome_unknown_not_acknowledged`; AK-G2 BN-7 coupling); (5) for `reopen`: the item is `closed` (else `not_closed`), its round is below 20 (else `round_limit`), and `queue_subject_present` is true (else `subject_erased`).
     - Then `audit.write_intent(AuditEvent(domain="queue", operation=<claim|release|close|reopen>, principal=person, source="queue", object_ref=tenant_key(tenant, item_id), inputs_hash=binding, decision=<outcome or None>, run_id=<the item's run_id>))`; `AuditUnavailable` refuses the action with `audit_unavailable` and changes nothing. Then the store compare-and-set; `StaleState` becomes `QueueRefused("stale")` (claim of a live lease held by another person, a wrong version or binding, a lost lease on close, a re-run whose receipt moved or whose run is still open). Then `write_outcome` with `result` = `done` or the refusal code.
     - `reopen` builds the new item (same subject ids, `round + 1`, `reopens`, `reason="reopened"`, `readers` = the tenant's CURRENT queue readers, new binding) and calls `reopen_queue_item`. It never re-runs anything.
     - `stats(tenant, now) -> QueueStats` over `runtime_store`.
     - `QueueRefused(code)`: ONE new exception class in `queue/items.py`, not derived from `ValueError` (the P1 rule, A13 (4)); `code` in the closed set `not_found`, `no_right`, `stale`, `bad_outcome`, `subject_erased`, `outcome_unknown_not_acknowledged`, `not_closed`, `round_limit`, `not_configured`, `audit_unavailable`; its message holds the code and ids only.

## Owner-visible limits (proposed; for `owner-visible-limits.md`, numbering after entry 12)
- **13. Nobody is told when a new item arrives.** The program keeps the item and fails its regular check loudly only when an item waits longer than the agreed service time. Before the pilot, the client names who looks at the queue and how often.
- **14. Until the approvals screen exists, a person can act on an item only through code the studio runs.**
- **15. A re-run of a message can cost money again,** and for a message whose earlier run may already have acted outside, it can propose the same action again; the approval step still applies, and the person must confirm that they saw this warning.
- **16. The queue trusts the person the screen names.** It does not log anyone in; the screen must check who the person is. Whoever holds the queue's database password can act as any queue person.
- **17. An item can point at content that was already deleted** (by the retention time or by a request to forget a person). The person then sees "content erased" and can only close the item.
- **18. Closed items are kept for ever in this version.** They hold ids, reason codes, times and the staff names of who handled them, no message text.
- **19. The check that a person sees only their own tenants' items is done by our code, not by the database itself.**
