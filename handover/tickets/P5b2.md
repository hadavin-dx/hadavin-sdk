- **Problem in plain words:** When the SDK refuses to start it raises `ConfigError` with a text the operator reads on the screen and that is stored as the last error. Some of those texts are written only by us ("backend llm is not configured"), some add a value the operator typed (a secret name, a file path), and a few paste in text that came from a library or from an exception, which can carry document or personal data (for example a validation error that quotes the bad value). The frozen design says: do not rewrite all of them, classify each place once, and change only the risky ones (P5b3). Today there is no list of these places and nothing stops a new risky one from being added. P5b2 makes the list, makes a script that rebuilds it from the code, and adds a test that fails when the code and the list disagree or when a human has not decided a new place.

- **Interface (names, argument and return types, errors):**
  - **CSV `tests/data/config_error_sites.csv`:** UTF-8, ASCII only, `\n` line endings (the repo's `.gitattributes` has `* text=auto eol=lf`; the writer passes `newline=""` and `lineterminator="\n"` to the `csv` module), one header row, rows sorted by (`file`, `symbol`, `snippet_hash`, `site`). Columns, in order:
    1. `site`: `<file>::<symbol>::<snippet_hash>::<k>`. `file` is the path under `src/hadavin_sdk/` with `/`; `symbol` is the dotted name of the enclosing classes and functions (`Config.load`, `_check`) or `<module>`; `k` is 1, 2, ... for sites with identical text in the same symbol. **No line numbers anywhere in the file.** Reformatting, or moving code inside the same symbol, keeps the row; renaming the symbol, or moving the site to another function or file, makes the old row `stale` and the new one `unclassified`.
    2. `file`, 3. `symbol` (as above, repeated so the table can be sorted and filtered in a spreadsheet).
    4. `kind`: the CANONICAL class name, with an import alias or attribute form resolved (`CE` or `errors.ConfigError` is recorded as `ConfigError`): `ConfigError`, `BundleError`, `StoreUnavailable`, or any later subclass. For the call of a factory (rule C4) it is the class the factory builds. The hash (column 5) still uses the text as written.
    5. `snippet_hash`: first `HASH_LEN` (16) hex characters of sha256 over the construction's TOKENS. The hash input is the source text of the construction's own `Call` node (`ast.get_source_segment`), in any context (`raise`, `return`, an assignment, an argument), run through `tokenize`, comments and line breaks dropped, tokens joined by one space. A bare `raise A` has no call, so it hashes the tokens of `A`. The call of a factory (rule C4) hashes the factory call. Before hashing, every call to a name in `HASH_TRANSPARENT_CALLS` (rule C3) is replaced by its argument. It does not use `ast.dump`: Python 3.13 changed `ast.dump` output for empty fields, so a hash made on 3.13 could differ from 3.12 (CI uses 3.13; production pins one Python, F3). A cross-version byte-equality run is an evidence row.
    6. `auto_class`: what the script proved. `LITERAL` (first argument is a string constant, implicit concatenation of constants, or an f-string with no `{}` part, or no argument) or `FOREIGN` (anything else). 7. `auto_reason`: `constant`, `exception-variable` or `unproven-origin`. `exception-variable` = an interpolated or passed expression uses a name bound by `except ... as NAME` in an enclosing handler, or a local that is tainted by it. Taint propagation: any assignment (plain, augmented, annotated, or with a tuple target) whose right side mentions a tainted name taints its target, repeated to a fixed point inside one function (the same propagation as design section 8, simplified). So `fields = ", ".join(x for x in e.errors())` taints `fields`. For the call of a factory (rule C4) the test runs over the arguments bound to the parameters the factory interpolates; the check includes `str(e)`, `repr(e)`, `e.args[0]`, `type(e).__name__`, `e.__class__.__name__`, `"%s" % e`, `.format(e)`, f-string parts. Everything else non-literal is `unproven-origin`.
    8. `class`: the reviewed class, one of `LITERAL`, `OPERATOR` (interpolates a value an operator typed in configuration: key, path, secret name, bucket name, id; design T1), `FOREIGN` (interpolates an exception, text of a response or body, or model or document data; design T2). The words match D7. 9. `code`: filled only for `FOREIGN`: the NAME of the `Code` member P5b3 will pass as `summary_code` to `ConfigError.from_cause` (for example `config_invalid`). 10. `reason`: at most 200 ASCII characters, no newline, no personal data and no secret; required for every `OPERATOR` row, every row whose `class` differs from `auto_class`, and every `FOREIGN` row with `auto_reason=unproven-origin`.
  - **Locked rows (the rule that stops a wrong downgrade, and a wrong upgrade to LITERAL):** a row with `auto_reason=exception-variable` MUST have `class=FOREIGN`. The CI test refuses `OPERATOR` there whatever the reason text says. The LITERAL rule is two-way: `class=LITERAL` if and only if `auto_class=LITERAL`. So a human cannot mark a non-literal `unproven-origin` row `LITERAL`, whatever the reason text says. A blank `class` is always a failure.
  - **Generator `tools/gen_config_error_sites.py`** (standard library only: `ast`, `csv`, `hashlib`, `io`, `os`, `pathlib`, `sys`, `tokenize`, `dataclasses`, `argparse`; **it never imports `hadavin_sdk` or runs any repository code**, it only reads files). Named constants at the top, in one place: `PACKAGE_DIR = "src/hadavin_sdk"`, `CSV_PATH = "tests/data/config_error_sites.csv"`, `BASE_CLASS = "ConfigError"`, `HASH_LEN = 16`, `CLASSES = ("LITERAL", "OPERATOR", "FOREIGN")`, `COLUMNS`, `REASON_MAX = 200`, `HASH_TRANSPARENT_CALLS = ("t1",)` (the D2 wrapper; the final helper name is set here by P5b3, PENDING LEAD 9).
    - `scan(package_dir: Path) -> list[Site]`; `Site` is a frozen dataclass (`file`, `symbol`, `kind`, `snippet_hash`, `k`, `auto_class`, `auto_reason`, `lineno` (never written to the CSV, used only in messages and the review sheet), `origin_hints`). It reads only `*.py` files under `package_dir` (never `__pycache__`, never other file types, no symlink followed outside the tree), parses each with `ast.parse`, and finds (a) the set of classes that are `ConfigError` or derive from it, by name, repeated to a fixed point across all modules (`class Foo(ConfigError)`, `class Bar(Foo)`, a base written as `errors.ConfigError` or as an import alias `from .errors import ConfigError as CE`), (b) every `Call` whose function is such a name or an attribute ending in such a name, and (c) every `raise NAME` where the raised object is the bare class (no call; counts as a site with no arguments, `LITERAL`), and (d) factories (rule C4): every function that `return`s or `raise`s a site whose message interpolates one of the function's own parameters (today only `k1b/bundle.py::_fail`; it `return`s the error and its callers write `raise _fail(...)`). Each CALL of a factory, in any file, is recorded as a site of its own, with `kind` = the class the factory builds, and `auto_class` and `auto_reason` computed over the arguments bound to the interpolated parameters; on ce70eb5 all 29 `_fail` calls are `FOREIGN / unproven-origin` because `case` is a name. The factory's own construction stays a row. A factory that is itself called through another factory raises `SitesError` (fail closed; one level only). There is no hand-kept list of factory names. It does NOT count `ConfigError.from_cause(...)`: that call builds its text from a Diagnostic at raise time (design D7), so it is not a place where text is written (P5b3 may add a rule if it disagrees). **Fail closed:** a file that does not parse, is not valid UTF-8, or a package directory with no `*.py`, or a scan that does not find the class `ConfigError` defined, raises `SitesError` (exit code 2); a scan never skips a file.
    - `load_csv(path: Path) -> list[Row]` (`Row` is the CSV record): refuses (raises `SitesError`) a wrong header, a class not in `CLASSES`, a duplicate `site`, a non-ASCII byte, a `reason` over `REASON_MAX` or with a newline.
    - `compare(sites, rows) -> Report`; `Report` lists, each as sorted `site` strings: `unclassified` (in the code, not in the CSV), `stale` (in the CSV, not in the code), `blank_class`, `locked_downgrade`, `missing_reason`, `code_mismatch`, `wrong_literal`. These are seven lists. `code_mismatch` = a `FOREIGN` row with no `code`, OR a non-`FOREIGN` row with a `code`. `wrong_literal` = `class` is `LITERAL` XOR `auto_class` is `LITERAL` (either direction). `Report.ok` is true only when all are empty. Changing the text of a site changes its hash, so the old row is `stale` and the new one `unclassified`: that is the "hash changed without review" case, in one rule.
    - `write(package_dir, csv_path) -> None`: rebuilds the file: for each site whose `site` key already exists the human fields (`class`, `code`, `reason`) are kept; a new site with `auto_class=LITERAL` gets `class=LITERAL`; a new site with `auto_reason=exception-variable` gets `class=FOREIGN`; every other new site gets a **blank `class`** (so the test fails until a human fills it in); stale rows are dropped. The file is written in one call, with no temporary file and no `os.replace`: a half-written table already fails closed (a bad row raises `SitesError`; missing rows are reported `unclassified`), so no atomic-write claim is made. It writes only the path given by `--csv` (default `CSV_PATH` under `--root`); the path must end in `.csv`, otherwise `SitesError`. Tests give a temporary folder for both.
    - `main(argv) -> int`: `--check` (default; prints the report, exit 1 on any entry, 0 clean), `--write`, `--review` (prints the review sheet below to standard output, ASCII), `--root PATH`, `--csv PATH`. Command lines: `uv run --all-extras --group test python -m tools.gen_config_error_sites --check|--write|--review`.
    - `tainted_names(func: ast.AST) -> frozenset[str]` is public so P5b3's guard (D11) can reuse the same propagation instead of writing a second one (one source of truth). P5b2 does not require P5b3 to use it.
    - **Review sheet (`--review`):** one block per row whose `class` is blank or `OPERATOR`, grouped by file and symbol, showing: the site key, the line, the source text of the call, and for each interpolated expression an origin hint computed from the syntax tree (`param NAME of FUNC`, `local assigned from CALL`, `attribute CHAIN`, `module constant`, `loop variable`, `join of LIST`). The hint helps the human; it is not a proof and does not change the class.
