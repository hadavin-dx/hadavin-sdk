- **Problem in plain words:** When the SDK refuses to start, it raises `ConfigError` with a text. The operator reads that text on the screen, and it is stored as the last error. Some of those texts are written only by us ("backend llm is not configured"). Some add a value the operator typed (a secret name, a file path). A few paste in text that came from a library or from an exception, and that text can carry document or personal data (for example a validation error that quotes the bad value). The frozen design says: do not rewrite all of them; classify each place once, and change only the risky ones (P5b3). Today there is no list of these places, and nothing stops a new risky one from being added. P5b2 makes the list, makes a script that rebuilds it from the code, and adds a test that fails when the code and the list disagree or when a person has not decided a new place.

- **Interface (names, argument and return types, errors):**
  - **CSV `tests/data/config_error_sites.csv`:** UTF-8, ASCII only, `\n` line endings (the writer passes `newline=""` and `lineterminator="\n"` to the `csv` module), one header row, rows sorted by `site` as a plain string. **Three columns, in this order:**
    1. `site`: `<file>::<symbol>::<snippet_hash>::<k>`. `file` is the path under `src/hadavin_sdk/` with `/`. `symbol` is the dotted name of the enclosing classes and functions (`Config.load`, `_check`) or `<module>`. `snippet_hash` is `node_hash` of the construction (below). `k` is 1, 2, ... for identical constructions in the same symbol. **No line numbers anywhere in the file.** Reformatting, or moving code inside the same symbol, keeps the row. Renaming the symbol, or moving the site to another function or file, makes the old row `stale` and the new one `unclassified`.
    2. `class`: the reviewed class, one of `LITERAL`, `OPERATOR` (interpolates a value an operator typed in configuration: a key, path, secret name, bucket name or id; design T1), `FOREIGN` (interpolates an exception, the text of a response or body, or model or document data; design T2). The words match D7.
    3. `reason`: at most 200 ASCII characters, one line, no personal data and no secret. Required for every `OPERATOR` row, every row whose `class` differs from the automatic class, and every `FOREIGN` row whose automatic reason is `unproven-origin`.
    - **The CSV stores no automatic value.** `kind`, `auto_class` and `auto_reason` exist only in `Site`, computed by `scan()` on every run. `compare` reads them **only from `scan()`**. So a person who edits the CSV cannot weaken a lock: there is no stored automatic value to edit. A CSV with an extra or an old column (for example revision 2's ten columns) fails as a wrong header.
  - **Automatic values, computed by `scan()` and never stored:**
    - `kind`: the canonical class name, with an import alias or attribute form resolved (`CE` or `errors.ConfigError` is recorded as `ConfigError`). For the call of a factory (rule C4) it is the class the factory builds.
    - `auto_class`: `LITERAL` when the first argument is a string constant, an implicit concatenation of constants, an f-string with no `{}` part, or absent; `FOREIGN` for anything else.
    - `auto_reason`: `constant`, `exception-variable` or `unproven-origin`. `exception-variable` means an interpolated or passed expression uses a name bound by `except ... as NAME` in an enclosing handler, or a local tainted by it. The check covers `str(e)`, `repr(e)`, `e.args[0]`, `type(e).__name__`, `e.__class__.__name__`, `"%s" % e`, `.format(e)` and f-string parts.
    - **Taint inside one function**, repeated to a fixed point. A name becomes tainted by: any assignment whose right side mentions a tainted name (plain, augmented, annotated, tuple target); a `for` target or comprehension target over a tainted iterable; the walrus operator; `with E as N` where `E` is tainted; a subscript or attribute assignment target (`X[k] = t` and `X.a = t` taint `X`); and the calls `X.append(t)`, `X.extend(t)`, `X.insert(i, t)`, `X.add(t)`, `X.update(t)`, `X.appendleft(t)`, which taint `X`. Taint does **not** cross function calls. A gap in taint never lets a row pass: the row lands in `unproven-origin` and needs a person, so a gap only moves a row from locked to human-reviewed.
    - For the call of a factory (rule C4), the taint test runs over the arguments bound to the parameters the factory interpolates.
  - **Locked rows (the rule that stops a wrong downgrade, and a wrong upgrade to LITERAL):** a row whose `auto_reason` is `exception-variable` MUST have `class=FOREIGN`; the CI test refuses `OPERATOR` and `LITERAL` there whatever the reason says. The LITERAL rule is two-way: `class=LITERAL` if and only if `auto_class=LITERAL`. A blank `class` is always a failure.
  - **Generator `tools/gen_config_error_sites.py`** (standard library only; **it never imports `hadavin_sdk` or runs any repository code**, it only reads files). Its imports are absolute (`ban-relative-imports = "all"`, `pyproject.toml:76`). Named constants at the top, in one place: `PACKAGE_DIR = "src/hadavin_sdk"`, `CSV_PATH = "tests/data/config_error_sites.csv"`, `BASE_CLASS = "ConfigError"`, `HASH_LEN = 16`, `CLASSES = ("LITERAL", "OPERATOR", "FOREIGN")`, `COLUMNS = ("site", "class", "reason")`, `REASON_MAX = 200`.
    - **`node_hash(node: ast.AST) -> str`** (public; P5b3's waiver `stmt_hash` should call it, see "What P5b3 takes"): the first `HASH_LEN` hex characters of sha256 over a **canonical walk of the node's syntax tree**. The walk writes the node type name, then each field in `_fields` order with its name, with brackets around each node and each list, so two different trees never give the same text. It skips `ctx`, `type_comment` and `Constant.kind`, and any field whose value is `None` or `[]`. It never writes position fields (`lineno`, `col_offset` and the rest of `_attributes`). It writes a `Constant` as its type name plus `repr(value)`. This is our own walker, NOT `ast.dump`, so the 3.13 change to how `ast.dump` prints empty fields cannot reach it. Because the tree has no quotes, commas, parentheses, comments, line breaks or spacing, the hash does not change when a formatter adds a trailing comma, changes quote style, adds or removes redundant parentheses, re-wraps a call, or changes spacing inside an f-string. It does change when a message word or an interpolated name changes. Reason: ruff is pinned (`ruff==0.17.1`, `pyproject.toml:50`) and Dependabot bumps it, and with no carry mechanism a formatter style change would otherwise turn every touched row into a `stale`/`unclassified` pair and wipe about 140 human decisions. What is hashed: the construction's own `Call` node in any context (`raise`, `return`, an assignment, an argument); for a bare `raise A`, the `Name` or `Attribute` node `A`; for the call of a factory, the factory's `Call` node. The tree keeps the class name as written, so an alias gives a different key from the canonical name.
    - `scan(package_dir: Path) -> list[Site]`. `Site` is a frozen dataclass (`file`, `symbol`, `kind`, `snippet_hash`, `k`, `auto_class`, `auto_reason`, `lineno`, `origin_hints`); `lineno` is used only in messages and the review sheet. It reads only `*.py` files under `package_dir` (never `__pycache__`, never other file types, no symlink followed outside the tree), parses each with `ast.parse`, and finds:
      - (a) the set of site classes: `ConfigError` and every class that derives from it, by name, repeated to a fixed point across all modules (`class Foo(ConfigError)`, `class Bar(Foo)`, a base written as `errors.ConfigError` or as an import alias);
      - (b) every `Call` whose function is such a name or an attribute ending in such a name;
      - (c) every `raise NAME` where the raised object is the bare class (a site with no arguments, `LITERAL`);
      - (d) **factories (rule C4):** a function whose body **`return`s** a site construction whose message interpolates one of the function's own parameters. **A function that raises is never a factory.** The counter-example is `tools.py::parse_manifest` (`tools.py:100-120`, re-read): it raises four constructions that interpolate its own parameter `where`, and it gives no call-site rows. Today the only factory is `k1b/bundle.py::_fail` (`k1b/bundle.py:106-107`: `def _fail(case, msg) -> BundleError: return BundleError(f"bundle {case}: {msg}")`). Each call of a factory, in any file, is a site of its own, with `kind` = the class the factory builds. On ce70eb5 all 29 `_fail` calls are `FOREIGN / unproven-origin` (`case` is a name). The factory's own construction stays a row. A factory called through another factory raises `SitesError` (one level only). There is no hand-kept list of factory names.
      - It does NOT count `ConfigError.from_cause(...)`: that call builds its text from a Diagnostic at raise time (D7), so it is not a place where text is written. The body of `from_cause` (P5b3, `errors.py`) builds through `cls(...)` and is not a site either (PENDING LEAD 7; P5b3's Tier A review reads that body).
      - **Fail closed, always exit code 2 with `SitesError`:** a file that does not parse or is not valid UTF-8; a package directory with no `*.py`; a scan that does not find the class `ConfigError` defined; a factory called through another factory; and **a site class that defines `__init__`, `__new__`, `__str__`, `__repr__` or `__format__`** (such a class could build its own text outside any construction the table sees; none does today, see Source). A scan never skips a file.

A general "class used as a value" rule is NOT built, because it would fail on legitimate uses: `except` tuples, `isinstance`, and the return annotation `-> BundleError` at `k1b/bundle.py:106`.

    - `compare(sites, rows) -> Report`. `Report` has **six lists**, each sorted `site` strings:
      - `unclassified` (in the code, not in the CSV) and `stale` (in the CSV, not in the code). These are about keys and are independent of the four below.
      - Four human-field lists. Each row lands in **at most one** of them, at the first match in this order: `blank_class`; `locked_downgrade` (an `exception-variable` row whose `class` is not `FOREIGN`, so `LITERAL` counts too); `wrong_literal` (`class` is `LITERAL` XOR `auto_class` is `LITERAL`, either direction); `missing_reason`.

An existing CSV that fails `load_csv` raises `SitesError`, and `write` does not overwrite it. For each site whose key already exists, `class` and `reason` are kept (nothing else is stored). A new site with `auto_class=LITERAL` gets `class=LITERAL`; a new site with `auto_reason=exception-variable` gets `class=FOREIGN`; every other new site gets a **blank `class`**, so the test fails until a person fills it in. Stale rows are dropped. The file is written in one call with no temporary file and no `os.replace`: a half-written table already fails closed (a bad row raises `SitesError`; missing rows are reported `unclassified`).
