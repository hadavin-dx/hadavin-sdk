## 0. Words (one meaning each)

- **inbound event**: something outside that should start work. v1 has one way in: a signed web request (a **webhook**) to our **door**. E-mail, files, queues and timers reach the door through a **forwarder** (the client's own mail, automation or scheduler tool, or a self-hosted no-code flow the client agrees to).
- **inbound source**: one configured webhook address, bound in config to exactly one tenant, one readers list, one agent and one principal. **ledger name** (`key_name`): the name the ledger stores for that address; default = the address name; a rename of the address keeps it.
- **sender id**: the id the sender gives its message, read only from the signed body, from the configured field `id_field`.
- **receipt**: the row we save BEFORE we answer the sender (write-ahead). Owner-facing text says "saved message record". **acknowledgement**: the 202 the sender hears.
- **delivery key**: a keyed hash (HMAC) of tenant, ledger name and sender id. We store hashes, never the raw sender id.
- **duplicate**: same sender id, same body bytes: nothing new happens. **id reuse**: same sender id, different body bytes: the first stays untouched, the new one becomes a refused row without its body, the sender hears 409.
- **claim / lease / release**: dispatch takes ONE receipt for a limited time (the lease); a crash lets the lease run out and another worker takes it; release hands it back unfinished.
- **try**: a counted attempt. A crash or overrun (lease ran out) counts once; a step failure (`step_error`) counts; an **infrastructure failure** that dispatch itself sees (audit trail or store unreachable at a dispatch call) does not count and ends that dispatch call.
- **the run row is the commit point**: once a run exists for a receipt's run id, dispatch never starts that work again; a cut-off run goes to a person.
- **generation**: counter on the receipt, 0 at first; a **reopen** (a person's action, built in AK-G15; here only its database side) raises it and gives a new run id. A reopen can cost money again.
- **final state**: `done`, `needs_person` ("a person must look"), `refused`. Open states: `received`, `claimed`. `done` = exactly one run exists for this generation and, when dispatch read it, it was not stuck, cut off, stopped by a limit, or waiting for a person.
- **key check**: a 16-hex-character fingerprint of the inbound key (`HMAC(key, fixed label)`, truncated). It reveals nothing about the key and is safe in a log line; it shows only WHETHER the key changed.
- **database trigger**: a PostgreSQL rule on a table (never an inbound event). **re-run owner role**: the one NOLOGIN database role that alone may move a receipt from `needs_person` back to `received`.
- **door role / dispatch role**: the two database logins of the door and of dispatch. **runtime role**: today's agent-runtime login; it gets nothing on the inbound tables.
- **UNVERIFIED**: not read in code or not run; each has a fallback in section 18.

## 3. Records, reasons, keys (-a)

- **`InboundReceipt(Shape)`** (`models.py`): `tenant` (AK1 `TENANT_PATTERN`), `source` (the ledger name), `readers: frozenset[str]` (AK1 `Readers`), `delivery_key` (64 lower-case hex), `body_sha256` (64 lower-case hex; keyed body hash), `key_check` (16 lower-case hex; the check in force when written; never changed), `generation: int = 0` (0-65535), `run_id: str | None` (`run_id_for(delivery_key, generation)`; `None` only on an id-reuse row), `state`, `reason`, `last_reason`, `attempts: int = 0`, `lease_until`, `claim_token`, `reuse_of` (original `delivery_key` on an id-reuse row, else `None`), `received_at`, `updated_at`. Derived `item_id = "inb-" + delivery_key[:32]` (same for every generation).
- **`InboundRunView`** (frozen): `run_id, agent_id, principal_id, trigger_ref, state, reason_code, updated_at` (dispatch's narrow run read).
- **Reasons.** `INBOUND_REASONS` (8) = `id_reuse`, `attempts_exhausted`, `body_missing`, `body_mismatch`, `run_interrupted`, `run_limits`, `run_mismatch`, `run_needs_person`. `INBOUND_RETRY_REASONS = {"step_error", "audit_unavailable"}`. Allowed per state (anything else is `ValueError` in Python and a CHECK refusal in SQL):

  | state | `reason` |
  |---|---|
  | `received`, `claimed`, `done` | `None` (`last_reason` is `None` or a retry reason) |
  | `refused` | `invalid_input`, `forbidden`, `duplicate` (AK1 `REASONS[refused]`), `id_reuse` |
  | `needs_person` | `low_quality`, `unreadable`, `over_budget`, `meter_unavailable`, `masking_refused`, `outbound_refused`, `policy` (AK1 `REASONS[needs_person]` minus the retry reasons), `attempts_exhausted`, `body_missing`, `body_mismatch`, `run_interrupted`, `run_limits`, `run_mismatch`, `run_needs_person` |

- **State moves:** `ALLOWED = {received: {claimed}, claimed: {claimed, received, done, needs_person, refused}, needs_person: {received}}` (the last for the re-run owner only); `done` and `refused` are final. One `check(frm, to)` in the shape of `runtime/runs.py` (`ALLOWED` `:10-21`, `check` `:29-34`) WITHOUT its "`STOPPED` always allowed" exception.
- **Keys** (`triggers/ledger.py`; exact): `hkey = hmac.new(restored_key, b"hadavin-inbound-key-v1", sha256).digest()` from the existing restored-hash key (`app.py:84-85`, at least 16 bytes, required in pilot and prod), or `None` without it (demo). `_h(k, data) = hmac.new(k, data, sha256).hexdigest()` if `k` else `sha256(data).hexdigest()` (the `_restored_digest` rule). `body_sha256 = _h(hkey, body)`. `delivery_key = _h(hkey, tenant_key(tenant, source, sender_id).encode())`. Reuse key = `_h(hkey, tenant_key(tenant, source, sender_id, "reuse", body_sha256).encode())` (AK1's length-prefixed `tenant_key`, so 5 parts never equal 3). `run_id_for(delivery_key, generation) = "run-" + delivery_key[:28] + format(generation, "04x")` (matches `RUN_ID_PATTERN`). `key_check = _h(hkey, b"hadavin-inbound-key-check-v1")[:16]`. `models.sha256_hex` (canonical JSON) is never used.
- **`check_sender_id(x)`**: `ValueError` (message names no value) unless `type(x) is str`, `1 <= len(x) <= INBOUND_MAX_SENDER_ID_CHARS` (256 accepted), and no character's `unicodedata.category` starts with `C`. Called by `Inbox.receive` before any store call (the choke point) and by the door for its 400.
- **Exceptions (2 new):** `InboundKeyChanged` (`triggers/ledger.py`; message holds tenant, source and both checks, never a key) and `RerunRefused(code)` (`store/protocol.py`, a `RuntimeError`, not an `OSError`, so `is_connectivity_error` never reads it as an outage). AK-G15-b reuses `RerunRefused`.

## 4. Schema: the migration file, literally (-a)

Every time column is written by the caller (no `now()`, no time `DEFAULT`). The three functions are pinned to `<schema>, pg_temp` by `migrate` (section 5), so a caller's temporary table can never shadow `inbound_rerun_owner` or `runs`.

```sql
CREATE TABLE inbound_key_checks (
    tenant         TEXT NOT NULL,
    source         TEXT NOT NULL,
    schema_version INTEGER NOT NULL,
    readers        TEXT[] NOT NULL,
    key_check      TEXT NOT NULL CHECK (key_check ~ '^[0-9a-f]{16}$'),
    set_at         TIMESTAMPTZ NOT NULL,
    PRIMARY KEY (tenant, source)
);

CREATE TABLE inbound_receipts (
    tenant         TEXT NOT NULL,
    source         TEXT NOT NULL,
    delivery_key   TEXT NOT NULL CHECK (delivery_key ~ '^[0-9a-f]{64}$'),
    schema_version INTEGER NOT NULL,
    readers        TEXT[] NOT NULL,
    body_sha256    TEXT NOT NULL CHECK (body_sha256 ~ '^[0-9a-f]{64}$'),
    key_check      TEXT NOT NULL CHECK (key_check ~ '^[0-9a-f]{16}$'),
    generation     INTEGER NOT NULL CHECK (generation BETWEEN 0 AND 65535),
    run_id         TEXT CHECK (run_id IS NULL OR run_id ~ '^run-[0-9a-f]{32}$'),
    state          TEXT NOT NULL CHECK (state IN ('received', 'claimed', 'done', 'needs_person', 'refused')),
    reason         TEXT,
    last_reason    TEXT CHECK (last_reason IS NULL OR last_reason IN ('step_error', 'audit_unavailable')),
    attempts       INTEGER NOT NULL CHECK (attempts >= 0),
    lease_until    TIMESTAMPTZ,
    claim_token    TEXT CHECK (claim_token IS NULL OR claim_token ~ '^clm-[0-9a-f]{32}$'),
    reuse_of       TEXT CHECK (reuse_of IS NULL OR reuse_of ~ '^[0-9a-f]{64}$'),
    received_at    TIMESTAMPTZ NOT NULL,
    updated_at     TIMESTAMPTZ NOT NULL,
    PRIMARY KEY (tenant, source, delivery_key),
    CONSTRAINT inbound_receipts_reason CHECK (CASE state
        WHEN 'refused' THEN COALESCE(reason IN ('invalid_input', 'forbidden', 'duplicate', 'id_reuse'), false)
        WHEN 'needs_person' THEN COALESCE(reason IN ('low_quality', 'unreadable', 'over_budget',
            'meter_unavailable', 'masking_refused', 'outbound_refused', 'policy', 'attempts_exhausted',
            'body_missing', 'body_mismatch', 'run_interrupted', 'run_limits', 'run_mismatch',
            'run_needs_person'), false)
        ELSE reason IS NULL END),
    CONSTRAINT inbound_receipts_lease CHECK ((state = 'claimed') = (lease_until IS NOT NULL AND claim_token IS NOT NULL)),
    CONSTRAINT inbound_receipts_reuse_run CHECK ((reuse_of IS NULL) = (run_id IS NOT NULL))
);

CREATE TABLE inbound_bodies (
    tenant         TEXT NOT NULL,
    source         TEXT NOT NULL,
    delivery_key   TEXT NOT NULL CHECK (delivery_key ~ '^[0-9a-f]{64}$'),
    schema_version INTEGER NOT NULL,
    readers        TEXT[] NOT NULL,
    body           BYTEA NOT NULL,
    received_at    TIMESTAMPTZ NOT NULL,
    PRIMARY KEY (tenant, source, delivery_key)
);

CREATE TABLE inbound_rerun_owner (
    id        BOOLEAN PRIMARY KEY DEFAULT true CHECK (id),
    role_name NAME NOT NULL
);

CREATE INDEX inbound_receipts_waiting ON inbound_receipts (tenant, source, state, lease_until)
    WHERE state IN ('received', 'claimed', 'needs_person');
CREATE INDEX inbound_receipts_reuse ON inbound_receipts (tenant, source, reuse_of) WHERE reuse_of IS NOT NULL;

CREATE OR REPLACE FUNCTION hadavin_inbound_receipt_update() RETURNS trigger LANGUAGE plpgsql SECURITY INVOKER AS
$f$
DECLARE owner_name name;
BEGIN
    IF NEW.tenant IS DISTINCT FROM OLD.tenant OR NEW.source IS DISTINCT FROM OLD.source
       OR NEW.delivery_key IS DISTINCT FROM OLD.delivery_key OR NEW.body_sha256 IS DISTINCT FROM OLD.body_sha256
       OR NEW.key_check IS DISTINCT FROM OLD.key_check OR NEW.readers IS DISTINCT FROM OLD.readers
       OR NEW.reuse_of IS DISTINCT FROM OLD.reuse_of OR NEW.received_at IS DISTINCT FROM OLD.received_at
       OR NEW.schema_version IS DISTINCT FROM OLD.schema_version THEN
        RAISE EXCEPTION 'inbound_immutable' USING ERRCODE = '23514';
    END IF;
    IF OLD.state = 'needs_person' AND NEW.state = 'received' THEN
        SELECT role_name INTO owner_name FROM inbound_rerun_owner WHERE id;
        IF owner_name IS NULL OR current_user <> owner_name THEN
            RAISE EXCEPTION 'rerun_owner_only' USING ERRCODE = '42501';
        END IF;
        IF EXISTS (SELECT 1 FROM runs WHERE run_id = OLD.run_id AND state IN
                   ('RECEIVED', 'WORKING', 'PLAN_READY', 'WAITING_FOR_APPROVAL', 'EXECUTING', 'VERIFYING')) THEN
            RAISE EXCEPTION 'rerun_run_open' USING ERRCODE = '55000';
        END IF;
        IF NEW.generation <> OLD.generation + 1
           OR NEW.run_id IS DISTINCT FROM 'run-' || substr(OLD.delivery_key, 1, 28) || lpad(to_hex(NEW.generation), 4, '0')
           OR NEW.attempts <> 0 OR NEW.reason IS NOT NULL OR NEW.last_reason IS NOT NULL
           OR NEW.lease_until IS NOT NULL OR NEW.claim_token IS NOT NULL THEN
            RAISE EXCEPTION 'inbound_reopen_shape' USING ERRCODE = '23514';
        END IF;
        RETURN NEW;
    END IF;
    IF NEW.generation <> OLD.generation OR NEW.run_id IS DISTINCT FROM OLD.run_id THEN
        RAISE EXCEPTION 'inbound_immutable' USING ERRCODE = '23514';
    END IF;
    IF NEW.attempts < OLD.attempts THEN
        RAISE EXCEPTION 'inbound_attempts_down' USING ERRCODE = '23514';
    END IF;
    IF NOT ((OLD.state = 'received' AND NEW.state = 'claimed')
            OR (OLD.state = 'claimed' AND NEW.state IN ('claimed', 'received', 'done', 'needs_person', 'refused'))) THEN
        RAISE EXCEPTION 'inbound_state_move' USING ERRCODE = '23514';
    END IF;
    RETURN NEW;
END
$f$;

CREATE OR REPLACE FUNCTION hadavin_inbound_receipt_insert() RETURNS trigger LANGUAGE plpgsql SECURITY INVOKER AS
$f$
DECLARE stored text;
BEGIN
    SELECT key_check INTO stored FROM inbound_key_checks WHERE tenant = NEW.tenant AND source = NEW.source;
    IF stored IS NULL OR NEW.key_check <> stored THEN
        RAISE EXCEPTION 'inbound_key_changed' USING ERRCODE = '23514';
    END IF;
    IF NEW.generation <> 0 OR NEW.attempts <> 0 OR NEW.last_reason IS NOT NULL OR NEW.lease_until IS NOT NULL
       OR NEW.claim_token IS NOT NULL OR NEW.updated_at <> NEW.received_at THEN
        RAISE EXCEPTION 'inbound_insert_refused' USING ERRCODE = '23514';
    END IF;
    IF NEW.state = 'received' AND NEW.reason IS NULL AND NEW.reuse_of IS NULL
       AND NEW.run_id = 'run-' || substr(NEW.delivery_key, 1, 28) || '0000' THEN
        RETURN NEW;
    END IF;
    IF NEW.state = 'refused' AND NEW.reason = 'id_reuse' AND NEW.reuse_of IS NOT NULL AND NEW.run_id IS NULL THEN
        RETURN NEW;
    END IF;
    RAISE EXCEPTION 'inbound_insert_refused' USING ERRCODE = '23514';
END
$f$;

CREATE OR REPLACE FUNCTION hadavin_inbound_body_insert() RETURNS trigger LANGUAGE plpgsql SECURITY INVOKER AS
$f$
BEGIN
    IF NOT EXISTS (SELECT 1 FROM inbound_receipts r
                   WHERE r.tenant = NEW.tenant AND r.source = NEW.source AND r.delivery_key = NEW.delivery_key
                     AND r.state = 'received' AND r.reuse_of IS NULL AND r.readers = NEW.readers) THEN
        RAISE EXCEPTION 'inbound_insert_refused' USING ERRCODE = '23514';
    END IF;
    RETURN NEW;
END
$f$;

CREATE OR REPLACE TRIGGER inbound_receipts_update BEFORE UPDATE ON inbound_receipts
    FOR EACH ROW EXECUTE FUNCTION hadavin_inbound_receipt_update();
CREATE OR REPLACE TRIGGER inbound_receipts_insert BEFORE INSERT ON inbound_receipts
    FOR EACH ROW EXECUTE FUNCTION hadavin_inbound_receipt_insert();
CREATE OR REPLACE TRIGGER inbound_bodies_insert BEFORE INSERT ON inbound_bodies
    FOR EACH ROW EXECUTE FUNCTION hadavin_inbound_body_insert();
ALTER TABLE inbound_receipts ENABLE ALWAYS TRIGGER inbound_receipts_update;
ALTER TABLE inbound_receipts ENABLE ALWAYS TRIGGER inbound_receipts_insert;
ALTER TABLE inbound_bodies ENABLE ALWAYS TRIGGER inbound_bodies_insert;
```

Notes: the receipt key-check equality comes before the shape test, so it binds both legal shapes (new receipt and id-reuse row). `migrate`'s `_scan` accepts every statement above (`CREATE TABLE name (`, `CREATE INDEX`, `CREATE OR REPLACE FUNCTION|TRIGGER`; `store/migrate.py:80-84`, read 2026-11-09). The open-state list and both reason lists are checked against `models.OPEN_STATES` and the Python sets by L15 (f).

**Database refusals and how the Postgres store maps them** (matched on SQLSTATE plus `exc.diag.message_primary`):

| SQLSTATE, message | raised by | store gives |
|---|---|---|
| `23514 inbound_key_changed` | receipt INSERT inside `receive_inbound` (a key change committed between the re-read and the insert) | the transaction is rolled back, caught OUTSIDE the transaction block, and `receive_inbound` returns `"key_changed"` (nothing written) |
| `42501` (`rerun_owner_only`, or PostgreSQL's own permission refusal) | `REOPEN_SQL` | `RerunRefused("rerun_owner_only")` |
| `55000 rerun_run_open` | `REOPEN_SQL` | `StaleState("rerun_run_open")` |
| `23514` (`inbound_reopen_shape` or the `generation` CHECK) | `REOPEN_SQL` | `StaleState("rerun_shape")` |
| `23514 inbound_insert_refused`, `inbound_immutable`, `inbound_state_move`, `inbound_attempts_down`, any other `42501`, any `23505` | any other inbound statement | NOT mapped: propagates (only a bug or a forged write reaches it); the door answers 500, dispatch lets the tick step fail loudly |

## 6. Store protocol `InboundStore` (-a; 11 methods; memory and Postgres)

`InboundStore` is a NEW protocol next to `Store`; `missing_methods` is unchanged and `missing_inbound_methods(store)` is new. Every time is an argument or a record field. Postgres writes run in `with self._lock, self._db.transaction():` with explicit SQL; `readers` is written as a sorted `list[str]` and read back as a `frozenset`. A missing receipt (or run, in 11) is `NotFound`; another state or token is `StaleState` (a three-column sibling of `_missing_or_stale`, `store/postgres.py:247`). The memory store enforces the same rules under its one lock.

1. **`receive_inbound(rec, body: bytes | None, *, max_reuse: int, max_open: int) -> Literal["new", "duplicate", "conflict", "conflict_capped", "busy", "key_changed"]`**, one transaction (`rec.key_check` is the caller's own check; there is no separate keyword):
   ```sql
   INSERT INTO inbound_key_checks (tenant, source, schema_version, readers, key_check, set_at)
   VALUES (%(tenant)s, %(source)s, 1, %(readers)s, %(key_check)s, %(received_at)s) ON CONFLICT (tenant, source) DO NOTHING;
   SELECT key_check FROM inbound_key_checks WHERE tenant = %(tenant)s AND source = %(source)s;      -- differs: return key_changed
   -- private no-op hook self._after_key_check_read() here (L25 (iv))
   SELECT body_sha256 FROM inbound_receipts WHERE tenant = %(tenant)s AND source = %(source)s AND delivery_key = %(delivery_key)s;
                                                                  -- found: equal -> duplicate, different -> conflict
   SELECT count(*) FROM inbound_receipts WHERE tenant = %(tenant)s AND source = %(source)s AND reuse_of = %(reuse_of)s;
                                                                  -- only when reuse_of is set: >= max_reuse -> conflict_capped
   SELECT count(*) FROM inbound_receipts WHERE tenant = %(tenant)s AND source = %(source)s AND state IN ('received', 'claimed');
                                                                  -- only when state = 'received': >= max_open -> busy
   INSERT INTO inbound_receipts (<all 18 columns>) VALUES (...) ON CONFLICT (tenant, source, delivery_key) DO NOTHING RETURNING delivery_key;
                                                                  -- no row: a racer committed first; re-run the dedupe SELECT
   -- private no-op hook self._before_body_insert() here (L1)
   INSERT INTO inbound_bodies (tenant, source, delivery_key, schema_version, readers, body, received_at) VALUES (...);
                                                                  -- only when the receipt INSERT returned a row and body is not None
   ```
   Then `new`. Racing receivers of one new message: one `new`, the rest `duplicate`, never a unique-violation (READ COMMITTED: the second INSERT waits, then does nothing, and the re-read sees the commit). Racing receivers can pass `max_open` (bound in L11) and `max_reuse` (up to `max_reuse + k - 1` rows for `k` receives of one id in flight; reuse rows hold no body and start no run). The door cannot lock the key-check row (`FOR SHARE` needs UPDATE, which the door does not hold), so the change race is mapped instead (section 4 table).
2. **`claim_inbound(tenant, source, now, lease_s) -> InboundReceipt | None`** (`token = new_id("clm")`, `lease_until = now + timedelta(seconds=lease_s)` computed in Python):
   ```sql
   UPDATE inbound_receipts r SET state = 'claimed', claim_token = %(token)s, lease_until = %(lease_until)s,
       attempts = r.attempts + CASE WHEN r.state = 'claimed' THEN 1 ELSE 0 END, updated_at = %(now)s
   WHERE (r.tenant, r.source, r.delivery_key) = (
       SELECT tenant, source, delivery_key FROM inbound_receipts
       WHERE tenant = %(tenant)s AND source = %(source)s
         AND (state = 'received' OR (state = 'claimed' AND lease_until < %(now)s))
       ORDER BY received_at, delivery_key LIMIT 1 FOR UPDATE SKIP LOCKED)
   RETURNING r.*;
   ```
3. **`get_inbound_body(tenant, source, delivery_key) -> bytes | None`**: `SELECT body FROM inbound_bodies WHERE tenant = .. AND source = .. AND delivery_key = ..`.
4. **`finish_inbound(tenant, source, delivery_key, claim_token, state, reason, now)`**: final `state` with an allowed `reason`, else `ValueError`.
   `UPDATE inbound_receipts SET state = %(state)s, reason = %(reason)s, lease_until = NULL, claim_token = NULL, updated_at = %(now)s WHERE tenant = .. AND source = .. AND delivery_key = .. AND state = 'claimed' AND claim_token = %(token)s RETURNING delivery_key;`
5. **`release_inbound(tenant, source, delivery_key, claim_token, reason, now)`**: `reason` in the retry set, else `ValueError`.
   `UPDATE inbound_receipts SET state = 'received', last_reason = %(reason)s, lease_until = NULL, claim_token = NULL, attempts = attempts + CASE WHEN %(reason)s = 'step_error' THEN 1 ELSE 0 END, updated_at = %(now)s WHERE ... AND state = 'claimed' AND claim_token = %(token)s RETURNING delivery_key;`
6. **`reopen_inbound(tenant, source, delivery_key, now) -> InboundReceipt`**: Postgres runs `REOPEN_SQL` as its own login and maps per section 4 (so through the door, dispatch or runtime store it is ALWAYS `RerunRefused`); memory raises `RerunRefused("rerun_owner_only")` always. Module constant in `store/postgres.py`:
   ```sql
   UPDATE inbound_receipts SET state = 'received', generation = generation + 1,
       run_id = 'run-' || substr(delivery_key, 1, 28) || lpad(to_hex(generation + 1), 4, '0'),
       attempts = 0, reason = NULL, last_reason = NULL, lease_until = NULL, claim_token = NULL, updated_at = %(now)s
   WHERE tenant = %(tenant)s AND source = %(source)s AND delivery_key = %(delivery_key)s AND state = 'needs_person'
   RETURNING *;
   ```
7. **`list_inbound_sources() -> list[tuple[str, str, int]]`**: `SELECT tenant, source, count(*) FROM inbound_receipts WHERE state IN ('received', 'claimed', 'needs_person') GROUP BY tenant, source ORDER BY tenant, source;` (names and counts only).
8. **`purge_inbound_bodies(before, ceiling) -> int`** (rowcount; purge role only):
   ```sql
   DELETE FROM inbound_bodies b
   USING inbound_receipts r LEFT JOIN runs u ON u.run_id = r.run_id
   WHERE r.tenant = b.tenant AND r.source = b.source AND r.delivery_key = b.delivery_key
     AND r.state IN ('done', 'needs_person', 'refused')
     AND (r.updated_at < %(ceiling)s
          OR (r.updated_at < %(before)s
              AND (r.state = 'refused'
                   OR (r.state = 'done' AND (u.run_id IS NULL OR u.state NOT IN
                       ('RECEIVED', 'WORKING', 'PLAN_READY', 'WAITING_FOR_APPROVAL', 'EXECUTING', 'VERIFYING',
                        'NEEDS_PERSON', 'STOPPED')))))));
   ```
   Never an open receipt's body; `needs_person` bodies and `done` bodies whose run is open, waiting for a person or stopped are kept to the ceiling (400 days). Receipts are never deleted in v1 (V6); reuse rows (at most 8 per sender id) too.
9. **`get_inbound_key_check(tenant, source) -> str | None`**.
10. **`set_inbound_key_check(tenant, source, old: str, new: str, now)`**: `UPDATE inbound_key_checks SET key_check = %(new)s, set_at = %(now)s WHERE tenant = .. AND source = .. AND key_check = %(old)s RETURNING tenant;` no row: `StaleState` (lost race) or `NotFound`. Dispatch only.
11. **`get_inbound_run(run_id) -> InboundRunView`**: `SELECT run_id, agent_id, principal_id, trigger_ref, state, reason_code, updated_at FROM runs WHERE run_id = %s` (`NotFound` as `get_run`; `get_run` selects every column, `store/postgres.py:244-245`, so the dispatch role cannot use it).

## 7. The inbox and dispatch (-a, `triggers/ledger.py`)

- **`InboundSource(name, tenant, readers, agent_id, principal_id, max_open, stuck_s)`** (frozen; `name` pattern `[a-z][a-z0-9_-]{0,39}`; `max_open >= 1`; `stuck_s >= 1`). **`DispatchSettings(lease_s, max_attempts, dispatch_budget_s, key_check_ack: str | None)`.** **`Inbox(store, audit, limits, clock, monotonic, settings, qualified: frozenset[str], hkey: bytes | None)`**; its own check `self.key_check` is computed once from `hkey`.
- **`receive(source, sender_id, body) -> Literal["new", "duplicate", "id_reuse", "id_reuse_capped", "busy"]`**: (0) `check_sender_id`; (1) `receive_inbound(rec, body, max_reuse=8, max_open=source.max_open)` with `generation=0`, `run_id=run_id_for(dk, 0)`, `key_check=self.key_check`, `received_at = updated_at = clock()`; `key_changed` raises `InboundKeyChanged` (re-read on EVERY receive; no cache); `new`, `duplicate`, `busy` returned as they are; (2) on `conflict`, one more `receive_inbound` of the reuse row (`refused`, `id_reuse`, `reuse_of` = original key, `run_id=None`, body `None`): its `new` or `duplicate` gives `id_reuse`, `conflict_capped` gives `id_reuse_capped`. A repeat of the same reused body is `id_reuse`, never `duplicate`. Store errors propagate.
- **`dispatch(sources, steps: Mapping[str, Step]) -> tuple[int, bool]`** (finished or released count, infrastructure stop). A source with no step is `ValueError` before any claim. FIRST, for EVERY configured source (even one with no waiting receipt): `get_inbound_key_check`; no row or equal: fine; different and `key_check_ack == self.key_check`: `set_inbound_key_check(old=stored, new=self.key_check)` and one WARNING; different otherwise: the source is failed for this call (reported to the tick step). Then round robin, one receipt per source per turn, until no work, `dispatch_budget_s` on the monotonic clock, or an infrastructure stop. Before each claim: agent in `qualified`, `limits.blocked(agent_id)` empty, key check not failed. Per claimed receipt:
  1. `get_inbound_run(rec.run_id)`: a run gives `_classify` and the receipt is finished (or left `claimed` by rule 3); only `NotFound` goes on.
  2. `attempts >= max_attempts`: if `list_dead_letters(rec.run_id)` has no `inbound_attempts_exhausted` row, add `DeadLetter(run_id, "inbound_attempts_exhausted", [rec.last_reason or "lease_expired"], now)`; then `finish_inbound(needs_person, attempts_exhausted)`.
  3. Body: `None` gives `body_missing`. When `rec.key_check == self.key_check`, `_h(hkey, body) != rec.body_sha256` gives `body_mismatch` with no step call. When they differ (written before an acknowledged key change), the hash check is skipped, the step runs, and one WARNING `body_check_old_key <tenant>/<source>=<count>` per source per call is logged (plain words: "some waiting messages were saved under the previous key; their stored text cannot be re-checked").
  4. `run_step(steps[source.name], StepInput(item_id, tenant, readers, body, run_id, agent_id), audit=audit, principal="trigger:" + source.name)`. Output `done`: `get_inbound_run` then `_classify` (`NotFound` gives `done`); `refused`: final with its reason; `needs_person step_error`: release (counted) and pause the source for this call; `needs_person audit_unavailable`: release (not counted) and end the call; other `needs_person`: final with its reason.
  `is_connectivity_error(exc)` at any dispatch site (`limits.blocked`, key-check read, claim, run read, body read, finish, release) ends the call with `(n, True)`; any other exception propagates. `StaleState` on finish or release is skipped at DEBUG. A stop request propagates (the lease brings the receipt back). Every `now` is `clock()`.
- **`_classify(run: InboundRunView, source, rec, now)`**, first match wins: (1) agent, principal or `trigger_ref` differs: `needs_person run_mismatch`; (2) `(state, reason_code)` in `LIMITS_END`: `run_limits`; (3) state in `tick.STUCK`'s keys and `run.updated_at >= now - source.stuck_s`: leave `claimed` (still running); (4) state in `STUCK`'s keys, or `NEEDS_PERSON` with `reason_code` in `STUCK`'s values (`interrupted`, `outcome_unknown`, `verify_interrupted`): `run_interrupted`; (5) `NEEDS_PERSON`: `run_needs_person`; (6) else `done`.
- **`LIMITS_END`** (closed, 7 pairs): `(STOPPED, "kill_switch")`, `(NEEDS_PERSON, "limits.daily_budget")`, `(NEEDS_PERSON, "limits.monthly_budget")`, `(NEEDS_PERSON, "limits_unavailable")`, `(DENIED, "limits.kill_switch")`, `(DENIED, "limits.daily_budget")`, `(DENIED, "limits.monthly_budget")`. Not in it on purpose: `recheck.limits.*` (after approval; rule 5) and `run_budget` (rule 5).
- **Remaining race, stated:** `blocked()` is a read, so a switch or wall can start between dispatch's check and `handle`'s; that run ends at once and the receipt goes to a person as `run_limits`, body kept (at most one per dispatching program per switch).

## 8. StartRun (-a, `triggers/start_run.py`)

`StartRun(runtime, principal_id)`, one per inbound source, a `Step` named `start_run`. `run(inp)` opens no meter scope or masking run and calls `runtime.handle(inp.agent_id, principal_id=self.principal_id, document=<body bytes>, trigger_kind="event", trigger_ref=inp.item_id, run_id=inp.run_id)`, returns `done`. It is the only production caller of `.handle(` in `src/hadavin_sdk/` and `demos/` (guard D15). `run_step`'s `principal="trigger:" + source.name` is the AUDIT principal of the step; `handle`'s `principal_id` is the RUN's principal, which `_classify` compares. Inbound runs use `trigger_kind="event"` and are recognised by `trigger_ref` starting `inb-` (ORDER 178 (2)).

### 8a. Two rules from the PEEL-run-id follow-up (lead ORDER 194 (A)3, 2026-11-09; AK-G2-a part)

1. **A run handed back is not an acknowledgement.** Since PR 87, `Runtime.handle(..., run_id=X)` for a message already started RETURNS the stored run at once (same agent, principal and `trigger_ref`; else `StaleState`). That run may be in `RECEIVED` or `WORKING`: the first call may be running in another thread, or it was cut off by a crash. `StartRun` and dispatch must therefore NOT treat "handle returned a run" as "this message is finished" and must not answer or finish the receipt on that alone. They read the returned run's `state`: a run in `RECEIVED` or `WORKING` is not acknowledged; the receipt stays open and the existing crash recovery of AK-G2-a (lease, then "cut off, goes to a person", section 0 "the run row is the commit point") owns that case. A run in a later state is read by `_classify` as the ticket already says. Test row to add: `handle` returns a run still in `WORKING` (a store holding it there): the receipt is NOT `done`; after the lease it ends `needs_person`, never a second run, never a second model call.
2. **Only the trusted inbound door derives `run_id` (squatting).** `run_id_for(delivery_key, generation)` is called only inside the ledger, from the keyed hash of tenant, ledger name and sender id, which exist only after the signature check. No other caller of `handle` may pass a `run_id` (guard D15 already allows one production caller; add: the only `run_id=` keyword in `src/hadavin_sdk/` and `demos/` is `StartRun`'s). Reason: a caller who can guess or choose an id could take the id of a message that has not arrived yet (squatting); the run would then exist with the wrong content, and the real message would be handed that run back. Two guards already in core after the follow-up: a `run_id` with the default `trigger_ref` `"-"` (or an empty or blank one) is refused with `InvalidRunId`, and a stored run is returned only when agent, principal and `trigger_ref` all equal. `StartRun` always passes `trigger_ref=inp.item_id` (`inb-...`), never `"-"`. Test row to add: a run stored beforehand under the derived id with another `trigger_ref` makes `StartRun` raise `StaleState` and the receipt go to `needs_person`; nothing is returned from the foreign run.

## 10. Security and least privilege (summary; detail in sections 4-9)

- **Identities:** six database roles (runtime, purge, portal existing; door, dispatch, re-run owner new), one per function, rights in section 5, each with a negative test (L14, L24, L28). The webhook principal can never be an approver. **Separation is per database connection, not per program, in v1:** every program `app.build` makes opens all four logins; code that takes over the program can use them all. Program separation is V13 and AK-G16, both in the PILOT GATE.
- **Secrets:** one or two signing secrets per address, read once through the secrets kind, never logged, never shared (C7). The inbound key is derived from the existing restored-hash key (no new secret). Rotation of the restored-hash key: rotate only after every sender's retry horizon; inbound then stops (503, tick exit 1) until `inbound.key_check_ack` names the new check copied from the ERROR line; from then on a retry of a message accepted before the change can start a second run; waiting messages still run (section 7 step 3).
- **Stolen database logins, said plainly:** a stolen door login can append receipts only in the two legal shapes with the current key check, cannot read bodies, cannot change rows; a stolen dispatch login can claim, release, finish and write another valid key check, which stops inbound loudly (503 and tick exit 1) but can never make a receipt skip the body re-check, because dispatch compares a receipt's check with its OWN computed check, and the door accepts only receipts whose check equals its own; a non-hex value is refused by the CHECK. No login can re-run a message except the NOLOGIN re-run owner.
- **Signed inputs:** unsigned, stale (over 300 s either way) or wrongly signed requests are refused before parsing or writing; a replay inside 300 s is a `duplicate`; the `aud` field stops a replay to another deployment or address. The sender id comes only from the signed body; tenant, readers, agent and principal only from config.
- **Personal data:** raw bodies only in `inbound_bodies` (never portal-readable, never readable by purge), deleted `body_days` after final or at the 400-day ceiling; receipts hold keyed hashes only, kept in v1 (V6); logs, audit and the ledger hold ids, hashes, counts and closed codes, never body text, sender ids, secrets or exception text. With `hkey = None` (demo without a restored key) the hashes are plain SHA-256 and guessable.
- **Tenant isolation (R369):** tenant first in every key; every store method but purge and `list_inbound_sources` takes the tenant; runs carry no tenant (one deployment per client, `AK1.md:172`), so the cross-tenant agent/principal refusal and `run_mismatch` keep one tenant's body out of another's run.
- **Cost before authentication:** at most `max_body_bytes` read and two HMACs per request; rate and connection limits are AK-G16's.
- **Dispatch capacity (arithmetic, not measured):** one program starts about `ceil(dispatch_budget_s / run time)` runs per tick (2 for 20 s and 10 s runs); faster senders get 503 after `max_open`; nothing is lost.

## 11. Owner-visible limits (plain words; copied to `owner-visible-limits.md` before any pilot)

1. A message whose run was cut off by a crash or an error is not re-run on its own: a person sees it as "interrupted" and decides. A reopen starts a new run, which can cost money again.
2. A sender must resend a retry byte for byte; a re-formatted retry is refused, and a person sees the refusal.
3. A sender that holds the signing secret can send any content it likes.
4. If the code is rolled back, waiting messages stay waiting, and nothing raises an alarm until the pre-revert count is run.
5. A message that arrives while a stop or a spending limit is being switched on can end up waiting for a person instead of in the queue (at most one per program per switch).
6. Two client deployments that share a signing secret cannot replay each other's requests, because each request names its audience; only two deployments set up with the same audience AND the same secret could (two configuration errors).
7. The development server tells a caller whether an inbound address name exists.
8. Comparing our received message ids with the sender's ids, listing waiting messages, and closing a waiting message without a re-run need a later package (AK-G15); until then nobody can do them without code.
9. If the key behind the inbound fingerprints is changed, inbound stops until a person acknowledges it. After that, a sender's retry of a message accepted before the change can start a second paid run. Messages already waiting still run, but for them we cannot re-check that the saved message record holds what arrived.
10. Reopening a message whose earlier run may already have acted outside (its outcome is unknown) can propose the same action again; the approval step still applies.
11. The core marks a run as interrupted after its model-time limit; time spent in tools is not counted, so a healthy but slow run can be marked interrupted (how the core already works).
12. The door, the step that starts runs and the clean-up each log in to the database as their own user with only the rights they need; in this version they run inside one program, so a fault that takes over the program can use all of them. A separate program comes before any pilot.
13. Each inbound address has a fixed ledger name. Renaming the address keeps it; changing the ledger name itself while a sender is still retrying can start a second run.
14. Someone who steals the database login of the step that starts runs can stop all inbound messages (senders are told "retry later" and the scheduled check reports an error), but cannot make the system skip the check of saved message records.
