## Words used in this ticket (defined once)
- **text**: the string a caller hands in (a name, an invoice number, a document line). **fold**: the function that turns text into a comparison form in which look-alike characters, invisible characters and case no longer matter.
- **key**: the folded text (a string) a view returns. A key can hold personal data; never log it. **key_digest**: the SHA-256 hex string of a key (the stored form; with a salt it is an HMAC). Unsalted it is only a pseudonym: anyone with a list of likely names can recompute it. **table_digest**: the SHA-256 of the look-alike table (not of a key).
- **view**: one named function that returns a key or a key-set for one purpose (`identity_key`, `id_key`, `scan_keyset`, `name_key`). A **view_name** is the string that names it in a stored record.
- **DENY decision**: "block this if it looks like a protected value" (blocklists, leak scans, same person); over-matching is the safe side. **ALLOW decision**: "accept only if it IS the verified value"; the fold is never used for it; `allow_equal` is the only allow path.
- **key-set**: the small fixed set of keys a DENY check builds for one text (P1b). **FOLD_VERSION**: ONE string naming exactly which fold produced a key (P1a).
