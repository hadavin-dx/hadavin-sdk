## Words used in this ticket (defined once)
- **fold**: the function that turns text into a comparison form in which look-alike characters, invisible characters and case no longer matter. **key**: the folded text (a string) a view returns. A key can hold personal data; never log it. **table_digest**: the SHA-256 of the look-alike table (not of a key).
- **view**: one named function that returns a key or a key-set for one purpose. The four view names are exactly `identity_key`, `id_key`, `scan_keyset`, `id_keyset` (the constant `VIEWS`); no other spelling is used anywhere (`names_equal` is a prose helper, not a view).
- **DENY decision**: "block this if it looks like a protected value" (blocklists, leak scans, same person); over-matching is the safe side. **ALLOW decision**: "accept only if it IS the verified value"; the fold is never used for it; `allow_equal` is the only allow path.
- **reading**: one complete way of turning a text into a key. A **key-set** is the small set of keys one text gets (one per reading); two texts match when their key-sets share a key. **FOLD_VERSION**: ONE string naming exactly which fold produced a key (P1a).
- **hidden channel**: a set of characters that show nothing (or almost nothing) and can carry text or bits. Exactly (defined once, used everywhere): (a) the tag block U+E0000 to U+E007F; (b) every character with the Unicode property `Variation_Selector`: U+180B to U+180D, U+180F, U+FE00 to U+FE0F, U+E0100 to U+E01EF (the property set, not a hand-written pair of ranges: round-4 finding A1); (c) a long run, or a large share of a text, made of characters that show nothing or almost nothing (the **invisible set**, defined exactly under Interface > Signals: every character `fold` removes because it is a format, control or private-use character, plus the Default_Ignorable code points outside those classes, plus the five fillers, minus a short named list `_EXCLUDED` whose members have their own rules; round-5 finding ADV-R5-1: it is NOT a hand-written list of a dozen characters). The two emoji selectors U+FE0E and U+FE0F are a special case (rule in Interface, `has_hidden_channel`). **refuse**: the caller treats the text as blocked.

## Which view each caller uses, and the stated limits
- **Blocklist and leak scan (DENY):** `prepare_needles` once, then `deny_hit` per text (scan view for words and names; id view for invoice numbers, account numbers and similar ids; a digit-only needle of 6 or 7 characters can be loaded in the scan view only, because the id-view minimum is 8; see `prepare_needles`). The caller treats `True` as "block". DENY comparisons use `scan_keyset` and `id_keyset` only, never `id_key` equality (ADV-R5-12).
- **Same person (DENY):** `same_person`. **ALLOW (accept only the verified value):** `allow_equal` only; never a key.
- **Lines of a document:** `line_view` (keeps the line structure). **Display or storage:** raw text; no key is stored (Interim rule).
- **Stated limits (not hidden):** (1) the scan view over-matches on purpose (`mark` is found in `tomark us` and in `market`; `Anna Maria` equals `Ann Amaria`); (2) the pass A/B case limit: a text that mixes capital and small Greek letters inside ONE word may be read one way only (`scan_match("ΗΗ","hn")` is False); (3) JSON, percent and `\x` escapes are not decoded; (4) digit-only needles are chance-matched in long numeric text: at 6 digits **about 4 % of random 50,000-digit tables and about 20 % of random 250,000-digit tables** hit one needle (prototype: 17 of 400 and 41 of 200; revision 6 wrote 8 % for the second, which was wrong; the evidence runner re-measures), at 8 digits 0 of 600 (prototype, small sample); (5) a hidden-channel haystack is refused by default, so a document with a long run of zero-width characters is blocked, never read; a document that contains an England, Scotland or Wales flag emoji is blocked too (rule 1 refuses the whole tag block); (6) no cache; (7) time is bounded by the budget, not by a promise per call; (8) the hidden-channel rules do not close every channel: up to 512 variation selectors (64 bytes), a bit channel below the run and share limits, and a channel made of combining marks or unassigned code points are neither refused nor decoded (stated under Signals; v1.1 rows).
