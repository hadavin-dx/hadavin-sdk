## Words used in this ticket (defined once)
- **redactor**: `guard/redact.py` `redact()`: it finds protected values (keys, e-mail addresses, card numbers, account numbers and so on, called **patterns** here) in text and replaces each with a **placeholder** such as `<EMAIL_1>`; the map placeholder-to-value is `RedactionResult.mapping`. **choke point**: `guard/runmap.py` `redact_text()`, the one function every production caller goes through (`guard/producers.py` lists 16 producers; `tests/test_k5_producers.py` enforces it).
- **look-alike**: a character that looks like another one (Cyrillic "a" for Latin "a", a full-width letter, a digit of another script). **fold** (`guard/textnorm.py` `fold`, from P1a): turns text into a form where look-alikes, invisible characters and accents are gone. An attacker uses look-alikes to hide a value from a pattern.
- **fold scan**: the second scan that PR #50 adds to `redact.py`: for a line with non-ASCII characters it also runs the patterns on the folded form of the line and, if the fold shows a protected value the line itself did not, it masks that value. **in place**: only the value is replaced, the rest of the line stays exactly as written. **withhold**: the whole line is replaced by the fixed note `FOLD_NOTE` plus the placeholders of the hits. The folded text is never shown.
- **written spelling**: the characters of a value exactly as they stand in the text the caller gave (`josé@exemple.fr` with the accent). **folded spelling**: what the fold makes of it (`jose@exemple.fr`).
- **budget**: `defaults.REDACT_BUDGET_S`, 6.0 seconds of work one `redact_text` call may use. **CPU time of the thread**: `time.thread_time()`, the processor time the calling thread used (not the wall clock). **wall time**: what a clock on the wall shows.
- **hole**: a text that this package knowingly leaves unmasked. Each hole in this ticket has a closing package, a trigger and an owner.
- **UTS #39 / UAX #15**: the Unicode standards for confusable characters and for normalisation; P1's look-alike table is generated from UTS #39.
- **stage 1 / stage 2**: inside `runmap.redact_text`, **stage 1** is the first `redact()` call, on the text itself; **stage 2** is the second `redact()` call, made for each extra view of the text (a decoded or normalised copy). The "check after stage 1" is the deadline check right after stage 1 (`runmap.py` line 496). (Revision 2 called these "pass one" and "the second pass".)
- **direct pass**: one run of the whole pattern table `PATTERNS` over one text. `defaults.py` (lines 45 to 48) says a single pass can take about 7 s on a hostile text. This is the only meaning of "pass" in this ticket; "one regex pass" and "one pattern pass" are not used (revision 2 used "pass" for two different things).
- **bare call**: calling `redact()` itself, not through `redact_text`.
- **sweep**: `redact.py` `sweep` / `_sweep` (lines 1294, 1485): the step that masks every other copy in clear of a value that is already masked. `_build` (line 1256) makes its rules from the values the run holds.
- **sweep_spellings**: the new sweep-only record (Interface): a dict from the folded spelling of a masked value to its placeholder, kept next to `mapping` so that `sweep` still finds clear copies after `mapping` holds the written spelling. `restore` never reads it.
- **raw output**: the `.text` that `redact()` returns, exactly as returned. A check on `fold(output)` is a check on a different text: `fold` drops tag characters and unassigned code points (fact V16), so a leak made of those cannot be seen there.
