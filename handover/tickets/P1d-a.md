## The problem in plain words
Before a person sees an approval card, two steps run on its text: a cleaning step (the "gate") and a redactor that replaces secrets and personal data with placeholders such as `<EMAIL_1>`. The gate runs FIRST and writes every dot of a web address or host name as `[.]`, so a chat app does not turn it into a link. After that the redactor no longer recognises `anna.m@example[.]org` as an e-mail address or `db01[.]corp[.]example[.]com` as an internal host name, so both are shown in full. Separately, the redactor treats `&` as the end of a password, so `password=ab12&cd34ef56gh78ij` shows `cd34ef56gh78ij`, on cards and in text sent to the model.

## Words used (defined once)
- **Gate** = `approvals/gate.py::sanitise_text` plus `withhold_commands`, called through `channel._neutralise_for_redaction` (renamed in rev 8: it runs BEFORE the redactor). **Defang** = writing each `.` of a domain or host as `[.]`.
- **Redactor** = `guard/runmap.py::redact_text`, the one function every caller goes through to redact (the "choke point"); it runs the `neutralise` hook on its input and on each decoded view BEFORE redacting.
- **Card path** = `channel.clean` and `SlackChannel._blocks`, both through `channel.redact_for_card(text, mapping)` = `defang_text(runmap.redact_text(text, mapping, neutralise=_neutralise_for_redaction))` (D1). **Model path** = `redact_text` with no `neutralise`.
- **Prose part** = text outside the body lines of a closed backtick fence and outside inline code (split by `_closed_fences` and `_INLINE_CODE`, as the gate does).
- **Query form** = an assignment whose key comes right after `?`, `&` or `&amp;` (`?password=x&next=/home`). **Plain form** = any other assignment (`password=x` in a config line or a message).
- **`&amp;` unit** = the five characters `&amp;` read as one character of a value (D2).
- **Over-mask** = text that is not secret but is hidden. Two kinds, counted apart: (a) text right after a secret (accepted by ORDER 166 item 2); (b) text after a host or logger name that holds a keyword, with NO secret before it (`token-service.internal.example.com: connection refused` hides `connection`): ORDER 166 item 2 does not cover it, NEEDS LEAD 1 decides. **Leak** = any part of a secret value still shown where the grammar says it is hidden (BS-1 labels it LEAK).
- **Key run** = a maximal run of key characters (`[\w.\-]`). **Atomic run** = the group `(?>[\w.\-]+)` that takes a whole key run and gives none of it back, so the engine tries each run once (D2). **Linear time** = the time of `redact_text` grows in proportion to the text length (checked by row HL1). **Frozen** = a value the tool wrote on the base worktree and the builder never edits.
- **Idempotent** = running it twice gives the same text as once. **Lookbehind / look-ahead** = a regex condition on the characters just before / after a position.
- Row classes: **fb** = fails on the base, passes after; **pb** = passes on the base with the same output; **ow** = accepted over-mask, counted.

## Design
- **D1 Defang after the redactor.** `sanitise_text(text, *, defang: bool = True)`; the internal helpers take `defang` as a REQUIRED argument (`_clean_line(line, defang)`, `_clean_prose(lines, defang)`, `_all_prose(lines, defang)`), so a call site that forgets it raises `TypeError` when it runs, and a row reaches every call site (PF1, PF2, E1, I2, FB1, FB2, H26). With `defang=False` `_clean_line` skips defang and writes wide dots as `.` on prose parts right after `normalise`, before the link steps (D4). **ZWSP rule kept:** with `defang=False` the "changed" test and the block test read `d = _defang_outside_code(c)`, so every line that gets a ZWSP today still gets one (Z1-Z4). The hook `channel._neutralise` is renamed `_neutralise_for_redaction` (it runs BEFORE redaction; the old name read as if it ran after) and passes `defang=False`. New `channel.redact_for_card(text, mapping) = defang_text(runmap.redact_text(text, mapping, neutralise=_neutralise_for_redaction))` is the ONE card-path redaction step. New `gate.defang_text(text)`: fences are read on the FINAL text (what a renderer reads); body lines of a closed backtick fence stay as they are; on every prose part, in this order: wide dots to `.`, D3, then `_NON_ASCII_HOST` and `_DOMAIN` again until the text stops changing (at most 4 passes: `digitalg‹.2` needs two); a paragraph whose inline code the gate reads differently from CommonMark is all prose (D6). The default `sanitise_text` keeps today's defang without D3 (`_defang_outside_code` keeps its expression, now through `_per_part`). The docstring of `sanitise_text` says, word for word: "`defang=True` (the default) writes `[.]` BEFORE any redactor, so its output must not feed a card; the card path uses `channel.redact_for_card`. `defang=False` leaves the dots for the redactor and writes wide dots as `.`." New `gate.undefang_text(text)`: on prose parts only, `[.]` between two name characters becomes `.` (the old gate wrote `[.]` only there). `clean` computes `out = redact_for_card(text, mapping)` and, when tags were removed, `alt = redact_for_card(joined, joined_map)`, and returns `alt` or `out`. `_blocks`: (1) `undefang_text(req.summary)` (summaries stored by the old code hold defanged, unmasked addresses); (2) `withhold_commands`; (3) `redact_for_card` (redact, then `defang_text`); (4) length check on the shown text. Model path: only the redactor changes (D2, D5).
- **D2 `&` follows the URL query grammar; a key is not cut at 40 characters.** The generic entry becomes two, same kind, PLAIN FIRST then QUERY (R4). **Key (atomic):** all four key entries (plain, query, the two quoted) read ONE key run that holds a keyword: a lookbehind starts the run, the look-ahead `(?=[\w.\-]*?KW)` tests that the run holds a keyword, and the atomic group `(?>[\w.\-]+)` takes the whole run. No bound before or after the keyword; each run is tried once, so the time is linear (rows HL1a-b). Rev 7 kept `[\w.\-]*` before the keyword and bounded the text after it to 255: P8 measured it up to 3.4x slower than base (3.22 s against 0.96 s at 262,144 characters, budget 6.0 s) and it left a key name over 255 characters shown (rev 7: N8, K42d); the atomic form is not slower than base on any probed input and hides those keys (rows K42a-e, K43a-d). KW = the key alternation of the base entry, copied unchanged into each entry. Cost: a key that holds a keyword and has a long harmless tail is hidden with its value (`tokenizer_max_sequence_length=512`), and so is a host name that holds a keyword: `token-service.internal.example.com: connection refused` hides `connection`, `secretsmanager.<region>.example.com:443` hides `443` (P9: 8 of 12 samples; base 0): measured by BS-1 shapes S8, S8b, S8c, S8d and the real-population differential, NEEDS LEAD 1 (not accepted by default). **Plain:** key lookbehinds `(?<![\w.\-?&])(?<!&amp;)`; value as today with `&` and the `&amp;` unit allowed (stops at white space, quote, `;`, the comma rule). **Query:** key lookbehind QLB = `(?:(?<=[?&])|(?<=&amp;))` (a key after `&amp;`, as in an HTML-escaped address, is a query key: row Q15); value as today plus: `&` continues the value unless the next segment is a field name followed by `=`. IDF = `[A-Za-z_][\w.\-]{0,20}=(?!=)` (a letter or `_`, then up to 20 letters, digits, `_`, `.`, `-`, then one `=` that no second `=` follows, so base64 padding `==` is not a field name: rows Q23, Q23c, S7c); QAMP1 = `&(?!(?:amp;)?IDF)`; QAMPU = `&amp;(?!IDF)`. Base64 padding and paths (`c+d/e=`) are not field names, so a secret holding them is hidden whole (rows Q18, S7b); a segment that does look like a field name is read as one (N4, row Q18b). Basis: in `application/x-www-form-urlencoded` `&` separates pairs and a literal `&` is `%26` (WHATWG URL Standard, section 5.1: UNVERIFIED, the network refused the page on 2026-11-09; BS-0 step 8 reads it and records the date). **`&amp;` unit:** the gate writes `&name;` as `&amp;name;` (R2), and `;` ends a value, so without it the card showed the part after `&` (P3). Plain reads `&amp;` as one character always; query reads it with the same field-name test as `&` (QAMPU). Both are tried before the single-character class. The fix sits in the redactor (all callers), not in the gate (whose rewrite is a reviewed defence).

- **D6 Inline code is read per paragraph.** The gate reads inline code per line (`_INLINE_CODE`), a renderer per paragraph, so a backtick pair that spans lines or is broken by a value left a name linkable (P9: 36 of 2,000 texts). `defang_text` reads the FINAL text: for each paragraph (markdown-it `inline` token with a line map) it compares the code spans CommonMark finds (`code_inline` children, `_cm_code` = one leading and one trailing space dropped when both are present and the span is not all spaces) with those `_INLINE_CODE` finds on its lines (lines holding a double backtick contribute none); when they differ, every line of that paragraph is defanged as prose (more defang, never less).
