## The problem in plain words
Before a person sees an approval card, two steps run on its text: a cleaning step (the "gate") and a redactor that replaces secrets and personal data with placeholders such as `<EMAIL_1>`. The gate runs FIRST and writes every dot of a web address or host name as `[.]`, so a chat app does not turn it into a link. After that the redactor no longer recognises `anna.m@example[.]org` as an e-mail address or `db01[.]corp[.]example[.]com` as an internal host name, so both are shown in full. Separately, the redactor treats `&` as the end of a password, so `password=ab12&cd34ef56gh78ij` shows `cd34ef56gh78ij`, on cards and in text sent to the model.

## Words used (defined once)
- **Gate** = `approvals/gate.py::sanitise_text` plus `withhold_commands`, called through `channel._neutralise_for_redaction` (renamed in rev 8: it runs BEFORE the redactor). **Defang** = writing each `.` of a domain or host as `[.]`.
- **Redactor** = `guard/runmap.py::redact_text`, the one function every caller goes through to redact (the "choke point"); it runs the `neutralise` hook on its input and on each decoded view BEFORE redacting.
- **Card path** = `channel.clean` and `SlackChannel._blocks`, both through `channel.redact_for_card(text, mapping)` = `defang_text(runmap.redact_text(text, mapping, neutralise=_neutralise_for_redaction))` (D1). **Model path** = `redact_text` with no `neutralise`.
- **Prose part** = text outside the body lines of a closed backtick fence and outside inline code (split by `_closed_fences` and `_INLINE_CODE`, as the gate does).
- **Query form** = an assignment whose key comes right after `?`, `&` or `&amp;` (`?password=x&next=/home`). **Plain form** = any other assignment (`password=x` in a config line or a message).
- **`&amp;` unit** = the five characters `&amp;` read as one character of a value (D2).
- **Over-mask** = text that is not secret but is hidden because it follows a secret (accepted by ORDER 166 item 2; measured apart from leaks). **Leak** = any part of a secret value still shown where the grammar says it is hidden (BS-1 labels it LEAK).
- **Key run** = a maximal run of key characters (`[\w.\-]`). **Atomic run** = the group `(?>[\w.\-]+)` that takes a whole key run and gives none of it back, so the engine tries each run once (D2). **Linear time** = the time of `redact_text` grows in proportion to the text length (checked by row HL1). **Frozen** = a value the tool wrote on the base worktree and the builder never edits.
- **Idempotent** = running it twice gives the same text as once. **Lookbehind / look-ahead** = a regex condition on the characters just before / after a position.
- Row classes: **fb** = fails on the base, passes after; **pb** = passes on the base with the same output; **ow** = accepted over-mask, counted.

## Design
- **D1 Defang after the redactor.** `sanitise_text(text, *, defang: bool = True)`; the internal helpers take `defang` as a REQUIRED argument (`_clean_line(line, defang)`, `_clean_prose(lines, defang)`, `_all_prose(lines, defang)`), so a call site that forgets it raises `TypeError` when it runs, and a row reaches every call site (PF1, PF2, E1, I2, FB1, FB2, H26). With `defang=False` `_clean_line` skips defang and writes wide dots as `.` on prose parts (D4). **ZWSP rule kept:** with `defang=False` the "changed" test and the block test read `d = _defang_outside_code(c)`, so every line that gets a ZWSP today still gets one (Z1-Z4). The hook `channel._neutralise` is renamed `_neutralise_for_redaction` (it runs BEFORE redaction; the old name read as if it ran after) and passes `defang=False`. New `channel.redact_for_card(text, mapping) = defang_text(runmap.redact_text(text, mapping, neutralise=_neutralise_for_redaction))` is the ONE card-path redaction step. New `gate.defang_text(text)`: fences are read on the FINAL text (what a renderer reads); body lines of a closed backtick fence stay as they are; on every prose part, in this order: wide dots to `.`, D3, `_NON_ASCII_HOST`, `_DOMAIN`. The default `sanitise_text` keeps today's defang without D3 (`_defang_outside_code` keeps its expression, now through `_per_part`). Its docstring says: `defang=True` writes `[.]` BEFORE any redactor, so it must not feed a card; the card path uses `channel.redact_for_card`. New `gate.undefang_text(text)`: on prose parts only, `[.]` between two name characters becomes `.` (the old gate wrote `[.]` only there). `clean` computes `out = redact_for_card(text, mapping)` and, when tags were removed, `alt = redact_for_card(joined, joined_map)`, and returns `alt` or `out`. `_blocks`: (1) `undefang_text(req.summary)` (summaries stored by the old code hold defanged, unmasked addresses); (2) `withhold_commands`; (3) `redact_for_card` (redact, then `defang_text`); (4) length check on the shown text. Model path unchanged.
- **D2 `&` follows the URL query grammar; a key is not cut at 40 characters.** The generic entry becomes two, same kind, PLAIN FIRST then QUERY (R4). **Key (atomic):** all four key entries (plain, query, the two quoted) read ONE key run that holds a keyword: a lookbehind starts the run, the look-ahead `(?=[\w.\-]*?KW)` tests that the run holds a keyword, and the atomic group `(?>[\w.\-]+)` takes the whole run. No bound before or after the keyword; each run is tried once, so the time is linear (rows HL1a-b). Rev 7 kept `[\w.\-]*` before the keyword and bounded the text after it to 255: P8 measured it up to 3.4x slower than base (3.22 s against 0.96 s at 262,144 characters, budget 6.0 s) and it left a key name over 255 characters shown (rev 7: N8, K42d); the atomic form is not slower than base on any probed input and hides those keys (rows K42a-e, K43a-d). KW = the key alternation of the base entry, copied unchanged into each entry. Cost: a key that holds a keyword and has a long harmless tail is hidden with its value (`tokenizer_max_sequence_length=512`), and so is a host name that holds a keyword: `token-service.internal.example.com: connection refused` hides `connection`, `secretsmanager.<region>.example.com:443` hides `443` (P9: 8 of 12 samples; base 0): measured by BS-1 shapes S8, S8b, S8c and the real-population differential, NEEDS LEAD 1. **Plain:** key lookbehinds `(?<![\w.\-?&])(?<!&amp;)`; value as today with `&` and the `&amp;` unit allowed (stops at white space, quote, `;`, the comma rule). **Query:** key lookbehind QLB = `(?:(?<=[?&])|(?<=&amp;))` (a key after `&amp;`, as in an HTML-escaped address, is a query key: row Q15); value as today plus: `&` continues the value unless the next segment is a field name followed by `=`. IDF = `[A-Za-z_][\w.\-]{0,20}=(?!=)` (a letter or `_`, then up to 20 letters, digits, `_`, `.`, `-`, then one `=` that no second `=` follows, so base64 padding `==` is not a field name: rows Q23, Q23c, S7c); QAMP1 = `&(?!(?:amp;)?IDF)`; QAMPU = `&amp;(?!IDF)`. Base64 padding and paths (`c+d/e=`) are not field names, so a secret holding them is hidden whole (rows Q18, S7b); a segment that does look like a field name is read as one (N4, row Q18b). Basis: in `application/x-www-form-urlencoded` `&` separates pairs and a literal `&` is `%26` (WHATWG URL Standard, section 5.1: UNVERIFIED, the network refused the page on 2026-11-09; BS-0 step 8 reads it and records the date). **`&amp;` unit:** the gate writes `&name;` as `&amp;name;` (R2), and `;` ends a value, so without it the card showed the part after `&` (P3). Plain reads `&amp;` as one character always; query reads it with the same field-name test as `&` (QAMPU). Both are tried before the single-character class. The fix sits in the redactor (all callers), not in the gate (whose rewrite is a reviewed defence).
- **D4 Wide dots on the card path.** `_wide_ascii(part)` writes U+3002, U+FF0E and U+FF61 as `.`. With `defang=False` every prose part of every line goes through it, so the redactor on the card path reads `anna。m@example。org` as an address (rows D4a, D4b); inline code is not touched (row D4c). The model path is not changed (NEEDS LEAD 2).
- **D3 Placeholder next to a dot.** The redactor masks only the internal part of a host (`<HOSTNAME_1>.example.com`), and `_DOMAIN` does not start a name after `.`, so `example.com` would stay (linking by Slack or GFM: UNVERIFIED; defanged on the safe side). `_PLACEHOLDER_DOT` writes `<KIND_n>.` + name character as `<KIND_n>[.]`. `\w` is Unicode. No left boundary (more defang, never less). `<A_1>.<B_2>` unchanged.

```python
# src/hadavin_sdk/approvals/gate.py   (imports: from collections.abc import Callable)
_PLACEHOLDER_DOT = re.compile(r"(<[A-Z][A-Z0-9]*_[0-9]+>)\.(?=[\w-])")
_LEGACY_DOT = re.compile(r"(?<=[\w-])\[\.\](?=[\w-])")
def _defang_plain(part: str) -> str:
    return _DOMAIN.sub(_defang, _NON_ASCII_HOST.sub(_defang, _WIDE_DOTS.sub(".", part)))
def _defang_prose(part: str) -> str:
    part = _WIDE_DOTS.sub(".", part)
    part = _PLACEHOLDER_DOT.sub(r"\1[.]", part)
    return _defang_plain(part)
def _per_part(line: str, fix: Callable[[str], str]) -> str:
    parts = [line] if "``" in line else _INLINE_CODE.split(line)
    return "".join(part if i % 2 else fix(part) for i, part in enumerate(parts))
def _defang_outside_code(line: str) -> str:        # docstring kept; body:
    return _per_part(line, _defang_plain)
def _outside_code(text: str, fix: Callable[[str], str]) -> str:
    body = {i for s, e, ch in _closed_fences(text) if ch == "`" for i in range(s + 1, e)}
    return "\n".join(line if i in body else _per_part(line, fix) for i, line in enumerate(text.split("\n")))
def defang_text(text: str) -> str:
    return _outside_code(text, _defang_prose)
def undefang_text(text: str) -> str:
    return _outside_code(text, lambda part: _LEGACY_DOT.sub(".", part))
# def _wide_ascii(part: str) -> str:   return _WIDE_DOTS.sub(".", part)

## Goals and Non-Goals
**Goals.** (G1) E-mail addresses and internal host names are masked on cards as on the model path, including requests stored before the fix. (G2) No linkable name outside code in the FINAL card text (property-tested on text without a backtick; the backtick cases are pinned by rows, N8). (G3) In plain form `&` no longer ends a password: the value runs to the first white space, quote, `;` or comma that starts `key=value`, as today (`password=ab&cd34;ef56` hides `ab&cd34` and shows `;ef56`, row SC1). In query form a value ends at `&` or `&amp;` only before a `key=value` segment whose name has at most 21 characters (a longer name is over-mask: row Q25). The card hides exactly what the model path hides for these values, including where the gate rewrote `&name;` (H34d, Q12, NE1). (G4) Card structure and command withholding unchanged (exact differential; the new card may withhold more, never less).
**Non-Goals.** (N1) Addresses split by formatting (H28a-b): P1d (ORDER 180). (N2) Over-mask in plain form (`password=hunter22&user=bob` hides `&user=bob`; `password=&user=bob` hides `&user=bob`) and of `=`-less query segments: accepted, measured by BS-1. (N3) Which names count as hosts. (N4) A query secret holding `&name=` with a field-name-shaped `name` is read as two fields, as the URL grammar says; the part after `&name=` is shown (measured as S7a, not gated; row Q18b; the report gives the number of S7a samples that show a part of B, on base and new). (N5) On the model path a host written with wide dots is not recognised as a host: NEEDS LEAD 2 (the card path is fixed, D4). (N6) A `#` fragment is not a separator; OAuth fragment links are not claimed. (N7) The gate removes schemes (`https://...` becomes `[link removed]`) and Slack mentions BEFORE redaction, also inside code spans (P8: rows BTK2, MENT1), so a value that swallows a closing backtick cannot make them live; this ticket does not repeat that after redaction. A bare domain in an un-paired span is the one case left to `defang_text` on the final text (row BTK1). (N8) A backtick pair that spans lines or is broken by a value can leave a name linkable: the gate reads inline code per line, a renderer per paragraph (P9: 36 of 2,000 generated texts, all with a backtick; base 222): not fixed here, NEEDS LEAD 8. (N9) A name behind a wide dot after `/` (`//evil。com/p`) is neither defanged nor removed, on base and after (P9; the ASCII form becomes `[link removed]`): not fixed here, NEEDS LEAD 8.
