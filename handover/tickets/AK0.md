## What AK0 is, in one paragraph
AK0 is a written note, `handover/ak0-decisions.md`, plus a folder of dated source notes, `handover/evidence/AK0/`. It writes down what the core already has for the Assembly Kit's document-question parts (RAG). For each part it lists the ready-made options on the tool ladder, with licence, cost and risk, and records one decision per part with the evidence behind it. The decisions that only the owner can take (licence and cost approval, scan reading, any spend) go to the lead with the numbers. Every later kit ticket (AK1 to AK4b) reads its defaults from this note instead of re-arguing them. AK0 builds nothing, installs nothing, signs up for nothing and spends nothing.

**Judging rule for every option row, applied in this order. The first rule an option fails rejects it:**
- **J1 licence.** Allows use in a closed, paid client build without releasing our code, when used as an unmodified library. - **J2 data path.** Runs inside the client's own cloud with no new outside party that sees client text (sub-processor). An option with a new outside party can be an alternative only, named as a sub-processor (GAPS G6, C2).
- **J3 cost** at the reference workload below.
- **J4 upkeep.** The project's own page shows a release within the last 12 months and more than one maintainer. Both are read and dated.
