Words used here. The *redactor* is the pattern-based masking code (`guard/redact.py`, reached through `guard.runmap.redact_text`). A *placeholder* is what it writes in place of a value (`<EMAIL_1>`). The *fixed mask* is the text `<SECRET_REDACTED>`. The *map* is the per-case list "placeholder -> original value"; a value in the map is *registered* and the redactor replaces its copies in every other text of the case. A *credential key* is a key whose name says its value is a login secret (rule in 1f). A *setting key* is a credential key whose last word says the entry is a setting about a credential (`password_policy_enabled`). A *card* is the text a person reads in a chat channel before approving an action. *Bracketing* a dot means writing `evil[.]com` so a chat program makes no link. *Outside code* means: not in the body of a closed backtick fence of the text (`gate._closed_fences`) and not in a single-backtick span of a line that has no double backtick.

## Behaviour 1: `k1b/redaction.py` (prototype text: appendix B)
1a. `_pair` accepts the redactor's result only when (i) it starts with `<key written>=`, (ii) if this function wrapped the value in a quote, the rest starts and ends with that quote, and (iii) what remains fully matches `_ONLY_PLACEHOLDERS = re.compile(rf"(?:{runmap.PLACEHOLDER.pattern})+")`. Anything else: next attempt; none left: `f(value)`, `return MASKED`. At most 4 calls of `f` per value (2 spellings x 2 attempts) plus the final one.
1b. What is written to the redactor. `FALLBACK_KEY = "secret"`, `MAX_SPELLING_CHARS = 255`, `MIN_REGISTER_CHARS = 8`, `_PLAIN_CHARS` = the visible ASCII characters U+0021 to U+007E minus `; & , " '` (an allowlist), `_SAFE_KEY = [A-Za-z0-9_.-]{1,60}`. For one spelling `text`:
- empty, or longer than 255 characters: nothing is tried.
- under a NON-credential key of a Secret: tried only when it has at least 8 characters and is neither all digits nor one run of lower-case letters (`[a-z]+`); otherwise nothing is tried, so the entry gets the fixed mask under its key as on main and its words (`info`, `true`, `prod`, `5432`, `postgres`, `orders`) are NOT replaced elsewhere.
- plain (every character in `_PLAIN_CHARS`): under a credential key that fully matches `_SAFE_KEY`, `key=text` then `secret=text`; otherwise only `secret=text`.
- not plain: NEVER under its real key, never unquoted: `secret="text"` if it holds no `"`, else `secret='text'` if it holds no `'`; both quote marks: nothing is tried.
- Spellings: the value as written and, when it decodes (line 109), its base64-decoded text. Outside a Secret the FIRST accepted spelling is returned. Inside a Secret (`known_secret=True`) every spelling is tried and the result of the LAST accepted one (the decoded text) is returned, so the placeholder under the key is the one in the log line (A2 row "M1 row 35 same placeholder": `<SECRET_3>` in both).
1c. `_walk(obj, f, key=None, secret_data=False, known_secret=False)`. `known_secret` is passed on unchanged to dict values, lists and tuples and to the env-entry value; it is set for the entries of `data` / `stringData` of a Secret. Lists and tuples pass `sens` (not `secret_data`) down, so an item of a list under a credential key is treated as under that key. A string under a non-credential key with `known_secret=False` (merely nested under a credential key) tries nothing: `f(value)`, fixed mask, as today.
1c-bis (F5c). A dict is a Secret when its `kind` is `"Secret"`; its `data` / `stringData` are looked for directly in it AND in its `spec` when `spec` is a dict (helper `_walk_dict(obj, f, sens, known_secret, secret)`, appendix B). Registration is capped: only the first `MAX_REGISTERED_ENTRIES = 256` entries of one `data` / `stringData` are passed `known_secret=True`; later entries get the fixed mask. Why: every registered value makes each later redaction slower (measured, two passes, entries under non-credential keys: 256 entries 2.1 s, 1,000 entries 26.4 s without the cap and 6.4 s with it; the same growth exists on main for one-word values under credential keys: 1,000 entries 11.9 s on main). The cap is per Secret, not per case: the total across many Secrets is not bounded here (Q8d).
1d. Kept: a string that is exactly a UTC timestamp (`parse_ts`) passes unmasked under a credential key. Near misses are masked (A2 rows "1d").
1e. BEHAVIOUR CHANGE, stated: an entry of a Secret that passes the 8-character rule of 1b is registered (as written and base64-decoded) and replaced wherever it appears in the case, within the limits below. Measured on the fixture (A3; replaces the replay-score condition of D-011): outside the Secret, of 114 strings, main changes 0 and the branch 1 (23 characters, 1 distinct log line: the made-up database password becomes the same placeholder as under its key); the evidence IDs returned by 24 tool calls with the masked spellings are equal on main and branch (24 of 24; 20 return records); the shown `level` values (`error`, `info`) and `service` values (`api`, `db`, `orders`, `postgres`) are unchanged. Cost that remains: a non-secret entry of 8 or more characters that is not one lower-case word (`orders-svc`) disappears from log lines the model reads.
1f. Credential-key rule, one function `sensitive(key)` replacing `SENSITIVE_KEY` (88-91) and 97-100. Words = the key split at camelCase boundaries, then at `_ . -` and white space, lower-cased, trailing digits of a word removed (`password2`). `sensitive(key)` is true when some word is in `CREDENTIAL_WORDS`, or ends with one of `GLUED_ENDINGS`, or forms with the word before it a pair in `WORD_PAIRS`, or is `tokens` unless the word before it is one of `max, min, input, output, prompt, completion, total, cached` or the word after it is `used` (lists: appendix B). **`sensitive(key)` has no setting-word exception: every key main accepts is accepted (random check with no exclusion: 200,000 keys, 107,041 accepted by main's rule, 0 of those refused).** The redactor's key words of `redact.py:598-606` are all added (`session`, `sessionid`, `jsessionid`, `phpsessid`, `sessid`, `auth`, `account_key`, `key_data`, `cert_data`, `certificate_data`, `connect.sid`); none is left out. Costs, stated in the docstring and CHANGELOG: `auth_method`, `session_duration`-like keys and env entries named `PWD`, `OLDPWD` or ending in `pwd` are masked.
Separately, `_setting_key(key)` is true when `sensitive(key)` and the last word is in `SETTING_WORDS = {enabled, disabled, required, policy, length, count, age, days, ttl, expiry, expires}`. In `_walk`, a value under a `_setting_key` (own key or env-entry name) is left unmasked ONLY when it is a bool, None, an int or float, a timestamp (`parse_ts`), or a string that fully matches `(?i)true|false|yes|no|on|off|none|[0-9]{1,10}[smhdw]?`. Every other string, and every dict or list under it, is treated exactly as under a credential key (as on main). Author's narrowing, fail closed: the gate applies only when the mask comes from the key itself, not when the entry sits under another credential key or in a Secret (A2 row "gate under a credential parent").
Env-entry shapes: a dict with a key whose lower-case form is `name` or `key` AND a key whose lower-case form is `value`, whose name is a credential key: its value, whatever its type, goes through `_walk(value, f, str(name), sens, known_secret)`. Bytes are not a route: bundles are strict JSON (`k1b/bundle.py:112`).
1g. `LIMITS` becomes exactly this text (it is printed in reports, `k1b/report.py:70,84`; the prototype's full suite ran WITH it): "The redactor is pattern based. It does not catch names in free text, customer or project names, ticket numbers, values in unusual formats, or anything else no pattern matches. A value under a key that names a credential, and every entry of a Kubernetes Secret, is always masked under its own key. The same value is also masked where it is repeated elsewhere in the case only when all of this holds: it is a text of 4 to 255 characters directly under that key; it is made of printable ASCII characters and white space; it does not hold both kinds of quote mark; no part of it is something another pattern masks (an e-mail address, a host name, a key); and the copy is spelled the same way. An entry of a Secret under a key that does not name a credential is masked elsewhere only when it also has at least 8 characters and is not all digits or one lower-case word. Not masked where repeated: longer or shorter values, numbers, values nested deeper under a credential key, values with control or other special characters, and copies in another spelling (base64, capitals, wrapped over lines). A setting about a credential (a key that ends in enabled, policy, count, expiry and the like) is shown only when its value is a yes or no word, a number or a time. Masking is a first filter, not proof that no client data reached the model." The `_pair` docstring says the same in short and names the timestamp exception.

## CHANGELOG ("## Unreleased"; existing headings "### Upgrade steps", "### Added", "### Changed")
Under "### Upgrade steps":
- **Approval cards mask identifiers outside code.** An e-mail address, a host name or another identifier outside code was shown with brackets in its dots; it is now a placeholder (`<EMAIL_1>`). A target system or an input shaped like a host name is shown as `<HOSTNAME_n>`: the approver cannot read it on the card; numbers are local to one card. Summaries stored before the upgrade keep their old text.
- **Incident cases: more keys count as credential keys.** `PGPASSWORD`, `pwd`, `secretkey`, `secrets`, `accessKey`, `DBPassword`, `api_tokens`, `session`, `auth`, `account_key`, `client-key-data`, `password2` and env entries written `Name`/`Value` or `key`/`value` are masked, also when the value is a number or a list. Cost: `auth_method`-like keys and env entries named `PWD` or `OLDPWD` are masked. A setting about a credential (`password_policy_enabled`, `token_expiry`, `secret_count`) is shown only when its value is a yes or no word, a number or a time; any other value under it stays masked.
- **Incident cases: entries of a Kubernetes Secret.** A Secret whose `data` sits under `spec` (the shape a case file has) is now recognised; before, its entries were shown as written. An entry of at least 8 characters that is not all digits or one lower-case word is replaced wherever it appears in the case, within the limits listed under Changed; shorter and common values (`info`, `true`, `5432`, `orders`) are masked under their key only. At most 256 entries of one Secret are treated this way.
Under "### Changed":
- **Fixed: a value under a credential key was shown partly masked** when it held a space, a tab, a line break, an escape character, `;`, `,`, `&` or a quote mark. It is now shown only as placeholders, or as `<SECRET_REDACTED>`.
- **Masked where repeated, with limits.** The `LIMITS` text of 1g, word for word (follow-up Q8d).
- **Fixed on cards:** a domain that ends up outside code after masking is bracketed; masking no longer creates a mention. Limits, same entry: masking is pattern based; an address written with a wide dot (`。`) inside a code fence or inside inline code is still shown.
