## Words used in this ticket (defined once)
- **alert message**: the message the monitoring tool (Datadog in the demo) posts in the client's Slack channel when an alert fires.
- **threaded reply**: a Slack message posted "in the thread" of another message, shown under it. Slack identifies the parent by the channel id and its time stamp, called `thread_ts`. **thread reference** (`ThreadRef`): that pair.
- **notice**: one incident summary posted (or to be posted) as a threaded reply. **notice record**: the stored row that makes a notice post once.
- **portal link**: the address of the incident's page in our portal, built by our code from the config value `portal_base_url` and the incident id.
- **choke point**: `approvals/channel.py` `clean()` (`:18-39`): removes links, images, HTML, mentions and control characters, withholds commands a person could paste, then runs ONE redaction through `guard/runmap.py` `redact_text`, the one function every text producer goes through (`guard/producers.py:1-9`).
- **recipient gate**: AK-G22's one path for text sent TO a person or system (`tickets/AK-G1.md:27`); no ticket exists yet.
- **policy level**: the config field `environment: Literal["dev","pilot","prod"]` (`config.py:317`). **environment name**: the new display value (for example `demo`); it is NOT the policy level.

## What JG-3 is and is NOT
It IS: a new capability `notifier` with kinds `recorded` (neutral default, dev only) and `slack`; the service `notify_incident`; the notice record (4 store methods on memory and Postgres, one migration); a `tick` step that retries; the config block `notify:`; one move of the Slack HTTP call so both Slack kinds share it. It is NOT: finding the alert message (JG-2); the portal pages or sign-in (JG-4, AK-G17); the recipient gate (AK-G22); e-mail or Teams backends (outline rows V1, V2); edits or deletes of a posted reply; mentions; buttons; any model call (no money path).

**Existing channel kind checked: this is a NEW kind, not an extension.** What `channel` offers today: approval cards and decisions (`approvals/channel.py:69-82`: `send`, `update`, `notify`, `post_card`, `parse_decision`); Slack `chat.postMessage` with no `thread_ts` (`approvals/slack_channel.py:124-133`, `:166-175`, `:195-198`); text that is link-free by contract (`channel.py:1`, `:19-21`; `slack_channel.py:7-9`); `post_card` never raises but records nothing and never retries (`slack_channel.py:161-178`); `Delivery.ref` is kept "for threads and updates" (`approvals/cards.py:37`) but nothing threads. A notice needs a thread, one code-built link and a stored once-only record; adding them to `Channel` would weaken the approval contract (design, Alternative A). Reused from it: `clean()`, the Slack HTTP call (moved, not copied), the https check and secret-name pattern of the Slack factory (`slack_channel.py:206-216`).
