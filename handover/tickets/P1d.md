## Words used in this ticket (defined once)
- **The clean function** = `approvals/channel.py::clean` (`:18-39`): the one function every approval text passes before a person sees it (cards, the approval summary, notices). It runs the gate's cleaning (`gate.sanitise_text`, then `gate.withhold_commands`) as the `neutralise` hook of ONE `runmap.redact_text` call, plus a second call on the text with HTML tags deleted.
- **A view** = another spelling of the same text that a reader or a renderer may see: markers deleted, entities decoded, escape sequences deleted, control characters deleted, look-alike letters folded.
- **Known value** = an original the redactor masked in this text (the run map of this call) or would mask in any VIEW of it (found by a learning pass, below).
- **Refuse** = raise `runmap.LookalikeCopy` (a `RedactionError`; the name and meaning are those of `designs/lookalike-leak.md` section 5): nothing of the text is shown; the existing fallback path of the caller runs, and a person looks.

## The problem in plain words
An approval card shows a person what an agent wants to do. Before it is shown, the clean function replaces secrets and personal data with placeholders such as `<APIKEY_1>`. But the redactor looks only at the text as written. If a secret is written with formatting characters inside it, for example `AKIA**IOSFODNN7EXAMPLE**` (two asterisks make the second half bold), the pattern does not match, the text is shown as written, and Slack or a Markdown viewer shows the whole key in one piece. The same happens with a terminal colour code inside the key, a backspace, a carriage return, an accent mark, or look-alike letters. A second hole of the same kind, found while writing this ticket: the clean function changes every `.` in a domain into `[.]` BEFORE the redactor runs, so a plain e-mail address or internal host name is never masked (`anna.m@example[.]org` is shown).
