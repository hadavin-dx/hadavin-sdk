## Interface
- **Command:** `python tools/proof_pack.py [--data <dir>]`. Default `--data` is `demo_only/proof_pack` relative to the repo root, found as `Path(__file__).resolve().parents[1]` (C-F17). There is no `--store` flag (D-F3 option a).
- **Config (C-F1, C-F2, D-F8):** the pack calls the core loader `hadavin_sdk.config.load_config(<data>)` (`config.py:436`; it reads `<data>/config.yaml`, `Config` is `extra="forbid"`, `config.py:52`). The file holds the real keys: `environment` (`config.py:317`; the one value where the core allows fake kinds, `config.py:366-369`), `routes` (one made-up route: `model_id`, two prices, `max_tokens`, `config.py:55-59`), `golden_dir`, `inputs_dir`, `backends.llm: {kind: fake, recorded_dir}` and `backends.audit: {kind: local_dir, dir}` (not in `DEFAULTS`, `backends/table.py:582-589`); store, channel, secrets, signer, anchor, detector take their defaults. The pack has NO stage or environment literal of its own: a non-demo environment with fake kinds is refused by the core (`ConfigError`), and the pack maps any `ConfigError` to exit 2. The pack's own check is only that `cfg.backends.llm.kind`, `.channel.kind` and `.store.kind` are `fake`, `fake`, `memory` (no live call, no network).
- **Step table (D-F6):** `EXPECTED_KINDS = ("textnorm", "stop_state", "meter", "redactor", "store", "diagnostic", "wall_alert")` is a fixed tuple; `STEPS: dict[str, Callable]` maps kind to step. Lines are printed by walking `EXPECTED_KINDS`, never `STEPS`: a kind missing from `STEPS` prints `runs=0 result=FAIL`.
- **Output:** per kind in that order, `proof_pack kind=<name> runs=<n> result=ok|FAIL`, with ` error=<ExceptionClass>` appended when the step raised (C-F6); then `proof_pack total_kinds=7 failed=<k> store=memory`. A refusal prints `proof_pack refused: <reason>` and no kind line.
- **Exit codes:** 0 = every kind `runs>=1` and no check failed; 1 = any kind `runs=0` or any check failed; 2 = refused before any step (`ConfigError`; llm, channel or store kind not fake/fake/memory; data folder or one of its files missing or empty), or the redactor step found no recording (`llm/fake.py:47` `UnknownRecording`: a data error, printed as `refused: no recording <name>`, not a kind failure; D-F5).
- **Counting rule (D-F2, C-F12):** a run counts only when (a) the step called the kind through one helper `_call(kind, fn, *args, **kw)`, (b) `fn` (or its `__func__` for a bound method) IS one of the objects in `ALLOWED[kind]` (identity, `is`; never `__module__` or `__name__`, which a stand-in or `functools.wraps` can copy), and (c) the step's check of the returned value passed. An exception is never swallowed: the count stays 0 and the class name is printed. The printed lines and the exit code are computed from one counter dict, which `main()` also returns (for the tests). Each kind gets a FRESH `MemoryStore`, `FakeChannel` and `FakeLLM` (C-F4), so one step's state (a stop switch left on, a spent day) can never make another step pass.
