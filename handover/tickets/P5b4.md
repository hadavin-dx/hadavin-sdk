## Words used in this ticket (defined once)
- **Foreign text:** any text our code did not write: a library's message, a document line, model output, the text of an exception (design zone T2). It must never be printed.
- **Own line:** a line written by the output guard itself, built only from fixed words, closed lists and P5a's `render(diagnose(...))`, or a line whose text P5b3 owns and whose writer is `output_guard.emit` (see Boundary).
- **Unattended tick:** the `hadavin-sdk tick` command, run by a scheduler every 30-60 s. Its stderr is a log stream that nobody reads live, so nothing raw may reach it.
- **Process entry:** the function that runs when the program is started as a command. After P5b4 that is `hadavin_sdk.output_guard:cli_entry` (console script) and the `__main__` block of `cli.py`. Today it is `hadavin_sdk.cli:main` (`pyproject.toml:46-47`) and `cli.py:413-414`. A test or an embedding program that calls `cli.main([...])` directly is **library mode**.
- **Install session:** the time from the first `bootstrap_logging` call (made when no level is installed) to the pop of its last level. One session has one `LoggingHandle`.
- **Stream guard:** a replacement for `sys.stderr` and `sys.stdout` that rewrites every line written through it to `stream_line len=N`, so the text is dropped and only its length is kept. (Revision 2 called this line `stderr_line`; it is renamed because the same guard rewrites stdout.)
- **fd 2 / fd 1:** the operating system's file numbers for stderr and stdout. Code in C (and `os.write(2, ...)`) writes to them directly and goes around any Python object.
- **Audit point:** a place where the guard lists the log handlers it did not install (foreign handlers) and, at process entry, removes them.

## What this package is, in one paragraph
P5b4 is step R2 of the frozen redesign (D13: R1, R1P, R3a, R3c+R3b, **R2**, R5). P5b3 makes the TEXT of our own error lines safe: each one becomes `render(diagnose(exc))` or checked operator text. P5b4 closes the **other channels** through which foreign text reaches a terminal or a log:
- (1) third-party log records, which today print their full message;
- (2) tracebacks (`exc_info`, the interpreter's own crash printer, threads, errors in finalizers and at shutdown);
- (3) `warnings`, which print the text a library passed in;
- (4) `argparse` error text, which echoes the value the user typed;
- (5) `print()` from a dependency during the unattended tick;
- (6) writes in C to fd 2 and fd 1 during the unattended tick.

It does this with one new top-level module, `src/hadavin_sdk/output_guard.py`, and a small change to `cli.py`. The `HADAVIN_DEBUG` branch is not in P5b4: P5b3 deletes it (see Boundary).

- **Interface (names, argument and return types, errors):**
  - `bootstrap_logging(*, unattended: bool = False, library_mode: bool = False) -> LoggingHandle`. Signature as D9.
    - **Session lifecycle (revision 3).** A call made when no level is installed starts a new install session: it creates a NEW `LoggingHandle` and reads `sys.stderr` and `sys.stdout` at that moment (these are the captured streams of the session). A call made while a level is installed returns that same handle. When the last level is popped, the session ends and the module forgets the handle. So a later session never writes to a stream captured by an earlier one (for example, a closed `capsys` stream of an earlier test).
    - **Levels, not a flag:** the handle keeps a stack of install levels. Each call pushes one level that records only the globals THAT call changed: the first call of a session changes all of them; a repeat call changes nothing; a call with `unattended=True` on a handle that is not yet unattended changes the stream guard, the `OwnHandler` level and the root level (both to INFO), and at process entry the fd redirect.
    - **What the first call installs:**
      - one `OwnHandler` on the root logger, level INFO when unattended and WARNING otherwise; the root logger's level is set to match. Unattended gives INFO and non-unattended gives WARNING, the same as today: `cli.py:287` gives INFO for the tick, and `lastResort` gives WARNING otherwise. The tick upgrade sets INFO too, because at process entry and in library mode the first call is not unattended (the command is not known yet);
      - `logging.raiseExceptions = False`;
      - `logging.captureWarnings(True)`;
      - `logging.lastResort` set to the same `OwnHandler` instance, so a record on a logger with no handler (for example `propagate=False`) still goes through our rules;
      - `sys.excepthook`, `threading.excepthook` and `sys.unraisablehook`.
    - **Unattended:** installs the stream guard on `sys.stderr` and `sys.stdout` (also in library mode, so the in-process tick tests see it).
    - **fd redirect:** happens only when `unattended` is True **and** `library_mode` is False. A non-tick command at process entry never redirects (U24).
    - **Order inside the upgrade at process entry:** (1) the fd redirect, (2) the stream guard, (3) the two levels. If the redirect fails, nothing is guarded yet, so only the partial redirect is undone (see fd redirect) and the process exits 2.
    - **Foreign-handler removal:** happens whenever `library_mode` is False, and only at the audit points below.
  - `LoggingHandle.uninstall() -> None`: pops ONE level and restores the globals that level changed: by identity the root handlers, `raiseExceptions`, the `captureWarnings` state, `logging.lastResort`, the three hooks, `sys.stderr` and `sys.stdout`; by value the root level (10 globals). A level pushed by the tick upgrade also restores, by value, the `OwnHandler`'s level it recorded. The pop flushes any half-written line of the stream guard first when that level installed it. When the stack is empty, a further call does nothing. **It never touches fds:** at process entry nothing is uninstalled (Shutdown), and library mode never redirects.
    - **Lock:** `emit`, the stream guard's `write` and `uninstall` share one `threading.RLock` (re-entrant). Reason: a garbage-collection pass can run a finalizer that raises while `emit` or a guarded `write` holds the lock, and `sys.unraisablehook` then calls `emit` in the same thread; a plain `Lock` cannot be taken again by its owner and the tick would hang (probe). What re-entry can do: the stream guard only ever outputs lengths, so a re-entrant guarded write can at worst merge or split one length count. It can never let text through. `uninstall` waits for a write in flight in another thread.
    - An embedder's own `bootstrap_logging` level survives `cli.main`'s `finally`, because `main()` pops only the levels it pushed.
  - `output_guard.emit(line: str) -> None`: **the one own-line writer** (revision 3). It writes through the live session's handle (`LoggingHandle.emit`). When no session is live, it writes the same escaped single line to `sys.stderr`; with no guard installed there is nothing to go around. `cli.py` (`main()`, `_tick`) and `cli_entry` call `output_guard.emit`, so `_tick` needs no new parameter.
  - `LoggingHandle.emit(line: str) -> None`: writes to the stream captured when the session started. If fd 2 was redirected, that is a new stream opened on a saved duplicate of the real fd 2 (see "fd redirect"). The line must be ASCII and one line: anything else is escaped with `backslashreplace`, and `\n` becomes `\\n`.
  - `audit_handlers(owned: Collection[logging.Handler], *, remove: bool = False) -> list[tuple[str, str]]`: signature as D9 plus the `remove` flag.
    - It lists every handler on root and on every value of `logging.Logger.manager.loggerDict` that is a `logging.Logger` (other values, such as `logging.PlaceHolder`, have no `handlers` and are skipped; probe), that is not in `owned` and is not exactly `logging.NullHandler`. Each entry is (logger name group, `class_name_of(type(h))` from P5a). The group is `hadavin_sdk` for an own logger name (rule below), `py.warnings` for that exact name, and `other` for everything else.
    - **At process entry** each entry is emitted as `foreign_handler logger=<group> class=<cls>`, and with `remove=True` the handler is removed. Then, if the `OwnHandler` is no longer on root (for example after a library called `logging.basicConfig(force=True)`), it is re-added and the line `own_handler_restored` is emitted.

    - It calls `main(argv, _process_entry=True)`, then audit point 5, then flushes `sys.stdout` through the guard, then `sys.exit(code)`. At process entry the handle is **not** uninstalled before exit (see Shutdown).
    - **Exit mapping (PENDING LEAD 10).** `main()` catches `KeyboardInterrupt` itself and does not catch `SystemExit` or other `BaseException`s. `cli_entry` catches what is raised anywhere inside it and maps it:

      | What reached `cli_entry` | Exit code | What is printed (through `output_guard.emit`) |
      |---|---|---|
      | `KeyboardInterrupt`, anywhere in `cli_entry`: during `import hadavin_sdk.cli`, at an audit point or at the final flush (revision 3) | 130 | the fixed `interrupted` |
      | `SystemExit` whose `code` is exactly an `int` (`type(code) is int`) | that integer | nothing |
      | `SystemExit(None)` | 0 | nothing |
      | `SystemExit` with any other payload (a string, `False`, an object) | 1 | nothing; the payload is never read or printed |
      | any other `BaseException`, including an `ImportError` of `hadavin_sdk.cli` | 1 | one `uncaught: <render(diagnose(exc, step=Where.other))>` line |

One fixed line `output_guard: flush_failed` is written through `emit` (best effort). Then `os.dup2(<null device fd>, 1)` points fd 1 at the null device at the fd level (the documented recipe), so that the original stdout wrapper's own flush at exit writes nothing visible; the exit code stays the one `main` returned (S7). That this prevents Python's `Exception ignored` text and exit code 120 is UNVERIFIED; S7 probes it.
  - `OwnHandler(logging.Handler)` writes one line per record through `emit`, using these rules:
    - **`N`, defined without formatting (revision 3):** `N` is `len(record.msg)` in characters when `type(record.msg) is str`, else 0. For a foreign record `msg_len` is therefore the length of the template, not of the formatted text (accepted loss).
    - **Formatting only when printed:** `getMessage()` is called ONLY for an own record that passed every check, the one case that prints `msg=`. A withheld record and a foreign record are never formatted, so their `args` never run `__str__` or `__repr__` inside our handler.
    - **Own record:** the logger name full-matches `^hadavin_sdk(\.[a-z0-9_]{1,40}){0,6}$`, AND `type(record.msg) is str`, AND `record.args` passes the **allow-list** (revision 3, PENDING LEAD 16): `record.args` is an empty tuple; or a plain tuple (`type(args) is tuple`) whose every item has `type(v)` in {`str`, `int`, `float`, `bool`, `NoneType`}; or a plain dict (`type(args) is dict`, logging's single-mapping form; probe) whose keys and values pass the same test. There is no nesting, so there is no depth walk, no depth or size bound and no cycle case. It prints `logger=<name> level=<L> msg=<text>`.
      - **`<text>`: cut first, then escape, no marker.** The raw `getMessage()` text is cut to its first `LOG_MSG_CHARS` characters. The cut text is then escaped: `\n` becomes `\\n`, and the rest is made ASCII with `backslashreplace` plus the control-character rule of U4. The cap counts only the message, not the `logger=... level=... msg=` prefix. A 1000-character message of ESC characters gives 1000 escapes (4,000 characters, bounded).
