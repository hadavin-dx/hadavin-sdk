## Words used in this ticket (defined once)
- **Foreign text:** any text our code did not write: a library's message, a document line, model output, the text of an exception (design zone T2). It must never be printed.
- **Own line:** a line written by the output guard itself, built only from fixed words, closed lists and P5a's `render(diagnose(...))`.
- **Unattended tick:** the `hadavin-sdk tick` command, run by a scheduler every 30-60 s. Its stderr is a log stream that nobody reads live, so nothing raw may reach it.
- **Process entry:** the function that runs when the program is started as a command. Today that is `hadavin_sdk.cli:main` (`pyproject.toml:46-47`) and the `__main__` block at `cli.py:413-414`. A test or an embedding program that calls `cli.main([...])` directly is **library mode**.
- **Stream guard:** a replacement for `sys.stderr` and `sys.stdout` that rewrites every line written through it to `stderr_line len=N`, so the text is dropped and only its length is kept.
- **fd 2 / fd 1:** the operating system's file numbers for stderr and stdout. Code in C (and `os.write(2, ...)`) writes to them directly and goes around any Python object.

## What this package is, in one paragraph
P5b4 is step R2 of the frozen redesign (D13: R1, R1P, R3a, R3c+R3b, **R2**, R5). P5b3 makes our own error lines safe: each one becomes `render(diagnose(exc))`. P5b4 closes the **other channels** through which foreign text reaches a terminal or a log:
- (1) third-party log records, which today print their full message;
- (2) tracebacks (`exc_info`, `HADAVIN_DEBUG=1`, the interpreter's own crash printer, threads, and errors at shutdown);
- (3) `warnings`, which print the text a library passed in;
- (4) `argparse` error text, which echoes the value the user typed;
- (5) `print()` from a dependency during the unattended tick;
- (6) writes in C to fd 2.

It does this with one new top-level module, `src/hadavin_sdk/output_guard.py`, and a small change to `cli.py`.

- **Problem in plain words:** Even after P5b3 makes our own error lines safe, foreign text still reaches stderr in these ways on main:
  - **Tick log handler.** `cli.py:287` installs `logging.basicConfig(level=INFO, stream=sys.stderr, format="%(message)s")` for the tick. Every record from every library is printed in full, with its traceback when one is attached (ledger rows 026 and 046).
  - **Other commands.** No handler is installed, so Python's fallback handler (`logging.lastResort`, level WARNING, probe) prints library warnings raw.
  - **Debug switch.** `HADAVIN_DEBUG=1` calls `traceback.print_exc()` (`cli.py:81-82`). That prints the whole cause chain, including the raw provider error that P5b1 deliberately keeps as `__cause__` (`P5b1.md:25`).
  - **`main()` catch scope.** `main()` catches only `Exception` (`cli.py:72-83`). `SystemExit("text")`, `KeyboardInterrupt` and other `BaseException`s reach Python's own printer (row 051).
  - **Errors outside the main thread.** Nothing handles errors raised in threads (`k1b/loop.py:104`, `tools.py:1122`, `guard/http.py:136` start threads), errors raised inside object finalizers, or failures inside the logging machinery itself. The last prints `--- Logging error ---` followed by the message and its arguments (row 045).
  - **Warnings.** Nothing handles `warnings`, which print the text they were given; pydantic's serializer warnings quote the input value (row 047).
  - **`argparse` errors.** `argparse` prints the value the user typed. The probe on 3.13.18 printed `invalid int value: '<value>'`, `invalid choice: '<value>'` and `unrecognized arguments: <value>`.
  - **Direct writes.** A dependency's `print()` or C code writing to fd 2 goes straight to the tick's log stream.

  P5b4 closes all of these at one place, the process entry and `main()`, with tests that plant a made-up value (a canary) in each channel and assert it never comes out.

- **Interface (names, argument and return types, errors):**
  - `bootstrap_logging(*, unattended: bool = False, library_mode: bool = False) -> LoggingHandle`. Signature as D9.
    - **Idempotent:** a second call returns the same handle. A second call with `unattended=True` **upgrades** the handle (see "When unattended is decided").
    - **What it installs:**
      - one `OwnHandler` on the root logger, level INFO when unattended and WARNING otherwise (the same as today's tick level, `cli.py:287`). The root logger's level is set to match.
      - `logging.raiseExceptions = False`;
      - `logging.captureWarnings(True)`;
      - `sys.excepthook`, `threading.excepthook` and `sys.unraisablehook`.
      - When unattended, it also installs the stream guard on `sys.stderr` and `sys.stdout`.
    - **What it does only when NOT `library_mode`:** redirect fd 2 (and fd 1, PENDING LEAD 3) and remove foreign handlers.
  - `LoggingHandle.uninstall() -> None`: restores every global it changed: root handlers and level, `raiseExceptions`, `captureWarnings` state, the three hooks, `sys.stderr` and `sys.stdout`, and fds 1 and 2. It flushes any half-written line of the stream guard first. Calling it twice does nothing the second time.
  - `LoggingHandle.emit(line: str) -> None`: the **one own-line writer**. It writes to the stream that was captured before the guard was installed. If fd 2 was redirected, that is a new stream opened on a saved duplicate of the real fd 2 (see "fd redirect"). The line must be ASCII and one line: anything else is escaped with `backslashreplace` and `\n` becomes `\\n`.
  - `audit_handlers(owned: Collection[logging.Handler], *, remove: bool = False) -> list[tuple[str, str]]`: signature as D9 plus the `remove` flag.
    - It lists every handler on every logger in `logging.Logger.manager.loggerDict` and on root that is not in `owned` and is not exactly `logging.NullHandler`. Each is listed as (logger root name through the closed list below, `class_name_of(type(h))` from P5a).
    - Each one is emitted as `foreign_handler logger=<root> class=<cls>`.
    - With `remove=True` they are also removed.
  - `cli_entry(argv: list[str] | None = None, *, main: Callable | None = None) -> NoReturn`: the new process entry. It calls `bootstrap_logging(library_mode=False)`, **then** imports `hadavin_sdk.cli` (or uses the `main` passed in by the `__main__` block, so that the module is not imported twice). It calls `main(argv, _process_entry=True)`, then `sys.stdout.flush()` through the guard, then `sys.exit(code)`. At process entry the handle is **not** uninstalled before exit (see "Shutdown").
  - `OwnHandler(logging.Handler)` writes one line per record through `emit`, using these rules:
    - **Own record:** the logger name full-matches `^hadavin_sdk(\.[a-z0-9_]{1,40}){0,6}$`, AND `record.args` holds no `BaseException` at any depth of a tuple or dict, checked by **type** only (D11). It prints `logger=<name> level=<L> msg=<getMessage(), escaped, at most LOG_MSG_CHARS characters>`. A record that fails only the `args` check prints `logger=<name> level=<L> msg_len=N withheld=exception_arg`.
    - **Any other record:** it prints `logger=<root> level=<L> msg_len=N`. The message is never shown (accepted loss, design 7b).
    - **Logger name list:** `<root>` is the first dotted part of the name, if it is in `LOGGER_ROOTS` = (`urllib3`, `httpx`, `httpcore`, `botocore`, `boto3`, `psycopg`, `py.warnings`, `asyncio`, `google`). Otherwise it is `other`. `py.warnings` is matched whole.
    - **Level:** `<L>` comes from `record.levelno` through the closed map {10 DEBUG, 20 INFO, 30 WARNING, 40 ERROR, 50 CRITICAL}; anything else prints `L<int>`. `record.levelname` is never read (`logging.addLevelName` can set it to any text).
    - **Dropped every time:** `exc_info`, `exc_text`, `stack_info` and `extra` fields.
    - `getMessage()` is called inside `try`. A failure prints `logger=<..> level=<..> msg_len=0 withheld=format_error`.
  - `OwnHandler.handleError(record)` writes ONE fixed line, `logging_error handler=OwnHandler`, and nothing else (row 045).
  - **Hooks:**
    - Each hook writes one own line: `uncaught: <render(diagnose(exc, step=Where.other))>`, `thread_uncaught thread=<name shape-checked by token40 else '-'>: <...>` or `unraisable: <...>`.
    - A hook never raises. Its last resort is the fixed line `<hook>: diag_failed`.
    - `threading.excepthook` ignores `SystemExit`, as Python's default does.
    - The text of `unraisable.err_msg` and `unraisable.object` is never read.
  - **Stream guard `_GuardedStream`** (D12 list, plus a size cap):
    - It buffers each line across partial writes and across threads, with one lock.
    - **Size cap:** a partial line longer than `GUARD_PARTIAL_MAX_CHARS` is emitted as a length-only line and the buffer is reset, so memory stays bounded.
    - It provides `encoding = "ascii"`, `errors = "backslashreplace"`, `isatty()` False, a `reconfigure()` that does nothing, a `fileno()` that raises `io.UnsupportedOperation`, plus `flush`, `write` (returns `len(s)`) and `writelines`.
    - `flush()` passes any half-written line on only at uninstall or at exit, not on every call.
    - The text written through it is never kept beyond the current line.
  - **`argparse`:** `cli.py` uses `_Parser(argparse.ArgumentParser)`. Subparsers inherit the class, because `add_subparsers` does `kwargs.setdefault('parser_class', type(self))`, read from the 3.13.18 standard library. `_Parser.error(message)` prints `print_usage()` plus `<prog>: error: <head>`. `<head>` is the start of the message cut at the first `:` only if it full-matches `^(argument [-a-zA-Z0-9_/ ]{1,60}|unrecognized arguments|the following arguments are required)$`; otherwise it is `invalid arguments`. Exit code 2, as today. `--help` and `--version` are unchanged.

    | `ConfigError` | 2 | P5b3's line |

  - **When unattended is decided** (the design says otherwise: PENDING LEAD 1):
    - The design (D9) decides it from a pre-parse of argv before argparse runs: "the first positional token is `tick`". The probe shows the risk. `argparse` accepts option abbreviations, so `--conf DIR tick` parses as `config='DIR', cmd='tick'`. A pre-parse that knows only `--config` would read `DIR` as the command, run the tick without the stream guard, and leak. That is the same class of fault as ledger row 041.
    - This ticket decides it **after** `p.parse_args(argv)` instead: `args.cmd == "tick"` calls `bootstrap_logging(unattended=True, ...)` again, which upgrades the handle.
    - Between the first statement of `main()` and that point, the only work is argparse (whose errors are already guarded) and setting `HADAVIN_CONFIG_DIR` (`cli.py:132-133`). The config is not loaded and the heavy app imports have not run (`_tick` imports lazily, `cli.py:282-284`).
  - **fd redirect** (unattended tick at process entry only; D12 changed, PENDING LEAD 2):
    - **Steps:** `saved = os.dup(2)`; open the null device (`os.devnull`); `os.dup2(null_fd, 2)`. The own-line stream is then `open(saved, "w", encoding="ascii", errors="backslashreplace", buffering=1, closefd=True)`.
    - **Design gap fixed here.** D12 tells our emitters to write to "the ORIGINAL stream objects captured before the swap". The probe shows that after `dup2`, the original `sys.stderr` object also writes into the redirect target: our own heartbeat and `tick:` lines would vanish into the hidden file. Writing own lines through the saved duplicate fd fixes this (probe: the saved-fd line reached the real stderr, and the `sys.stderr` line reached the file).
    - Uninstall reverses it: `os.dup2(saved, 2)` and close.
  - **Removing foreign handlers:** only at process entry (D12), and only on the unattended upgrade. It runs once after `build(None, agents)` returns in `_tick` (after the lazy imports) and once at the end of the tick, both with `remove=True`. At bootstrap and in every non-tick command it only lists (`remove=False`). The design also asks for a check at each tick step boundary; that is cut (PENDING LEAD 4).
  - **Shutdown:**
    - **Design gap fixed here.** D12 says `main()` uninstalls in `finally`. At process entry that would put Python's own hooks back before the interpreter exits. The probe shows that an object whose finalizer raises at exit then prints `Exception ignored in ...` plus the exception text (the canary) in full.
    - So at process entry nothing is uninstalled: `cli_entry` exits with the guard still installed, and an `atexit` function flushes the stream guard. In library mode `finally: uninstall()` stays, as D12 says.
  - **Errors:** none new. `bootstrap_logging` never raises because of bad input. A failure of `os.dup` or `os.dup2` at process entry is a start-up failure: one fixed line `output_guard: fd_redirect_failed errno=<int>`, then exit 2. It fails closed: the tick does not run unguarded.

  - The only environment read is the existing `HADAVIN_DEBUG` (`cli.py:81`). It is already on the allow-list that P6b2 will check (A6), and P5b4 adds no new read.
  - fd 2 goes to the null device, so the design's "a protected file that can hold raw text" does not exist at all, and there is no file permission or retention to get wrong.
  - Made-up canaries are built from parts (the e-mail domain `example.invalid`, the AWS documentation key put together from parts). No variable is named `password`, `secret` or `token`.
  - **What this package does NOT stop (stated plainly):**
    - (a) An embedding program that calls library code without `main()` keeps its own handlers and Python's `lastResort` (design 7e: embedders are responsible).
    - (b) `python -m hadavin_sdk.cli` runs `cli.py`'s top-level imports (`cli.py:36-46`) before the guard is up, so output from those imports is not guarded. The console script `hadavin-sdk` (the production path) guards before any package import.
    - (c) A library imported lazily inside a tick step that installs its own file or network handler during that step is not removed until the end-of-tick check, and records it handles during that step can leak (PENDING LEAD 4). Whether any pinned dependency does this is UNVERIFIED.
    - (d) If fd 1 stays unredirected (PENDING LEAD 3), C writes to stdout during the tick are not intercepted.
    - (e) Operators lose all third-party message text, and with fd 2 going to the null device they also lose crash output written in C (for example `faulthandler`). That is the accepted loss of the frozen design, made stricter here.
    - (f) The receiver's HTTP server (`approvals/receiver.py:65`, `ThreadingHTTPServer`) uses the standard `socketserver` `handle_error`, which prints a traceback with `print(...)` and `traceback.print_exc()` (standard library source read on 3.13.18). When the server runs inside the tick or the CLI, that text goes through the stream guard or our hooks only if those are installed. `serve()` has no caller in `src/` (grep finds none), so an embedder runs it in library mode, which is case (a). P5b3 removes `log_message` (D11), but `handle_error` stays. Recommended: a v1.1 row, V-OG-4.
