## Words used in this ticket (defined once)
- **diagnostic**: the small record that replaces an error message in logs, stored error fields and the operator's screen. It holds only parts taken from fixed lists (a code, a step name, a file name with a line number, a few numbers). It never holds text that came from a document, a model, a person or a library. **render**: the one function that turns a diagnostic into a line of plain ASCII text.
- **code**: one word from the closed list below that says what kind of failure it is (for example `store_unavailable`). **closed list**: a list that only a reviewed code change can extend; a value outside it is dropped, never printed.
- **own class**: an exception class defined in this package (`hadavin_sdk`). **foreign exception**: any other exception (Python itself, pydantic, psycopg, an HTTP library, a model SDK).
- **fact**: one named number or one word from a closed list attached to a diagnostic (for example `http_status=429`). **locator**: `file.py:line` of the innermost frame in this package. **step**: where the failure happened (`extract`, a tick step name, ...).
- **personal data**: names, account numbers, e-mail addresses and similar (the plan never uses the abbreviation "PII"). **canary**: a made-up piece of personal data planted in a test input so that the test can check it never comes out.
- **hostile row**: one test input built to get personal data past a safety check. **corpus**: the file of all hostile rows. **ledger row**: one finding of the earlier (superseded) diagnostics design, `BL-core-c18a-NNN`, in `handover/ledger-seed.md`; the plan calls them inputs for the corpus, not work items.
- **DENY check**: "block this if it looks like a protected value"; over-matching is the safe side (P1 uses the same words). **ALLOW check**: "accept only if it IS the allowed value"; here every allow-list is an exact string match and the text-folding module is never used for it.
