**Words used (plain meaning, one meaning each).**
- **step**: one unit of pipeline work on one item (for example: read a document, cut it into passages, make embeddings). **item**: the one thing a step works on (a document, a message, a passage).
- **step contract**: the fixed shape every step takes in and gives back, and the rule that every item ends in exactly ONE final state.
- **final state** (terminal state): `done`, `needs_person` ("a person must look") or `refused`. Exactly one per item per step.
- **tenant**: one customer of the system; text of one tenant must never reach another. **readers**: the list of people or roles allowed to see an item. A step may narrow the readers, never widen them.
- **outbound text**: text that leaves our process to be PROCESSED by a third party (a model, an embedding service, a re-ranking service, a scan reader). **gate**: the one path every outbound text call goes through, doing four things in a fixed order: mask, audit, meter, check the no-training statement.
- **gated kind**: a replaceable part (kind) whose calls send outbound text, so it must go through the gate. **adapter**: the small wrapper that puts one gated kind behind the gate.
- **mask / placeholder / mask session**: as in P5c (`tickets/P5c.md`, "Words used"): a protected value is replaced with a placeholder such as `<EMAIL_1>`; the mask session holds the run's placeholder map and cannot be copied.
- **hold / reserve / settle / W**: as in P4b1 (`tickets/P4b1.md:5`): money is set aside before a call (the worst case), then replaced by the real cost.
- **no-training statement**: as in P6b1 (`tickets/P6b1.md:105`): a dated, written record by the operator that the provider's terms or account setting keep our text out of training. It records a promise; it does not stop a provider from training.
- **pilot/prod**: a config whose `environment` is pilot or production (the client profile, P6a).
- "UNVERIFIED" = I did not read it in code or could not run it. "PENDING LEAD" = an owner-only decision, with numbers; the lead takes it to the owner. "INFORM" = my decision on my recommendation, reported, final unless the lead says otherwise (order 23 item 4, order 6(g)).

## The decision that shapes this ticket (INFORM I1, recommended; read before the fields)

The money and masking parts of "the gate" already exist as frozen ticket designs, for the llm only: P5c's `MaskedLLM` masks, checks and writes one audit event before the call (`tickets/P5c.md`, item 7 (b)-(e)); P4b1's `MeteredLLM` takes a hold (`tickets/P4b1.md:258-268`); P6b1 refuses a pilot/prod llm kind without a no-training statement at config load. The order is `MaskedLLM(MeteredLLM(raw))` (`tickets/P5c.md:114`; order 22 items 22 and 30: ONE `MeteredLLM` on `deps.llm`, Runtime refuses anything else). So AK1 must NOT write a second masking engine, a second meter or a second statement check.

Options:
- (a) Rebuild: one new `Gate` class that every kind including the llm goes through; `MaskedLLM` and `MeteredLLM` are re-written on top of it. Biggest surface; re-opens two frozen money/redaction tickets.
- (b) **Compose (recommended):** the gate is ONE module, `guard/outbound.py`, with ONE function `gated_call` that runs the four steps by calling the existing choke points: P5c's redactor and mask session (one leaf-masking function, moved out of `MaskedLLM` so both use it), the `AuditSink`, P4b1's `Limits.hold`, and P6b1's statement. The llm keeps `MaskedLLM(MeteredLLM(raw))` as its registered adapter (same four steps, same order, same functions). Every other gated kind (embedder AK2b, reranker AK2c, scan reader when it exists, the guardrail detector) gets a thin adapter over `gated_call`. A lint test lists every kind that could send text out and fails when one is not classified or not gated.
- (c) A network-level gate in `guard/http.py` (`checked_connection`): rejected, because by the time bytes reach a socket the text is already serialised and cannot be masked or priced; vendor SDKs also bypass `urllib`.

Why (b): it closes the hole (every outbound kind gated, proved by a lint) with the least new code; "one gate" holds because each of the four steps has exactly one implementation; it re-opens no frozen design except one behaviour-preserving refactor (row G14). Cost: the llm path and the other kinds share functions, not one class; a later refactor of `MaskedLLM` onto `gated_call` is a v1.1 row (V1). Confidence 80 percent; reversible (the adapters are small).

     - (1) **Classification and statement.** `(capability, kind)` must classify as `gated` (else `OutboundRefused("ungated_kind")`). If the environment is pilot/prod and `statement_ok` is false, `OutboundRefused("no_training_statement")`. `statement_ok` is computed ONCE by the adapter factory from P6b1's statement for that kind (AK1-c); an adapter built outside the factory has `statement_ok=False`, so an object handed in by code is refused in pilot/prod (P6a's "test objects handed in by code" rule).
     - (2) **Context.** The open mask session and run come from P5c's run context (`MaskedLLM.run(...)`'s `ContextVar`, `tickets/P5c.md` item 7); the agent and run for money from P4b1-b's scope. No session: `SessionClosed` (P5c) and no call. No meter scope: `MeterError` (P4b1) and no call. If P4b1-b's scope variable is per wrapper instance rather than module level (UNVERIFIED from the ticket text, `P4b1.md:258`), AK1-b adds one read-only accessor `current_scope()` in `llm/metered.py`; that is its only edit there.
     - (3) **Mask and check.** `masked = mask_leaves(list(texts), redactor, session)`, the SAME function `MaskedLLM` uses for its leaves (P5c item 7 (b): trusted re-mask, pass 1 in list order, pass 2 when the session's map grew, then `redactor.check` on every leaf). The gate never escapes: raw external text is escaped once where it enters (P5c's one-mode-per-input-class table). Any refusal is `RedactorRefusal`/`RedactionError` and no call.
     - (4) **Audit before the call.** `audit.write_intent(AuditEvent(domain=capability, operation="outbound", source=kind, inputs_hash=sha256_hex(masked), rule_id=redactor.fingerprint, result="items=<n>;chars=<in>/<out>;" + sorted "kind:count" pairs))`. `sha256_hex` over the LIST (`models.py:46`), so `["ab","c"]` and `["a","bc"]` hash differently (row G10). `AuditUnavailable` goes to the caller; no call.
     - (5) **Hold.** `with limits.hold(agent_id, worst, run_id=run_id) as h:` (P4b1-a). `worst` must be a `SpendMicro` greater than zero; zero or negative is `ValueError` before step (1)'s audit (an unpriced gated call is refused; the 1 micro-dollar floor of P4b1-b applies to the adapter's price function, row G13). `OverBudget`/`MeterUnavailable` propagate; no call.
     - (6) **Call.** `result = call(masked)`. Then `c = cost_of(result)`: a `SpendMicro` records that amount (`measured=True` only when the adapter's usage figure is a provider figure; the adapter says so); `None` records the reserved worst case. Any exception from `call` or `cost_of` keeps the worst case (P4b1 caller rule: a SENT call is never released) and propagates unchanged; P4b2-a's billing classification decides the only release cases (a non-billing error class), through its one helper, not a second copy.
     - (7) **No put-back.** The gate returns `result` unchanged. It never calls `restore` (embeddings and scores carry no placeholders to put back; put-back stays at P5c-4's three seams).
  6. **Errors (AK1-b).** `class OutboundRefused(RuntimeError)` with `.code` in `OUTBOUND_CODES = ("ungated_kind", "no_training_statement", "unpriced_kind")`; `__str__` returns the code only; raised `from None`.
