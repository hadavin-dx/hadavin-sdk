## Rules stated once (both sub-tickets)
1. **The one rule (fail closed).** A reservation is RELEASED only on positive proof that no bill is possible. Every doubt, every unreadable value, every exception type nobody classified, and every error on the billing path keeps the worst case (settle at the worst case). The only direction a mistake may go is "counted too much". Releasing a call that was billed is the one error this package must make impossible.
2. **Terms of proof (one definition each).**
   - *never sent*: no request left this process. Proven in exactly one way: the error that came out of the model call carries counts that show every attempt was `unsent` (the retry layer counted it, below) or that no attempt started (`attempts == 0`, stamped by a layer that refused before sending). The metered-call wrapper (P4b1-b) takes its hold immediately before `inner.chat`, so it has no step of its own between reserve and call that could prove "never sent"; an exception from the inner model that carries no stamp is therefore *unknown*.
   - *refused*: the provider answered the attempt with an HTTP status from 400 to 499 except 408. The provider received the request and said no. 429 is included.
   - *unknown*: every other end of an attempt: 408, any 5xx, a timeout, a reset or EOF after connecting, any other `OSError`, a parse failure of an answer (billed), any exception with no status, an attempt whose thread was abandoned.
   - Per attempt, exactly one of the three. For an error: `attempts` = attempts started; `refused`; `unsent`; unknown = `attempts - refused - unsent`.
3. **Release rule.** The wrapper releases iff the error is a `ProviderError` (or subclass) whose three counts are plain ints in 0..`MAX_COUNT` (10**6), `refused + unsent <= attempts`, and unknown == 0 (this includes `attempts == 0`). Anything else keeps the worst case. The decision is by COUNTS, never by exception class: a `ProviderExhausted` made of three 429s is released; a `ProviderError` made of a billed answer that could not be parsed is kept (test G10).
4. **Class defaults are UNKNOWN.** `ProviderError.attempts = 1`, `refused = 0`, `unsent = 0` (one request, outcome unknown). A raiser that does not stamp is kept at the worst case. This reverses PR #48's default (`refused = 1`), which fails open. A repo guard test (AST) allows the names `attempts`, `refused`, `unsent` to be assigned as class attributes only in `llm/protocol.py` and as instance stamps only in `llm/retry.py`; a subclass that sets `refused = 1` fails the guard.
5. **Provider error vs timeout.** The two classes keep their meaning for the agent loop (`provider_error` vs `provider_exhausted` end codes) and do not decide billing. A timeout after the request was sent is *unknown* (kept). A refused connection, a DNS failure or a certificate-check failure before any request byte is *unsent* (released). A 401, 400 or 429 is *refused* (released). A 5xx is *unknown* (kept).
6. **Release vs settle at zero.** Release is a cancellation (status `released`). Settle at zero is a price (status `settled`, `settled_usd` 0). The meter releases only through rule 3. In v1 it never settles at zero: P4b1 refuses `Hold.record(SpendMicro(0))` ("zero is never a measurement, use `release()`"), and a reply with missing, zero-token or invalid usage is settled at the worst case (C2, A9 F10: P4a/P4b1). The store keeps both statuses; the difference is visible in the row (`released` vs `settled`) and in the log line. Mutant a11 implements a release as a settle; the status value kills it.
7. **Money type.** Storage stays `NUMERIC`, the Store boundary takes exact `Decimal` USD with at most 6 decimals (A9 B1, P4d). The meter works in integer micro-dollars, rounds UP once per call (R214). P4b2 adds no money column, no new money SQL and no rounding rule.
8. **Error rule.** A refused store write is `StaleState` or `ValueError` (P4d rule). The forbidden-actor refusal of P4b2-b is a PRIVILEGE error (SQLSTATE `42501`) that passes through as a driver error like a missing grant, and `is_connectivity_error` is false for it. On any deny or refuse path the answer is refuse.
9. **Lock order.** P4b2 adds no multi-row SQL. The sweep takes one lock kind (the reservation rows, `FOR UPDATE SKIP LOCKED`, P4d), the trigger reads only the row being updated and catalog entries. The P4d total lock order is unchanged.
10. **Fail-before wording.** As in P4d: a fail-before test fails on an ASSERTION on the named head; a new-feature row that fails only because a symbol is missing is labelled "new feature; killed by mutants"; a row that already passes is a "regression pin; killed by mutant Mx". - Problem in plain words: When a model call fails, the meter today has to guess what the failure cost. Intake's meter settles every failure at the worst case, which is safe but wrong in one way: a call that was refused (a bad key, a malformed request, a rate-limit answer) or never left the machine (the provider's address could not be reached) cost nothing, yet its worst case stays counted until the day or month rolls over. During a provider outage or after a key expires, every retry of every run adds a phantom worst case, and the daily limit is reached by calls that were never billed. The opposite error is worse: releasing a call that WAS billed (for example an answer that arrived but could not be read) lets the real total pass the limit. The model layer also gives the meter nothing to decide with, because errors carry no information about what was sent. This package makes the layer say what it knows, makes "I do not know" the default, and releases only on proof.
- Source of the code (MANIFEST ids, source repo, commit sha) and what is NOT taken: the idea comes from PR #48 `llm/protocol.py` (`cost_to_settle`, `ProviderError` count attributes; local ref `origin/core-hardening-1`, `8986cb5`) and memo-2 gap 10; Intake `budget.py`/`model.py` (promotion-inputs `intake-a12`, MANIFEST rows 1265-1271) for the "sent" mark (`begin_send`) and the settle-in-`finally` shape. Written new on ce70eb5; no file is copied. NOT taken: see "What is NOT taken" above (#48's default, billed pricing, marks, deadline thread, maintenance role).
- Target module and path in `src/hadavin_sdk/`: `llm/protocol.py` (count attributes, `BillingOutcome`, `billing_outcome`), `llm/retry.py` (per-attempt classification and stamping), `llm/common.py` (pass the optional status hook), `llm/bedrock.py` (the hook), `llm/metered.py` (`MeteredLLM.chat`; PENDING P4b1), `k1b/loop.py` (only with item 6), `CHANGELOG.md`.
- Interface (names, argument and return types, errors):
  - `llm/protocol.py`.
    - `MAX_COUNT: int = 10**6`.
    - `ProviderError` gains class attributes `attempts: int = 1`, `refused: int = 0`, `unsent: int = 0` (rule 4). `ProviderExhausted` is unchanged (it does NOT set `refused`).
    - `BillingReason = Literal["never_sent", "all_refused", "refused_or_unsent", "unknown_billing", "unreadable_counts", "not_a_provider_error"]` and the tuple `BILLING_REASONS` (closed set; a test lists it).
    - `@dataclass(frozen=True) class BillingOutcome: release: bool; reason: BillingReason; attempts: int | None; refused: int | None; unsent: int | None` (the three counts are `None` when unreadable or not applicable).
    - `billing_outcome(exc: BaseException) -> BillingOutcome`. NEVER raises (wraps everything after the first line in `except Exception`). Steps: (1) `isinstance(exc, ProviderError)` else keep, `not_a_provider_error`; (2) read `attempts`, `refused`, `unsent` ONCE each into locals (a property that returns a different value on a second read cannot split the decision); (3) each must satisfy `type(v) is int and 0 <= v <= MAX_COUNT` (bool, float, str, None, negative, huge are garbage) else keep, `unreadable_counts`; (4) `refused + unsent <= attempts` else keep, `unreadable_counts`; (5) `unknown = attempts - refused - unsent`; `unknown > 0` is keep, `unknown_billing`; (6) otherwise release, reason `never_sent` if `attempts == 0 or unsent == attempts`, `all_refused` if `refused == attempts`, else `refused_or_unsent`.
  - `llm/retry.py`.
    - New private `classify_attempt(exc: BaseException, status_of: Callable[[BaseException], int | None] | None = None) -> Literal["refused", "unsent", "unknown"]`. Order: (1) `code = status_of(exc)` when the hook is given (a hook that raises or returns a non-int counts as `None`), else `status(exc)`; if `code` is an int (not bool): `400 <= code <= 499 and code != 408` is `refused`, any other int is `unknown`. (2) no int status: `unsent` iff the EXPLICIT cause chain (only `__cause__` and `.reason`, at most 8 deep, never `__context__`) contains at least one of `ConnectionRefusedError`, `socket.gaierror`, `ssl.SSLCertVerificationError` AND contains none of `TimeoutError`, `ConnectionResetError`, `ConnectionAbortedError`, `BrokenPipeError`, `EOFError`, `ssl.SSLEOFError`, `ssl.SSLZeroReturnError`, `http.client.HTTPException`. (3) everything else is `unknown`. Reasons for the lists: those three failures happen before any request byte (connect, name lookup, certificate check); the "may have sent" list are failures that can happen after bytes left. `__context__` is excluded because an unrelated earlier error can be implicitly chained to a later timeout. The lists are module constants with a comment naming the standard-library source for each.
    - `with_retry(..., status_of: Callable[[BaseException], int | None] | None = None)` (new optional keyword; every existing call keeps working). It counts per attempt: `sent` (incremented when the callable is entered), `refused`, `unsent` (from `classify_attempt` for each failed attempt). When it raises `ProviderError` (non-transient failure) or `ProviderExhausted` (last attempt failed), it sets `err.attempts, err.refused, err.unsent = sent, refused, unsent` UNLESS the error already carries its own instance stamps (an error raised by an inner layer passes through the existing `except ProviderError: raise` untouched, so an inner layer's counts are not overwritten). Counts accumulate over all attempts of the call (three 429 then a 500: `attempts 4, refused 3, unsent 0`: unknown 1, kept).
    - Success after earlier failed attempts needs no stamp (the reply is priced from its usage, P4a).

- Problem in plain words: When a process dies in the middle of a model call, its reservation stays open for ever and holds its worst case in the counters. P4d adds the means to mark such rows "expired" (sweep), but leaves open WHICH database login may do it, and today that would be the same login that runs every model call. This sub-ticket gives the sweep its own login that can do that one thing and nothing else (it cannot create, delete or change amounts, and it cannot touch the spend counters), makes the runtime login unable to expire a row, wires the sweep as a bounded step in the tick, and fixes the rules for how old a reservation is (measured on a clock that cannot be moved by the application, a caller or a host clock change on an application server).

Text (the builder may change names, not behaviour):
    ```sql
    CREATE OR REPLACE FUNCTION spend_reservations_actor_guard() RETURNS trigger
    LANGUAGE plpgsql
    SET search_path = pg_catalog, pg_temp
    AS $$
    BEGIN
      IF current_user = (SELECT pg_get_userbyid(c.relowner) FROM pg_class c WHERE c.oid = TG_RELID)
         OR (SELECT r.rolsuper FROM pg_roles r WHERE r.rolname = current_user) THEN
        RETURN NEW;                       -- the owner and superusers are outside this model (as in P4d-b)
      END IF;
      IF has_table_privilege(current_user, TG_RELID, 'INSERT') THEN
        -- a role that can insert (the runtime) settles and releases; it never expires a row
        IF NEW.status = 'expired' AND OLD.status IS DISTINCT FROM 'expired' THEN
          RAISE EXCEPTION 'spend_reservations: actor refused' USING ERRCODE = '42501';
        END IF;
      ELSE
        -- a role that cannot insert (the maintenance role) may only expire an open row at its reserved amount
        IF NOT (OLD.status = 'open' AND NEW.status = 'expired' AND NEW.settled_usd = OLD.reserved_usd) THEN
          RAISE EXCEPTION 'spend_reservations: actor refused' USING ERRCODE = '42501';
        END IF;
      END IF;
      RETURN NEW;
    END;
    $$;
    CREATE TRIGGER spend_reservations_actor_guard BEFORE UPDATE ON spend_reservations
      FOR EACH ROW EXECUTE FUNCTION spend_reservations_actor_guard();
    ALTER TABLE spend_reservations ENABLE ALWAYS TRIGGER spend_reservations_actor_guard;
    ```

    - A1. The age of an open reservation is measured by ONE clock that no application, caller or application host can move: on Postgres, `clock_timestamp() - created_at`, both from the database server (the column default is `clock_timestamp()`, P4d-b); on the memory store, the injected `clock=time.monotonic` (P4d-b). A reservation swept too early (the database clock stepped forward, a very slow call, a too-small `orphan_age_s`) becomes `expired` but KEEPS its amount in all three counters. So early expiry cannot cause an overspend. If the call finishes, its real settle corrects the row downward ONCE (P4d-b rule) and a second close returns that result. The only effects of a wrong clock are a mislabel and a late correction. A clock stepped BACKWARD only delays expiry (more rows stay open longer: over-counted, safe).
    - A4. The database server's own wall clock can step (an NTP correction). It is not monotonic. This package does not claim otherwise: it claims that no APPLICATION clock participates, that one server clock serves every process (so processes cannot disagree), and that a step cannot overspend (A3).
