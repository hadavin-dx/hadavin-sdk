Words used here. "Migration": one file `NNNN_<name>.sql` in `src/hadavin_sdk/store/migrations/` ("the folder") that changes the stored data layout. "Ledger": the database table `schema_migrations`; it stores each file name without `.sql` (the "stem", for example `0005_evidence`). "Applied": the stem is in the ledger. "Late": a file that is not applied and whose number is at or below the highest applied number. "Orphan": a ledger name with no file in the folder. "Recipe": the short SQL file that the refusal message prints for a late file; a database administrator saves it and runs it with `psql -X -v ON_ERROR_STOP=1 -f recipe.sql` (`-X` means "do not read my own startup file", `-f` means "run this file"; `ON_ERROR_STOP` means "stop at the first error"). "Previous release": the migration named by the constant `PREVIOUS_RELEASE_LAST` in `tests/test_migration_postgres.py`; the lead sets it when the first tag exists (no tag exists yet: `git tag` is empty). "Layer 1": the CI test that compares the database structure of the previous release with the structure after the new migrations. "Layer 2": a manual run of the old code against the new schema. "Read-back": after each migration file, `migrate()` reads the database role (current and session user), the replication-role setting, the search path, three settings that change how SQL text is read (`standard_conforming_strings`, `backslash_quote`, `client_encoding`) and the state of every trigger again, and compares them with the values it saved before the first file; it finds what is LEFT changed at the end of a file. "Comparer kind": one group of database objects that layer 1 compares (for example columns). "Mutant": a deliberate small break of the new code that a named test must catch. "SAVED", "R6-UNSAVED" and "UNVERIFIED" are explained in the first paragraph.

The number, order and gone refusals, and the folder check, are the subclass `MigrationNumberError`; the new statement refusals travel through `check_grants` and stay a plain `ConfigError`, as every grant-scan problem does today. The tests of the new number, order and gone code check `type(e) is MigrationNumberError`; the tests of the statement refusals check `isinstance(e, ConfigError)` and the file name in the message. Message of the subclass: `"migrations are inconsistent: "` + problems joined by `"; "`, capped.
