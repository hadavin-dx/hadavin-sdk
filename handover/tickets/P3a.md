- Interface (names, argument and return types, errors):
  - Constants, each with a reason: `NAME = re.compile(r"[0-9]{4}_[a-z0-9_]+\.sql")` (four ASCII digits, at most 9999 migrations; used with `fullmatch`, never `\d`); `STEM = re.compile(r"[0-9]{4}_[a-z0-9_]+")`; `MAX_PROBLEMS_SHOWN = 20` (one hostile name once produced thousands of lines; the message shows 20 problems and then `and N more`, so 21 problems show 20 plus `and 1 more`). `MIGRATIONS: Path` moves here and is imported back into `migrate.py` (tests use `mig.MIGRATIONS`; `tests/test_p2_postgres.py` imports it).
  - `class MigrationNumberError(ConfigError)`, field `problems: tuple[str, ...]`. `ConfigError` derives from `ValueError` (`errors.py:4`), so tests of the new code check `type(e) is MigrationNumberError`. Message: `"migrations are inconsistent: "` + problems joined by `"; "`, capped. Every file name or ledger name in a message is written with `ascii()` (escapes control characters, ANSI escapes and undecodable bytes, so a hostile name cannot inject into a terminal or make `print` fail). At the CLI a `ConfigError` is printed as `refused: <message>` and exits 2 (`cli.py`, function `main`); other exceptions exit 3, so `MigrationNumberError` must never be anything else.
  - `list_migration_files(folder: Path) -> list[Path]`: `os.scandir` entries whose name ends in `.sql` in any letter case, sorted. Entries without that suffix are ignored at runtime, as today.
  - `check_ledger(paths: list[Path]) -> list[str]`: THE implementation (list-based). It returns problems and never raises for a bad file. For each path: a name not matching `NAME`; an entry that is not a regular file or a symlink to one (`not p.is_file()`: directory, dangling link); then `p.read_bytes()` decoded as UTF-8, where `OSError` or `UnicodeDecodeError` becomes `<file>: cannot be read (<exception class name>)`, because `is_file()` is not a readability test. Across files: two files with one number; a gap. The old messages stay word for word (`two migrations are numbered 0002`, `migration 0002 is missing`, `<file>: not named NNNN_<name>.sql`; the last with the file name escaped). A symlink to a regular file is accepted here (installers may link files).
  - `folder_problems(folder: Path) -> list[str]` = `check_ledger(list_migration_files(folder))`.
  - `late_files(applied: Collection[str], files: Sequence[Path]) -> list[Path]` (pure). `applied` holds stems, `files` are paths. The number of an applied stem is `int(stem[:4])` only when it matches `STEM`; other applied names are ignored (the `gone` refusal reports them). Returns the files whose stem is not in `applied` and whose number is at or below the HIGHEST applied number, sorted by number; an empty ledger gives `[]`.
  - `order_problems(applied, files) -> list[str]` wraps `late_files`. Message per late file (self-contained; no command that could fail; names escaped): `'0004_x.sql' is numbered at or below the applied '0005_y' and must not run in the normal way. Do not rename it. First check that the file also works on a fresh install (CI does for committed files). Write the date, the file and your name in the change log. No other migrate may run at the same time.` The number is `_LOCK`, built into the text from the constant, never typed (see the lock test).
