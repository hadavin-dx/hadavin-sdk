## Words used in this ticket (one meaning each)
- **client profile**: a configuration whose `environment` is `pilot` or `prod`. There is no other profile object. `Config.environment` is `Literal["dev", "pilot", "prod"]` (`config.py:317`) and `deferred.LIVE = ("pilot", "prod")` (`deferred.py:33`). P6a adds no new profile concept (PENDING LEAD 5).
- **dev-only kind**: a `(capability, kind)` pair in `DEV_ONLY` (`backends/table.py:593-602`): `llm/fake`, `channel/fake`, `secrets/fake`, `secrets/env`, `store/memory`, `audit/local_dir`.
- **masking wrapper**: the object P5c builds that masks text before the model sees it. The frozen C1 design calls it `MaskedLLM` in `llm/masked.py` (`studio-notes/C1-ticket-v3.md` D2/D3, `C1-ticket-v3-FROZEN-amendments.md` F1, F5). Its final names are PENDING P5c.
- **test double**: an object a test passes into `app.build` in place of a configured part (`ScriptedLLM`, `FakeChannel`, a spy secret provider).
- **model-call site**: a place in `src/` that reads the attribute `chat` or `apply_guardrail` of an object, in any form (a call, an alias, a `getattr` with that string).

## What is already true on main (read in code)
1. **Dev-only kinds are already refused outside dev.** `Config._cross_checks` (`config.py:350`) builds a refusal list when `environment != "dev"` from every `(capability, kind)` of `backends.entries()` that is in `DEV_ONLY` (`config.py:365-369`), adds `allow_insecure_loopback` (`:370`) and the anchor rules (`:371`, `_anchor_refusals` at `:377`, which adds `NOT_PROD` pairs in prod at `:391-392`), and raises ONE `ValueError` naming all of them (`:372-373`); `load_config` turns it into `ConfigError` (`config.py:453-454`). Capabilities left out of a config get `DEFAULTS` (`table.py:582-589`: secrets `fake`, store `memory`, channel `fake`, ...), and those defaults are then refused in pilot and prod by the same check, because `entries()` lists every capability (`config.py:72-74`). So the plan's "turn on the check" is, for the configuration path, a check that exists today. memo-6 said the same (row "rule 9(g)") and A6 decided: "P6a builds on it" (no parallel per-kind flag).
2. **The llm kind has no default.** `Backends.llm` has no default (`config.py:68`) and `DEFAULTS` has no `llm` entry (`table.py:582-589`), so every config names one. "The llm kind refused unless the redactor kind is selected" therefore means: in a client profile, the redactor must be named. There is no `redactor` capability on main (`Backends` fields at `config.py:63-70`; `TABLE` capabilities); P5c adds it.
3. **The hole on main: `app.build` takes test doubles in a client profile.** `app.build` accepts `secrets=`, `channel=`, `detector=`, `llm=` (`app.py:62-69`) and uses them instead of the configured kinds (`app.py:82`, `:162`, `:163-166`, `:170`). In pilot and prod it refuses only `sources=` (`app.py:90-92`) and `tools=` (`app.py:93-98`). So a pilot app can run with a `FakeChannel` and a scripted model while its config names Slack and a real model; the dev-only table is never consulted for these objects. The repository's own test does exactly this and passes: `tests/test_k3_pilot_env.py:184-191` builds a pilot app with `secrets=spy, channel=FakeChannel(), llm=ScriptedLLM(...)`. No module in `src/` or `demos/` passes these keywords to `app.build` (the only `src/` caller is `cli.py:282`, `from hadavin_sdk.app import build`, used without them; grep of `demos/` for `build(` finds no `app.build` call). So the hole is reachable only by a client's own Python code, not by configuration.
4. **The existing model-call scan is not alias-proof.** `tests/test_k5_producers.py:22` sets `SINK_METHODS = {"chat", "apply_guardrail"}` and `_sink_callers` (`:78-95`) counts a module only for an `ast.Call` whose function is an `ast.Attribute` with that name (`:89-94`). `getattr(llm, "chat")(...)`, `f = llm.chat; f(...)` and `functools.partial(llm.chat)` are not counted. The C1 design's choke-point test (F5 (a): "the set of modules containing an `X.chat(` call equals EXACTLY ...") is written in the same call-only shape.
5. **Model-call sites in `src/` outside `llm/` today** (an AST walk over every `Attribute` named `chat` or `apply_guardrail`, run by me on 124258b): `evals.py:73` (`gate`), `extract.py:47` (`extract`), `guard/bedrock_guardrail.py:101` (`GuardrailDetector.check`), `guard/judge.py:72` (`JudgeDetector.check`), `k1b/loop.py:94` (`_chat_bounded.work`; `_chat_bounded` at `:84`), `runtime/agent_loop.py:425` (`Runtime.handle`).
