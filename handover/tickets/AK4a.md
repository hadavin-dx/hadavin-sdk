**Words used (plain meaning, one meaning each).**
- **pipeline**: several steps run one after another on many items. AK1's words "step", "item", "final state", "tenant", "readers" and "gate" keep AK1's meanings (`tickets/AK1.md:10-13`).
- **the AK1 gate** and **the AK-G22 recipient gate**: AK1's two barriers. The AK1 gate covers text sent out to be processed (classes `gated` and `through_llm`). The recipient gate (AK-G22, not yet written) covers text delivered to a named person or system (class `recipient`). Order 27 item 63: every outbound-text path goes through one of the two; no path goes through neither.
- **harness**: test code that runs a whole pipeline on made-up items with a fake model, then runs a fixed list of **checks** over everything the run left behind (log records, printed text, audit events, written files, the texts the fake model received, the outputs).
- **canary**: a made-up value planted in the input as if it were personal data, the e-mail shape `canary-<32 hex>@example.invalid`. If it is found where personal data must never be, a check fails. The hex part is random per run, so it cannot appear by chance.
- **item marker**: a line of text, exactly `item-<item_id>`, that every made-up item document carries (for k1b the item id is the case id). The harness uses it to tell which item each model attempt belongs to (INFORM I17).
- **finding**: one failed check, given as a closed code plus a place (a logger name, an audit field name, a file path relative to the run folder). A finding never shows the canary.
- **fault**: something broken on purpose by the fake model on one ATTEMPT (one try of a call): a timeout, a "too many requests" answer (HTTP 429), a bad reply, a reply cut off part way, an echo of everything it received, or a **hang** (the attempt waits until the test releases it, then times out).
- **billing ledger**: the list the fake model keeps of what a real provider would have charged for each attempt (made-up prices). It is the truth a spend check compares with the cap. It is NOT the core's own meter, which is what the check exists to catch.
- **W**: P4a's worst case of ONE request: prompt bytes times the input price plus `max_tokens` times the output price (`tickets/P4a.md:86-88`). **Whole-call maximum**: request count times attempts times W (P4a PL54, `tickets/P4a.md:47`).
- **golden set, bucket, trap**: the agent's examples with the right answers (`golden_dir/<agent>.jsonl`), each line labelled `easy`, `hard` or `trap`. A trap is a request that must be refused (the right answer is "no action").
- **abstain / false abstain**: the agent proposes no action. A false abstain is an answerable item-run pair (one whose right answer IS an action) that was abstained. It is reported apart from correct refusals of traps.
- **qualify / green run**: a gate run that passed. It is one line in `qualified.jsonl`, and an agent with no matching green line cannot start (`evals.py:1-5`, `runtime/agent_loop.py:141-157`).
- **pilot/prod**: a config whose `environment` is `pilot` or `prod` (`config.py:317`).
- **strict expected failure**: a test row marked `pytest.mark.xfail(strict=True, raises=AssertionError, reason=...)`: it must fail by its own assertion today, and the suite fails the day it passes, so the marker cannot be forgotten.
- "UNVERIFIED" = I did not read it in code or could not run it. "PENDING LEAD" = a lead or owner decision, with options and my recommendation; "NEEDS LEAD" marks one the lead must answer (money). "INFORM" = my decision on my recommendation, reported, final unless the lead says otherwise (order 23 item 4, order 6(g)).
