Plain words used here (each keeps one meaning):
- **usage**: the token counts a model provider reports for one call.
- **the classes of usage**: input (prompt tokens billed at the normal input price), cache write (prompt tokens the provider stored for reuse), cache read (prompt tokens served from that store), output (tokens the model wrote; on Claude and Gemini this includes the private working the provider calls thinking, which this core does not report as a separate count: V26). This core prices only input and output; a non-zero cache count is refused.
- **prompt tokens**: input + cache write + cache read (everything the model was sent).
- **reserved amount**: the money the meter (P4b1) sets aside BEFORE a call. Only the meter has one.
- **the byte bound** (PL47): the UTF-8 byte length of the system text, the messages and the tool specs of a call, divided by `PROMPT_BYTES_PER_TOKEN` (1) and rounded up. The bytes are counted with `.encode("utf-8", "surrogatepass")`: a lone surrogate (half of a character pair, which a model's tool-call input can carry) counts 3 bytes, like a valid character of that range, so the count never raises (M4; C13q clause, C13(k), a2-57). It is an upper bound on the tokens of the text sent only under P4b1's stated assumption (every token covers at least one byte; not measured per model), and it does not count tokens the provider bills beyond the bytes of the system text, the messages and the tool specs (its own template, tool wrappers, the `tool_choice` instruction; V35).
- **W, "one request's worth of the worst case"**: for one request, the byte bound of its prompt times the input price, plus `max_tokens` times the output price, per million tokens, rounded up once to 8 decimals. In the C13 rows: P = 4,000 bytes, prices 3 and 15 USD per million tokens, `max_tokens` 1,024, so W = 0.027360. 2W means two requests' worth, and so on. W is the amount `k1b.loop.worst_case_usd(route, system, messages, *, tools, requests=1)` returns for one request; with `requests=F` it returns F times the exact (unrounded) W, rounded up once; for a W that is not whole at 8 decimals this can differ from F times the rounded W. The C13 values are whole at 6 decimals; C13p clause 2 uses a W that is not whole at 8 decimals (0.016300160557) and pins the single upward rounding of the exact product. It lives in `k1b/loop.py` and has no other consumer (V33); the meter (P4b1) sizes its reserved amount with its own function; P4d and P4b1 own what happens when the real cost is higher. W rests on three assumptions (PL59): the provider honours `max_tokens` (all four kinds send a cap: `openai_compat.py:99`, `gemini.py:63`, `bedrock.py:137`, `anthropic.py:109`, per the round 9 reviewer; a local server behind the OpenAI-compatible kind may not, UNVERIFIED); Gemini thinking counts inside `maxOutputTokens` (UNVERIFIED); input is priced at 1x, so a surprise cache write (1.25x to 2x input, UNVERIFIED) is above W (at 2x, three attempts of one request cost 0.118080 against 3W = 0.082080). This core sends no cache instruction (grep of `src/` for `cache_control`: no hit), and k1b is fake-only in v1 (PL55), so no v1 money path books it.
- **refuse**: raise a typed error and return nothing; no cost number is made up.
- **request count of one call** (`request_bound(llm)`): the most billed requests one `chat()` can send when every request is answered, as DECLARED by the kind in its class attribute `REQUESTS_PER_CHAT`: 2 for the OpenAI-compatible kind (it may ask once more when the forced answer is missing), 1 for every other kind and for `FakeLLM`. It does not count retries after a failure. It is STRICT: an object with no declaration, or a bad value, is refused (`TypeError` or `ValueError`). It is for the reservation; `k1b/loop.py` multiplies the same request count by the attempts through `_charge_factor` (below) in every booking after a possibly billed call.
- **reservation versus charge after the fact**: the reservation is set aside BEFORE a call (the meter, P4b1-b); a loud refusal there is intended, because no money has been spent. A booking after the fact records money that has ALREADY been spent or may have been spent (an abandoned call, a refused reply, a failed request 1 or request 2); there the code must never raise, and a missing value is replaced by the larger fallback so that the number of requests and attempts is not under-counted. The size of each request is the byte bound; because the loop sees only the LAST error of a call and cannot count earlier attempts, it books the whole-call maximum (request count times attempts times W; PL54), and P4b2-a may later lower it per attempt (PL51).
- **charge factor** (`_charge_factor(llm)` in `k1b/loop.py`, private, total, plain): the number of requests' worth of the worst case that every booking after a possibly billed call books (`CallTimeout`, `ProviderExhausted`, plain `ProviderError` with every `UsageMissing` inside it): the request count of one call TIMES the number of attempts. For the stub of the C13 rows (2 requests, 3 attempts) the factor is 6, so 6W = 0.164160. Each of the two numbers is read from the object when it is an `int` of at least 1 and otherwise taken from a named fallback constant (`CHARGE_FALLBACK_REQUESTS`, `CHARGE_FALLBACK_ATTEMPTS`, `defaults.py`).
- **attempts**: after a failure with no answer (for example a read timeout) `with_retry` sends the SAME request again, up to `max_attempts` times (default 3, `backends/table.py:40`). The provider may have processed and billed an attempt whose answer never arrived; no `Reply` carries that usage.
- **route**: one entry of `routes` in `config.yaml`: a model id, its prices and `max_tokens` (`Route`, `config.py:55-59`).
- **a model with prompt-length price tiers**: a model whose price per token rises above a stated prompt size.
