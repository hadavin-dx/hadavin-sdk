Plain words used here (each keeps one meaning):
- **usage**: the token counts a model provider reports for one call.
- **the five classes of usage**: input (prompt tokens billed at the normal input price), cache write (prompt tokens the provider stored for reuse), cache read (prompt tokens served from that store), output (tokens the model wrote, thinking included on Claude), thinking (the part of output spent on private working; shown for visibility, never priced again). This core prices only input and output; a non-zero cache count is refused.
- **prompt tokens**: input + cache write + cache read (everything the model was sent).
- **reserved amount**: the money the meter (P4b1) sets aside BEFORE a call. Only the meter has one.
- **estimated worst-case amount**: `estimated_worst_case_usd(...)`: a prompt-size ESTIMATE times the input price, plus `max_tokens` times the output price, times the number of requests one call can send. It is an estimate, NOT a bound: three characters a token is a guess, and a token-dense prompt can cost more. The meter may use it as the size of a reserved amount; P4d and P4b1 own what happens when the real cost is higher.
- **refuse**: raise a typed error and return nothing; no cost number is made up.
- **request count of one call** (`request_bound(llm)`): the most billed requests one `chat()` can send when every request is answered, as DECLARED by the kind in its class attribute `REQUESTS_PER_CHAT`: 2 for the OpenAI-compatible kind (it may ask once more when the forced answer is missing), 1 for every other kind and for `FakeLLM`. It does not count retries after a failure. It is STRICT: an object with no declaration, or a bad value, is refused (`TypeError` or `ValueError`). It is for the reservation only.
- **reservation versus charge after the fact**: the reservation is set aside BEFORE a call (the meter, P4b1-b); a loud refusal there is intended, because no money has been spent. A charge after the fact books money that has ALREADY been spent or may have been spent (an abandoned call, a refused reply, exhausted retries); there the code must never raise and must never under-charge, so a missing value is replaced by the larger fallback.
- **charge factor** (`_charge_factor(llm)` in `k1b/loop.py`, private, total): the number of requests' worth of the worst case that one of those after-the-fact charges books: the request count of one call times the number of attempts, each taken from the object when it is usable and from a named fallback constant (`CHARGE_FALLBACK_REQUESTS`, `CHARGE_FALLBACK_ATTEMPTS`, `defaults.py`) when it is not.
- **attempts**: after a failure with no answer (for example a read timeout) `with_retry` sends the SAME request again, up to `max_attempts` times (default 3, `backends/table.py:40`). The provider may have processed and billed an attempt whose answer never arrived; no `Reply` carries that usage.
- **route**: one entry of `routes` in `config.yaml`: a model id, its prices and `max_tokens` (`Route`, `config.py:55-59`).
- **a model with prompt-length price tiers**: a model whose price per token rises above a stated prompt size.

## Rules stated once (both sub-tickets)

- **One error rule.** Anything that makes the cost of a call unknowable or unpriceable is a `UsageMissing` (or its subclass `UnpricedUsage`): REFUSE. No default substitutes a number. Both are `ProviderError`s, neither is `ProviderExhausted`, neither is retried. The message is built only from a fixed reason and a fixed field name; it never holds response text, request text or a reported value (a provider reply can echo a document; personal-data rule).
- **Closed reasons** (`USAGE_REASONS` in `llm/protocol.py`): `absent` (no usable usage object, or the field is missing or null), `invalid` (not a plain int, negative, above the cap, thinking above output, a sum above the cap), `implausible_zero` (the input count is zero on a route with a positive input price, in `cost_usd`; or the reported output count is zero while the reply holds non-empty text or at least one tool call, in `reply()`; field `input_tokens` or `output_tokens`), `unpriced_class` (a cache class has a non-zero or unreadable count, or an unknown pricing word). `UnpricedUsage` always has reason `unpriced_class`. Closed field names: `usage`, `input_tokens`, `output_tokens`, `cache_write_tokens`, `cache_read_tokens`, `thinking_tokens`, `service_tier`, `speed`.
- **No raw `ValueError` or `decimal` error may leave a kind's `chat()` for an ADMITTED input** (a validated route and counts a provider can send). `agent_loop.py:432-439` catches only `ProviderError`, and `with_retry` turns a stray `ValueError` raised inside the retried call into a plain `ProviderError` that `pipeline.py:163` settles at zero.
