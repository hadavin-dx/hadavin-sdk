Plain words used here (each keeps one meaning):
- **usage**: the token counts a model provider reports for one call.
- **the five classes of usage**: input (prompt tokens billed at the normal input price), cache write (prompt tokens the provider stored for reuse), cache read (prompt tokens served from that store, cheaper), output (tokens the model wrote, thinking included on Claude), and thinking (the part of output the model spent on its private working; shown for visibility only, never priced again).
- **prompt tokens**: input + cache write + cache read (everything the model was sent).
- **worst case**: the most one call can cost, worked out BEFORE the call from the prompt size and the route's `max_tokens`. The meter (P4b1) reserves it.
- **refuse**: raise a typed error and return nothing; no cost number is made up.
- **route**: one entry of `routes` in `config.yaml`: a model id, its prices and `max_tokens` (`Route`, `config.py`).

## Rules stated once (all three sub-tickets)

- **One error rule.** Anything that makes the cost of a call unknowable or unpriceable is a `UsageMissing` (or its subclass `UnpricedUsage`): REFUSE. There is no default that substitutes a number. Both are `ProviderError`s, neither is `ProviderExhausted`, neither is retried. Their message is built only from a fixed reason and a fixed field name; it never contains response text, request text or a reported value (the personal-data rule: a provider reply can echo a document).
- **Closed reasons** (constant `USAGE_REASONS` in `llm/protocol.py`): `absent` (the provider sent no usable usage object or the field is missing or null), `invalid` (not a plain int, negative, above the cap, thinking above output, counts that contradict the provider's own total), `implausible_zero` (all prompt classes are zero on a route with a positive input price), `unpriced_class` (a class with a non-zero count has no price on the route). `UnpricedUsage` always has reason `unpriced_class`.
- **Only the llm kind may read a provider's usage object.** Callers see `Reply` and `Usage`.
- **Money type.** Exact `Decimal` USD; token counts are plain `int` (bool refused); prices are USD per million tokens with at most 6 decimals, so every price is a whole number of micro-dollars per million tokens (plan section 6 note on P4b, A9 B1). All arithmetic runs in a local `decimal` context with 60 digits and the `Inexact` trap on, so a rounding step cannot happen silently.
- **Named constants** (one place, `defaults.py`, validated where they are used): `MAX_USAGE_TOKENS_PER_CLASS = 1_000_000_000` (the same bound Intake's `_count` uses, `model_anthropic.py:178-182`; far above any context window; a garbage `2**63` is refused), `MAX_PRICE_USD_PER_MTOK = 1000`, `MAX_GEO_MULTIPLIER = 2`, `PRICE_CHECK_MAX_AGE_DAYS = 30` (P4a-3). # P4a-1: refuse instead of estimate (C2)

- **Package id and name:** P4a-1, "refuse instead of estimate; a reported zero is a zero" (WORK-PACKAGES C2; first of three pull requests of P4a).
- **Path class:** money. Extended review (no round cap): yes. Tier A. Counts as a money pull request (one at a time with P4d and P4b1).
- **Depends on (merged first):** P0e (done by the memos) and P4d (plan row P4a). PENDING LEAD whether P4a-1 may be authored and reviewed before P4d merges (recommended: yes; merge order stays the lead's, because he verifies one money pull request at a time).
- **Problem in plain words:** When a model provider's reply has no token counts, the shared code guesses them from the text it sent and received, and when a provider reports a real zero (for example zero output tokens) the same line replaces it with a guess. The guess becomes the cost that the spend counters add up, so a cap can be reached late and the books can show a number the provider never charged. One provider kind (Anthropic) does not even fail cleanly: with no usage object it raises a plain error that the ask-your-data pipeline then settles as free. This pull request makes the shared code refuse: a reply without usable counts raises `UsageMissing`, a reported zero is kept as zero, and nothing is retried. Settling the unknown cost at the reserved worst case is the meter's job (P4b1); this package only guarantees the meter is told.
- **Source of the code (MANIFEST ids, source repo, commit sha) and what is NOT taken:** nothing promoted. Extends ce70eb5. - **Problem in plain words:** Some providers charge a higher price for every token of a call whose prompt is longer than a stated size (the studio's own rules note a model whose prices rise above 100,000 prompt tokens), and some charge a surcharge for keeping inference in one region. This pull request adds an optional long-prompt price block per route, an optional region multiplier, settlement by the ACTUAL prompt tokens the provider reports (cache classes included), a worst case that always uses the dearest tier, and a dated price check per route that pilot and prod refuse when it is missing, stale, in the future, or disagrees with the route's prices.
