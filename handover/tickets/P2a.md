## 4. Problem in plain words

Hadavin agents need an emergency stop that stays on when parts of the system are down, and a reset that only a named person can do and that leaves a record. Core has an on/off row and two audited calls, `Limits.stop(by)` and `Limits.reset(by)` (read: core `limits.py`, `stop` 43-46 and `reset` 48+). Today any caller can reset under any name, and the runtime database login can write the row. P2a-1 lands: (1) a stop that is durable in the database and that cannot be held up: it is one INSERT of a new row, takes no lock that anyone else can wait on, and the runtime and the stop login hold no right on the tables at all, only the right to call one function and to read one view; (2) a reset that only a separate database credential can do, recorded by the database itself, that clears exactly the stops the operator saw; (3) names stored as keyed labels, never typed text. P2a-1 does NOT make a running program refuse a new outside action after a stop: today that is done only by `limits.blocked` at the three call sites in `agent_loop.py`; an executor entry that must refuse is the trigger of the v1.1 row "in-process gate". It does not close the reserve-after-stop window (PENDING LEAD 26) and does not stop actions already running in other processes.

  ```sql
  CREATE VIEW kill_switch_state AS
  SELECT (k."on" OR r.id IS NOT NULL) AS "on",
         CASE WHEN k."on" THEN k."by" WHEN r.id IS NOT NULL THEN r."by" ELSE k."by" END AS "by",
         CASE WHEN k."on" THEN k.ts   WHEN r.id IS NOT NULL THEN r.ts   ELSE k.ts   END AS ts,
         k.schema_version, k.version,
         (SELECT count(*) FROM kill_switch_stop_requests WHERE cleared_by IS NULL)::int AS open_requests
  FROM kill_switch k
  LEFT JOIN LATERAL (SELECT id, "by", ts FROM kill_switch_stop_requests
                     WHERE cleared_by IS NULL ORDER BY id LIMIT 1) r ON true
  WHERE k.id = 1;
  ```

- The reset function (model text). It takes no lock another caller can wait on EXCEPT the row lock on `kill_switch`, which only the reset group's functions ever take (the runtime and the stop role cannot reach that table), so two resets serialise there.  
  ```sql
  CREATE OR REPLACE FUNCTION <S>.hadavin_kill_switch_reset(p_by text, p_expected_open int)
  RETURNS TABLE ("on" boolean, "by" text, ts timestamptz, schema_version int, version bigint, open_requests int)
  LANGUAGE plpgsql SECURITY DEFINER SET search_path = pg_catalog, pg_temp AS $f$
  DECLARE v bigint; was_on boolean; n int;
  BEGIN
    IF p_by IS NULL OR p_by !~ '^id:[A-Za-z0-9_-]{1,32}:[0-9a-f]{32}$' THEN
      RAISE EXCEPTION 'kill switch: name not accepted' USING ERRCODE = 'HD004'; END IF;
    SELECT k.version, k."on" INTO v, was_on FROM <S>.kill_switch k WHERE k.id = 1 FOR UPDATE;
    IF NOT FOUND THEN RAISE EXCEPTION 'kill switch: row missing' USING ERRCODE = 'HD005'; END IF;
    UPDATE <S>.kill_switch_stop_requests r SET cleared_by = v + 1 WHERE r.cleared_by IS NULL;   -- ONE statement
    GET DIAGNOSTICS n = ROW_COUNT;
    IF p_expected_open IS NULL OR n <> p_expected_open OR (n = 0 AND NOT was_on) THEN
      RAISE EXCEPTION 'kill switch: the open count changed' USING ERRCODE = 'HD003'; END IF;
    PERFORM set_config('hadavin.reset_typed_by', p_by, true);
    IF NOT was_on THEN UPDATE <S>.kill_switch SET "on" = true WHERE id = 1; END IF;   -- OFF to ON: the trigger sets ts only
    UPDATE <S>.kill_switch SET "on" = false WHERE id = 1;                             -- ON to OFF: the trigger records the reset
    RETURN QUERY SELECT s."on", s."by", s.ts, s.schema_version, s.version, s.open_requests
                 FROM <S>.kill_switch_state s;
  END $f$;
  ```

  ```sql
  CREATE OR REPLACE FUNCTION <S>.hadavin_kill_switch_guard() RETURNS trigger
  LANGUAGE plpgsql SECURITY DEFINER SET search_path = pg_catalog, pg_temp AS $f$
  DECLARE grp text; lbl text;

    IF OLD."on" AND NOT NEW."on" THEN
      SELECT reset_group INTO grp FROM <S>.kill_switch_guard_config WHERE id = 1;
      IF grp IS NULL OR grp = '' OR NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = grp) THEN
        RAISE EXCEPTION 'kill switch: reset group not set up' USING ERRCODE = 'HD002'; END IF;
      IF NOT pg_has_role(session_user, grp, 'MEMBER') THEN
  ```
