PR #50 holds a gate (425 lines), a small in-memory row store (225 lines) and a read-only configuration view (181 lines) that do most of this. PR50-local has one failing test in the lead's full run and one mutation row that proves nothing. P2a fixes both first, then lands the three modules as one `stop_state` kind with an audited reset that only a person can perform.

- Interface (names, argument and return types, errors). Read at PR50-local unless "NEW" (P2a adds it).
  - Stored state (existing, reused): table `kill_switch`, one row `id=1`, columns `on` bool, `by` text, `ts` time (`models.py:251-254`; seeded OFF in `migrations/0003_approvals_tick.sql:24-27`). States: OFF, ON. Transitions: OFF to ON (`stop`); ON to OFF (`reset`); ON to ON (a second `stop` overwrites `by` and `ts`). No "paused" state, no reason text. One global row; a per-tenant or per-agent stop needs a schema change and is out of P2a (PR50 `docs/promoted-controls.md` says each client deployment has its own database).
  - `Limits.stop(by: str, source: str = "cli") -> None`: switch first, then audit, so a stop works with the audit store down. `Limits.reset(by, source="cli", expect: tuple[str|None, object]|None = None) -> None`: audit intent row first (if that fails, `AuditUnavailable`, switch stays ON); with `expect=(by, ts)` it reads the switch again and refuses (`SwitchChanged`, audit row `reset_refused`) if the stop is no longer the caller's own. `Limits.is_stopped() -> bool` (raises if the store is unreadable) and `Limits.switch() -> KillSwitch` are new in PR50 (`limits.py:21,48,53,57-70`).
  - `StopGate(limits=None, *, cache_ttl=0.0, unaudited=False, label_key: bytes|None=None)` (`stop_gate.py:118`). `StopGate(None)` raises `ValueError` unless `unaudited=True`; a `Limits` without `source` raises `TypeError`. Methods: `engaged` (process flag only), `durable_on()` (store read; unreadable counts as ON), `blocked()`, `effect()` / `aeffect()` (wrap every outside action; raise `EffectBlocked` when blocked, else count the action in flight), `engage(items, undo, *, by, timeout=30.0) -> EngageResult` (flag first, then durable write, then wait up to `timeout` for actions in flight, then `undo` each item; result fields `results`, `complete`, `in_flight_at_timeout`, `durable`, `store_error` = class name only, `already_sweeping`), `release(by)` (audit first; compare-and-set against the stop THIS gate wrote; `StopGateBusy` if a sweep runs, if someone else changed the switch, or if an `engage` ran meanwhile, in which case the stop is written again and `StopGateBusy.durable` says whether that worked), `restore(on, by=None)` (set the flag after a restart; `restore(False)` needs `by`, writes an intent row, then `restore_done` or `restore_refused`).
  - Audited reset, defined. A reset is one `release(by)`, `Limits.reset(by)`, or the CLI `limits reset --by X`. It writes, in order: audit row 1 (intent: `operation="reset"`, `result="off"`), then the switch, and on refusal audit row 2 (`reset_refused`). Fields of every row (verified `limits.py:38-46`, `models.py:188-215`): `event_id`, `ts` (UTC), `run_id="-"`, `domain="limits"`, `operation` (`stop`, `reset`, `reset_refused`, `restore`, `restore_done`, `restore_refused`), `principal` (masked label of who), `source` (`gate` or `cli`), `result` (`on`/`off`), `error_code` (for example `durable_write_failed:<ErrorClassName>`, at most 60 characters). No free text, no reason, no driver message.
