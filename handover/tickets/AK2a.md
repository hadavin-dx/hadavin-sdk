**Words used (plain meaning, one meaning each).**
- **document**: one file a client gives us (a PDF or a plain-text file). **page**: one page of it, as the reader returns it. **reader**: the part that turns the file's bytes into page texts. **text PDF**: a PDF whose pages carry real text; a **scan** is a PDF whose pages are pictures of text.
- **quality report**: numbers about one document (pages, characters per page, share of characters that are not text, counts of invisible characters, how many pages look like scans) plus one **quality code** from a closed list. It never holds document text. It names neither the language nor the writing system (row V3).
- **cleaning**: a fixed list of small text repairs (line endings, control characters, words split by a line-end hyphen, repeated page headers and footers, page-number lines, extra spaces). **removal report**: for each repair, how many characters it removed. Never text.
- **chunk** (passage): one piece of the cleaned document, cut at headings, paragraphs, sentences or spaces, with its page range and position. **chunker**: the part that cuts. **cut point**: a place where one chunk may end and the next begin. **chunk set**: all chunks of one document plus the two reports.
- **child process**: a separate Python process the PDF reader starts for each PDF, so a hostile or broken file cannot crash, hang or fill the memory of our own process. **parent**: our own process, which starts the child. **process runner**: the library-independent part of AK2a-2 (starting, feeding, timing, killing and checking the child). **library addendum**: the part of AK2a-2 that depends on the named PDF library; it is written after AK0 names it.
- **format characters** (Unicode category Cf): invisible characters such as the zero-width space U+200B, the zero width joiner U+200D (ZWJ), the soft hyphen U+00AD and bidirectional marks. **tag characters**: the format characters U+E0000 to U+E007F, which can spell hidden words that a person does not see.
- **step**, **item**, **final state** (`done`, `needs_person` = "a person must look", `refused`), **tenant**, **readers** (the people allowed to read an item), **gate**, **`Gated`** (the one wrapper the gate gives code instead of a raw outbound part): as in AK1 revision 3 (`tickets/AK1.md`, "Words used", `:10-16`).

- **Problem in plain words:** A document-question system (RAG) must first turn a client's files into clean passages. Today the core cannot read a PDF at all: every document is decoded as UTF-8 text with bad bytes replaced and sent to the model as it is (`llm/common.py:92`), so a PDF arrives as garbled characters, a scanned PDF arrives as nothing useful, and no step notices. Nothing measures whether a document was read well, so a poor document would be indexed and later give wrong or empty answers with no warning. The only splitter in the core cuts on blank lines (`k1b/bundle.py:181-183`) and knows no headings, so a passage does not say which section it belongs to, and one very long paragraph becomes one very long passage. PDF parsing runs code over bytes written by someone else; a broken or hostile file can hang, crash or fill the memory of our process. AK2a adds a reader that reports how well each document was read and sends poor or broken documents to a person, a cleaning step that says exactly what it removed, a chunker that follows headings and sentences and never cuts inside a word, and a child process that contains a bad PDF. Said plainly, the costs: a PDF goes to a person when every page is short, or when at least 2 pages and more than 1 in 10 pages are short and the library cannot tell whether they hold pictures; a document also goes to a person when a paragraph of 2,000 or more characters has no sentence end and no space, or when invisible characters sit inside a word or an address. Each costs a person's time and indexes nothing wrong; the rates are unmeasured (row V6).

  4. **`pick_reader(data, readers, settings) -> DocumentReader | None`**, by content, never by file name. The file goes to the PDF path when `%PDF-` occurs in the first `KIT_PDF_HEADER_SCAN_BYTES` (1,024) bytes, OR at the start of any line anywhere in the body (at byte 0 or right after `\n` or `\r`; one fast byte search). On the PDF path the reader named `pdf` handles the file, or `None` (step code `unsupported_type`) when no `pdf` reader is registered; otherwise `TextReader` handles it (and returns `bad_encoding` itself for bytes that are not UTF-8). So `unsupported_type` means only "a PDF and no PDF reader", and the 32 MiB body is decoded once, not twice. Readers commonly accept bytes before the PDF header; AK2a looks in the first 1,024 bytes and fails closed (the ISO 32000 wording is not relied on). **Stated cost:** a text file with a line that starts `%PDF-` goes to the PDF path, so to a person in AK2a-1 or on Windows. **Stated limit:** a `%PDF-` in the middle of a line after byte 1,024 is read as text, like any text file holding PDF syntax.
  5. **Cleaning (AK2a-1, `ingest/clean.py`).** `clean(pages: tuple[Page, ...], settings) -> tuple[tuple[Page, ...], RemovalReport, bool]` (the `bool` is "over-cleaned"). **Cleaning works per page:** every rule sees one page at a time, so c3 never joins across a page break and a word split over a page break keeps its hyphen (stated cost). c4 and c5 compare across pages but remove only lines of single pages. `CLEAN_RULES: Final`, closed; ids unchanged, **applied in this order: c1, c2, c6, c4, c5, c3, c7**:
     - `c1_newlines`: `\r\n` becomes `\n` and counts 1 (the `\r` that disappears); a lone `\r` becomes `\n` and counts 0, because the length does not change. This is the one replacement in cleaning: it changes a line ending, never a letter.
     - `c2_controls`: removes C0 controls except `\t` and `\n`, DEL, and C1 controls (U+0080-U+009F). Does NOT touch format characters (category Cf: zero-width, bidirectional marks, tag characters), combining marks or U+FFFD (I7).
     - `c6_spaces`: runs of spaces and tabs inside a line become one space; trailing spaces removed.
     - `c4_running_lines`: a line that is the first or last non-blank line of at least `KIT_RUNNING_LINE_MIN_PAGES` (3) pages AND of at least `KIT_RUNNING_LINE_MIN_SHARE_PPM` (500,000 = half) of all pages, compared after digits are replaced by `#` and spaces collapsed, is removed, together with the one line break that joins it to the rest of the page, from every page where it is the first or last line.
     - `c5_page_numbers`: only on documents of 2 pages or more, a first or last line that is only a page number is removed when the number equals the page's position (1-based) or the position minus 1 (one unnumbered cover page), in the forms `12`, `- 12 -`, `page 12` (any case), or is `n/m` or `page n of m` with `m` equal to the page count. Any other number line (`2024`, `42` on page 3) is kept.
     - `c3_hyphen_join`: a letter-hyphen-newline-letter sequence inside one page where both letters are lower case (`str.islower`) loses the hyphen and the newline. Upper case or digits on either side: kept. Stated limit: a real compound split at a line end (`"well-\nknown"`) also loses its hyphen.
     - `c7_blank_lines`: three or more newlines become two.
     - **Passes and the check pass:** `clean` runs the whole list up to `KIT_CLEAN_MAX_PASSES` (3) times and stops at the first pass that removes nothing. If the last allowed pass still removed something, one **check pass** runs: the result is over-cleaned only if the check pass would remove something more; otherwise the result is already a fixed point and is used. Each pass, the check pass included, is linear in the text. So every result that is not over-cleaned is a fixed point of cleaning, whatever the pass limit.
     - **Over-cleaning share:** over-cleaned also when the characters removed by the **content rules c3, c4 and c5** exceed `KIT_MAX_REMOVED_SHARE_PPM` (300,000 = 30 percent) of `chars_before`. c1, c6 and c7 (line structure and spaces) do not count toward the share, and neither does c2 (control characters are already limited to 5 percent by `high_nontext` before cleaning); all four still count in the removal report. The step maps over-cleaned to `over_cleaned`. **Stated cost:** c4 peels one repeated line per page edge per pass, so a document with four or more stacked repeated header lines (or footer lines) is still changing at the check pass and goes to a person (pinned in R11; measured in V6; the setting can be raised).
  6. **Chunking (AK2a-1, `ingest/chunk.py`).** `Chunker` (Protocol): `name: str`, `chunk(pages, settings, *, tenant, item_id, content_sha256, reader) -> tuple[tuple[Chunk, ...] | None, str]`: `(chunks, "ok")`, or `(None, "unsplittable")` when some window holds no valid cut point. One implementation in v1, `StructureChunker` (`name = "structure-1"`); the blank-line alternative of revision 1 is cut (row V15).
     - **Text the chunker works on** (`joined`): the cleaned pages joined with `"\n\n"`; `char_start`/`char_end` index into it; `page_start`/`page_end` are the pages of the first and last character.
     - **Blocks and headings.** Blocks = text between blank lines. A **heading** is the FIRST line of a block when that line is at most `KIT_HEADING_MAX_CHARS` (120) characters, does not end in `.`, `,` or `;`, and is either (a) numbered (`1`, `1.2`, `1.2.3`, with at most `KIT_MAX_HEADING_DEPTH` (8) parts, or a Roman numeral or a single capital letter followed by `.` or `)`, then a space and text), (b) a Markdown heading (`#` then a space, with at most 6 and at most `KIT_MAX_HEADING_DEPTH` `#`), or (c) at least 3 letters with every letter upper case. A number with more parts, or more `#`, is not a heading: the line is paragraph text. The rest of the block is the section's first paragraph. A line in the middle of a block is never a heading (numbered list items inside a paragraph stay paragraph text). Level: the number of numbered parts, the `#` count, or 1 for (c). A heading closes every open section of its level or deeper and starts a new chunk; the heading line stays in the text of the first chunk of its section (so coverage holds) and is also in `heading_path` (outermost first). This is the ONE depth cap: the path length follows from the levels, so it is at most `KIT_MAX_HEADING_DEPTH` entries with no second cap.
     - **Packing and cuts (no hard cut).** Blocks of one section are packed into a chunk until adding the next would pass `KIT_CHUNK_MAX_CHARS` (2,000). A longer block is split inside a window that ends at the limit. A cut point is **valid** only if the character right after it is not a combining mark (category M), not a ZWJ (U+200D) and not a variation selector (U+FE00-U+FE0F, U+E0100-U+E01EF). The chunker takes the last valid cut point before the limit that follows a **sentence end** (`.`, `?`, `!` or `;` followed by whitespace; or U+3002, U+FF01 or U+FF1F, which need no whitespace after them, because Chinese and Japanese text has no spaces), else the last valid cut point at a whitespace character. **If the window holds neither, `chunk` returns `(None, "unsplittable")` and the document goes to a person.** So the size bound is exact (no chunk is longer than `KIT_CHUNK_MAX_CHARS + KIT_CHUNK_OVERLAP_CHARS`), the settings check of Interface 8 is true, and a cut never falls inside a token: a whitespace or sentence cut never splits a word, and a heading cut sits on a blank line, so a value such as an e-mail address is never split across two chunks. **Stated cost:** a paragraph of 2,000 or more characters with no sentence end and no space (a base64 blob, Thai text, a very long URL) sends the document to a person (row V6 measures the rate). A chunk shorter than `KIT_CHUNK_MIN_CHARS` (200) merges into the next chunk of the same section only if the result stays at or under `KIT_CHUNK_MAX_CHARS`; otherwise it stays short (the size cap wins). The sentence and whitespace searches look only inside one chunk window, so the work is at most `len(joined) x (KIT_CHUNK_MAX_CHARS + KIT_CHUNK_OVERLAP_CHARS)`.
     - **Overlap**: each chunk after the first in a section starts with up to `KIT_CHUNK_OVERLAP_CHARS` (150) characters of the previous chunk's end, moved forward to a whitespace boundary that is also a valid cut point (so the overlap never starts inside a token either); 0 when that window holds no such boundary, and 0 after a heading; `overlap_chars` says how many. Overlap repeats text, so a personal value near a cut appears whole in two chunks; the gate masks each.
     - **Coverage rule** (K5): for every chunk `text == joined[char_start:char_end]`; dropping each chunk's first `overlap_chars` characters and joining the rest, separated by the block gaps the cut fell in, reproduces `joined` without losing or repeating a non-space character.
     - **Chunk ids**: `chunk_id(...) = "chk-" + sha256_hex(tenant_key(tenant, content_sha256, settings_fp, chunker_name, reader, str(index), sha256_hex(text)))[:32]` (AK1's length-prefixed `tenant_key`, each part a `str` of 1 to 512 characters, `tickets/AK1.md:108`; the `prefix-<32 hex>` shape of `models.py:23-24`, but derived, not random). Same bytes, tenant, FP settings (Interface 8), chunker and library version give the same ids (AK2d needs that); another tenant, another chunker name, another library version (it is in `reader`) or another chunk text gives another id. `chunk_id` is a module function so K8 and `from_bytes` call it directly.
     - **Injection flag**: per chunk, `injection_flag = injection_check(detector, chunk.text, source="kit_ingest").flagged OR (the chunk holds any tag character U+E0000-U+E007F)`. The text is never changed (I7). Stated plainly: a phrase split by zero-width characters is caught only for the three squashed phrases (`guard/injection.py:35`, `:44-48`); a phrase cut at a heading boundary (where there is no overlap) is caught only if one side alone matches; tag-spelled words are not read, only flagged; ordinary text such as "act as" is flagged too (I5).
  7. **The step (AK2a-1, `ingest/step.py`).** `DocumentStep(readers: Mapping[str, DocumentReader], chunker: Chunker, detector: Detector, settings: IngestSettings)`, `name = "read_and_chunk"`, implements AK1-a's `Step` (`tickets/AK1.md:115`). Construction refuses (`TypeError`): a detector with `type(detector) not in LOCAL_DETECTORS = (RegexDetector,)` (exact type, no subclass, I5); a reader map whose keys are not a subset of `{"text", "pdf"}` or that lacks `"text"`. `run(inp: StepInput) -> StepOutput`, in order:

     - (b) `len(inp.body) > KIT_MAX_FILE_BYTES` (32 MiB) gives `too_large` BEFORE any reader is called.
     - (c) `pick_reader`; `None` gives `unsupported_type`.
     - (d) `reader.read(...)`; a non-`ok` code ends here. The step re-checks page count (`too_many_pages`) and characters (`too_many_chars`), and any lone surrogate (U+D800-U+DFFF) in a page gives `bad_encoding` (a fake or future reader could return one; `sha256_hex` would raise on it, `models.py:46-47`).
     - (e) `ingest.quality.assess(pages, settings) -> QualityReport` (its `code` is the first failure below, or `ok`): all pages have zero non-space characters -> `empty`; `nontext_share_ppm > KIT_MAX_NONTEXT_PPM` (50,000 = 5 percent) -> `high_nontext`, where the numerator counts U+FFFD, private-use (Co), unassigned (Cn), surrogate (Cs) and control characters other than `\t`, `\n`, `\r` and `\f` (line and page structure that c1 and the reader remove), and the denominator is all characters of all raw pages, spaces included; then the **scan rule**: let P be the number of pages, and let a **poor page** be one whose `has_images` is `True` or `None` (unknown counts: fail closed) and that has fewer than `KIT_MIN_CHARS_PER_PAGE` (100) non-space characters; the result is `suspected_scan` when every page is poor, or when there are at least `KIT_MIN_POOR_PAGES` (2) poor pages and `poor x 1,000,000 > KIT_MAX_POOR_PAGE_PPM x P` (100,000 = 1 page in 10). Results: 1 short page in 9 is `ok`; one image page of 50 characters among text pages is `ok`; 2 short pages in 10 give `suspected_scan`; a 1-page short PDF with `has_images=None` gives `suspected_scan`; every scan whose pages are all poor is caught.
     - (f) `clean(...)`; over-cleaned gives `over_cleaned`.
     - (f2) `ingest.quality.hidden_chars(cleaned_pages) -> bool` (PENDING LEAD 5 option (a)): `True` when a run of one or more format characters (category Cf) has an ASCII letter, an ASCII digit or one of `@ . _ + -` directly before it AND directly after it, on one page; `True` gives `hidden_chars`. It runs on the cleaned text, so a control character that cleaning removed cannot hide the run. Tag characters are NOT left out (author correction AUTH-4: a tag character inside an e-mail address hides it from masking just as a zero-width space does; the resolve left them out because I5 flags them, but the flag does not stop the text reaching the gate unmasked). The reader already removed the leading BOM. Indic and emoji ZWJ and ZWNJ sequences have non-ASCII neighbours, so they are not affected. **Stated cost:** soft hyphens (U+00AD) inside words, which some PDF tools write, bidirectional marks next to ASCII digits, and text pasted from the web that carries zero-width spaces inside words send the document to a person (rate unmeasured, V6).
     - (g) `chunk(...)`; `(None, "unsplittable")` gives `unsplittable`. Then flag, build the `ChunkSet` (tenant and readers copied from `inp`, unchanged; `content_sha256` copied from `inp.content_sha256`, `tickets/AK1.md:111`), `done` with `body = chunk_set.to_bytes()`.

  8. **Settings (AK2a-1, `ingest/settings.py`; AK2a-2 adds the other four `KIT_PDF_*` rows; `KIT_PDF_HEADER_SCAN_BYTES` is AK2a-1's, because `pick_reader`, R20 and R22 use it).** `IngestSettings` (pydantic, frozen, `extra="forbid"`) with one field per `KIT_*` constant, defaulted from `defaults.py`, bounds as below (integers only). A reader thread reads stdout in pieces and ends at the first `\n` (the result is one line), at end of file, or when it has read `KIT_PDF_MAX_RESULT_BYTES + 1` bytes, which gives `too_many_chars`. The main thread joins the reader thread with what is left of the deadline; if it is still alive, the result is `timeout` (author correction AUTH-6: waiting on the reader thread rather than on the process is what lets the kill come before `wait()`). `communicate()` is NOT used (it buffers unbounded output).

Until it is reaped, the child keeps its process-group id, so the id cannot be reused by another process yet; the library's own children (and any grandchild) die with the group. Then `proc.wait()` reaps it.
     - **Trust boundary: the parent treats the child's line as hostile.** The line is parsed with `json.loads`; `ValueError` and `RecursionError` (both measured, resolve fact 3) give `worker_crash`. The result must be one JSON object with exactly the keys `code`, `pages`, `reader`; `code` is `ok` or one of `corrupt`, `encrypted`, `memory`, `too_many_pages`, `too_many_chars`; `pages` is a list exactly when `code` is `ok`, each page `[str, bool or null]` with the flag checked as `type(x) is bool` or `x is None`; no lone surrogate anywhere (the parent checks again, because `json.loads` accepts `\ud800`); `reader` fullmatches `pdf:[A-Za-z0-9_.-]{1,64}==[A-Za-z0-9_.+-]{1,32}`; the parent re-counts pages and characters against the caps. No valid result, whatever the exit status, gives `worker_crash`. `read()` never raises for a bad child.

**BN-8. The cut algorithm, exactly (R3-ADV-7). This replaces Interface 6 "Packing and cuts", "Overlap" and "Coverage rule" where they differ.**
- **Offsets and limit.**
  - A chunk's **new text** is `joined[s:e]`. `e` is an EXCLUSIVE end offset, and `s` is the previous chunk's `e` (or the section's start).
  - The limit is INCLUSIVE: `e - s <= KIT_CHUNK_MAX_CHARS`.
  - `char_end = e` and `char_start = s - overlap_chars`.
  - Chunks TILE `joined` exactly: the first chunk has `char_start == 0`, each later chunk's new text starts at the previous `char_end`, and the last has `char_end == len(joined)`.
- **Cut positions.**
  - A **sentence cut** after a sentence-end character at index `i` is `e = i + 1`. The character is `.`, `?`, `!` or `;` followed by whitespace, or U+3002, U+FF01 or U+FF1F.
  - A **whitespace cut** at a whitespace character at index `w` is `e = w`.
  - So the whitespace after a cut always begins the NEXT chunk.
  - A section boundary is a cut at the start of the blank-line gap before the heading line. The new section's first chunk starts with that gap and then the heading line.
- **Valid cut.** `e` is valid only if ALL of these hold:
  - (1) `s < e <= s + KIT_CHUNK_MAX_CHARS`;
  - (2) `joined[s:e]` holds at least one non-whitespace character (so no zero-length or whitespace-only chunk, and the cut always makes progress);
  - (3) `joined[e]` is not a combining mark, a ZWJ or a variation selector;
  - (4) for a whitespace cut, BN-9's digit rule.
- **Choice.** Take the largest valid sentence cut. If there is none, take the largest valid whitespace cut. If there is none and `section_end - s > KIT_CHUNK_MAX_CHARS`, `chunk` returns `(None, "unsplittable")`. If `section_end - s <= KIT_CHUNK_MAX_CHARS`, the rest of the section is one chunk.
- **Packing.** Blocks are packed from `s`. The next block (including the whitespace that separates it) is added while the new text's end stays `<= s + KIT_CHUNK_MAX_CHARS`. The `\n\n` separators count toward the limit. When the next block does not fit, the cut is the whitespace cut at the start of its gap. When one block alone does not fit, the window search above runs inside it. The tail after the last cut in a long block starts a new chunk, and packing continues with the following blocks of the same section.
- **Merging.**
  - It runs once per section, left to right, after all cuts.
  - A chunk whose new text is shorter than `KIT_CHUNK_MIN_CHARS`, and that is not the last chunk of its section, merges into the next chunk of the same section when the merged new text satisfies `next.e - this.s <= KIT_CHUNK_MAX_CHARS`. The merged chunk is checked again against its own next chunk.
  - A tail piece is an ordinary chunk for this rule. The last chunk of a section never merges.
- **Overlap**, computed last for each chunk after the first of its section:
  - `overlap_chars` is the largest `k <= KIT_CHUNK_OVERLAP_CHARS` such that `joined[s - k]` is a non-whitespace character preceded by whitespace and is a valid start under rule (3);
  - it is 0 if no such `k` exists, and 0 after a heading.
- **K5 coverage (replaces the old rule):** `chunks[0].text + "".join(c.text[c.overlap_chars:] for c in chunks[1:]) == joined` exactly, and `chunks[0].char_start == 0`.
- **K2 check (replaces its formula):** for every chunk `c` that is not the last of its section and whose new-text length `c.char_end - c.char_start - c.overlap_chars < KIT_CHUNK_MIN_CHARS`, assert `next.char_end - (c.char_start + c.overlap_chars) > KIT_CHUNK_MAX_CHARS`.
- **`from_bytes`, the overlap-0 neighbour rule tightened:** `overlap_chars == 0` requires `char_start == prev.char_end` (no gap). The first chunk requires `char_start == 0`.
- **M-72 redefined (F14):** "`from_bytes` accepts an overlap-0 chunk that starts after `prev.char_end` (a gap)". Killed by a new K11 refusal case (a set with a 1-character gap).
