## Words used here (defined once)
- **foreign text**: text this package did not write. Examples: a library's error message, a model reply, a line of a document, a line of a configuration file that a parser quotes back. The design calls it zone T2. It must never reach a log, a stored error field or the screen.
- **own error text**: the message of an exception raised by our own code. It is built only from fixed words we wrote (T0) and from values the operator typed into configuration (T1: a secret name, a path, a kind name).
- **writer**: a place in `src/` that turns a failure into text that leaves the process. That is a log call, a `print`, a stored field (`TickState.last_error`, `DeadLetter.errors`, `Delivery.reason`), an audit field, or the extract retry prompt.
- **the diagnostic**: P5a's record of a failure. It is built only from closed parts: a code word, a step, `file:line`, a short hash and a few numbers. `render` turns it into one ASCII line, called "Grammar A": `<Kind>: diag_v=1 code=<code> step=<step> at=<file:line> fp=<8 hex>[ k=v ...]`. The line is at most 400 characters (`DIAG_LINE_CHARS`).
- **`validation_text(exc)`**: P5a's closed text for a pydantic validation error. It is a list of closed pydantic error-type names only, for example `extra_forbidden; missing`, at most 108 characters. It holds no value from the input and no `loc` path.
- **`class_name_of(x)`**: P5a's only allowed way to turn an exception class into text.
  - Our own classes and built-in classes print their bare name.
  - A foreign class prints its `module.qualname` only when it passes P5a's identity and allow-list rule; otherwise it prints `foreign_class`.
  - A class built at run time prints `dynamic_class`. So a class named from document text cannot leak.
- **`own_text(exc)`**: the new gate in `errors.py` (see Interface). It lets our own short ASCII configuration text through and turns everything else into the diagnostic.
- **taint guard**: a CI test that reads the source with Python's `ast` module and fails when text derived from an exception reaches a writer (design section 8, D11).
- **STOP**: the builder stops work, writes the reason in the evidence, and the lead decides before work goes on.

## What this package is, in one paragraph
P5a builds the diagnostic, P5b1 fills in provider facts, and P5b2 lists every place that builds a `ConfigError`. None of them changes what the program prints. P5b3 is the step that does: it connects that code to every writer. After P5b3, **no stored field and no log line carries foreign text, and no `refused:` line from a FOREIGN place carries it** (P5b2's label for a place that pastes exception text; see "What P5b3 does NOT stop" for the limit on `OPERATOR` places). The package has two parts:
- **R3c**: rewires the writers in `cli.py`, `runtime/tick.py`, `extract.py`, `guard/injection.py` and `approvals/receiver.py`; replaces every exception class name that reaches a writer with `class_name_of`; and adds the taint guard.
- **R3b**: rewrites the configuration-error places that paste exception text. 13 of them paste a class name and 5 paste library text.

On `cd2243f` the design's "six legacy entry points" (`safe_message`, `safe_text`, `class_name`, `locator`, `validation_text`, `with_class`) do not exist. `guard/safe_message.py` lives only on the old branch `core/c18a-injection-log-redact`, and P5a keeps only `validation_text`, as a new function. So the part of R3c that would redirect those entry points does nothing on main.

  - **The taint guard, `tests/test_taint_guard.py`** (design section 8 and D11, narrowed; PENDING LEAD 7, changed by RES-4):
    - **Sources:** a name bound by `except ... as NAME`; a parameter annotated with an exception type; a parameter named `e`, `exc`, `err` or `ex`. A plain parameter named `error` is not a source unless it is annotated (D11).
    - **Two levels.**
      - The exception OBJECT may be passed to any function. The receiving function's exception-typed or exception-named parameter makes it a source there, so that helper is checked in its own body.
      - The exception TEXT is:
        - `str`, `repr`, `format` or `ascii` of it;
        - an f-string, `%` or `.format` with it;
        - **any attribute read of it** (`.args`, `.msg`, `.reason`, `.strerror`, `.filename`, `.problem`, `.text`, `.doc`, `.code`, `.__name__`, ...), of `type(it)` or of `it.__class__`;
        - `getattr(it, ...)`;
        - `traceback.*(it)`;
        - any `+`, `join`, tuple, list or dict built from these.
      - An attribute read wrapped directly in a SAFE call is not TEXT, for example `int(exc.code)` or `isinstance(exc.reason, X)` (finding RES-4).
      - Calling a method of the exception (`exc.close()`, `tools.py:619`) makes the RESULT text. The call is not a sink, because the sink rule looks at arguments.
      - Text taint propagates to a fixed point inside the function through assignment, walrus, unpacking, for-targets, lambdas and comprehensions.
    - **Sinks for TEXT:**
      - `print` and `write`;
      - `warnings.warn`;
      - every call on a logger name (`_LOG.*`, `log.*`, `logging.*`, `logging.getLogger(...).*`);
      - `raise X(...)` of any class;
      - the keywords `extra=`, `last_error=`, `errors=` and `reason=`;
      - audit `emit`/`emit_outcome` (any keyword);
      - **any call not on the SAFE list**, kept because narrowing to "calls that leave the process" would miss a helper that logs text it received (finding R1-ADV-3).
    - **Sinks for the OBJECT:** `logging.*(..., exc_info=...)` and `logger.exception(...)`, because `exc_info` prints the message.
