## Words used here (defined once)
- **foreign text**: text this package did not write. Examples: a library's error message, a model reply, a line of a document, a line of a configuration file quoted back by a parser. The design calls it zone T2. It must never reach a log, a stored error field or the screen.
- **own error text**: the message of an exception raised by our own code. It is built only from fixed words we wrote (T0) and from values the operator typed in configuration (T1: a secret name, a path, a kind name).
- **writer**: a place in `src/` that turns a failure into text that leaves the process: a log call, a `print`, a stored field (`TickState.last_error`, `DeadLetter.errors`), an audit field, or the extract retry prompt.
- **the diagnostic**: P5a's record of a failure, built only from closed parts: a code word, a step, `file:line`, a short hash and a few numbers. `render` turns it into one ASCII line, "Grammar A": `<Kind>: diag_v=1 code=<code> step=<step> at=<file:line> fp=<8 hex> [k=v ...]`.
- **`class_name_of(x)`**: P5a's only allowed way to turn an exception class into text. Our own classes and built-in classes print their bare name. A foreign class prints its `module.qualname` only when it passes P5a's identity and allow-list rule; otherwise it prints a fixed word. So a class built at run time with a name taken from a document cannot leak. (PENDING P5a: the fixed word is `dynamic_class` in revision 1 and `foreign_class` in the resolve.)
- **taint guard**: a CI test that reads the source with Python's `ast` module and fails when text derived from an exception reaches a writer (design section 8, D11).

## What this package is, in one paragraph
P5a builds the diagnostic, P5b1 fills in provider facts, and P5b2 lists every place that builds a `ConfigError`. None of them changes what the program prints. P5b3 is the step that does: it connects the new code to every writer. After P5b3, no stored field, log line or `refused:` / `failed:` / `tick:` line can carry foreign text. The package has three parts:
- **R3c**: rewires the writers in `cli.py`, `runtime/tick.py`, `extract.py` and `guard/injection.py`, replaces every exception class name that reaches a writer with `class_name_of`, and adds the taint guard.
- **R3b**: rewrites the 18 `ConfigError` places that paste text from an exception.
- **D8**: SDK configuration validators raise a closed `SdkValueError`, so a configuration error keeps its reason without free text.

On `cd2243f` the design's "six legacy entry points" (`safe_message`, `safe_text`, `class_name`, `locator`, `validation_text`, `with_class`) do not exist: `guard/safe_message.py` lives only on the old branch `core/c18a-injection-log-redact`, and P5a's resolve kept only `validation_text`, as a new function. So the part of R3c that would redirect those entry points does nothing on main. What is left is the writers listed below.
