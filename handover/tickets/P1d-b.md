## The problem in plain words
The incident-case masker (`k1b/redaction.py`) decides from a key NAME whether the value under it is a password or other credential; if yes, the value is hidden whole. It reads the name only as written, so `db_pass` + an invisible zero-width space + `word`, the same name with one Cyrillic letter that looks Latin, or `db-pass**word**` is "not a credential", and a password with no known pattern (like `hunter2xyz`) is sent to the evaluation model. The same file finds the keys `name`, `kind`, `value`, `data` and the value `Secret` by exact comparison, so one look-alike letter in any of them shows a Kubernetes secret or an environment password. When a credential key IS recognised, a value with spaces is masked only up to the first space, and other copies of the value elsewhere in the case are not masked. Last, the small local server for approval clicks writes the raw request line (with any value in the address) to the debug log.

## Words used
- **Key name** = a dictionary key, or the `name` of an environment entry `{"name": ..., "value": ...}`.
- **Ordinary key** = a key made only of ASCII letters and digits in words joined by single separators from `_ . - / : @` or a space: the grammar `^[A-Za-z0-9]+([_.\-/:@ ][A-Za-z0-9]+)*$`, read on the key as written. Every other key is a **non-ordinary key** (it holds a non-ASCII character, a marker such as `*`, two separators in a row, a leading or trailing separator, and so on). Rev 1 called this "plain spelling"; rev 2 uses "ordinary key" only, because "plain" also described values.
- **Credential word** = the words `SENSITIVE_KEY` already lists: pass, password, passwd, passphrase, secret, token, api key, authorization, credential(s), private key, bearer. No word is added.
- **Fold views** = `textnorm.fold_views(key, scripts=frozenset(), casefold=True)` (P1b: look-alike letters mapped, accents, invisible and format characters dropped; R `textnorm.py:795`, drop list `_DROP_CATEGORIES` line 359 holds Cc, Cf, Mn, Me, Co).
- **Squeeze views** = `textnorm.squeeze_views(key)` (the same views, upper case, only ASCII letters and digits kept; R line 939).
- **Fail closed** = when a check cannot decide, the value is hidden.
- **fb row** = a fail-before row: it fails on the base and passes after the change. **pb row** = a pin row: the same result before and after. **BS-0** = build step 0: reads and probes on the build base before any product code is written; it records each result in `handover/evidence/P1d-b/bs0.md`.
- **S11, S12a, S16** = items of the sibling report `handover/studio-notes/p1d-siblings.md`; S12a is the part of S12 this package fixes: `_pair` shows a credential value in part and does not learn it for its other copies.

## Behaviour, exactly
1. **`sensitive(key)`** (clauses named C1-C5 for the catch table):
   - not a `str` -> False (unchanged).
   - C5a: `len(key) > K1B_MAX_KEY_CHARS` -> True without any folding (fail closed, constant time).
   - C1: `SENSITIVE_KEY` matches the camel-split key as written -> True. `SENSITIVE_KEY`'s boundary class is widened from `[_.\-\s]` to the ordinary separators `[_.\-/:@\s]` (K13).
   - ordinary key -> False here (fast path: no `textnorm` call; K11, K12 unchanged).
   - non-ordinary key, with `K1B_NONORDINARY_KEYS = "fold"` (default):
     - C2: `SENSITIVE_KEY` matches any fold view of the camel-split key -> True.
     - C3: any squeeze view CONTAINS a credential word written without separators (`PASS`, `SECRET`, `TOKEN`, `APIKEY`, `AUTHORIZATION`, `CREDENTIAL`, `PRIVATEKEY`, `BEARER`) -> True. This substring rule applies to non-ordinary keys only; on those it accepts the over-mask of `compàss` or `by**pass**` (measured, rule 7).
     - C4: `textnorm.has_hidden_channel(key)` or `textnorm.has_mixed_script(key)`, or a character that the fold deletes stands between two ASCII letters or digits (checked with `textnorm.fold(ch) == ""` per character) -> True. A Persian key with a zero-width non-joiner between two Arabic letters is NOT caught by C4 (no ASCII neighbours).
     - C5b: any `TextnormError` -> True.
     - otherwise False.
   - with `K1B_NONORDINARY_KEYS = "credential"` (the tested alternative, no `textnorm` call): every non-ordinary key -> True.
   - **Memo:** `redact_bundle` keeps one dict `{key: bool}` for the call (both passes) and drops it at the end; no module-level cache (R371: nothing shared across runs or clients).
2. **`_is_name(key, word)`:** True if `key` is a `str` and (`key == word`, or `key` is non-ordinary, at most `K1B_MAX_KEY_CHARS` long, and a fold view equals `word.casefold()` or a squeeze view equals `word.upper()`). A `TextnormError` -> True (fail closed: a key that cannot be read is treated as the structural word, which leads to masking, never to showing). Uses in `_walk` for each dict:
   - `name_keys = [k for k in obj if _is_name(k, "name")]`; `named = any(sensitive(obj[k]) for k in name_keys)` (W04, W05).
   - `secret = any(_is_name(k, "kind") and _is_name(obj[k], "Secret") for k in obj)` (W02, W06).
3. **Inversion inside credential objects (fail closed), depth 1 only:**
   - under an object with `secret` true, every key except the EXACT ordinary names `apiVersion`, `kind`, `metadata`, `type` is secret data (its whole subtree is masked through `_pair`); inside `metadata`, the values of `annotations` are masked whole (`MASKED`; W07); `name`, `namespace` and `labels` are walked as today. A disguised `metadata` is not an exact name, so it is secret data (fail closed).
   - under an environment entry with `named` true, every DIRECT string or number value of a key other than the name keys goes through `_pair` (W03); a nested dict or list (`valueFrom`) is walked normally with its own key (W08; review Major 5).
4. **`_pair(key, value, f, learn)`:** always returns `MASKED`. It still calls `f(f"{key}={text}")` for `text` in (the value, its base64 decoding when valid UTF-8), output thrown away, so pass 1 of `redact_bundle` learns what the patterns find. In addition, `learn(text)` registers the whole value (and the decoding) as a SECRET original in the bundle's run map when it is at least `P1D_MIN_KEY_CHARS` long (the floor P1d defines; default 8; R: `P1d.md:45`), so pass 2 masks its other copies (W09, W10). `learn` is a closure made in `redact_bundle` over its run map; it calls the redactor's EXISTING function that adds an original (BS-0 names it; if only a private one exists, this package adds one public wrapper `runmap.learn_value(mapping, kind, original)` around it and a test that its placeholder numbers match the redactor's own; no second numbering code). Because the result is always `MASKED`, the questions of rev 1 (with or without the `key=` prefix, removing placeholders, the interaction with `is_withheld` and with the counter of `redact_bundle`) no longer arise: the counter counts run-map entries, which `learn` adds to (BS-0 pins the counter for W09/W10 in a test).
5. **Cost (review Major 4):** `_walk` computes `sensitive` once per dict key through the memo and passes the boolean (not the key) into list and tuple elements, so a list of 100,000 strings under one key costs one `sensitive` call. Size is already bounded by `defaults.MAX_BUNDLE_CHARS` (R `defaults.py:40`, `8 * MAX_REDACT_CHARS`) and each key by `K1B_MAX_KEY_CHARS`.
6. **`receiver.serve` (S16, review Major 7):** the handler overrides all three stdlib log hooks and logs only fixed words:
   - `log_request(code, size)`: `"receiver: %s %s %s"` with the method if it is exactly `POST`, `GET` or `HEAD` (read with `getattr(self, "command", None)`), else `OTHER`; the path class `actions` if `getattr(self, "path", None) == PATH` (the SAME full-path test `do_POST` uses, so `/slack/actions?t=...` is `other`, matching its 404), else `other`; and the status as `int(code)` if it is an `int` or `HTTPStatus`, else `-`.
   - `log_error(format, *args)`: `"receiver: request refused before handling"`; `format` and `args` are not used (they can hold the method text, L04).
   - `log_message(format, *args)`: `"receiver: message"`; nothing from `format` or `args` (a future stdlib caller cannot reintroduce request text).
   - the server is a `ThreadingHTTPServer` subclass whose `handle_error` logs `"receiver: handler error %s"` with the exception class name only (L05).
   - the client address was not logged before either (R `receiver.py:62-63`: the override passes only `format, *args`; the stdlib default would add `address_string()`); unchanged.
   - BS-0 reads the 3.12 `http.server` source for the same three routes (3.13 read: `server.py:481`, `516`, `568`).
7. **`serve` in the client profile (ORDER 173, overrules the rev 1 default):** `serve(approvals, host="127.0.0.1", port=8080, *, environment: str)`: it raises `ConfigError` unless `environment` is the demo stage (today the configuration value `dev`, read as demo per R449 and build note P0t; the check calls the ONE helper the configuration uses for that comparison, `config.py:366`, never a second literal; if P0t has merged, its demo-stage helper), and unless `host` is a loopback address (`127.0.0.1`, `::1`, `localhost`). `serve` is the local server for clicks in a demo; pilot and prod host the receiver elsewhere (decided at S11, R `receiver.py:5`). The docstring word "development" becomes "local use in the demo stage" (R449).
8. **Marker and start-up canary:** `runmap.P1DB_APPLIED = True` (P1d defines the name and the check). The client-profile start function (P1d) gets one more canary: `sensitive("db_p" + "а" + "ssword")` must be True.
