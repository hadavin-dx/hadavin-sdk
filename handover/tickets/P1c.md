New private `_b64_view(text: str, current: dict[str, str], cache, started: float) -> tuple[str, dict[str, str]]`. **Behaviour, exactly:**
  1. **Where it runs.** Inside the existing `try` of `redact_text` (`:487-523`), at two places. (a) On the input, after `neutralise` (`:489-490`) and BEFORE the `scan` gate and pass one (`:491-494`): pass one and `_decoded_masks` then read the step's output and map. (b) On each view, after `_keep_earlier_masks` (`:514`) and before that view's `redact` (`:515`). It is never behind the `scan` gate, because a base64 token is plain ASCII with none of `\ % &`.
  2. **Candidate (exact).** `re.finditer` of `[A-Za-z0-9+/_-]{N,}(?:(?<=[A-Za-z0-9+/_-]{60})\r?\n[A-Za-z0-9+/_-]{4,})*(?:=|%3[dD]){0,2}`, where N = `B64_MIN_TOKEN_CHARS` (16, order 64). This is the maximal run over the UNION of both alphabets. A line break continues the run only after a line of 60 or more alphabet characters (MIME wraps at 76, PEM at 64). Trailing padding, written `=` or `%3D`, belongs to the run. Any other `=` ends a run (`key=<token>`).
  3. **Decode.** First the length check of item 6 (a run longer than `B64_MAX_TOKEN_CHARS` is not decoded). Then remove line breaks and padding; translate `-` to `+` and `_` to `/`. For each start s in 0, 1, 2, 3: take the run from s; if its length mod 4 is 1, drop the last character, otherwise complete the padding; skip it if shorter than N; `base64.b64decode(piece, validate=True)`. Four alignments cover a glued prefix of any length and delimiter exactly. Only `binascii.Error` is caught, and only to mean "not this alignment".
  4. **Read as text for SCANNING (the `strings` rule).** Bytes are decoded `utf-8` with `errors="replace"`, so a bad byte cannot hide a value (order 70, PL1). Every character that is not `isprintable()`, or is U+FFFD, cuts the text, except `\t\n\r`. Pieces with at least `B64_MIN_FRAGMENT_CHARS` (6, the shortest maskable value `a@b.co`) non-space characters are kept. A run with no piece is left as it is. There is no UTF-16LE reading (PL8 dropped; limit L5).
  5. **Redact and mask.** T = the run's pieces (all alignments, de-duplicated, joined by `\n`); T = T + `\n` + `fits_after_nfkc(canonical(undo(T)))`; T = `neutralise_untrusted(T)`, ALWAYS, whatever `neutralise` the caller gave (decoded bytes are untrusted by origin; this is done after the view, so `&lt;...&gt;` cannot come back as a placeholder). `again = redact(T, mapping=current, _cache=cache)`, the plain redactor. If `again.text` holds a placeholder (after neutralising, each one was placed by this call), the run's SPAN is replaced by those placeholders, de-duplicated, in order, and `current = again.mapping`. **Nothing decoded is ever written back (order 70, PL1):** T and `again.text` are used only to find placeholders. At each run's span the output receives either the run's original characters, unchanged, or the placeholders this call placed; no decoded character (a piece, its canonical view, a U+FFFD) ever reaches the output, for a run with a value, a run without one, or a refused text (B27, M19). The output is built with `re.sub` over the runs and a per-call memo, so the same run is computed once and a copy inside a longer run is judged as part of that run. Secret kinds stay unstored (`STORED_KINDS`, `runmap.py:30`, `defaults.py:108-122`). A stored kind restores to the DECODED spelling (`RedactionResult.restore`, `redact.py:855`), and the CHANGELOG says so.
  6. **Bounds, each with its reason.** Depth 1: pieces are never searched for runs again (order 64). No recursion: only `redact`, `canonical` and `undo` are called, never `redact_text`. At most one `redact` pass per run; runs are disjoint and at least 17 characters including their boundary, so a text has at most `MAX_REDACT_CHARS / 17` passes. Each run costs 4 linear decodes. **Maximum token length (order 70, PL2):** a run longer than `B64_MAX_TOKEN_CHARS` (65,536 characters of the match, line breaks and padding counted) is never decoded, so a hostile text cannot make the step's work per run grow with the run (the lead's reason: no quadratic scan). Such a run is left as it is ONLY when every line of it is matched whole (`fullmatch`) by one of the two HIGHENTROPY patterns (`redact.py:637-643`, `:690-695`); pass one then replaces each line with `<HIGHENTROPY_n>`, today's output. Otherwise the call raises `InputTooLarge`, whose message names the run's length and the constant and never holds run content (fail closed). Default 65,536: resolve fact 11 measured one 190,000-character run at 1.35 s; at that rate 65,536 characters cost about 0.47 s (scaled, UNVERIFIED at that size), under a tenth of `REDACT_BUDGET_S` (6.0 s, `defaults.py:49`); it is a quarter of `MAX_REDACT_CHARS` (262,144, `defaults.py:31-38`), and it holds B4's 20,000-character run and the base64 of an RSA-8192 PEM block (about 8,600 characters; `defaults.py:41-42`).
