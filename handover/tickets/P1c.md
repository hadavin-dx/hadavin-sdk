New private `_b64_view(text: str, current: dict[str, str], cache, started: float, memo: dict[str, str]) -> tuple[str, dict[str, str]]`. **Behaviour, exactly:**
  1. **Where it runs.** Inside the `try` of `redact_text` (`:487-523`), three edits. (a) On the input, after `neutralise` (`:489-490`) and BEFORE the `scan` gate and pass one (`:491-494`). (b) Pass one (`:494`) is called on the step's output with the step's map (`mapping=current`), and `_decoded_masks` reads both. (c) On each view, after `_keep_earlier_masks` (`:514`), before that view's `redact` (`:515`). Never behind the `scan` gate: a base64 token is plain ASCII with none of `\ % &`.
  2. **Candidate (exact).** With A = `[A-Za-z0-9+/_-]`, N = `B64_MIN_TOKEN_CHARS` (16) and J = `B64_MIME_JOIN_CHARS` (60): `re.finditer` of `(?:A{N,}\.){0,2}A{N,}(?:(?<=A{J})\r?\nA{2,}(?:=|%3[dD]){0,2}(?=\r?\n|\Z))*(?:=|%3[dD]){0,2}`. One match is one UNIT. Up to three dot-joined segments of N or more characters are one unit (the JWT compact form, RFC 7519), so a token's header and signature are masked with its payload. A line break continues the last segment only after a line of J or more alphabet characters (MIME wraps at 76, PEM at 64), and only with a WHOLE line of 2 or more alphabet characters (one group with padding, `bw==`, joins; a prose line does not). Trailing padding (`=` or `%3D`) belongs to the unit; any other `=` ends it (`key=<token>`).
  3. **Decode.** The unit is split at `.` into segments; each segment loses its line breaks (`\r`, `\n`) and padding, and `-` becomes `+`, `_` becomes `/`. A segment of at most `B64_WINDOW_CHARS` (65,536) characters is one window. A longer one is cut into windows of `B64_WINDOW_CHARS` characters, each starting `B64_WINDOW_CHARS - defaults.CUT_MARGIN` (57,344, a multiple of 4) after the previous one, the last one ending at the segment's end; so a value whose base64 is up to `CUT_MARGIN` (8,192) characters lies whole inside one window. Every window is decoded; nothing is refused for its length. Per window, for each start s in 0, 1, 2, 3: take the window from s; length mod 4 = 1 drops the last character, otherwise padding is completed; skip it if shorter than N; `base64.b64decode(piece, validate=True)` (the module does `import base64`). Only `binascii.Error` is caught, meaning "not this alignment".
  4. **Read as text for SCANNING.** Bytes are decoded `utf-8` with `errors="replace"`. Every character that is not `isprintable()`, or is U+FFFD, cuts the text, except `\t\n\r`; pieces with at least `B64_MIN_FRAGMENT_CHARS` (6) non-space characters are kept (the `strings` rule). **Deleted reading:** when the decoded text holds no U+FFFD (it was valid UTF-8), the text with every cut character DELETED is kept too, if it has 6 or more non-space characters; this reads one junk control byte inside a value and UTF-16LE of ASCII. Without the UTF-8 condition it over-masks random binary (prototype: 9 of 20,000 tokens). A window with no piece adds nothing.
  5. **Redact and mask.** Per window: P = its pieces, de-duplicated, joined by `\n`; `_within_cap(P)`; U = `fits_after_nfkc(undo(P))` (the order and guard of the existing view at `:410`); T = P + `\n` + `fits_after_nfkc(canonical(U))`; `_within_cap(T)`; T = `neutralise_untrusted(T)` ALWAYS, whatever `neutralise` the caller gave; the budget check of item 6; `again = redact(T, mapping=current, _cache=cache)`; `current = again.mapping`. If any window of the unit leaves a placeholder in `again.text` (each was placed by this call), the unit's SPAN is replaced by those placeholders, de-duplicated, in order. **Nothing decoded is ever written back (PL1):** at each unit's span the output receives the original characters unchanged or this call's placeholders only (B27, M19). The output is built with `re.sub` over the units and a per-call memo keyed by the unit's text, shared by the input and the views (a view repeats every unchanged unit; prototype: one token 9,000 times, 1.38 s without the memo, 0.14 s with it). Secret kinds stay unstored (`STORED_KINDS`, `runmap.py:30`). A stored kind restores to the DECODED spelling (`RedactionResult.restore`, `redact.py:855`); the CHANGELOG says so.
  6. **Bounds, each with its reason.** Depth 1: pieces are never searched for units again (order 64). No recursion: only `redact`, `canonical` and `undo` are called. One pass = one `redact` call on one window's T, which is at most `MAX_REDACT_CHARS` (262,144). `REDACT_BUDGET_S` (6.0 s) is checked before EVERY pass, inside the unit and window loop, so a call takes at most the budget plus one capped pass, the contract of the existing views (`defaults.py:45-48`). Work is linear in run length (prototype: a 261,336-character run, 5 windows, 1.49 s; a 253,376-character run, 2.51 s). The measured cost driver is the NUMBER of distinct values (each grows the map and `redact` rebuilds its finders, `redact.py:915`): prototype 100 values 0.12 s, 300 1.00 s, 600 4.48 s, 1,200 refused at 6.01 s after 697 passes; quadratic in values (UNVERIFIED in the build until B38 records it); L4. **Refusal message (order 72 item 1)**, for the step's own `InputTooLarge`: "This text holds more encoded (base64) data than the redactor can check within its limits (`REDACT_BUDGET_S` = 6 s per text, `MAX_REDACT_CHARS` = 262,144 characters per check).   7. **Fail closed.** Any other exception reaches `except Exception` (`:522-523`) and becomes `RedactionError`; `TooDeep` and `InputTooLarge` are re-raised (`:520-521`). Nothing is sent.
