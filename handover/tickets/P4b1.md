Words used (plain meaning): a **reservation** is money set aside in the store BEFORE a model call, equal to the most the call could cost (the "worst case"); to **settle** is to replace the reservation with what the call really cost; to **release** is to give the whole reservation back; a **hold** is one reservation seen from the code that made it. **Spend** means model-call cost only; **business money** means amounts of the client's own business, such as a refund; the two never mix. A **micro-dollar** is one millionth of a US dollar, kept as a whole number inside the meter. **W** is the most ONE request can cost, sized from the bytes sent (defined in P4b1-b). A **scope** is a block of code during which the wrapper knows which agent and run its calls belong to. The **floor** is the smallest amount the wrapper books for one request: 1 micro-dollar (`METER_MIN_MICRO`, PENDING LEAD 19), so a route priced at zero still takes a hold.

- **Error rule (fail closed).** Everything the meter raises on the way to a model call is a `MeterError` (a `RuntimeError`; NOT an `OSError`, because `store/protocol.py` calls every `OSError` "unreachable", and NOT a `ValueError`). # P4b1-b: the wrapper around model calls (`MeteredLLM`)

- Package id and name: P4b1-b. The wrapper that puts every model call behind a hold.
- Path class: money. Extended review: yes; the ticket's own review rounds are capped at 3 plus one extra for a money package (order 20 item 6). Tier A.
- Depends on (merged first): P4b1-a; both P4a pull requests (P4a-1 and P4a-2: the usage and refusal types, `request_bound`, `UsageMissing`, the constants). If P4a has not merged, -b does not start.
- Problem in plain words: Callers that are not the agent loop (the `extract` helper, the evaluation gate, scripts, and soon the loop itself through P4c) call a model through the `LLM` interface with nothing around it that sets money aside. This pull request adds a wrapper with the same `chat` signature that works out the worst case of the request, takes a hold, calls the model, records the real cost, and always settles. One wrapper sits on the shared model object; the agent and run are named by a scope the caller opens, so a judge call that shares the object is covered too (A8, PENDING LEAD 14).
- Source of the code (MANIFEST ids, source repo, commit sha) and what is NOT taken: shape from PR #48 `src/hadavin_sdk/llm/metered.py` (branch `origin/core-hardening-1`, head `8986cb5`; class name, `__getattr__` delegation, `chat` signature, `prompt_bytes` sizing rule) and the `GuardedModel.call` finally structure from Intake `model.py` (`b6592b9`, MANIFEST 1266). Rewritten for whole micro-dollars and the context manager. NOT taken: the billing contract (`cost_to_settle`, `reply_cost_to_settle`, `prior_unknown_requests`: P4b2), Intake's gate, body check, tiers, fallback table and error codes, PR #48's Decimal arithmetic.
- Target module and path in `src/hadavin_sdk/`: NEW `llm/metered.py`; CHANGE `defaults.py` (the five -b constants). Tests: `tests/test_meter_llm.py`.
- Interface (names, argument and return types, errors):
  - `MeteredLLM(inner: LLM, limits: Limits, routes: dict[str, Route])`. `routes` is the SAME mapping object the inner kind was built from (`cfg.routes`), not a copy (A15). `metered.scope(agent_id: str, *, run_id: str | None = None)` is a context manager that sets a `contextvars.ContextVar`; it is reset in a `finally`; a nested scope restores the outer one. A `chat()` with no open scope raises `MeterError` BEFORE any call. The scope object (yielded by `with metered.scope(...) as s:`) has a read-only `refusal: MeterError | None`. `chat` stores the `OverBudget` or `MeterUnavailable` it is about to raise there, the first one only, before it raises, so a caller whose own code swallows the exception (`guard/injection.py` `injection_check`, `:85`, with `except Exception` at `:89`) can still read it after the call. A second refusal does not overwrite the first; a nested scope keeps its own `refusal`. Test B21 (the P4c relay's "B-new"); mutant W30. P4c-2 opens the scope once per run. The scope does not cross threads (a new thread opens its own; a row proves it). `chat(messages, *, system, route, tools=None, documents=None, output_schema=None) -> Reply` has exactly the `LLM` protocol signature (`llm/protocol.py`); `__getattr__` delegates other names to `inner` but refuses names starting with `__` and a missing `inner`.
