Words used (plain meaning): a **reservation** is money set aside in the store BEFORE a model call, equal to the most the call could cost (the "worst case"); to **settle** is to replace the reservation with what the call really cost; to **release** is to give the whole reservation back; a **hold** is one reservation seen from the code that made it. **Spend** means model-call cost only; **business money** means amounts of the client's own business, such as a refund; the two never mix. A **micro-dollar** is one millionth of a US dollar, kept as a whole number inside the meter. **W** is the most ONE request can cost, sized from the bytes sent (defined in P4b1-b). A **scope** is a block of code during which the wrapper knows which agent and run its calls belong to.

- **Money type and rounding.** Inside the meter every amount is a `SpendMicro` (whole micro-dollars, never a float, a bare int or a Decimal). At the store boundary it becomes a `Decimal` with exponent -6 exactly (the conversion is exact or fails). The ONE rounding of a call's cost: the sum over the two token classes of tokens x price (micro-dollars per million tokens) is a whole number divided by 1,000,000 rounding UP, once per call (bible R214). W itself is one such call-sized rounding for one request. Never round to nearest or down.
- **Error rule (fail closed).** Everything the meter raises on the way to a model call is a `MeterError` (a `RuntimeError`; NOT an `OSError`, because `store/protocol.py` calls every `OSError` "unreachable", and NOT a `ValueError`). Any `MeterError`, and any other exception from `reserve`, means the model is NOT called. A refusal writes nothing (P4d rolls the transaction back). Two subclasses: `OverBudget(reasons, *, which, cap, current, requested, day)` and `MeterUnavailable(code)` with the closed error table below. Wrong-type or out-of-range arguments are `TypeError`/`ValueError` raised before any store call.
- **One error table (C17), codes closed.** `reserve`: `KillSwitchOn` -> `OverBudget(("kill_switch",), which=None)` with no numbers; `SpendCapExceeded` -> `OverBudget` (below); `ReservationConflict`, `StaleState` -> `conflict`; `NotFound` -> `unknown_run`; `StoreBusy` -> `store_busy`; `CounterDamaged` -> `counter_damaged`; `ValueError` from the store -> `store_rejected`; any other exception -> `store_unreachable` (after the lost-acknowledgement release). `settle` and `release`: `NotFound` -> `unknown_reservation`; `StaleState` (a replay of a closed row whose content conflicts) -> `conflict`; `StoreBusy` -> `store_busy`; `CounterDamaged` -> `counter_damaged`; `ValueError` -> `store_rejected`; any other -> `store_unreachable`. - Interface (names, argument and return types, errors):
  - `money.py`. `SpendMicro` (frozen dataclass, one field `micro: int`): `type(micro) is int` and `0 <= micro <= MAX_USD x MICRO_PER_USD` (`MAX_USD` is P4d's constant in `defaults.py`; UNVERIFIED in code), else `ValueError`. `SpendMicro.from_usd(x: Decimal)` calls P4d's `check_usd(x, max_decimals=6)` first (one validator; it reads the scale without context rounding, never `normalize()`, the trap P4d measured) and keeps its own T1 rows as pins. `to_usd() -> Decimal` returns exponent -6 exactly. `SpendMicro.ceil_cost(numerator: int, denominator: int = MICRO_PER_USD)` returns `-(-numerator // denominator)` as a `SpendMicro`; a zero denominator or a negative numerator is `ValueError`. `+` and `-` accept only another `SpendMicro` (`-` refuses a negative result); ordering only against `SpendMicro`; every other operand (int, float, Decimal, `BusinessMoney`) is `TypeError`. No `__int__`, `__float__` or `__index__`.
  - `BusinessMoney` (frozen dataclass: `minor: int` with `type(minor) is int`, `currency: str` matching `[A-Z]{3}` by `fullmatch`): arithmetic only with the same currency; NO conversion to or from `SpendMicro` (a test lists its attributes and asserts there is none). Bible R171. It exists so a refund amount can never be added to a spend counter.
  - `meter.py`. `REASON_BY_WHICH = {"run": "run_budget", "day": "daily_budget", "month": "monthly_budget"}` (C1: one explicit table, used by `reserve`; P4c's `WALLS` imports it). `Caps` (frozen dataclass, THREE required keyword-only fields `day`, `month`, `run`, each `Decimal | None`, no defaults; `None` means "no cap at this level"). `Meter(store, *, clock=None, monotonic=None, max_hold_s=None, on_overshoot=None, on_settle_failed=None)`: `clock` and `monotonic` default to `models.now` and `time.monotonic` resolved at CALL time (nothing bound at definition); `max_hold_s` defaults to `METER_MAX_HOLD_S`. At construction it calls `store.protocol.missing_methods(store)` and raises `MeterError` naming missing reservation methods.
  - `OverBudget(reasons, *, which, cap, current, requested, day)`: carries P4d's numbers unconditionally (R215) plus the UTC day (a refusal returns no `Hold`, so the numbers must be on the error). `kill_switch` carries `which=None` and no numbers.
  - `Meter.reserve(agent_id: str, worst: SpendMicro, caps: Caps, *, run_id: str | None = None) -> Hold`. Steps: validate (`worst` is a `SpendMicro` greater than zero, `caps` is a `Caps`); the ONLY run rule is P4d's: `caps.run` must be `None` when `run_id` is `None` (else `ValueError`). `run_id` is optional and independent of `Caps.run`: pass `run_id` whenever the caller has one, also when `caps.run` is `None` (round 1 A2/C2), so `runs.cost_usd` follows the settles of an uncapped run. Take the cap day with `spend_day()`; make the id `new_id("rsv")`; call `store.reserve_spend(id, agent_id, day, worst.to_usd(), day_cap=..., month_cap=..., run_id=..., run_cap=...)` with every cap passed explicitly (keyword-only, no default, P4d). The whole store call sits in `except BaseException`: on ANY exception the meter makes one best-effort `store.release_spend(id)` (the call was never sent to a provider, so the caller rule allows this release; its own errors are swallowed and logged by class name only), then re-raises `KeyboardInterrupt` and `SystemExit` unchanged and maps every other exception by the error table. Late-commit window (A11), stated plainly: a transaction that commits AFTER the release saw `NotFound` leaves an open row at the worst case. That is the safe direction (books too high, never too low), and the P4b2 sweep closes it; the T5 test-only wrapper row covers it. No release is ever attempted after `OverBudget` or `store_busy` (the store wrote nothing / the claim is unknown but retried by the caller).

# P4b1-b: the wrapper around model calls (`MeteredLLM`)

- Package id and name: P4b1-b. The wrapper that puts every model call behind a hold.
- Path class: money. Extended review (no round cap): yes. Tier A.

- Problem in plain words: Callers that are not the agent loop (the `extract` helper, the evaluation gate, scripts, and soon the loop itself through P4c) call a model through the `LLM` interface with nothing around it that sets money aside. This pull request adds a wrapper with the same `chat` signature that works out the worst case of the request, takes a hold, calls the model, records the real cost, and always settles. One wrapper sits on the shared model object; the agent and run are named by a scope the caller opens, so a judge call that shares the object is covered too (A8, PENDING LEAD 14).
