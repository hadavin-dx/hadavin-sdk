- **Money type and rounding.** Inside the meter every amount is a `SpendMicro` (whole micro-dollars, never a float, never a bare int, never a Decimal). At the store boundary a `SpendMicro` becomes a `Decimal` with exponent -6 exactly (no rounding happens there: the conversion is exact or it fails). The ONE rounding is the cost of a call: the sum over all token classes of tokens x price (micro-dollars per million tokens) is computed as a whole number and divided by 1,000,000 rounding UP, once per call (bible R214; A1 item 4 replaces plan-v3's "round up per token class"). - **Error rule (fail closed).** Everything the meter raises on the way to a model call is a `MeterError` (a `RuntimeError`; NOT an `OSError`, because `store/protocol.py` calls every `OSError` "unreachable", and NOT a `ValueError`). Two subclasses: `OverBudget(reasons)` with the names `Limits.blocked` already uses (`kill_switch`, `daily_budget`, `monthly_budget`, `run_budget`) and `MeterUnavailable(code)` with a closed set of codes (`store_unreachable`, `store_busy`, `store_rejected`, `conflict`, `unknown_reservation`). - Interface (names, argument and return types, errors):
  - `money.py`. `SpendMicro` (frozen dataclass, one field `micro: int`): the constructor requires `type(micro) is int` and `0 <= micro <= MAX_USD x MICRO_PER_USD` (`MAX_USD` is P4d's `store.protocol.MAX_USD`, 10**12: PENDING P4d for the name), else `ValueError`. `SpendMicro.from_usd(x: Decimal)` requires `type(x) is Decimal`, finite, not negative, at most 6 decimal places READ WITHOUT context rounding (the scale is read from `as_tuple()` with trailing zeros stripped by hand, never `normalize()`, because `normalize()` rounds to 28 digits and passes a 31-decimal amount; this is the trap P4d's ticket measured), else `ValueError`. `to_usd() -> Decimal` returns exponent -6 exactly. `SpendMicro.ceil_cost(numerator: int, denominator: int = MICRO_PER_USD)` returns `-(-numerator // denominator)` as a `SpendMicro` (the single round-up). `+` and `-` accept only another `SpendMicro` (`-` refuses a negative result); ordering only against `SpendMicro`; every other operand (int, float, Decimal, `BusinessMoney`) is `TypeError`. There is no `__int__`, `__float__` or `__index__`.
  - `BusinessMoney` (frozen dataclass: `minor: int`, `currency: str` matching `[A-Z]{3}` by `fullmatch`): arithmetic only with the same currency; NO conversion to or from `SpendMicro` (a test lists its attributes and asserts there is none). Bible R171: typed integer minor units. It exists so a refund amount can never be added to a spend counter; it has no other use in P4b1.
  - `meter.py`. `Caps` (frozen dataclass, THREE required keyword-only fields `day`, `month`, `run`, each `Decimal | None`, no defaults: leaving one out is a `TypeError`; `None` must be written and means "no cap at this level"). `Meter(store, *, clock=models.now, monotonic=time.monotonic, zone=defaults.METER_CAP_ZONE, max_hold_s=defaults.METER_MAX_HOLD_S, on_overshoot=None, on_settle_failed=None)`. At construction it calls `store.protocol.missing_methods(store)` and raises `MeterError` naming the missing reservation methods.
  - `Meter.reserve(agent_id: str, worst: SpendMicro, caps: Caps, *, run_id: str | None = None) -> Hold`. Steps: validate (`worst` is a `SpendMicro` greater than zero, `caps` is a `Caps`; `run_id` given if and only if the run cap is not `None`, else `ValueError`); take the cap day with `spend_day()` (below); make the id `new_id("rsv")`; call `store.reserve_spend(id, agent_id, day, worst.to_usd(), day_cap=..., month_cap=..., run_id=..., run_cap=...)` with every cap passed explicitly (P4d round-3 finding A5 wants them keyword-only with no default; I always pass all three, so this works with revision 4 and with the stricter shape). Mapping: `KillSwitchOn` -> `OverBudget(("kill_switch",))`; `SpendCapExceeded(which)` -> `OverBudget((which + "_budget",))` for `day` and `month`, `("run_budget",)` for `run` (the reason names `Limits.blocked` already prints); `ReservationConflict`, `StaleState` -> `MeterUnavailable("conflict")`; `NotFound` -> `MeterUnavailable("unknown_reservation")` (an unknown run); `StoreBusy` -> `MeterUnavailable("store_busy")`; `ValueError` from the store -> `MeterUnavailable("store_rejected")`; any other exception (`StoreUnavailable`, a driver error, a lost connection) -> `MeterUnavailable("store_unreachable")` AFTER one best-effort `store.release_spend(id)` with the same id (a lost acknowledgement may have left the reservation open; releasing by id is safe because it is idempotent, and a `NotFound` answer means it never existed; the release's own errors are swallowed and logged by class name only). Returns a `Hold`.
  - `Hold` (not constructed by callers): `reservation_id`, `agent_id`, `run_id`, `reserved: SpendMicro`, `day: date`; `age_s() -> float` (from the injected `monotonic` clock captured at reserve; wall time is never used for age); `record(actual: SpendMicro | None, *, halt: str | None = None) -> None` (stores the planned settlement; makes no store call; `None` means "no usable measurement": settle at the reserved worst case; `SpendMicro(0)` is `ValueError` because zero is never a measurement, use `release()`; `halt`, if given, must `fullmatch` `[a-z_]{1,40}` and asks for a stop after the settle); `release() -> None` (plans a release); read-only `settled: Settled | None` and `settle_error: str | None` after exit. A forged `Hold` needs no unforgeable token (Intake's `_MINT` guarded a local row id): the store looks the id up and answers `NotFound` for an invented one.
  - `Meter.settle(reservation_id: str, actual: SpendMicro | None) -> Settled` and `Meter.release(reservation_id: str) -> Settled`. `Settled` (frozen dataclass): `reservation_id`, `status` (`"settled"` or `"released"`), `charged: SpendMicro` (the amount the books now carry for the call; zero for a release), `applied: bool` (true only when THIS call changed the books), `overshoot: SpendMicro` (zero unless the real cost passed the reservation). IDEMPOTENT: the second call for the same id, with any amount, returns the first call's `Settled` with `applied=False` and changes nothing (P4d's `settle_spend` returns the stored first result; the meter maps it). `actual=None` settles at the reserved worst case (read from `get_spend_reservation`). `actual` equal to zero is `ValueError`.
  - `Meter.hold(agent_id, worst, caps, *, run_id=None)` is a context manager: `with meter.hold(...) as h:` reserves (any `MeterError` propagates, the body never runs); on EVERY exit, including `KeyboardInterrupt` and `SystemExit` (the exit is a `finally`), it settles: `h.release()` was called -> `release`; `h.record(x)` was called -> settle at `x`; neither -> settle at the reserved worst case. If the body raised, that exception keeps propagating unchanged; a failure inside the exit settle is logged (reservation id, agent id, class name, never text) and stored in `h.settle_error` and passed to `on_settle_failed`, and it NEVER replaces the body's exception. If the body succeeded and the exit settle failed, the context manager returns normally: the reservation stays open at its worst case (the books can only be too high, never too low) and the P4b2 sweep will expire it; the reply the caller already paid for is not thrown away (PENDING LEAD 3: Intake's guard instead ends the process; recommended: the version here).
  - **Overshoot.** If the measured cost is more than the reservation (our worst-case estimate was wrong), the books must carry the REAL cost: Intake settles the actual amount and halts (`budget.py:611-613`, test `test_settle_above_reserved_settles_actual_halts_and_refuses_the_next_reserve`). P4d revision 4 instead makes `settle_spend` with `actual > reserved` a `ValueError` (the meter would then be forced to settle at the reserved amount and lose the excess). Needs from P4d (PENDING P4d, recommended answer: do it now, while the Protocol is open): `settle_spend(id, actual)` accepts `actual > reserved` from an `open` row, books the excess on the same three counters WITHOUT a cap check (the money is already spent), stores `settled_usd = actual` (the table CHECK `settled_usd <= reserved_usd` is relaxed for this), and returns `SpendOutcome` with the first result. Then the meter's code is: settle once, `Settled.overshoot = actual - reserved`, call `on_overshoot`. If the lead refuses, the fallback inside the meter is: settle at the reserved amount, then book the excess with the OLD `add_spend(agent, day, excess)` and `add_cost(run_id, excess)` (the old methods are uncapped); written plainly, a crash between the two calls loses the excess from the books (the books are too LOW by the excess for that one call) and a test pins that window by injecting the crash; the same call also trips the stop below, so nothing more is spent. In both versions `on_overshoot(Settled)` is called, and `Limits` wires it to `Limits.stop("meter:estimate_exceeded")` (PENDING LEAD 4).

# P4b1-b: the wrapper around model calls (`MeteredLLM`)

- Package id and name: P4b1-b. The wrapper that puts every model call behind a hold.
- Path class: money. Extended review (no round cap): yes. Tier A.
- Depends on (merged first): P4b1-a; P4a (all three pull requests: the five-class usage, the typed refusal when usage is missing, the price table and tiers; PENDING P4a for the names listed under "Needs from P4a"). If P4a has not merged, -b does not start.
- Problem in plain words: Callers that are not the agent loop (the `extract` helper, the evaluation gate, scripts, and soon the loop itself through P4c) call a model through the `LLM` interface with nothing around it that sets money aside.
