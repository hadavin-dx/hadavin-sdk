**Words used (plain meaning, one meaning each).**
- **person**: the human who writes to the agent (for example a shop's customer). **user id**: the made-up, opaque id of that person in our records (for example `user-1`; never an e-mail address).
- **conversation**: one chat between one person and one agent, kept as an ordered list of **turns**. A **turn** is one message: either the person's (role `user`) or the agent's (role `assistant`). One **exchange** = the person's turn plus the agent's answer turn.
- **reply**: the text the agent sends back to the person for one exchange. A **fixed reply** is a reply whose words come from configuration, not from the model (for example "A person will take over this conversation.").
- **hand-off**: the agent stops answering in this conversation and a person takes over; one item is put into the "needs a person" queue (AK-G15).
- **history**: the earlier turns the model is shown on each call (the model remembers nothing between calls, R94).
- **mask / placeholder / put back**: as in P5c (`tickets/P5c.md:64`): a protected value such as an e-mail address is replaced with a placeholder such as `<EMAIL_1>` before text goes to the model; put back = replace the placeholder with the real value again. **label**: the plain text `[hidden email]` shown in place of a placeholder.
- **conversation map**: the saved list "placeholder -> original value" of one conversation (identifier kinds only). **saved kind / unsaved kind**: a kind of value whose originals may be stored (`STORED_KINDS`, `defaults.py:108`) or may not.
- **lease**: a short claim on a conversation while one exchange is being answered, so two messages of one conversation are never answered at the same time. The lease belongs to that exchange's run. It is **live** while the run is not final AND the run has written a heartbeat (`store.touch`) within the agent's stuck-run time; otherwise it is **dead**. That is the same rule the tick uses to call a run stuck, on the same heartbeat, so a crash cannot block the conversation for ever and a healthy exchange never loses its lease before the tick would stop it (revision 3).
- **version**: a counter on the conversation row. Every write to the row adds 1. A writer that read the row first passes the number it read, and the write is refused (`stale`) when the row changed since (revision 3).
- **sweep**: a tick step that finds conversations whose lease is dead and makes sure a "needs a person" item exists for the lost exchange, for a person who never writes again (revision 3).
- **stop reason**: a closed code that says why an exchange stopped before a normal reply (for example `asked_for_person`, `max_steps`, `kill_switch`). A stop in the closed set `HANDOFF_STOPS` hands the conversation off for good; every other stop is a **passing fault** (for example a provider outage): the conversation stays open and the person gets the fixed "paused" reply (revision 3).
- **retry**: an outcome that means "this message was NOT accepted; send the same message again later with the same message id".
- **subject**: the person a read tool works for in this exchange (tenant and user id), set by our code, never by the model.
- **recipient gate**: AK-G22's one path for text sent TO a named person or system. **AK1 gate**: AK1's one path for text sent to a third party for PROCESSING (the model).
- **pilot/prod**: a config whose `environment` is `pilot` or `prod` (`config.py:317`).
- "UNVERIFIED" = not read in code by me, or not run. "PENDING LEAD" = a decision for the lead or the owner, my recommendation first; each item is marked NEEDS LEAD (owner-only, or an owner hard rule). "INFORM" = my decision on my recommendation, final unless the lead says otherwise (order 23 item 4).

Why the tick cannot move a healthy exchange: one quiet stretch between two heartbeats is at most one model call, one tool call (whose caller returns within its timeout, `tools.py:495`, `:1127`), or one hook call (bounded by `CONVERSATION_HOOK_TIMEOUT_S`, 30 s, with a `touch` before it), while `quiet_s` is a whole-run figure (960 s for `max_steps` 5 with real defaults). Said plainly: `call_timeout_s` is a per-socket-operation timeout, not a wall clock (`backends/table.py:37-39`), so this is a large margin, not a hard guarantee; E6's wrapped transition covers the rare case (round 2's R2-ADV-5 is CONTESTED for model and tool steps and accepted for the unbounded hooks, which now have a timeout and a `touch`). `touch` writes `models.now()` (`store/memory.py:90`, `store/postgres.py:280`), so `claim_turn`'s `now` must be `models.now()` in production; tests age a run by setting `updated_at`, as `tests/test_p7_tick.py:225-243` does.

`claim_turn` checks in this order: state open (else `ConversationNotOpen`), duplicate `message_id`, live lease (`busy`), `version != expect_version` (`stale`), dead lease (lost exchange), then appends and writes the run row. A dead lease is taken over only when `take_over` names its busy run (F7: the item is already open); otherwise the result is `lost` and NOTHING is written. For a duplicate: if its answer slot holds a turn, `handle_turn` reads the first run and maps it by the outcome rule below, from the run's reason: `replied` -> `replied`; a reason in `HANDOFF_STOPS` -> `with_person`; another stop -> `paused`; anything else (`lease_lost`, `handoff_unavailable`, `store_unavailable`, `interrupted`) -> `with_person` (`delivered=False`: nothing is delivered by this call). If the slot is empty and the lease is live, the first run is still going: `retry`. If the slot is empty and the lease is dead, the result is `lost` (no write); after F7 opened the item, the second call with `take_over` writes the lost-answer turn into that slot, clears the lease and adds 1 to `version` in one transaction, and returns `duplicate` with `lost` set; `handle_turn` returns `with_person`. So a message whose exchange was lost ends in one hand-off whether the next message, its own resend or the sweep comes first. Revision 2's sentence about a hand-off item naming a run id with no run row is deleted: the claim writes the run row, so that case no longer exists (resolve row R2-ADV-4).

**The sweep (revision 3, resolve rows R2-ADV-2 and R2-RES-1; INFORM I15).** For a person who never writes again. `Runtime.sweep_conversations(now) -> int` builds `quiet = {agent_id: quiet_s}` for its conversational agents, calls `store.lost_exchanges(now, quiet)` (read: every conversation whose lease is dead; nothing written), and for each result calls the wrapped `open_handoff(HandoffRequest(tenant, conversation_id, run_id=lost.run_id, reason="interrupted", idempotency_key=lost.run_id))`. After an `interrupted` item the conversation stays `open`, as for F7 in revision 2: the person who takes the item sees the run's reason on the run row.

**Mapping of results to `TurnResult.outcome` (rewritten in revision 3, resolve row R2-ADV-6; INFORM I16).** The outcome follows what THIS exchange wrote to the conversation, not the run: `finish_turn` wrote `handed_off` -> `with_person`; it wrote `open` with no stop -> `replied`; it wrote `open` with a stop (a passing fault, the kill switch included) -> `paused`; nothing was written (`lease_lost`, `handoff_unavailable`, the store-failure rule, or E6 found the run already moved by the tick) -> `with_person`, because only a person can sort it out.
