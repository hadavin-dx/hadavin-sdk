**Words used (plain meaning, one meaning each).**
- **person**: the human who writes to the agent (for example a shop's customer). **user id**: the made-up, opaque id of that person in our records (for example `user-1`; never an e-mail address).
- **conversation**: one chat between one person and one agent, kept as an ordered list of **turns**. A **turn** is one message: either the person's (role `user`) or the agent's (role `assistant`). One **exchange** = the person's turn plus the agent's answer turn.
- **reply**: the text the agent sends back to the person for one exchange. A **fixed reply** is a reply whose words come from configuration, not from the model (for example "A person will take over this conversation.").
- **hand-off**: the agent stops answering in this conversation and a person takes over; one item is put into the "needs a person" queue (AK-G15).
- **history**: the earlier turns the model is shown on each call (the model remembers nothing between calls, R94).
- **mask / placeholder / put back**: as in P5c (`tickets/P5c.md:64`): a protected value such as an e-mail address is replaced with a placeholder such as `<EMAIL_1>` before text goes to the model; put back = replace the placeholder with the real value again. **label**: the plain text `[hidden email]` shown in place of a placeholder.
- **conversation map**: the saved list "placeholder -> original value" of one conversation (identifier kinds only). **saved kind / unsaved kind**: a kind of value whose originals may be stored (`STORED_KINDS`, `defaults.py:108`) or may not.
- **lease**: a short claim on a conversation while one exchange is being answered, so two messages of one conversation are never answered at the same time. It expires after a set time so a crash cannot block the conversation for ever.
- **stop reason**: a closed code that says why an exchange stopped before a normal reply (for example `asked_for_person`, `max_steps`, `kill_switch`).
- **retry**: an outcome that means "this message was NOT accepted; send the same message again later with the same message id".
- **subject**: the person a read tool works for in this exchange (tenant and user id), set by our code, never by the model.
- **recipient gate**: AK-G22's one path for text sent TO a named person or system. **AK1 gate**: AK1's one path for text sent to a third party for PROCESSING (the model).
- **pilot/prod**: a config whose `environment` is `pilot` or `prod` (`config.py:317`).
- "UNVERIFIED" = not read in code by me, or not run. "PENDING LEAD" = a decision for the lead or the owner, my recommendation first; each item is marked NEEDS LEAD (owner-only, or an owner hard rule). "INFORM" = my decision on my recommendation, final unless the lead says otherwise (order 23 item 4).

**D2 (INFORM I2): one run per exchange, ending `NO_ACTION` with reason `replied`.** Each accepted person message starts one `Run(trigger_kind="user", trigger_ref="<conversation id>:<turn number>")`; ids only. A new `REPLIED` state would need a migration of the `runs.state` CHECK (`0001_core.sql:12`) for no safety gain: cut (row V9). `STOPPED` is reachable from any non-final state (`runs.py:31`), so a paused exchange needs no new state either.

**D3 (INFORM I3): no put-back into replies in v1.** The model's reply is masked again with `redact_text` (model-written text: a placeholder it writes is meant to be one, `runmap.py:298-303`), then every placeholder-shaped text, including one the model invented and a look-alike such as `‹EMAIL_1›`, is shown as a label (`[hidden email]`). Reason: a placeholder can stand for a value from a TOOL result; putting it back could send another person's value. Owner-visible limit: PENDING LEAD 3. Cut item: row V3.

**D4 (INFORM I4): a placeholder never means two values in one conversation, with no new counter state.** (1) The conversation map is a column of the conversation row (`conversations.mapping`, identifier kinds only, `storable`). It is written only by the three store methods that also write turns: `claim_turn` and `finish_turn` (fenced by the lease) and `record_user_turn` (fenced by a compare-and-set on `next_turn`; INFORM I13). A refused, busy, stale or lease-lost exchange writes no map. (2) Before any turn text is stored, every placeholder whose key is NOT in `storable(rmap)` is replaced by its label. So every placeholder in stored history has its value in the saved map, and `_Redactor` already numbers new values above the highest saved key (`redact.py:893-908`). A placeholder can never mean two values, and P5c needs no `floors` keyword. Correction of revision 1's example: `EMAIL` is a saved kind (`defaults.py:108-113`); the risk was for unsaved kinds and for originals that fail `storable_original` (`runmap.py:218-226`). (3) The run's own map is still saved under its `run_id` by `_tool_step`, as today.

## The `handle_turn` flow (one table; replaces revision 1's steps (a) to (l))

`handle_turn(agent_id, *, tenant, conversation_id, user_id, message_id, text) -> TurnResult` (Interface 9). The rows run top to bottom; a row that ends the call says so in the last column. Rows F1-F7 happen before any run exists: they create no run, call no model and deliver nothing. Every row from F8 on ends in exactly one call of `_end_exchange` (rows E1-E6), which makes the run's ONE transition after `WORKING`. `rmap` is this exchange's map: `RunMap(conversation.mapping)`, grown by masking and by tool results. `label_unsaved(t)` = `PLACEHOLDER` matches in `t` whose key is not in `storable(rmap)` become `[hidden <kind>]`. `render(t)` = `escape_placeholders(t)` (`runmap.py:275-279`), then every `‹KIND_n›` (any case) becomes `[hidden <kind in lower case>]`; labels hold no `_` (`redact.py:817`), so the split is exact.
