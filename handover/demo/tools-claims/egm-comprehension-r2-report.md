## How the existing system works, per these documents
- A program called "the desk" records every incoming lead request in a receipt before acting on it. The same request number sent twice gets the stored answer ("replayed"). The same email under a new request number is a "duplicate". Incomplete requests go to "review".
- The desk drives a follow-up email and a CRM row for each new lead. Everything runs on one computer against demo servers, with no real service.
- A background job, the "reaper", puts stuck follow-ups back in line and retries refused sends. A crash is simulated at ten named points (a real kill only at D2). A mail system or CRM that cannot recognise a repeated key is "blind". On a blind system a follow-up that may have been sent becomes UNKNOWN and waits for a person.
- A portal shows the records, masks personal values on screen only, and has a few write buttons.
- n8n workflows in `n8n/` can sit in front of the desk. No result of running them is stored.
