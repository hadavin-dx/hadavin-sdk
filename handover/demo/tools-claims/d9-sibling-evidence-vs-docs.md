## B. Evidence findings that no doc sentence mentions but a reader would need

I grepped README.md, docs/*.md, versions.md and contract.md for: basetemp, TMPDIR, LEAD_DESK_PATH_ROOTS, isreserved, root, hang, hard link, foreign tools, TypeError. The only hit relevant here is docs/settings.md:125, which describes LEAD_DESK_PATH_ROOTS and says "the system temporary folder" is allowed, but says nothing about running the tests.

1. **56 tests fail when pytest's `--basetemp` is outside TMPDIR** (failures.md:4, summary.md:51; 49 in test_load_tools.py, 5 in test_n8n_api_url.py, 1 in test_http.py, 1 in test_path_confinement.py; 57 on PR #12). Reproduced: same 56 ids fail outside, pass inside (6.65 s). Not in any doc.
   Suggested sentence for docs/tests.md ("How to run the tests"): "If you give pytest its own scratch folder with `--basetemp`, keep it inside your system temporary folder (the folder named by `TMPDIR` on Linux); otherwise the tools refuse it with 'path is outside the allowed folders' and 56 tests fail, which is a set-up problem, not a fault in the desk."
2. **Linux with Python 3.13 passes** (summary.md:6,8: 3684 passed, 0 failed, 199 skipped). The README says other combinations were not tried. Suggested sentence for README.md and docs/tests.md: "Linux with Python 3.13 and `requirements-dev.txt` was also run once on commit f3c39cf8: 3684 passed, 0 failed, 199 skipped (no log is shipped); it is not a supported combination."
3. **Two skip reasons are not listed in the docs**: the Python 3.13-only test (`ntpath.isreserved`, test_path_confinement.py:284) and the test that skips when run as the root user (test_n8n_api_url.py:510). Suggested sentence for docs/tests.md near line 88: "Two more tests skip on purpose: one needs Python 3.13 (it asks Python for the list of reserved Windows file names), and one skips when the tests run as the administrator user (root on Linux), because root can read a file that has no read permission."
4. **Skip count on the current commit is unstated**: docs say "more than 3 skips"; evidence says 200 on Linux without Playwright, gitleaks and Node-independent (summary.md:5), made of 166 Playwright + 30 gitleaks + 4 on purpose (summary.md:21). Suggested sentence for docs/tests.md:78: "On commit f3c39cf8, Linux, Python 3.12, with neither Playwright nor gitleaks installed, 3683 tests passed and 200 were skipped (166 need Playwright, 30 need gitleaks, 4 are skipped on purpose); no test failed (from a sibling run; no log is shipped)."
5. **A full run takes about 20 minutes now** (1189-1192 s on f3c39cf8). README.md:130 says it was "not timed on the current set". Suggested sentence: "A full run on commit f3c39cf8 took about 20 minutes (1189 s) on a 4-core Linux machine with Python 3.12."
6. **Test-run logs can be cut by version-control commands** (failures.md:5): running `git pull --rebase`, `stash` or `checkout` in the folder while a test run writes its log into that folder cut four logs and produced a false "stops at 71 percent, exit 1" picture. Suggested sentence for docs/tests.md: "Do not run `git pull`, `git stash` or `git checkout` in the same folder while a test run is still writing its output file into it; the file can be replaced and the end of the output (including the summary line) is lost, even though the run itself finishes."
7. **A path object whose `__fspath__` returns an int or None raises a plain `TypeError`, not `PathRefused`** (hostile-f7-rerun-c14a514.md:65; on both 6b1fe49 and c14a514; "not fixed here"). No doc names the PathRefused contract at all. Suggested sentence for docs/settings.md near line 125: "A path given in an unusual way (an object whose file-name method returns a number or nothing) stops the tool with a Python error instead of the usual 'path refused' message; nothing is opened."  (A product fix is outside this runner's job; this is the doc side only.)
8. **Hard links bypass the folder confinement** (hostile.md:14, F6; a hard link inside the allowed folder to a file outside it is read and overwritten; same on main and PR #12; "PR12 documents it"). docs/settings.md:125 describes the allowed folders without this caveat. Suggested sentence: "The folder limit does not follow hard links: a hard link inside an allowed folder that points to a file outside it can be read and changed by these tools."
9. **A second project's `tools` package on PYTHONPATH breaks or hijacks the tools** (hostile.md:9-13, F1-F5): `catcher.py` silently uses a foreign `tools` package with the same names; `python tools/scrub_n8n_export.py`, `scripts/n8n_api.py` and `python -m demo_only.fake_model_server --help` fail with `ModuleNotFoundError`/`ImportError` when another project's `tools` is first on the path. README.md:150 describes `tools/` and the scrubber without this. Suggested sentence: "Run these tools in a shell where no other project's `tools` folder is on `PYTHONPATH`; if one is, the tools either use that foreign code or stop with 'No module named tools.pathconfine'."
10. **`LEAD_DESK_PATH_ROOTS=/` removes the limit** (hostile.md:16, F8; `--key-file /etc/hostname` then starts the fake server). docs/settings.md:125 does not warn. Suggested sentence: "Do not set `LEAD_DESK_PATH_ROOTS` to `/` or to a drive root: that allows the tools to read and write any file the user can."
11. **No hang found in a test run, and no flake data** (hang-hunt.md:7; claims-stack-tests.md:14, summary.md:32: one run per head except a 10-run burst test). Docs do not say that the suite was run only once per commit and never repeated for flakiness (tests.md:74 says one run only for the Playwright measurement). Suggested sentence for docs/tests.md: "Each full run was done once per commit, so no flake rate is known; a ten-fold repeat of the burst test and five-fold repeats of its file, also under CPU load, all passed (2 to 11 s each)."
12. **Wall-time spread for one file** (path-tests-c14a514.md:12, summary.md:39: 67.56 s vs 36.69 s for the same 378 tests, "not investigated"). Open question in evidence, no doc effect; listed so the lead knows it is unexplained.
