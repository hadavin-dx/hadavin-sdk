## The scan guard (the review's nits)
- DPLD_REQUIRE_SCAN: a lost scan is a FAILURE with the variable set (as test_hygiene.py:29 does for a missing gitleaks), a skip without. Skip text: "the scan of this repository's tracked files was NOT run: <why>. A client copy without .git cannot run it. To run it: use a git clone, or run `git init && git add -A` in <folder>. With DPLD_REQUIRE_SCAN=1 (as CI sets it) this is a failure, not a skip."
- Location: the 7 scan tests are registered in tests/_repo_root.py SCAN_TESTS and ended by conftest with a skip MARK (pytest prints the test's own file, e.g. `tests/test_raw_bidi_chars.py:`; no helper location); with the variable set the failure is raised in the call phase. test_hygiene_scan_public keeps an inline guard so its canary checks run first. A registry (not edits in each file) so a file that another patch adds (nosemgrep_form) needs no edit; test_every_registered_scan_test_exists pins the names.
- ".git presence" vs "git rev-parse --show-toplevel == REPO": measured both and `git ls-files -- pyproject.toml` (evidence-nodemo6-1b-git-cases.txt, 8 cases). Both of the first two give the WRONG answer in a `git init` with nothing added (.git exists, toplevel == REPO, lists nothing: a planted 169.254.169.254 is NOT found and the scan would pass on no files) and both wrongly refuse a client copy that its parent repository tracks (git grep finds the literal there). The chosen check (git lists the tracked marker file) is right in all 8: clone, linked worktree (.git is a FILE), submodule, tracked sub-folder = scan; no git, init without add, untracked or ignored sub-folder = lost scan.
