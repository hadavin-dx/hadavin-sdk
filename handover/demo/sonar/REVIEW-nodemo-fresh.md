## FAILURES / FINDINGS FIRST
### MAJOR 1: the skip condition is too broad; a typo or rename in ANY row path silently skips forever, even with demo present
`_present` skips a row when `(REPO / row[0]).is_file()` is false, for every row (product rows too), and the reason text always says "demo_only/ was removed".
Measured: db54e13 + patch, demo_only PRESENT, DPLD_REQUIRE_DEMO=1, typo `smtp_outbox.py` -> `smtp_outbx.py` in HANDLERS and STILL_CAUGHT:
`46 passed, 3 skipped` (3 skips with reason "src/lead_desk/smtp_outbx.py: demo_only/ was removed"). Same typo on plain db54e13: `2 failed`. So the patch removes a guard that existed for product rows. A moved/renamed product file during a refactor would turn the row into a skip, and CI (which sets DPLD_REQUIRE_DEMO=1) would stay green.
Fix (measured, diff in /tmp/work/rv14-narrow-guard.diff, whole-file diff vs db54e13): skip only when the row path starts with `demo_only/` AND the folder `demo_only/` is absent (`not (REPO/"demo_only").is_dir()`). Then: demo present 49 passed; demo deleted 43 passed, 6 skipped (same 6 rows); typo with demo present: 2 failed (FileNotFoundError); typo with demo deleted: 2 failed; one demo file missing while the folder exists: fails (correct, not a client cut). Row ids identical to db54e13 (49 ids, diffed). ruff check/format and mypy linux+win32 clean on it. This makes the "at least N rows ran" assert unnecessary: product rows cannot skip by construction. If you still want a count guard, put it in a no-demo CI job (see Minor 2).
