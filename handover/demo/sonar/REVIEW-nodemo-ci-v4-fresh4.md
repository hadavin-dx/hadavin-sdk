## FAILURES FIRST

### MAJOR 1: the 85 percent floor does NOT bound silent loss of tests; the notes' "about 6 percent (58 tests)" is wrong by a factor of about 8
Why: a file that turns into a conftest placeholder (`import support` / `from support` anywhere, even inside a function, or one `def test_x(env)`) lowers `passed` AND `collected` (the file becomes ONE skipped item), and the placeholder skip names demo_only so it is "expected". So the share barely moves: passed/(passed+84 fixed skips) stays >= 85 % until passed < ~476 on this stack (1 - 0.85 = 15 %; 84 skips / 0.15 = 560 collected). Measured on stack A (clean 880 passed / 84 skipped / 964 collected):
| case | result |
|---|---|
| `import support` added to the biggest real test file (test_real_check_dry.py, -65 tests) | GREEN 815/79/894, share 91.2 % |
| `def test_zz_added(env)` appended to the same file | GREEN 815/79/894 |
| `import support` added to two real files | **GREEN, 461 passed of 541, share 85.2 %**: 52 % of the executed tests vanished silently |
| `git rm` of a whole real test file (-65 tests) | GREEN 815/78/893, floor falls with collected (760) |
| `git rm` of real files totalling about 357 passed tests (40 %) | GREEN 523/78/601, share 87.0 % |
| `git rm` of about 800 passed tests | RED only because share < 85 % ("only 65 of 143 tests passed") |
Only a hook-based or ignore-based loss that makes pytest's own counts disagree is caught (conftest drop of 5/10/20 %: RED, "N tests reported but 964 collected"; `collect_ignore` of a file: RED "pytest collects 893 tests under tests/ but only 964"; deselect with pytest_deselected: RED "no 'N tests collected' line"; an addopts `-qq`: RED). So the claim "I did not find a green silent-drop construction" is true for hooks and false for the two ordinary routes: a one-line edit that turns a big real file into a placeholder, and deleting tests.
Is it acceptable? A deletion shows in the PR diff. A conversion does not: one `env` argument added to one test (the normal way to use the demo fakes) makes the whole file stop running in the no-demo copy, and nothing is red or even printed. Today only 14 of 86 test files run for real in the no-demo copy on stack A (72 are placeholders; P3's whole test_path_confinement.py is one placeholder because of a `from support` inside a function), so the job's coverage is small and can shrink unnoticed.
Message check: the floor message says "a PR that removes many tests lowers the share": it does so only past about 46 %, and says nothing about a single conversion.
Fix (class level, cheap, stack independent): count the files that really run: `real_files = files - placeholders` is 14 on stack A (the number is printed already as "placeholder files"). Add `MIN_REAL_TEST_FILES` (measured minus 0..1) or bound `placeholders` from above (MAX_PLACEHOLDER_FILES, measured + a small margin); the failure message prints the files that became placeholders (the TOTAL line can list `classname` of every needs-demo-only testcase against the base run). A new test file that needs the demo adds a placeholder legitimately, so prefer the real-file floor (new real files only raise it). Run it against the cases above: they must turn RED.

### MAJOR 2: MAX_UNEXPLAINED_SKIPPED = 2 has zero margin on the second optional stack (v5): the stack coupling that rv29 Major 1 reported is back for this number
Stack C (v5 optional patch, f3d9dca, 3.12, my sandbox is root; also re-run as user `nobody` to imitate the non-root runner): GREEN 1563 passed / 76 skipped / 1639 collected, share 95.4 %, **unexplained skips 2 of 2**. The two skips (not naming demo_only), as root: test_n8n_api_url "root (and Windows) can read a file with no permissions" + test_path_confinement "ntpath.isreserved needs Python 3.13"; as non-root: test_path_confinement "needs root to start as another user" + the same 3.13 one. So on the real runner (non-root, Python 3.12) the count is permanently 2 of 2: the first environment difference on the runner (no /dev/fd, a file system that cannot store a newline or the two Unicode forms, a missing symlink privilege: all `pytest.skip(...)` lines in test_path_confinement.py, which v5 turns into a real file) makes the job RED with "3 skips that do not name demo_only". Stacks A and B have 0 unexplained (so 2 is a margin there). The YAML comment "measured: 0 on both stacks, so 2 is the margin for a platform or Python difference" is therefore only true for A and B.
Fix: either re-measure on a real runner before merging v5 and set the limit from that (and write "0 on A/B, 2 on C" in the comment), or make the skips explicit: for known environment skips name them in an allowlist of reasons, or give the limit more room (5) because the gate that matters is the share. The decision depends on whether v5 ships with this job; it must be stated in the NOTES either way.

## MINOR

Cause: collect-only does not count the module-level skip, the junit file lists it as a skipped testcase. Measured on A (tests/test_zz_ios.py). The repo has no module-level skip today (its importorskip calls are inside functions), so no red now; a future file would trip it. A test that FORGES the junit file and calls os._exit(0) is GREEN (the builder did not build it; I did, stack A and B): tests/test_aa_forge.py reads `request.config.option.xmlpath` and `request.session.items`, writes an XML listing every item of its chunk as passed, then `os._exit(0)`: GREEN, 890 passed / 75 skipped / 965 collected (more "passed" than the honest run: forged items for placeholders too), the rest of the chunk never ran. Fine in the full CI, worth one sentence in the NOTES.
