## Findings (failures first)
### MAJOR 1 - the dash guard is bypassed when BASH_VERSION is in the environment, and then reset.sh DELETES a database outside ./data
Measured: copy of reset.sh in a scratch repo, DB at ../outside/desk.sqlite3 (outside data/), `export BASH_VERSION=5.2; dash scripts/reset.sh` printed `[[: not found` x3, "reset done", rc 0, and the outside file was deleted. With BASH_VERSION unset the guard refuses (rc 2). Bash itself refuses correctly (rc 2). dash imports any environment variable, and BASH_VERSION can be exported (set -a, `export BASH_VERSION`, container ENV, a wrapper). It is an unusual setup, but the guard exists precisely to stop this deletion, and a variable-name test cannot prove the shell is bash.
Fix (measured, small, still POSIX-parsable, same 1 line): test the feature, not the name:
`case "$( (eval '[[ a == a ]]') 2>/dev/null && echo bash)" in bash) ;; *) echo "refused: ..." >&2; exit 2 ;; esac`
Result: bash runs; dash refuses even with BASH_VERSION=5 exported; busybox ash, zsh (and zsh --emulate sh) run (they do support `[[`), which is correct. Add a dash test with `BASH_VERSION` set in the env (the current dash tests only run with it unset).

### MINOR 2 - hygiene scan misses tests inside "$( ... )" in double quotes, backticks, `test`, `command [`, `time [`
Own probe (90 snippets, probe.py): false negatives: `x="$( [ -e y ] && echo 1 )"`, `echo "$(if [ -e x ]; then ...)"` (the quote blanker blanks everything between the quotes, command substitution included); backticks `` x=`[ -e y ]` ``; `test -e x` (S7688 text could cover only `[`; unverified); `command [ ..`, `time [ ..`; escaped quote outside quotes (`echo it\'s ; [ -e x ]`) and `"a \" b"` flip the quote state so the rest of the line is hidden. False positives: heredoc bodies (`cat <<EOF\n[ -e x ]\nEOF`), multi-line quoted strings, `$(( 1 + 2 )) [ ` (the `)` prefix), `if[ ` (invalid anyway). None of these occurs in the repo today (all 3 shipped probes classes pass), so only a future risk; the docstring already says heredocs are not handled. Everything the NOTES claim as caught IS caught: do/then/else/case ) / tab / `!` / `$( [` / `&&` `||` `;` `|` / `if !` / `while !` / `until` / `{ ` / `( ` / line-continuation line starting with `&&` or `[` (all verified true).

### MINOR 3 - lint.yml pip spelling: `--only-binary :all:` vs `=:all:`
sonar.yml (same repo, db54e13) already uses `--only-binary=:all:` and has no S8541 issue in issues-pr4-0253.json, so that spelling is the one with evidence of being clean. lint.yml uses the space form. Both are accepted by pip; whether the Sonar rule accepts the space form is UNVERIFIED (rule text not served). Cheap hedge: use `=:all:` in lint.yml (the test regex accepts both).
