## Findings handled
MAJOR 1 (here-strings and heredoc delimiters): `_scan` now consumes `<<<` as a whole (never a heredoc) and reads the heredoc word as a full shell word (any run of characters except blanks and `; & | ( ) >`, with '..', ".." and backslash pieces; quote marks removed), so `<<'E-1'`, `<<E.1`, `<<"E 1"`, `<<\E-1`, `<<1` work. The end line must equal the word exactly (`<<-`: after leading tabs only), as in bash. Safety net: the scan result flag "ends open" is now also set when a heredoc end line is never found (or when `<<WORD` is the last thing in the text). The test that runs it over every .sh file and run block fails in that case. Probes: 7 here-string probes, 8 delimiter probes plus 6 "ends open" and 6 "closed" probes. The `<<<` mutant dies (evidence-p1v31-4); on the v3 scanner 25 of the new probes fail (evidence-p1v31-3).
MINOR 2 (false positives): quoted text is now blanked to `_`, not to blanks, so `["a"]` stays `[___]`; `[[ ... ]]` spans are neutralised (see holes); a continuation line is read as part of the line before it (`echo a \` then `[ -e x ]` is an argument and is not flagged; `cmd && \` then `[ -e x ]` is flagged, and so is `if \`). Fixed: `m=(["a"]=1)`, `[[ $x =~ a|[ ]b ]]`, the continuation case. Not fixed, by choice: `["$x" = y]` (invalid shell) is no longer flagged, which is right.
MINOR 3 (quadratic): the look-back slice for `((` is replaced by a once-per-line search, and the `[[` pattern is bounded to 400 characters. Measured on the final scanner (evidence-p1v31-5): 1 MB line holding 150 000 `<<`: 0.4 s (v3: 86 s per the reviewer); worst case I found 200 000 `[[ ` on one line 1.5 s and 300 000 lines of `[[ ` 2.4 s. A test runs five shapes with a 20 s bound (fails on v3 with a re-created look-back; mutant N7 killed in 40 s).
MINOR 4: README now says "in any shell where `[[` does not run, for example where `sh` is dash", and that a shell that does run `[[` (busybox sh, zsh) goes on. The test docstring still says "stop at once" in a sentence about the dash case only.
NITs: test_the_guard_line_refuses_under_dash_even_without_set_e (both scripts; runs the guard line alone with `dash -c`, no set -e, expects rc 2 and no text after it, and the same line under bash goes on); mutants G1/G2 (`&&` to `;`) die. `exec [ -e x ]` probe (mutant S1 dies). `_workflow_shell_problems(name, doc)` is a helper used by the repo test, with 6 synthetic workflow texts (no shell key, bash, sh, pwsh, default shell sh, two problems); mutants S9, S9b die.
