## Major
M-1 (noqa question). `tests/run_cmd.py` is an API swap, not a fix. It still starts `git`, `bash` and `gitleaks` by partial name (PATH lookup at run time), which is exactly what S607 flags; the only change is that the call is `asyncio.create_subprocess_exec`, which no active rule checks. Measured: the same `["git", ...]` call with `subprocess.run` gives S603 + S607 under the repo's ruff config; the asyncio call passes even `ruff --select ALL`; bandit 1.9.4 has no asyncio entry at all (grep of the package: none) and tests/ is excluded from bandit anyway. The module docstring says in so many words that the call "is not one of the calls those rules look at". What the PR body tells the reader (line 5: "avoids the finding by using a different standard-library call that those rules do not check") is honest and I count it as disclosed. But it also creates a second, parallel way to run programs next to the three existing noqa-carrying ones (tests/test_hygiene.py `_run`, tools/hygiene.py `_git_text`, tests/support.py `start_proc`), and it is a ready-made bypass for every later author. Args: all fixed lists (git grep/init/add, gitleaks dir with a tmp path, bash -e -c <workflow run block>); no scanned-file text reaches a command line, with the exception in M-2. SonarCloud (python:S4721 / S2076): could not be checked offline; I cannot say whether S4721 lists asyncio.create_subprocess_exec (UNVERIFIED); tests/ count as test code in sonar-project.properties, and S2076 needs tainted input, which is absent. Semgrep registry rules for asyncio exec (dangerous-asyncio-*) exist as far as I remember (UNVERIFIED, no registry offline); they would be WARNING/audit and tests/ is not scanned. Recommendation: not a Blocker. Preferred alternative (zero new suppression, zero new mechanism): reuse the existing helpers (move `_run` of test_hygiene.py to tests/support.py, where `start_proc` already sits, and import it from the two new files). If the lead wants to keep run_cmd.py: make it satisfy the concern, not only dodge it: resolve each program once with `shutil.which` to an absolute path, refuse any argv[0] that is not in a small allowlist (git, bash, the gitleaks path), and rename the docstring sentence from "not one of the calls" to what it does. The owner decides whether "avoid by API swap" meets his no-suppression rule; I would not call it a circumvention in bad faith, but it is circumvention in spirit.
