- **Subject token constant** `SUBJECT_TOKEN_PREFIX = "[demo] lead "` and the key regex `L[0-9a-f]{16}` live in ONE module, `src/lead_desk/imap_count.py` (WP2 owns them); WP3a, WP3b and WP1 import them. The take generates keys as `"L" + sha256(f"{TAKE_TAG}:{person}").hexdigest()[:16]`.
- **Reply JSON (flow reply):** fields `verdict` (str), `lead_key` (str), `repeat` (bool), `n8n_error` (bool). A missing field gives `None` / `False`. `Reply(status, verdict, lead_key, repeat, n8n_error, tries)` lives in `scripts/n8n_drive.py`; WP3b imports it.
- **Table read format.** Table `mf_leads` (name pinned in `scripts/n8n_drive.py` and verified by WP4's test against the generated flow). Command, as an argument list (no shell): `docker exec <PG_CONTAINER> psql -U <PG_USER> -d <PG_DB> -At -F '|' -c "<SQL>"`. SQL (fixed text): `SELECT lead_key, state, mail_sent, (crm_id ~ '^[0-9]+$') AS has_crm, alert_sent FROM mf_leads WHERE lead_key = ANY(ARRAY[...]) ORDER BY lead_key;` Keys are checked against `^L[0-9a-f]{16}$` before they go in. Output line: 5 fields; booleans only `t` or `f`; NULL or anything else raises `TableError`; non-zero rc, timeout (15 s) or a wrong field count raises `TableError`. `has_crm` means a numeric CRM id (so "undefined" is false).

Optional: none. Unknown names are refused. (2) `stage.env` (the stage process only): `DESK_LIVE_*` names and `STAGE_WINDOW_END_UTC`; read by WP1, never by the take. No SMTP sender names anywhere in the take (it sends no mail). The secret files named hold only passwords/tokens and never print.
- **n8n start (manual, fixed script).** `scripts/n8n_start.sh <take folder>` (WP3a owns; about 15 lines): writes `$$` to `n8n.pid`, then `exec env -i PATH=... HOME=... N8N_USER_FOLDER=<take folder>/n8n ... n8n start` with only the names listed in `<take folder>/n8n.env` (non-secret n8n settings plus `N8N_ENCRYPTION_KEY`, which sits in a 0600 file read by the shell and never appears in a command line or the console). Because of `exec`, the pid in `n8n.pid` is the n8n process itself (no wrapper); the kill helper also kills the process group.
