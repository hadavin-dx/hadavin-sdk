<h4>Feedback</h4>
<p><strong>JavaScript scoping and error handling</strong></p>

<ul>
<li>The JS issues cluster around loose scoping and lifecycle: <code>Portal</code> not defined, <code>booted</code> used before definition, lots of implicit <code>var</code> via missing <code>let/const</code>, and functions declared in loops. They’re all symptoms of relying on implicit, mutable globals.</li>
<li>Being deliberate about scope and declaration in the portal code would likely clear most of these in one pass.</li>
</ul>

<p><strong>Retry/exception structure in Python</strong></p>

<ul>
<li>The overlapping exceptions, unused <code>tries</code> variables, cell var <code>tries_now</code> in a loop, and handlers that immediately re‑raise all show the same thing: retry and error paths are a bit tangled across modules.</li>
<li>Stepping back once to align how retries and exception hierarchies work would simplify the logic and avoid subtle reliability bugs.</li>
</ul>
