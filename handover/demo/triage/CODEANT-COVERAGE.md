## 4. The security-looking findings, one by one

**.gitleaks.toml:91 (CA-01).** Who controls the input: whoever adds a file. Attack: put a 40- or 64-hex token into any file named `requirements-dev.txt` or `requirements-dev-win.txt` in a subfolder (for example `docs/`); the long-hex rule skips it, the scan stays green. Needs: a commit by someone who is allowed to push, or a pull request that nobody reads closely; and the file must be named like a lock file. No such file exists now. Proof: gitleaks 8.30.1 run before and after (`evidence-codeant-gitleaks.txt`). Fix: anchor to the root. Not a live leak today; a hole in the guard.

**scripts/n8n_api.py:32 (CA-02).** Controlled by the person running the script: `N8N_URL` is an environment variable on their own computer, the API key is a file they name. Attack: not an outsider attack on its own; it is a footgun. If that person points `N8N_URL` at `http://some-host:5678` (n8n running on another machine without TLS), the key is sent unencrypted and anyone on the network path can read it. Default is `http://127.0.0.1:5679`, which stays allowed. Severity "Critical" is too high; "hardening, low" is right. The fix refuses plain http to anything but this computer and keeps https and loopback http. Tested: 13 cases, 7 fail before (the 6 accepted addresses pass both times).

**tools/scrub_n8n_export.py:40-41 (CA-03, CA-04).** Controlled by the licence holder who exports their own n8n workflow with made-up data and then publishes the scrubbed copy. The data is the node parameters of the workflow (free text typed in n8n). Failure scenario (no attacker needed): a parameter holds `ftp://user:secret@files.corp.example/in/x.csv` or `file:///home/name/key`, or a real address on a domain that begins with the made-up one; the scrub kept the address (or the user name and path) and the file goes to the public repo. Proof: run on 558d37f and on the patched code (`evidence-codeant-scripts-*.txt`). Fixed: any scheme is replaced, the made-up domain must end the domain. Limits: it still does not catch scheme-less hosts (`//host/x`, `host:5432`), tokens in free text or key names; the tool's docstring never promised those.

**scripts/reset.ps1:20 (CA-08).** Controlled by the person on Windows who runs the reset; the database path comes from `DESK_DB_PATH` (their environment) and the link inside `data\` must already exist (creating a junction needs write access to the repository's `data` folder). Attack: someone who can place a junction in `data\` and set or influence `DESK_DB_PATH` (a hostile shared account, or a mistaken junction) makes the reset delete the file named by `DESK_DB_PATH` plus `-wal`, `-shm`, `.lock`, `desk.log`, `fakes.log`, `crash.flag` in the linked folder. Without a junction the old check was correct (it also normalises `..`). The Linux script was already safe (`realpath`). Fixed by the same real-path check as `reset.sh`. **Not run on Windows.** Severity: low (local, needs prior write access to `data\`).

**src/lead_desk/desk.py:397 (CA-06).** Not a security issue: a robustness flaw. Input controlled by whoever starts the desk (`DESK_DB_PATH`). Failure: with `:memory:` the first request thread works and every other thread gets a 500 because each thread's connection is a new empty database. Nothing leaks; data is not lost (it was never stored for those threads). The bot's "Critical" is overstated. Fixed: the desk refuses the setting at start (exit code 4 with a message).

**src/lead_desk/desk.py:785 (CA-07).** Not a security issue: a correctness race with a third party (the CRM). Attacker needed: none; a slow or briefly unreachable CRM is enough. The first call times out (the desk gives up after the send deadline), the stage moves on, the second call goes out, then the first lands late, so the CRM ends on the old stage while the desk's book says the new one was copied. Proof: the test starts two calls on the old code (`evidence-codeant-desk.txt`). Fix: `exclusive=True`, so a new copy for that lead waits while an abandoned one still runs; the existing `except AdapterBusy: return` ends the pass without counting a try. Side effect to know: while one lead's abandoned call is running the whole copy pass stops (same as at the worker cap today) and resumes at the next pass.

**CA-14 (demo_only/portal_demo.py:414), called Critical by the bot.** No attacker: the demo controls are for one person at a computer. The request pair "arm" and "clear" only conflicts when both are in flight at the same instant; then either order is valid and each answer tells the truth about its own effect. The flag is written as a private temporary file and one atomic replace. No fix needed.
