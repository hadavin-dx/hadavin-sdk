# A4 review round 2, security and loss lens (egm design, agent a51bc7f52c8876b60)
Read-only, by code reading (no execution). Verdict: NOT CLEAN: 0 Blockers, 3 Majors, 5 Nits. No slot leaked or released twice on any traced path.
M1 server.py:143-145, 367-372 (header_done/parse_request), 197, 101-118: eviction can close a connection whose whole request is already buffered (a lead POST under 8 KB arrives in the first recv). If _take_slot runs between that recv and header_done(), the victim is shut down, never rechecks _aborted(), still runs desk.process (receipt and lead committed), and the reply write hits the dead socket: client sees EOF, no reply. Retry with the same id returns the stored answer (no duplicate) but the rule "eviction never closes a connection that has a receipt" is broken. Fix: header_done() takes the lock and returns slot.evicted; raise ConnectionAbortedError right after parse_request if evicted, before dispatch. Test: evict at exactly that point with the full request buffered; assert leads()==0 and the connection closed.
M2 server.py:249-278 (_refuse_busy on the accept loop), test_slow_sender.py:258-268: a client that keeps sending (byte under every 50 ms, or up to 1 MiB) keeps the accept loop busy until BUSY_WRITE_TIMEOUT (1.0 s): all accepts stall about 1 s per such connection; the silent-client test bound (<3 s) is too weak and no trickler is tested. Fix: bound the in-loop refusal to one QUIET_DRAIN (50 ms) in total, or hand it to a bounded refuser; test with a 20 ms trickler and a second connection answered in under about 0.3 s.
M3 (a) body-phase slowloris holds all 256 slots (connections past the headers are never evicted): about 26 connections per second keeps every slot taken; every real caller gets 503. Fix: evictable state = still reading (header or body), end when the body is complete; evict the oldest reading connection (fewest bytes first); test with the cap filled by body-phase connections. (b) README overclaims "at most 256 threads": the slot is released at the first reply byte; reply write, drain and follow-up threads are unbounded. Fix: correct the README (done in the A4 tree); better also cap total handler threads.
N1 shutdown on victim.sock can race with the victim closing (fd reuse window). N2 timed_out_in is never cleared after a drain timeout: later TimeoutError reported as 408 "drain" instead of 500. N3 start_background/stop_background: check-then-set without lock; stop does not clear _background; stop then start while old reaper still running leaves two reapers; add a double-start test.
