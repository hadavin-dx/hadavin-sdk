# WP-A result review, round 1, SECURITY lens (egm-design, read-only, snapshot portal-A-wt on baseline bfb28cf, 2026-11-09). Verdict: no Blocker, 5 Major, 7 Nit. Reviewer ran nothing. Saved by the cloud session.
No write path, SQL injection, path traversal or open CORS hole found. Sound: connect_readonly (mode=ro + query_only), fixed SQL with parameters, LIKE escaping, control-char/NUL rejection, digit-only pagination with caps (limit<=100, offset<=100000, q<=100), gate runs in _dispatch before routing for every route incl. 404/405 (only stdlib send_error paths bypass it), Origin exact match, Sec-Fetch-Site same-origin/none only, no CORS headers, headers via single writer _send_bytes, fixed 500 body, no envelope leakage.
M1 Host/Origin gate is not authentication: README says "listens on this computer only" but tells Docker users to set DESK_BIND to a reachable address; any LAN host sends `Host: localhost` and reads every lead (name, email, phone, message) via /api/ui/leads?q= (100 rows per request) and /api/ui/leads/{id}; before, a 48-bit lead id was a capability. Fix: say plainly in README/contract that the gate stops browsers, DNS rebinding and cross-site requests only; tell Docker users to bind the specific bridge/host address, not 0.0.0.0; startup warning when bind is not loopback (server.py main).
M2 "one read transaction on a separate read-only connection" is false for /api/ui/review: _review calls desk.review() on the thread-local write-capable connection (autocommit read) and only the lead-name lookup uses the snapshot; docstring "write connections are never used for a page" untrue; test_every_reply_comes_from_one_transaction spies only on connect_readonly and skips /leads/{id}; two-snapshots mutant survives for /review. Fix: run _REVIEW_SQL and hint rules inside _snapshot; else correct docstring/README/contract and add a test; add /leads/{id} to the spy test.
M3 Security tests would pass on a gate broken for GET/HEAD/OPTIONS: foreign Origin and Sec-Fetch-Site only tested on POST /leads; HEAD/OPTIONS with foreign Host missing; security-header test skips 403/308/405/send_error and never asserts no Access-Control-*; no tests for trailing-dot Host, uppercase/expanded IPv6, Host:localhost:99999, Host with control char. Fix: parametrize over GET /api/ui/summary, GET /ui/, GET /api/ui/leads/L..., POST /leads; add HEAD/OPTIONS; header test on error replies; add Host variants.
M4 Unbounded query cost, unmeasured: repeats column is a correlated count(*) over receipts (outcome_lead_id not indexed) evaluated per candidate row before LIMIT; ORDER BY created_at DESC, lead_id DESC unindexed; _LEADS_TOTAL repeats the join; /summary does ~10 full receipts scans and Overview polls every 2 s per tab; ThreadingHTTPServer unbounded threads, a new connection per request. Fix: compute repeats only for page rows (or one grouped LEFT JOIN), or index receipts(outcome_lead_id) WHERE outcome='duplicate' (schema change: coordinate with lead); a test with a few thousand leads/receipts asserting latency or statement budget; at least a concurrency cap on /api/ui; record measured timings.
M5 Red tests unexplained: builder says 5 identical on baseline + 1 flaky; log shows follow-up failures ('pending' vs 'failed', desk.py:999 TypeError) in the area _dispatch touches. Fix: run the six tests on baseline and show the same red set with a root cause for the TypeError at desk.py:999.
