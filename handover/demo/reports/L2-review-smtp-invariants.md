Check 3 (unknown + message allowed): correct in substance (a blind sender legitimately leaves unknown with a message: SendAmbiguous, crash at D2, drop-after-DATA); cannot hide a duplicate (a key seen twice always fails first; failed-with-message still fails). BLOCKER A1: `unknown` becomes a free pass: a desk bug parking every follow-up in unknown passes checks 2,3,4. Fix: read last_error and send_started; allow unknown-with-message only for last_error in {ambiguous, crash_while_sending, ambiguous_prior, mode_mismatch}; unknown with crm_unconfirmed and a message is a fault; per-scenario ceiling on unknown/failed counts (only drop-after-data and crash scenarios may have unknowns); print counts of unknown with and without message. MAJOR A2: key is only X-Send-Key (= lead_id): count messages per recipient `to` too (fault_double_to test).
B. BLOCKER B3: check 1 reads only the client log; an empty/partial log passes (driver crash leaves an empty file; `_post` does not catch http.client.IncompleteRead/BadStatusLine, so a desk killed mid-body kills the worker thread, the request is never logged, never "lost"; driver exits 0 when logged != intended; driver_exit not used in `worst`). Fix: catch Exception per attempt; try/finally so every scheduled item logs; check_receipts takes intended count and fails if lines != intended; driver returns 1 if logged != intended; campaign counts non-zero driver_exit as failure. BLOCKER B4: on drain timeout the marker has drained_ts null and check_drain falls back to the book's updated_at: check 7 passes on a desk that never drained; open receipts (outcome IS NULL) not counted. Fix: marker with null must fail check 7; count receipts with outcome NULL (must be 0). MAJOR B5: check 2 compares to leads, not to submitted: assert len(leads)==distinct request ids, every `new` receipt has its lead, no NULL outcome. MAJOR B6: crash scenarios do not require the crash to have happened; unexpected exit codes restarted forever and ignored. Fix: fail if no 137 in a crash scenario, crash.flag still present at the end, any `unexpected`/`restart_failed`, or any restart in a non-crash scenario. MAJOR B7: fake model logs a timeout-mode call only after the 15 s hold; the campaign kills it right after drain: check 5 undercounts in model-timeout and model-flaps. Fix: log an arrival line at call start. MAJOR B8 (false alarm): default model bound 3 but SEND_MAX_ATTEMPTS is 5 (gate.py:38): correct behaviour fails in ~5 scenarios. Fix: bound = SEND_MAX_ATTEMPTS + stated slack imported from lead_desk.gate; pass it from the campaign.
