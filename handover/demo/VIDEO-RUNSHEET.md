## Risks the owner must see
1. The table screen is built but NOT RUN: it was never started in my sandbox; expressions and the content-type header option are unverified. Fallback, owner decides: (a) a plain screenshot of the rows taken during rehearsal, columns lead id, state, attempts, mail_sent, alert_sent, alert_attempts, updated at only; or (b) a one-time database-node preview in the n8n editor with the same safe columns. Not the n8n execution list.
2. Timing of the hand-made kill in scene 4 and option B of scene 7: the kill must land at the right point (after the claim row, before the CRM write; after delivery, before the table update). The harness hits these points; a human may not. If the kill lands elsewhere the result differs from K1 or K3, so the number would not back the scene. Fix by rehearsal or by using a slowed stand-in step.
3. The numbers are at a 20 s lease. The take must show lease 20 s as a label or use the same lease. At the design lease of 120 s the waits are longer and not measured.
4. Alert counts: v3 can send two alerts when an alert send is slow; the unknown-case "one alert" is lead-read from the first table but the V7 final note says the per-lead alert count is not separately verified for K1, K2, K3, K3B, T10, T11, T13.
5. Step-2 fault for a real mailbox and the Slack alert are NOT BUILT; the take uses the stand-in or cuts, and says which.

## What must be rehearsed on the laptop before the take
1. Import and activate the table screen flow; open it once; confirm it shows the seven columns and no name or address column; if it fails, take the fallback screenshot.
2. The prepared send note: one lead through mf-form on the LOOPBACK address; check reply wording for done, for the repeat, and for unknown (scene 8 text is unchecked on v3).
3. Option A (stand-in drop fault) on v3: it was never run on v3 (T12 not run). Run it five times, note the intake count (0 or 1), the alert count, the state, the seconds to alert.
4. Option B or the K1 kill by hand: time the stop note against the stand-in step, 5 tries, record how often the kill lands at the intended point.
5. The refuse-every-call switch and recovery to failed (scene 5): note real seconds on the clock overlay.
6. The alert-only refusal (scene 11): confirm the sped-up cut and the overlay text.
7. Check that the screens never show the execution list, real names, real addresses or any key.
8. Check there is no 40-character code or host name visible in any pane or caption.
9. Run the whole take once with a stopwatch; compare to the EST column.
