## Findings (a stranger would meet these)
F1 (README Try it, Linux block vs docs/tests.md line 26): the crash scene is not part of the README Linux block; it exists only in docs/tests.md line 26 ("PYTHONPATH=src python scripts/crash_desk.py"), and the instruction does not say the normal desk must be stopped first (both want port 8765). A stranger who starts crash_desk.py while start_all's desk is running would get a port clash. Not tested (brief said stop the normal desk by pid file; I did). Would change: add to docs/tests.md line 26, after "The crash scene:", the words "first stop the normal desk (kill the process id in data/desk.pid and delete that file), then run".
F2 (docs/tests.md line 26): after "ends at once" the doc does not say how to restart. Needed knowledge: the restart command is python -m lead_desk.server (the same as the desk alone line), and the pid file is not updated by it. I wrote the new pid into data/desk.pid myself so that reset.sh could stop it; without that, reset.sh would not stop the restarted desk and its later check (reset_check.py) would stop with exit 4 (something answers on the port). I did not test the no-pid-file case. Would change: add "then start the desk again with PYTHONPATH=src:. python -m lead_desk.server and write its process id into data/desk.pid before running scripts/reset.sh".
F3 (environment difference, fact): start_all.sh sets DESK_LEADFLOW_FILE=demo_only/leadflow.json and DESK_NUDGE_TO=reminder@example.test for the desk it starts; crash_desk.py and a hand-started desk do not set them. I exported the same two values in the driver before starting the crash desk and the restarted desk so all three desks ran the same settings. Without them the crash desk would have run without lead owner, lead stage and reminder. Not tested without them.
F4 (observation, not a failure): the process id file of the crash desk showed as still alive (kill -0 rc 0) one second after "simulate crash" was printed. The port was free for the restart, so the desk had stopped listening; whether it was an unreaped ended process was not checked (no process listing taken at that moment).
F5 (hygiene): crash_desk.log and a pid file that I put in data/ stay after reset.sh (reset deletes only its own files); I removed them by hand.
