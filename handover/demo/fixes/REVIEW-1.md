## MAJOR
- M1 (rule 20): the decoder `_png_pixels` (tests/test_portal_lead_pages.py:418-461 in the patched tree) is own code with no RUNG TABLE (a missing table is a Major), no safety guarantee, and higher rungs exist that the builder did not try: (a) Pillow, free library; (b) decode INSIDE Chromium: Playwright is already required, so load the screenshot bytes as a data-URL image in the page, draw it to a canvas and read `getImageData` (about 8 lines of JS; Chromium does all the PNG decoding; tolerance 6 should absorb colour-management differences; not tried by the reviewer); (c) avoid pixels (computed background and box height against scrollHeight): changes what the test proves, not recommended. The decoder is called only from the two Playwright tests, which skip in CI (lint.yml installs only requirements-dev.txt: lines 50-51, 98), so the five-filter logic (incl. Paeth and Average) is never run by any committed test in CI. Reviewer's reading of the logic: correct (Sub, Up, Average floor((a+b)/2), Paeth per spec with tie order a, b, c; in-place update right; multiple IDAT concatenated); colour types 0, 3, 4, bit depth other than 8, and interlace hit the `assert (depth, interlace) == (8, 0) and colour in (2, 6)` at line 435 and raise (no silent wrong colours); filter type above 4 asserts at line 458 (asserts are stripped under `python -O`, not the case here); Chromium's Skia encoder is 8-bit RGB/RGBA, not interlaced; output matches Pillow's .convert('RGB') for RGBA (both drop alpha without compositing). Recommended fix, either (1) option (b) decode in Chromium, or (2) keep the decoder, add a stdlib-only unit test that is not Playwright-gated and runs in CI (small PNGs built with zlib for each filter type 0-4, plus an unsupported-type case that raises; rule 7), and add the rung table either way.
- M2 (docs/tests.md patch lines 47-49): counts labelled 'this commit' and 'measured' were not measured on b29bb1f, and 2462 was never measured on any tree without Pillow. Sources: speed/RUNBOOK-INPUTS.md lines 27-30: 2349/116 was run on 43110e7 (lane 1) and bee6fff4 (lane 4); 2462/3 was run on 43110e7: the raw log (outsider/08-full-with-playwright-rerun.txt:2567) says '2 failed, 2460 passed, 3 skipped'; 2462 is the lane's own 'would be' figure after `pip install pillow`. Nothing ran the full suite on b29bb1f with the decoder (PLAN.md item 1 admits it; the doc does not). The doc says 'What a full run gives (Linux, Python 3.12, this commit, 2465 tests)' and calls the steps 'measured'; the 2465 total at b29bb1f is unverified (2349+116 = 2465 only on the other commits). Fix: name the commits and the Pillow caveat, or run the full suite once on the final tree.
- M3 (rule 6/14): the 'why' for the two lead numbers is stated as fact, but the raw evidence shows a hypothesis, and one source contradicts the log. The doc says the 2329/135 count 'is what you get when Node is not installed': only the 8-file run (evidence-4: 134 vs 113 skips) supports the Node effect; the full-run 2328/137 is the builder's arithmetic, not a measurement. Lane 1's SUMMARY.md:13 says 'node was not on PATH in this run' but its own raw log (outsider/02-unit.txt:49-57) has no 'node is not installed' skip, and 116 = 113 + 3 leaves no room for 21 Node skips: so the 2349/116 run HAD Node (the builder's reading of the raw skip list is right; the contradiction is not mentioned). The 'not explained' paragraph is imprecise: it offers 'one fewer test OR gitleaks', but neither alone fits (with gitleaks present, Node off, no Playwright, passed is exactly 2329 and only one skip is left, 136 vs 135). The lead's with-Playwright figure 2462 passed / 2 skipped (RUNBOOK-INPUTS line 14 note, outsider/SUMMARY.md:14) is not reconciled (gitleaks present would give 2463 here).
