## B. Issue by issue

**Issue 1 (Major), one review-day helper, empty and partial states.** Class: the same question ("which day is the review day?") answered in several places, each one able to take the wrong list or fail on an empty one. Choke point: `pp.review_day(*lists, latest=False)` in `tools/policy_page.py` takes the earliest (or latest) `review_by` of the lists it is given, each list from its own entries, and `None` for no entry. `review_date()`, the page text, the three date tests (`_date_test_problems`), the runner (`review_days`, `canary_day`, `expected_red`) and the probe all call it. Siblings searched: `grep -rn "review_by" tests tools` and `grep -rn "min(" tests/policy_mutants.py tests/test_policy_*.py`; no other place works out a review day. `kinds_sentence(pending)` builds the one changelog sentence that may hold days for none, one, two or more groups of days. The docs test branches on `None`. No test writes a day: the dates come from the lists (`_dated(...)` builds made-up lists on the tool's decision day). The three date tests have their own failing proof for an empty list (`_date_test_problems` branches, plants in `test_the_date_test_rule_finds_an_empty_list_that_reports_and_a_list_that_never_goes_red`).
*The exit 1 with empty lists, explained.* With both dated lists emptied, `--check` and `--write` correctly exit 1 today: the 16 kind modules still hold unchecked permission names (`verified=None`) and unchecked claims (`claims_unverified`), and the two dated-list rules refuse a name or claim that has no dated entry. That refusal is the rule working, not a bug. The test `test_with_both_dated_lists_empty_the_page_names_no_day_and_the_commands_still_report` therefore covers TWO states, both with the real commands and the real `data_problems`: (1) the state of today with empty lists: `--check` and `--write` exit 1, nothing is written, one refusal line per unchecked name or claim; (2) the END state (`_end_state`): both lists empty AND every name checked and no claim unchecked. The only thing faked is the policies fed to the two dated-list rules (`name_pending_problems`, `claim_pending_problems` are wrapped to receive cleared copies); every other rule of `data_problems` runs for real on the real kind modules, and `--check` and `--write` are the real commands, run on two days. What the end-state test cannot show: that the kind modules themselves will be cleared by a real Vault run (that work is the IMPOSSIBLE-NOW engine run).
Mutants: B11 the review day takes only the first list / ignores the latest option / is a date and not None for empty lists; B11 the date test rule accepts an empty list that reports an overdue line / a list that never goes red / a problem that is not an overdue line / a helper that is red on the review day; B11 the kinds sentence has no form for one group of days / names no kinds for an empty list / drops the middle groups.
