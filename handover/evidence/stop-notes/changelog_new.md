- **Mutation runner: what to do when you take this version.** The mutation runner (`tools/mutation_runner.py`) is the developer tool that puts one deliberate bug at a time into a copy of the code and checks that a test fails for the stated reason. Its function `run_mutants` gains five keywords: `conftest`, `pass_env`, `forbid_skips`, `throwaway_hosts` and `shown_classes`. A call that gives none of them takes the same arguments as before. Two of its results change and one row gets a new label (step 3).
  1. **Which files to re-copy.** A repository that keeps its own copy re-copies FOUR files in one commit: `tools/__init__.py`, `tools/mutation_runner.py`, `src/hadavin_sdk/testing/__init__.py` and `src/hadavin_sdk/testing/mutation.py`. It then updates its pins to the sha256 values in the list at the end of the section "Added (P1m, test tooling: the mutation runner and judge)" below. The same values are in `tests/fixtures/mutation_manifest.json`. A repository that installs the SDK as a package already has the two `testing` files. It re-copies the two `tools` files and moves its SDK pin to the same commit. The new runner does not start with an older `mutation.py`: it needs the new function `judge_report`.
  2. **Run your mutant list once.** Expect about twice the run time when you use `pass_env` with a database address that is present (one extra test run per mutant).
  3. **What can turn a passing mutant list red after the re-copy, and what to do.**
     - Every caller:
       - A mutant that was "killed" by an assertion inside a fixture (setup or teardown) is now the row `FIXTURE ERROR`. It is not a kill, because the test never ran as written. Do: move the assertion into the test body, or name a test that fails in its body.
       - A mutant with `allow_crash=True` whose crash came from a fixture is now `FIXTURE ERROR` too. Do: the same.
       - A run that failed (exit code 1) while the result file named no failing test is now `ERROR`. Before it was `CRASH` or `KILLED`. Do: find out why the result file is empty (a crash of pytest itself is the usual cause).
       - `first_lines` (the dictionary a caller may pass to get the first failure line per mutant) has an entry only for a row that has such a line. Before, some rows got an empty entry. Do: read it with `first_lines.get(name, "")`.
       - New label only: a test file that cannot be imported is the row `COLLECTION ERROR`. It was an `ERROR` row before, with the module name in the test-id column. Do: nothing, unless your script matches on that column.
     - Only with `pass_env`:
       - A test that is skipped, or marked as an expected failure, is the row `SKIPPED TESTS`, and a first run that skips stops the call. This is on as soon as a name is listed in `pass_env`. Do: make the tests run (start the database), or pass `forbid_skips=False` when the skip is intended.
       - The first run on the unmutated code is repeated after every mutant on the same database (the canary run). When it no longer passes, the call stops with `CanaryFailed`, and the rows so far are in its `rows`. Do: make the tests clean up after themselves, or give the mutant list a fresh database.
       - An address the runner cannot check is refused before any test runs (next entry). Do: write the address in one of the two accepted shapes and list its host.
       - The first failure line and the test id are replaced by short fixed texts while the address is present (entry "what is shown"). Do: if a script reads `first_lines`, match on the caller's own `expect` text, which is kept.
  4. **Windows.** Only Linux is run in CI. Nobody has run the mutant list of this tool (`tests/mutation_runner_mutants.py`, 251 mutants of the runner and its judge) on Windows. By reading the skip markers, 26 of those mutants would not be killed there, because the tests that kill them need POSIX signals, file owners, file modes or links. Their names are in the header of that file. What to do on Windows: use the runner as it is. The lock and the checks of the lock folder described below are not checked there, so give each run a database of its own.
- **Mutation runner, keyword `pass_env`: what it does and what it does NOT do.** `pass_env=("HADAVIN_TEST_PG_DSN",)` gives the test process the listed environment variable, which holds the address of a test database. Words used below: the *passed variable* is that variable; its *address* is the whole value of the variable; a *replacement text* is a fixed text shown in place of text from the tests. The runner checks the variable's name only (one name is allowed today). The tests, and every process they start, receive the full address, a password in it included. So pass only the address of a test database, never a token or a key.

  What a listed name switches on depends on the variable:

  | the variable | skip check (`forbid_skips`) | canary run and lock | output replaced |
  |---|---|---|---|
  | listed, variable absent | on (unless set to off) | no | no |
  | listed, variable present but empty | the call is refused before any run | | |
  | listed, variable present with a value | on (unless set to off) | yes | yes |

- **Mutation runner, keyword `pass_env`: what is refused before any test runs, in this order.** Each refusal is an error that names the variable and the reason, never the address.
  1. A value longer than 2,000 characters.
  2. A quote mark, a backslash, a control character or a non-ASCII character in the address, or in its password after percent-decoding.
  3. An address that gives more than 300 texts to search for (a password written in many encoded layers).
  4. An address outside the two accepted shapes. Shape one is a `postgresql://` URL with an optional login, a host, an optional port and ONE database name, and nothing after it. Shape two is `key=value` words separated by one space, with these keys only, each at most once: `host`, `hostaddr`, `port`, `dbname`, `user`, `sslmode`, `connect_timeout`. An IPv6 host is written `[::1]` in a URL and `host=::1` in words. An empty text is refused here too. Changed in this round: the keys `sslrootcert` and `application_name` are no longer accepted, and every key is checked for a repeat.
  5. An address with no `host` and no `hostaddr`. It would use the default local socket of the machine, which the runner cannot check.
  6. A host that is not listed. `host` and `hostaddr`, each when written, must be an exact member of the keyword `throwaway_hosts`. Its default is `localhost`, `127.0.0.1` and `::1`. A unix socket folder (`host=/var/run/postgresql`) is accepted only when the caller lists that exact folder; the default list holds none. There is no pattern and no override. Do: pass `throwaway_hosts=("the-exact-name",)`. The address CI uses, `postgresql://postgres@localhost:5432/postgres`, passes.
  7. A second runner on the same address in the same lock folder (entry "the lock").

  The entries of `throwaway_hosts` are checked for every call, also when no variable is passed. **Not usable any more, by decision (fail closed):** a `key=value` address with a password key, and a URL whose password holds `@`, `/`, `?` or `#`. Do: use a test database whose login needs no password in the address, or a password without those four characters in the login part of the URL.
- **Mutation runner, keyword `pass_env`: what the runner cannot check.** It cannot check that the database is disposable. It cannot see what the login may do. The host list is the only check of where the tests write. A local name does not prove a local database, because a tunnel or a proxy can point it at a shared one. Adding a host to `throwaway_hosts` removes that one check for that host. Every mutant run writes to the database, and a mutant can make the tests drop or fill tables. So you must know that the database is disposable and that its login can touch only that database.
- **Mutation runner, keyword `pass_env`: what protects the address, and what is shown.**
  - The console output of the tests (stdout and stderr) goes to the null device. The runner never reads or prints it.
  - The tests get a fixed short list of environment variables plus the passed variable. No variable of the database library (`PGHOST`, `PGSERVICE`, `PGPASSFILE` and the like) is on it; a test checks that. `HOME` IS inherited, so a `~/.pgpass` file of the caller is used by the tests' database library.
  - The environment is read once, at the start of the call. A variable changed during the run changes nothing.
  - While the passed variable has a value, text from the tests is shown only when it is on an allowlist of text that the caller or Python owns. A list of the forms a secret can take (a slice, a reversed copy, base64, hex) can never be complete, so the earlier rule "hide what shares four characters with the address" is gone. That rule let a reversed password through as a "class name", and for the CI address, which holds no secret, it hid ordinary names such as `PostgresError` and `test_postgres_store`.

    | the place | what is shown |
    |---|---|
    | the exception class name | shown when it is a built-in Python exception name, pytest's `Failed`, a `crash_type` of a mutant of this call, or a name in the new keyword `shown_classes`; else `[class not shown]` |
    | the rest of the failing line | never shown; instead `[expect found]` or `[expect not found]` and the caller's own `expect` text |
    | a test id | the file part when it equals one of the caller's `tests` entries (the caller's text is printed, without `.py`); a class or function name when `def name` or `class name` stands in the caller's copy of that file, or the caller named it on the mutant (`only_test`, `pinned`); else `[test id not shown]` |
    | the `[...]` part of a test id | always `[parameters hidden]` |
    | how a run ended | exit code, timed out or reaped, in fixed words |

    This holds for every text the runner returns or raises: `first_lines`, the test id of a row, the messages of the `COLLECTION ERROR`, `FIXTURE ERROR` and `SKIPPED TESTS` rows, and the messages about a failed or skipped first run and canary run.
  - Second layer: what is left is searched for the address, its password and the percent-encoded forms of the password. Each hit is replaced by `[REDACTED]`. This layer finds known texts only.
  - `first_lines` and `crash_type`, stated once: the judge and the `crash_type` check read the real line of the tests inside the runner. `first_lines` gets what the table shows. With no passed variable that has a value, nothing is replaced.
  - Not covered: the caller's own `expect` text and mutant names are shown as given. A test that itself writes the address to a file or to the network is out of reach of this tool.
- **Mutation runner, the lock: one runner per address in one lock folder.** Its reach is small. It stops a second runner only when that runner uses the same lock folder and the same spelling of host, `hostaddr`, port and database name. It does NOT see a runner of another user, a runner with another temp folder or on another machine, the same database written another way (`localhost` and `127.0.0.1`, a port written or left out), or an older copy of this tool. Old and new copies keep their lock in different places, so they do not see each other's lock. The canary run does not replace the lock: it proves only that the unmutated tests still pass. So give each run a database of its own.
  - Where: on Linux and macOS the lock folder is `hadavin_mutation_locks_<user id>`. It lies in `XDG_RUNTIME_DIR` when that names a folder of this user that is closed to others, else in the temp folder. The runner makes it with mode 0700, opens it without following a link, checks what it opened, and creates the lock file under the opened folder.
  - A folder under that name that belongs to someone else, is a link, or is open to group or others is REFUSED: the run stops with an error. The runner cannot prevent another user of a shared temp folder from putting such a folder there first. Do: give the run a temp folder of its own with `TMPDIR`.
  - Two databases behind one unix socket folder now get two lock names (before, every socket address shared one name).
  - Windows: the lock file lies directly in the temp folder. The runner checks nothing about that folder or file there.
- **Mutation runner, keywords `conftest`, `forbid_skips` and `shown_classes`.**
  - `conftest="tests/conftest.py"`: one file of the tree that every test run loads as a pytest plugin. The path must be plain ASCII names ending in `.py`, and the file must be called `conftest.py` or lie in a folder called `tests`. No other `conftest.py` is read.
  - `forbid_skips=True`: a run where any selected test is skipped (or is an expected failure) is the row `SKIPPED TESTS`, never a kill. A first run that skips stops the call. A run with no result file is the row `JUNIT MISSING`. Default: on when a name is LISTED in `pass_env`, whether or not the variable is present; off otherwise. `forbid_skips=False` turns it off.
  - `shown_classes=("PostgresError",)`: exception class names of your own libraries that may be shown while the passed variable has a value. Plain identifiers only.
- **Mutation runner: background (not needed for the upgrade).**
  - Why we wrote code: ready-made mutation tools cannot say why a mutant died. `pytest` runs the tests, and whole-file mutation tools neither judge the reason nor name the killer test. No no-code tool fits a developer check. The product's redaction function was read and not reused: it finds secret-shaped text by pattern, not one given value, and it would tie a tool that demos copy byte for byte to the product module.
  - The changed results in detail. (1) A run whose FIRST failing test case failed in a fixture is `FIXTURE ERROR`; a test body that failed and whose teardown failed afterwards is still judged by the body's failure (confirmed by a real run). (2) `judge()` returns `ERROR` when the run failed with exit code 1 and no failing test id is known. The row then says `NO FAILING TEST NAMED`; for any other exit code with no failing test it says `EXIT CODE <n>`. (3) `COLLECTION ERROR` is a new label only: pytest exits 2 for it and `judge()` already returned `ERROR`.
  - Evidence for (3). The unchanged runner of `main` (commit 2a8c2aa, `tools/mutation_runner.py` sha256 `489517fb224f0598e14244ded1b37fe2a68be69e2396e56e450be0d8b1c0a1a7`) was run on a tree whose test file starts with `assert go(True) is True, 'at import'`. It gave the row `('flip', ERROR, '::tests.test_core', False)` with the first line `E   AssertionError: at import`. pytest exited 0 for the first run and 2 for the mutant run.
  - Judge helpers. `src/hadavin_sdk/testing/mutation.py` gains `skipped_tests(xml_text)`, `fixture_errors(xml_text)`, `read_junit(xml_text)` (one parse of the result file) and `judge_report(rc, report, ...)`. `judge_report` is the one call that judges a run correctly. `judge()` alone cannot know about a fixture error, so a harness that feeds it `first_failure_junit(xml)` only can still count one as a kill.
  - The result file is read only when it is a regular file, and its size is checked first. A file that is refused, truncated or cannot be read is that mutant's row `JUNIT REFUSED`, and the run goes on.
  - Lock folder, the choice made: a private folder, not a keyed hash (a key would need its own protected file) and not a lock inside the database (the runner uses the standard library only and has no database driver).
  - Tests (`tests/test_mutation_runner_keywords.py`). A seeded test makes 60 random passwords and 8 forms of each as text from the tests (plain, slice, reversed, base64, hex, rot13, upper case, percent-encoded): 480 iterations. In each it takes 13 outputs from the real code paths (nine kinds of result row, the message of a failed first run, of a skipped first run and the two canary messages; 6,240 outputs) plus the `first_lines` entry of every row that has one. It checks that each output is one of the texts that can be built from the caller's side alone. A control switches the allowlist off and the same check must fail. One real run raises exceptions whose class NAME is the password reversed and in five more forms; on the previous version of the runner that test fails by showing the name. Further tests: every refusal of an address, a host that is almost a listed one (trailing dot, decimal, hex and short forms of `127.0.0.1`, an IPv4 address inside an IPv6 one, 300 seeded random hosts), a refused neighbour for every allowed key, the order of the refusals, the three cases of the table above, and one run through the real address check, the real lock folder and the allowlist together. No test switches the address check off any more: tests that need a made-up address name the made-up host `db.invalid` in `throwaway_hosts`, as a caller would.
  - The mutant list of the runner itself has 251 mutants (27 added in this round: the allowlist, the address check and its call, the key rules, the socket rule, the lock folder checks, three older gaps).
