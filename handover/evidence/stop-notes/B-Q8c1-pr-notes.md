## What changed in fix batch 1 (result review round 1 of head 7af13809)

- **Grant R17 is no wider than the code.** It was `{mount}/data/{path_prefix}*`, which also allowed every path below the prefix at any depth. It is now `{mount}/data/{path_prefix}+`: exactly one path part below the prefix, which is what the code reads (the code refuses a secret name with a `/` before it sends anything; a test pins that). The `path_prefix` setting always ends in `/`, so the `+` is a whole path part, the only form the server matches.
- **Each Vault grant must equal its one request**: the resource is the request's path with every object attribute replaced by its setting and the caller-chosen name replaced by `+`; the capability is the one the request's verb needs. A grant wider than, or different from, its request fails.
- **Guard gaps closed, by class (indirect or renamed access to a request call)**: `getattr` with a literal name (only names on a per-module list may be read so); a banned name that arrives through an import alias; `attrgetter`, `partial`, `vars`, `__dict__`, `__import__` and similar; every import of a declared module must be on that module's list (a new HTTP library fails until a person adds it); `open` and other raw HTTP calls, and any use of the HTTP opener, outside the one sending function; another module importing the Vault client, loading it by name, subclassing its classes or using `.authed`; a local variable named like a setting no longer counts as the setting.
- **Kubernetes query strings: refused by the guard.** What the code can send today: `limit` and `continue` on the two list requests (added by the paging wrapper) and `timestamps`, `sinceTime`, `limitBytes` on the log request. None changes the verb. Any other parameter name written in the module fails the guard, so `watch` and `follow` cannot be added under a declared operation id. The path of each request must also fit the path bound to its operation id, and each value put into a path must be `quote(name, safe="")` or a setting. No run-time behaviour was changed.
- **Renderer**: refuses control characters in every text of a literal, a key written twice, a brace or angle bracket that is not a placeholder, a placeholder left after filling, a namespace named twice, values longer than the limit, and well-formed values that name a reserved thing (decision: refuse, not warn, because such a value can never be right for this identity): a Vault mount starting with `sys`, `auth`, `identity` or `cubbyhole`; a namespace starting with `kube-`; the role names `cluster-admin`, `admin`, `edit`, `view` or one starting with `system`; the ServiceAccount `default`. A mount with a slash (a nested mount) stays accepted, because nested mounts are real. Limit: the page is not filled in by a command, so an operator who replaces placeholders by hand gets none of these refusals; the page says so.
- **`--check`** now runs every check of the data that the tests run and prints one line per problem with exit code 1 (rules of each literal, rules across kinds, source ids, a `POLICY` in a module nobody reads, a file that cannot be read or is not valid Python). Three checks stay tests only because they need the package imported or today's date: the requests written in a module equal the declared ones, the dated list of kinds, and "every placeholder is a real setting".
- **Page**: renamed to `docs/declared-permissions.md`, title "Declared permissions per backend kind". It states that a token holding only the generated policy does not represent sign-in through AppRole or Kubernetes roles, where the role and identity groups can add policies; which one server image is exercised and its licence; and the Kubernetes self-review exception (the namespaced Role cannot grant it).
- **Never-lists** gained: `patch` on the data path, `delete`, `undelete`, `subkeys` (Vault secrets); `byok-export`, `rotate`, `trim`, `restore` (Transit); a note on the optional hash-algorithm part of the sign path.
- **Sources file**: every row is pinned to a commit that is written in its URL (a row naming a branch is refused); the header says who read what and who produced each hash.
- **Engine tests**: clean-up (decision: teardown, best effort; a killed test still leaves objects, so the address must point at a throwaway server); admin control must answer 200 or 204; no token can appear in a failure message; one more refusal (a read two levels below the prefix).
- **Mutants**: 41 (were 14), and a CI step next to the stage mutants.
