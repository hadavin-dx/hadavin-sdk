## Refuse a public bind while a real service is configured; one function makes every server; one shared loopback check

promoted from the public demo repo duplicate-proof-lead-desk-n8n at 43110e7

### LEAD DECIDES BEFORE MERGE: Breaking change of the public signature of `approvals.receiver.serve`
Round 1 review (design F1, codebase M1) found that the refusal only ran when a caller passed `config=`; every existing call `serve(approvals, host="0.0.0.0")` was unchecked. The recommended fix is applied: `serve(approvals, *, config, host="127.0.0.1", port=8080, allow_public_bind_reason=None)`. `config` is required and keyword-only. A call without it raises `TypeError` (the old positional `serve(approvals, host, port)` too). A caller adds `config=<the Config the approvals were built with>`; an `Approvals` made by hand must now carry `config=` or `serve` refuses it. `Approvals.config` and the new `Approvals.overrides` cannot be assigned after construction. This is a breaking change of a public name; the lead decides before merge. (No caller exists in `src`, `demos` or `tools`; the only callers are tests.)

### What this adds, in plain words
A server that is started with a real service behind it (a real model, store, chat channel, secrets manager, read source, outside system, custom tool or check code, or a live outbound host) must stay on this computer. If it listened on an address that other computers can reach, any program that reaches the port could use the real service. This change adds one function that makes every server and asks that question first, and one shared answer to "is this address this computer?".

* `hadavin_sdk/bindguard.py`: `listen(config, host, port, handler, *, allow_public_bind_reason=None)` is the only place in the package that creates a server socket. It checks first, then builds. Any other host than `localhost` must be an IP address written out; `localhost` is bound as `127.0.0.1`; an IPv6 address gets an IPv6 socket; the standard server's own reverse name lookup of the bound address is replaced; after binding it checks the address the socket got.
* `real_services(config)` also counts `tool_modules` (`tools:<module>`), `check_modules` (`checks:<module>`) and every `egress_hosts` entry that is not loopback or cannot be read (`egress <host>`). Only the loaded `Config` is read; the docstring says what is not known.
* `allow_public_bind_reason`: the named, logged way past the refusal (one printable line, 10 to 200 characters after trimming; a short, empty or unusable reason is refused). It is a log line, not an audit record. Logged at WARNING on logger `hadavin_sdk.bindguard` with the services it lets through. No audit sink is reachable from `bindguard` without a new dependency, so the log line is the record (stated in the module docstring).
* `Approvals(..., config=None, overrides=None)` keeps the `Config` it was built from and the objects `build()` was handed (`channel`, `llm`, `detector`, `tools`, `sources`, `secrets`), both read-only; `serve` refuses with `BindRefused` unless `approvals.config is config`, and counts what the approvals really hold (round 2, below).
* `hadavin_sdk/netguard.py`: one list (`LOOPBACK_LITERALS`) and two named questions (`is_loopback_literal`, `is_loopback_host`) with a table in the docstring; `parse_ip_literal` and `is_localhost_name` are the shared steps; a zero in front of a number is refused by our own check (not left to the Python patch release).
* `backends/table.py`: one comment per `IN_PROCESS` kind (what it holds and why a bind does not widen it).
* The private copies of the three-spelling loopback list (`config.py`, `llm/openai_compat.py`, `backends/table.py`, `guard/http.py`, `actions/secrets_vault.py`) read `netguard`, as in round 0.
