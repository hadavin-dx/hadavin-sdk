**A step that does not finish in one session (rev 3, M3, F3): side-branch squash rule.** The builder works on a LOCAL branch `wip/P3a-2-<commit>` made from the current head of `core/P3a-2-clean`. WIP commits there may be red; their message starts "WIP". The side branch is never pushed. When the step is green, the builder runs `git checkout core/P3a-2-clean && git merge --squash wip/P3a-2-<commit> && git commit` (ONE commit, run G on it), and deletes the side branch after the lead has pushed. This rewrites nothing that was pushed; `core/P3a-2-clean` stays fast-forward only.

Commit messages end with the attribution lines the session reminder gives. The draft pull request stays the existing one for `core/P3a-2-clean` if there is one; otherwise the lead opens it. The lead pushes; the builder never does.

### 9.4 Work packages, each in sessions of at most 60 minutes (rev 3)

A session writes a checkpoint note every 30 minutes (done / next / blockers / commit SHA or side-branch SHA) and STOPS at 60 minutes: if the step is green, it commits on `core/P3a-2-clean`; if not, it commits "WIP" on the side branch and writes in the note which tests are red. A fresh builder resumes from the note. Estimates are guesses until the first package measures its own time; the lead re-plans after A1.
