## What the answers fix (the new rules, one line each)

- 49 minutes = the take program's own run only. The program computes it: 2630 s + 6 x lease, lease 45 s = 2630 + 270 = 2900 s = 48 min 20 s, rounded up to 49 min (answers 6, 14). It is not a stored setting. It covers posts, table and mail waits, final reads and the margin (answer 15 b, c, e, f, g). It does not cover the owner's typed answers before the window check (15 a) and has no term for a film pause (15 d).
- Latest start: the PROGRAM accepts a start up to 17:40Z (23:10 IST): it refuses a start that leaves less than 49 min before the stop time 18:29Z (23:59 IST); 18:29 minus 49 min = 17:40 (answer 7). The PLAN's latest start is 17:30Z (23:00 IST) because the 10-minute pause is outside the 49 and the program has no pause term: 17:30 + 49 min = 18:19, + 10 min = 18:29 (b2-2).
- Planning target: start by 12:00Z (17:30 IST). It is a comfort margin only: no later day exists on Mon 23 Nov and noon is not a promise of a rerun (b2-3; this replaces the reason "so a failed run still has the afternoon" of answer 16).
- Pause while filming: at most 10 minutes, outside the 49. The program does not enforce it; the limit is the owner's own clock alarm (answer 8, b2-2, b2-13). Typing before the window check is planned at 5 minutes, also outside the 49 (b2-6).
- No same-day rerun after a FAILED take; the next try is a new day inside the credit window, chosen by the owner (Thu 19 Nov default offer). Rehearsals and recording-defect retakes are allowed if the owner approves a new run yes (answers 6, 9; b2-4, b2-7).
- Clean-up and teardown: next morning (answer 17, b2-6). After `end` the program archives this take's three made-up contacts (see the correction above, UNVERIFIED); the owner's clean-up covers what is left.
- Notice: the program prints its own notice at every start; the lead sends the owner a message at least 3 hours before the start time the notice names (answer 10, b2-5).
- Obsolete: the 14-minute figure, and 18:15 and 18:14:40. A search of v4.2 found none of them (they sit in the owner sheet v5, see timing-check-a.md). Nothing to delete in v4.2.
