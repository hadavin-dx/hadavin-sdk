## 4. Lane file template (exact; the scripts parse it)
The lane file is `work/<lane>.md` and has exactly these sections, in this order, with these headings:
`# Lane <id>`, `## Coverage`, `## Components`, `## Stores`, `## Workflows`, `## Workflow walk`, `## Scripts`, `## Jobs`, `## Credentials`, `## Docs and tests and folders`, `## Findings`, `## Checkpoint`.
Empty section: one line `NONE FOUND: <what was searched>`. Not applicable cell: `N/A: <reason>`. Not found cell: `NOT FOUND`. Not run or runtime-only: `UNVERIFIED`. A blank cell is a defect.
- Coverage table header: `| path | bytes | status | note |`. Status is READ, SKIMMED or NOT-READ (rules in section 6). Lane Coverage tables never hold OWNER-ONLY rows: OWNER-ONLY paths are removed before the manifests are made and appear only in MASTER-MAP under `## Not visible or out of scope`; check (c) needs no change. One row per manifest file (the lead pre-fills the table from the manifest with NOT-READ; the lane changes rows as it reads).
- Full-row kinds (Stores S, Workflows W, Scripts X, Jobs J, Credentials K): header `| id | name | purpose | job owner | inputs | outputs | failure path | retry | timeout | idempotency | logs to | identity | tested where | used by | evidence | job keys |`. For K (credentials, NAME only) inputs, outputs, retry, timeout are `N/A: credential`.
- Short-row kinds (Components C, Ports P, Agents A, Repos R, Docs D, Tests T, Folders F): header `| id | name | purpose | evidence | job keys |`.
- Workflow walk: one row per node, header `| id | flow | node | type | trigger or branch | error path | retry or timeout | on kill or restart | on duplicate | on out-of-order | on empty or huge input | writes where | person sees | identity | evidence |`. Cells not decidable statically: `UNVERIFIED`.
- Findings header: `| id | claim type | severity | evidence | conflicts with | job key |`. Claim type is one of: duplicate, dead, idle, inconsistent, unverified, security, ops.
- Ids: `<lane>-<kind>-<nnn>` (for example `L2-S-001`; kinds C S W X J K P D T A R F, findings `FD`, walk rows `WK`). Rows of kinds P, A and R go in `## Components` (the kind letter in the id tells them apart); the lead splits them into MASTER-MAP sections on merge. A `job keys` cell holds one or more registry keys separated by `, ` (or `none`).
- Citation form (fixed everywhere): `path:line "quote"` in backticks; repo-relative path with no spaces, one line number, quote copied exactly from that line, 6 to 120 characters, no `"` or `|` inside the quote (use a shorter piece of the line). One or more citations per cell, separated by `; `. A source that is not in this box is written `NOT VISIBLE: <name>` (never a citation; the scripts skip it). `conflicts with` uses the same citation form, or `DECISION line <n>`, or `none`.
- Checkpoint: a section the lane rewrites (not appends) after every 25 files read: done, next, blockers. The lane writes its output file incrementally, so a stopped lane leaves a usable file with an accurate Coverage table.

### 5.1 MASTER-MAP.md

Same column headers as the lane template. Rows keep their lane ids; two lane rows for one thing are merged into the earlier id with `also: <other id>` in the purpose cell.
### 5.2 SWEEP.md
`## Findings` (all lane finding rows, severity-sorted, plus L6 findings with ids `L6-FD-nnn`), `## Fix plan` (header `| order | finding ids | action | owner | needs owner yes |`), `## Exceptions` (header `| id | what | reason | owner | removal trigger | decision line |`), `## Claims check` (header `| claim | where claimed | evidence | status |`, status PROVEN, UNVERIFIED or CONTRADICTED), `## Lessons` (bullets for checklist, memory, brief preamble), `## Counts` (findings per claim type and per severity).
Severity table: Blocker = contradicts DECISION-one-store.md, or touches money, credentials, mail or personal data, or a claim that is false; Major = a duplicate, dead or idle part, or an inconsistency, that costs time or confuses the take; Nit = wording or tidiness.
### 5.3 ONE-PLACE-TABLE.md
One block per job key in the registry: `## Job: <KEY>`, then a line `Owner: <name> | evidence | exception: none or <exception id>`, then a table `| copy | where | verdict | exception | proposal | owner yes needed | reason | evidence |`. The `Owner:` line is the single counted owner and is not a table row; the owner's own copy appears in the table with verdict OWNER. `exception` is `none` or an id from SWEEP.md `## Exceptions`. Then `## Seed check against DECISION` (six rows, each CONSISTENT or `CONFLICT WITH DECISION (line n)`), then the TAKE-REPO row.
Job-key registry (closed; only the lead may add): STORE (holds state), LOG (execution or audit record), FILTER (decides what enters: dedupe, validity, spam), COUNTER (counts used for caps or proof), RETRY (re-runs stuck or failed work), NOTICE (tells a person: mail, alert, screen), OTHER (a job a lane found that fits none; the lead decides to add a key or keep OTHER).
Owner-count rule: exactly one `Owner:` line per job block, and every table row with verdict NEEDED (a further place the take needs) must carry an `exception` id from SWEEP.md `## Exceptions` (DECISION keeps three stores by design: n8n data, `mf_leads`, `stage.journal`, the last as the stated exception). A NEEDED row with `exception` none is a defect. Verdict values: OWNER, NEEDED, CRM-COULD-DO, DUPLICATE, NOT-NEEDED.
Verdicts (precedence, first true wins): OWNER = the single owner of the job; NEEDED = a further place the take uses (exception rule above); CRM-COULD-DO = the client's CRM or a ready-made node would do the job, needs a dated source else UNVERIFIED; DUPLICATE = a second place does a job that already has an owner; NOT-NEEDED = nothing in this repo or in DECISION calls it (take repo not visible, so the verdict says `UNVERIFIED for take repo`). Every non-NEEDED row has a proposal: ARCHIVE (move to `archive/<same path>` after the owner says yes) or MERGE-INTO <owner>. Never delete.
Single owner = the one file or process that is the only writer of that job in the take per DECISION; where DECISION is silent, the place the final flow calls (evidence required).
DECISION seed (six rows): n8n internal data, Postgres `mf_leads`, desk SQLite plus portal (retired from the take), `stage.journal`, process logs, HubSpot and Gmail. A differing row is flagged `CONFLICT WITH DECISION (DECISION-one-store.md line n)`. Unverified items stay UNVERIFIED unless a raw file proves them.
### 5.4 Ledger rows (patches/ledger-rows.md)
Columns: `| id | source (file and finding id) | severity | area | summary | status | fixing artifact | verified-by | date |`. Status values OPEN, FIXED-UNVERIFIED, FIXED-VERIFIED, OWNER-ONLY, IMPOSSIBLE-NOW.
