## 4. Lane file template (exact; the scripts parse it)
The lane file is `work/<lane>.md` and has exactly these sections, in this order, with these headings:
`# Lane <id>`, `## Coverage`, `## Components`, `## Stores`, `## Workflows`, `## Workflow walk`, `## Scripts`, `## Jobs`, `## Credentials`, `## Docs and tests and folders`, `## Findings`, `## Checkpoint`.
Empty section: one line `NONE FOUND: <what was searched>`. Not applicable cell: `N/A: <reason>`. Not found cell: `NOT FOUND`. Not run or runtime-only: `UNVERIFIED`. A blank cell is a defect.
- Coverage table header: `| path | bytes | status | note |`. Status is READ, SKIMMED or NOT-READ (rules in section 6). One row per manifest file (the lead pre-fills the table from the manifest with NOT-READ; the lane changes rows as it reads).
- Full-row kinds (Stores S, Workflows W, Scripts X, Jobs J, Credentials K): header `| id | name | purpose | job owner | inputs | outputs | failure path | retry | timeout | idempotency | logs to | identity | tested where | used by | evidence | job keys |`. For K (credentials, NAME only) inputs, outputs, retry, timeout are `N/A: credential`.
- Short-row kinds (Components C, Ports P, Agents A, Repos R, Docs D, Tests T, Folders F): header `| id | name | purpose | evidence | job keys |`.
- Workflow walk: one row per node, header `| id | flow | node | type | trigger or branch | error path | retry or timeout | on kill or restart | on duplicate | on out-of-order | on empty or huge input | writes where | person sees | identity | evidence |`. Cells not decidable statically: `UNVERIFIED`.
- Findings header: `| id | claim type | severity | evidence | conflicts with | job key |`. Claim type is one of: duplicate, dead, idle, inconsistent, unverified, security, ops.
- Ids: `<lane>-<kind>-<nnn>` (for example `L2-S-001`; kinds C S W X J K P D T A R F, findings `FD`, walk rows `WK`).
- Citation form (fixed everywhere): `path:line "quote"` in backticks; repo-relative path with no spaces, one line number, quote copied exactly from that line, 6 to 120 characters, no `"` or `|` inside the quote (use a shorter piece of the line). One or more citations per cell, separated by `; `. A source that is not in this box is written `NOT VISIBLE: <name>` (never a citation; the scripts skip it). `conflicts with` uses the same citation form, or `DECISION line <n>`, or `none`.
- Checkpoint: a section the lane rewrites (not appends) after every 25 files read: done, next, blockers. The lane writes its output file incrementally, so a stopped lane leaves a usable file with an accurate Coverage table.

## 5. Merge layouts (the lead writes these three files; one source of truth is the lane files)
### 5.1 MASTER-MAP.md
Headings `## Components`, `## Stores`, `## Workflows`, `## Workflow walk`, `## Scripts`, `## Jobs`, `## Credentials`, `## Ports and hosts`, `## Agents and sessions`, `## Repos and branches`, `## Docs`, `## Tests`, `## Folders`, `## Not visible or out of scope` (TAKE-REPO and CORE rows, untracked files). Same column headers as the lane template. Rows keep their lane ids; two lane rows for one thing are merged into the earlier id with `also: <other id>` in the purpose cell.
### 5.2 SWEEP.md
`## Findings` (all lane finding rows, severity-sorted, plus L6 findings with ids `L6-FD-nnn`), `## Fix plan` (header `| order | finding ids | action | owner | needs owner yes |`), `## Exceptions` (header `| id | what | reason | owner | removal trigger | decision line |`), `## Claims check` (header `| claim | where claimed | evidence | status |`, status PROVEN, UNVERIFIED or CONTRADICTED), `## Lessons` (bullets for checklist, memory, brief preamble), `## Counts` (findings per claim type and per severity).
Severity table: Blocker = contradicts DECISION-one-store.md, or touches money, credentials, mail or personal data, or a claim that is false; Major = a duplicate, dead or idle part, or an inconsistency, that costs time or confuses the take; Nit = wording or tidiness.
### 5.3 ONE-PLACE-TABLE.md
One block per job key in the registry: `## Job: <KEY>`, then a line `Owner: <name> | evidence | exception: none or <exception id>`, then a table `| copy | where | verdict | proposal | owner yes needed | reason | evidence |`. Then `## Seed check against DECISION` (six rows, each CONSISTENT or `CONFLICT WITH DECISION (line n)`), then the TAKE-REPO row.
Job-key registry (closed; only the lead may add): STORE (holds state), LOG (execution or audit record), FILTER (decides what enters: dedupe, validity, spam), COUNTER (counts used for caps or proof), RETRY (re-runs stuck or failed work), NOTICE (tells a person: mail, alert, screen), OTHER (a job a lane found that fits none; the lead decides to add a key or keep OTHER).
Owner-count rule: exactly one owner row per job key, plus any further row that has an `exception:` entry pointing at an id in SWEEP.md `## Exceptions` (DECISION keeps three stores by design: n8n data, `mf_leads`, `stage.journal`, the last as the stated exception). Any other second NEEDED row is a defect.
Verdicts (precedence, first true wins): NEEDED = the owner of a job the take uses (with the exception rule above); CRM-COULD-DO = the client's CRM or a ready-made node would do the job, needs a dated source else UNVERIFIED; DUPLICATE = a second place does a job that already has an owner; NOT-NEEDED = nothing in this repo or in DECISION calls it (take repo not visible, so the verdict says `UNVERIFIED for take repo`). Every non-NEEDED row has a proposal: ARCHIVE (move to `archive/<same path>` after the owner says yes) or MERGE-INTO <owner>. Never delete.
Single owner = the one file or process that is the only writer of that job in the take per DECISION; where DECISION is silent, the place the final flow calls (evidence required).
DECISION seed (six rows): n8n internal data, Postgres `mf_leads`, desk SQLite plus portal (retired from the take), `stage.journal`, process logs, HubSpot and Gmail. A differing row is flagged `CONFLICT WITH DECISION (DECISION-one-store.md line n)`. Unverified items stay UNVERIFIED unless a raw file proves them.
### 5.4 Ledger rows (patches/ledger-rows.md)
Columns: `| id | source (file and finding id) | severity | area | summary | status | fixing artifact | verified-by | date |`. Status values OPEN, FIXED-UNVERIFIED, FIXED-VERIFIED, OWNER-ONLY, IMPOSSIBLE-NOW.

## 6. Coverage, scripts and checks
Statuses: READ = opened fully (files over 2000 lines in slices of 2000; the slices read are written in `note`). SKIMMED = headers, grep, or first and last slice; allowed ONLY for patch chains `lane3-fix-*`, `checkpoint-*`, run logs under `kill/data/runs/**`, scan outputs, screenshots, and files over 200 KB (searched by job key, section headers read). Anything else must be READ or stays NOT-READ. A NOT-READ file is never reported as "nothing found".
Time box proxy: lanes have no clock. The lead stops a lane at 60 minutes wall clock; the lane's own file (written incrementally) is then the result; unread files stay NOT-READ and the lane is marked PARTIAL in `## Coverage`. The lead may start ONE continuation lane per PARTIAL lane for its NOT-READ list.
Job-key grep terms for L6 and L5b: STORE (sqlite, postgres, journal, .db, INSERT, table), LOG (log, audit, execution), FILTER (dedupe, duplicate, valid, spam, claim), COUNTER (count, cap, budget, limit), RETRY (retry, recovery, backoff, stuck, sweep), NOTICE (mail, smtp, alert, notify, slack).
Scripts (lead writes, evidence runner runs):
- `tools/partition.py <root> <out_dir>`: manifest per lane, exit 1 on REMAINDER or double match. Tests (exist, 9 pass): no rule fails, one lane per file, double match detected, counts add up. Needs an update for L5a/L5b (lead).
- `tools/check_citations.py <root> <out.tsv> <files...>`: extracts every citation in backticks matching the fixed form from markdown table cells and text; resolves paths against the repo root; match rule = quote trimmed is an exact substring of the line; results FOUND, LINE-DRIFT (found within 5 lines), MISMATCH, NO-FILE; a line shorter than the quote is MISMATCH; lines `NOT VISIBLE:` are skipped; output columns `file, path, line, result`; exit 1 unless every result is FOUND. Tests (6, exist): found, missing file, drift within 5, mismatch, far line is mismatch, binary file does not crash.
- `tools/scan_outputs.py <system-map dir>` (new): (a) empty-field scan: any blank cell or missing section heading in lane files and the three outputs fails; (b) owner-count per job key per the rule in 5.3; (c) coverage: every manifest path has a status READ or SKIMMED or NOT-READ and the PARTIAL flag matches; (d) secret scan over all of handover/system-map/ including work/: if `gitleaks` is installed run `gitleaks detect --no-git --source <dir> --config .gitleaks.toml`, else regexes: `AKIA[0-9A-Z]{16}`, `-----BEGIN [A-Z ]*PRIVATE KEY-----`, `ghp_[A-Za-z0-9]{36}`, `xox[baprs]-[A-Za-z0-9-]{10,}`, `sk-[A-Za-z0-9]{20,}`, `[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[a-z]{2,}` (personal e-mail); pass = zero findings except the literal `AKIAIOSFODNN7EXAMPLE`. Tests (new, unittest): blank cell found, missing heading found, second NEEDED without exception fails, exception passes, planted fake key found, allowed literal passes.
Correction loop: after the lead merge, run check_citations. The lead fixes LINE-DRIFT (correct the line) and removes or corrects MISMATCH and NO-FILE, then reruns once. If any non-FOUND remains after that one pass, the lead lists them in REPORT.md and the plan's result review treats each as a Major.
Secrets and personal data: a lane that meets a value that looks like a key, token, password or personal e-mail address records `path:line` and the TYPE only, never the value. Credentials are listed by NAME only.

## 8. EGM sequence and stop rules
1. Plan review: egm:egm-review-loop (Skill) with fresh egm:* reviewer agents (Agent calls with model set), then egm:egm-resolve (Skill, opus); repeat review, resolve for up to 3 rounds; stop after a round with no Blocker and no Major. 2. Build: lanes, then L6, then lead merge (time box 40 minutes). If partition.py still exits non-zero after the lead's fix, do not launch. If a lane yields zero rows for a kind, its section says `NONE FOUND: <what was searched>`.
3. EVIDENCE RUNNER: a separate sonnet agent whose brief says "EVIDENCE RUNNER": runs partition.py, check_citations.py, scan_outputs.py and the unit tests, saves raw output to work/evidence-<n>.md, never judges.
4. Result review: fresh egm:* agents with different lenses: codebase-details (are the cited facts true), zoom-out (duplicates, dead parts, verdict size), comprehension (can a non-technical reader follow), design (does the map match DECISION-one-store.md); each reads the outputs and the evidence, never the author's verdict.
5. egm:egm-resolve (Skill), fix every Blocker and Major, repeat step 4 for at most 2 rounds; Nits fixed in the same push. Then egm:egm-drift-report before FINAL.
No heavy jobs. Max 6 agents at once.
