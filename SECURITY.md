# Security

Please report a suspected vulnerability privately through GitHub: the **Security** tab of this repository,
**Report a vulnerability**. If that button is not shown, open an issue titled "Security contact request" with no
details, and a private channel will be arranged. Do not post vulnerability details publicly.

Reports are answered within 5 working days.

## Stated limits of redaction (reviewed, not bugs)

Redaction is pattern based and treats the end of a value the way the redactor's own value pattern does. Two consequences are known and stated:

- A secret value that itself contains a plain (not encoded) space, `;`, `,` or `&` (for example `password="my secret phrase"`) is masked only up to that character in pass one: its tail is shown, because by the redactor's definition the value ended there. Put such a secret in quotes handled by the pattern, or do not hand it to a tool.
- A form-encoded `;` or `&` inside a value is ambiguous: `password%3Dab%3Bzq9` can be one secret or a key and a value followed by more text. The redactor decodes it, masks what its value pattern reaches, and keeps what pass one masked whole when the decoded view would mask less; it cannot know which reading the sender meant.
- A secret written with spaces between its characters (`A K I A ...`), with or without a hidden character between them, is masked in three places, and only there. (1) A value the system already holds (a secret the run found, or a value handed to a tool) of 12 or more characters is looked for with the spaces taken out, on the direct `redact` call, in a run (`redact_untrusted`) and in a tool result; the gap between its characters may be any spaces, tabs or line breaks. (2) A value the system does not hold, in a run only, is masked when a stretch of 10 or more single-character words (any spaces, tabs or line breaks between them) holds at least 6 different characters and, with the spaces taken out, reads as a secret: a value the patterns know by its shape (a key with a known prefix, a token, a private key block), or a value written after a key word such as `password=` (the 64 characters before the stretch are read with it). A value glued to its key (`key=A K I A ...`), trailing punctuation after the last character and up to three one-letter words in front are handled. A text with more than 32 such stretches is withheld whole (nothing is shown), never skipped. (3) NOT covered, by design: a value of no pattern's shape (for example 17 random letters and digits that no pattern and no key word names) written with spaces, unless the system already holds that value; reading it would mean masking every list of single characters, and there is no rule that tells the two apart. Also not covered: a known value shorter than 12 characters; an unknown value on the direct `redact` call or in a tool result (only a known one is); a value spaced out between only some of its characters; a stretch of fewer than 10 words or with fewer than 6 different characters. Measured on 2026-11-12 (`handover/evidence/PRH/b9/spaced_rate.py`): of 86,698 lines of the repository's own text, 19 hold a stretch of spaced single characters and 4 change; those 4 are the example key written out with spaces in saved test output, so they are correct finds. Of 1,933,591 lines of the Python 3.13 library, 71 hold such a stretch and 0 change. Tests: `tests/test_prh_b9.py`, `tests/test_prh_b8.py`, `tests/test_prh_b7.py`. A combining mark (U+0301) inside a value is not a hidden item either: it makes a different string and is left as written.
- Hidden-character and spaced-out redaction: what it costs and what is left (measured 2026-11-12, batch 9; raw output in `handover/evidence/PRH/b9/`). Withholding instead of showing costs availability: of 7,947 lines of ordinary repository text (README, CHANGELOG, SECURITY, docs and source, grouped in 8-line texts, with colour codes and invisible characters added), the tool path withholds 138 (1.74 percent) on this head and on the previous head, and 72 (0.91 percent) on main, which showed the secret instead. The price is accepted because the alternative is a readable secret. On the builder's 3,000 hostile texts, in which a hidden item cuts a value, 155 are withheld on the tool path (5.2 percent) and 14 on the direct `redact` call (0.5 percent). A secret written with a backslash-e spelling of ESC (`\e[0m`) is read like `\x1b`. NOT fixed in this batch, each with its reason and next step: (a) the two halves of one value placed apart with ordinary words between them (261 of the evidence runner's 4,691 texts) each stay readable; masking every 8-character stretch of every known value would withhold 898 of the 3,000 hostile texts (30 percent), so the owner decides (question `q-prh-piece-masking`); (b) a spelled-out escape (`\x1b`, `\033`, `\e`) followed by a title string that a raw bell closes leaves the key readable (the same before this batch); next step: build the decoded readings also from the text with its hidden items intact; (c) 3 of the 4,691 texts, in which each lone ESC in one value must eat or keep its letter on its own; next step: a gap pattern that allows ESC and one optional letter between any two characters; (d) a hyphen used as the gap between characters of a spaced-out value. Cost bound: a text that needs more than 24 reading passes is refused (nothing is shown); the seeded search of 600 texts needs at most 16, and a 50-second search that mixes every kind of cut and spelling reaches 24 in about 43 percent of its texts, on this head and on the previous head alike.

Control that does not depend on these limits: a tool is not handed a secret it does not need (least privilege).

## Hidden characters and escape sequences (pull request H)

Redaction reads text after taking out the control characters and terminal escape sequences a reader does not see, so a secret that a colour code cuts is masked like the uncut secret. This does not imitate a terminal (a backspace overstrike or a carriage-return overwrite is not played), so `AKIA` + `X` + backspace + the rest of a key is not read as the whole key. A key or value with a tab, form feed, line separator or line break inside it is masked only up to that character; a word glued in front of a cut value is not split off; look-alike letters and base64, hex or quoted-printable spellings of pattern-shaped values are not masked. A value that main removed only because it stood after an escape string that main read as never ending (a string closed by the C1 string terminator U+009C, which main did not read) is now kept as text and is masked only if the plain value would be masked; a string that really never ends is still removed to the end of its line, or of the text, as before. A text that needs more than the counted number of passes (`defaults.MAX_REDACT_PASSES`), that cannot be read within the time budget, or whose two readings of a cut escape sequence cannot be merged, is refused, not shown. The pinned test rows are in `tests/fixtures/prh_regressions.json` (`NOT_PROMISED` in `tests/test_prh_regressions.py` names each one and its reason).
