# Security

Please report a suspected vulnerability privately through GitHub: the **Security** tab of this repository,
**Report a vulnerability**. If that button is not shown, open an issue titled "Security contact request" with no
details, and a private channel will be arranged. Do not post vulnerability details publicly.

Reports are answered within 5 working days.

## Stated limits of redaction (reviewed, not bugs)

Redaction is pattern based and treats the end of a value the way the redactor's own value pattern does. Two consequences are known and stated:

- A secret value that itself contains a plain (not encoded) space, `;`, `,` or `&` (for example `password="my secret phrase"`) is masked only up to that character in pass one: its tail is shown, because by the redactor's definition the value ended there. Put such a secret in quotes handled by the pattern, or do not hand it to a tool.
- A form-encoded `;` or `&` inside a value is ambiguous: `password%3Dab%3Bzq9` can be one secret or a key and a value followed by more text. The redactor decodes it, masks what its value pattern reaches, and keeps what pass one masked whole when the decoded view would mask less; it cannot know which reading the sender meant.
- A secret written with spaces between its characters (`A K I A ...`), with or without a hidden character between them, is masked in three places, and only there. (1) A value the system already holds (a secret the run found, or a value handed to a tool) of 12 or more characters is looked for with the spaces taken out, on the direct `redact` call, in a run (`redact_untrusted`) and in a tool result; the gap between its characters may be any spaces, tabs or line breaks. (2) A value the system does not hold, in a run only, is masked when a stretch of 10 or more single-character words (any spaces, tabs or line breaks between them) holds at least 6 different characters and, with the spaces taken out, reads as a secret: a value the patterns know by its shape (a key with a known prefix, a token, a private key block), or a value written after a key word such as `password=` (the 64 characters before the stretch are read with it). A value glued to its key (`key=A K I A ...`), one of the wrapper characters ` * _ ~ < > { } | glued to the first or last character (a code span, bold or italic), trailing punctuation after the last character and up to three one-letter words in front are handled. What may stand between the single characters: white space and invisible characters, for any value; for a value the system does NOT hold, in a run, also one of `- _ . , | / : ;` (`A-K-I-A`, `A, K, I, A`). For a value the system DOES hold, a visible separator such as a hyphen is not a gap, so `A-K-I-A ...` written from a held value is NOT found (pinned by a test). A gap written encoded (`A%20K%20I%20A ...`) is read too: the run rule is applied to each decoded view of the text, so a value of a pattern's shape is masked; an unknown value of no pattern's shape is still not read. Cost bounds: a run is read at most 4 times (as it stands and without its first one, two and three words); the characters those reads scan are counted before each read, and a text that needs more than 200,000 characters of reading is withheld whole; a text with more than 32 such stretches is withheld whole (nothing is shown), never skipped; the search for held values is one pass over the text (an automaton), whatever the values share. (3) NOT covered, by design: a value of no pattern's shape (for example 17 random letters and digits that no pattern and no key word names) written with spaces, unless the system already holds that value; reading it would mean masking every list of single characters, and there is no rule that tells the two apart. Also not covered: a known value shorter than 12 characters; an unknown value on the direct `redact` call or in a tool result (only a known one is); a value spaced out between only some of its characters; a stretch of fewer than 10 words or with fewer than 6 different characters. Measured in batch 10 (`handover/evidence/PRH/f01a9f8f/spaced_rate.py`, output in `handover/evidence/PRH/b10/`): of 90,506 lines of the repository's own text and saved evidence (495 files), 29 hold a stretch of spaced single characters and 11 change; all 11 are the example key written out with spaces inside saved test-failure output under `handover/`, so they are correct finds, and none lies outside `handover/`. Of 1,933,591 lines of the Python 3.13 library (4,695 files), 71 hold such a stretch and 0 change. Not covered either: a value of 4 characters or more that a reading masked is checked for standing in the output (the final guard), but a value of fewer than 4 characters is not. Tests: `tests/test_prh_b10.py`, `tests/test_prh_b9.py`, `tests/test_prh_b8.py`, `tests/test_prh_b7.py`. A combining mark (U+0301) inside a value is not a hidden item either: it makes a different string and is left as written.
- Hidden-character and spaced-out redaction: what it costs and what is left (measured 2026-11-12, batch 9; raw output in `handover/evidence/PRH/b9/`). Withholding instead of showing costs availability. Ordinary text: of 7,950 texts made from the repository's own text (README, CHANGELOG, SECURITY, docs and source, in groups of 8 lines, with colour codes and invisible characters added, no cut secret in any of them, and one made-up handed-out value that is not in the text), the tool path withholds 126 (1.58 percent) on this head, 128 (1.61 percent) on the previous head (ea6dbdaf), 126 on the batch 9 head (f01a9f8f) and 69 (0.87 percent) on main. Every one of these is a false alarm, not a protected secret: this head withholds 57 texts more than main (0.72 percentage points of ordinary text). The batch 9 sentence that said main "showed the secret instead" was wrong (the 72 of main were false alarms on a corpus with no cut secret) and is withdrawn. Whether this price is accepted is the owner's choice (question `q-prh-piece-masking`). Hostile text: on the evidence runner's 5,455 generated texts (a secret cut, spaced out or split; the generator is `handover/evidence/PRH/f01a9f8f/own_fuzz_b9.py`), a readable 8-character stretch of the planted secret stays in 3,515 texts on main, 611 on ea6dbdaf, 321 on the batch 9 head and 321 on this head; withheld: 0, 375, 465 and 467 (main, ea6dbdaf, the batch 9 head and this head, in that order); errors raised: 0, 2, 2 and 0. No text is readable on this head that is not readable on main, on ea6dbdaf and on the batch 9 head (per-text comparison in `handover/evidence/PRH/b10/`). A secret written with a backslash-e spelling of ESC (`\e[0m`, `\e(B`) is read like `\x1b`; backslash-e is read this way only when a bracket or a parenthesis follows, so a Windows path such as `C:\env` is left as written. NOT fixed in this batch, each with its reason and next step: (a) the two halves of one value placed apart with ordinary words between them (261 of the evidence runner's 4,691 texts) each stay readable; masking every 8-character stretch of every known value would withhold 898 of the 3,000 hostile texts (30 percent), so the owner decides (question `q-prh-piece-masking`); (b) a spelled-out escape (`\x1b`, `\033`, `\e`) followed by a title string that a raw bell closes leaves the key readable (the same before this batch); next step: build the decoded readings also from the text with its hidden items intact; (c) 3 of the 4,691 texts, in which each lone ESC in one value must eat or keep its letter on its own; next step: a gap pattern that allows ESC and one optional letter between any two characters; (d) a known value (one the system already holds) written with a hyphen between its characters; an unknown value inside a run is read with a hyphen between its characters (see the spaced-out bullet above). Cost bound: a text that needs more than 24 reading passes is refused (nothing is shown); the seeded search of 600 texts needs at most 16, and a 50-second search that mixes every kind of cut and spelling reaches 24 in about 43 percent of its texts, on this head and on the previous head alike.

Control that does not depend on these limits: a tool is not handed a secret it does not need (least privilege).

## Hidden characters and escape sequences (pull request H)

Redaction reads text after taking out the control characters and terminal escape sequences a reader does not see, so a secret that a colour code cuts is masked like the uncut secret. This does not imitate a terminal (a backspace overstrike or a carriage-return overwrite is not played), so `AKIA` + `X` + backspace + the rest of a key is not read as the whole key. A key or value with a tab, form feed, line separator or line break inside it is masked only up to that character; a word glued in front of a cut value is not split off; look-alike letters and base64, hex or quoted-printable spellings of pattern-shaped values are not masked. A value that main removed only because it stood after an escape string that main read as never ending (a string closed by the C1 string terminator U+009C, which main did not read) is now kept as text and is masked only if the plain value would be masked; a string that really never ends is still removed to the end of its line, or of the text, as before. A text that needs more than the counted number of passes (`defaults.MAX_REDACT_PASSES`), that cannot be read within the time budget, or whose two readings of a cut escape sequence cannot be merged, is refused, not shown. The pinned test rows are in `tests/fixtures/prh_regressions.json` (`NOT_PROMISED` in `tests/test_prh_regressions.py` names each one and its reason).
