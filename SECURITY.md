# Security

Please report a suspected vulnerability privately through GitHub: the **Security** tab of this repository,
**Report a vulnerability**. If that button is not shown, open an issue titled "Security contact request" with no
details, and a private channel will be arranged. Do not post vulnerability details publicly.

Reports are answered within 5 working days.

## Stated limits of redaction (reviewed, not bugs)

Redaction is pattern based and treats the end of a value the way the redactor's own value pattern does. Two consequences are known and stated:

- A secret value that itself contains a plain (not encoded) space, `;`, `,` or `&` (for example `password="my secret phrase"`) is masked only up to that character in pass one: its tail is shown, because by the redactor's definition the value ended there. Put such a secret in quotes handled by the pattern, or do not hand it to a tool.
- A form-encoded `;` or `&` inside a value is ambiguous: `password%3Dab%3Bzq9` can be one secret or a key and a value followed by more text. The redactor decodes it, masks what its value pattern reaches, and keeps what pass one masked whole when the decoded view would mask less; it cannot know which reading the sender meant.
- A secret written with spaces between its characters (`A K I A ...`), with or without a hidden character between them, is masked in three places, and only there. (1) A value the system already holds (a secret the run found, or a value handed to a tool) of 12 or more characters is looked for with the spaces taken out, on the direct `redact` call, in a run (`redact_untrusted`) and in a tool result; the gap between its characters may be any spaces, tabs or line breaks. (2) A value the system does not hold, in a run only, is masked when a stretch of 10 or more single-character words (any spaces, tabs or line breaks between them) holds at least 6 different characters and, with the spaces taken out, reads as a secret: a value the patterns know by its shape (a key with a known prefix, a token, a private key block), or a value written after a key word such as `password=` (the 64 characters before the stretch are read with it). A value glued to its key (`key=A K I A ...`), any character that is not a letter, a digit or a combining mark (Unicode categories L, N and M, any script) glued to the first or last character is a wrapper and is no part of the value (a code span, bold, quotes of any language such as curly, angle and corner quotes, a currency sign, a hash, an at sign, a slash, a backslash, a percent sign, a dash, a bracket); a letter, a digit or a combining mark glued in front of the first character makes the run part of a longer word, so no run is read from there; trailing punctuation after the last character and up to three one-letter words in front are handled. What may stand between the single characters: white space and invisible characters, for any value; for a value the system does NOT hold, in a run, also one of `- _ . , | / : ;` (`A-K-I-A`, `A, K, I, A`). For a value the system DOES hold, a visible separator such as a hyphen is not a gap, so `A-K-I-A ...` written from a held value is NOT found (pinned by a test). A gap written encoded (`A%20K%20I%20A ...`) is read too: the run rule is applied to each decoded view of the text, so a value of a pattern's shape is masked; an unknown value of no pattern's shape is still not read. Cost bounds: a run is read at most 4 times (as it stands and without its first one, two and three words); the characters those reads scan are counted before each read, over every reading of the text in one call (as written and each decoded view together, not each view alone), and a text that needs more than 200,000 characters of reading is withheld whole; a text with more than 32 such stretches is withheld whole (nothing is shown), never skipped; the search for held values is one pass over the text (an automaton), whatever the values share. (3) NOT covered, by design: a value of no pattern's shape (for example 17 random letters and digits that no pattern and no key word names) written with spaces, unless the system already holds that value; reading it would mean masking every list of single characters, and there is no rule that tells the two apart. Also not covered: a known value shorter than 12 characters; an unknown value on the direct `redact` call or in a tool result (only a known one is); a value spaced out between only some of its characters; a stretch of fewer than 10 words or with fewer than 6 different characters. Measured in batch 11 (`handover/evidence/PRH/b11/spaced_rate.py`, output in `handover/evidence/PRH/b11/`): of 92,727 lines of the repository's own text and saved evidence (516 files, the tree at 5c430b6a), 50 hold a stretch of spaced single characters and 23 change; none of the 23 lies outside `handover/` (the 15 the file lists are saved test-failure output that holds the example key written with spaces). Of 1,933,591 lines of the Python 3.13 library (4,695 files), 75 hold such a stretch and 0 change. Not covered either: a value of 4 characters or more that a reading masked is checked for standing in the output (the final guard), but a value of fewer than 4 characters is not. Tests: `tests/test_prh_b11.py`, `tests/test_prh_b10.py`, `tests/test_prh_b9.py`, `tests/test_prh_b8.py`, `tests/test_prh_b7.py`. A combining mark (U+0301) inside a value is not a hidden item either: it makes a different string and is left as written.
- Hidden-character and spaced-out redaction: what it costs and what is left (measured 2026-11-12, batch 12; raw output in `handover/evidence/PRH/b12/`, figures in `numbers.txt`; every figure here is a line of that file, and a test compares them). Withholding instead of showing costs availability. Ordinary text: of 22,935 texts made from the repository's own text at 242dfd66 (README, CHANGELOG, SECURITY, docs, source and earlier evidence files, in lines cut to 60 characters, every seventh line, with colour codes and invisible characters added; no cut secret in any of them, and one made-up handed-out value that is not in the text), the tool path withholds 83 (0.36 percent) on this head, 83 on 242dfd66 (the previous head), 83 on ea6dbdaf and 69 (0.30 percent) on main. Every one of these is a false alarm, not a protected secret: this head withholds 14 texts more than main (0.06 of a percentage point of ordinary text), and batch 12 itself added none to the previous head. These figures cannot be compared with those of earlier batches, because the corpus grew (earlier batches used 21,783 texts). A text with a cut-up opener (an ESC P string) and one plain copy of the handed-out value is withheld in 22,935 of 22,935 texts on this head and on 242dfd66, 107 on ea6dbdaf and 69 on main; the same with a secret made of everyday letter groups: 283 (1.23 percent) on this head and on 242dfd66, 107 on ea6dbdaf and 69 on main. Hostile text: on the evidence runner's 5,455 generated texts (a secret cut, spaced out or split; the generator is `handover/evidence/PRH/b12/own_fuzz_b9.py`), a readable 8-character stretch of the planted secret stays in 3,515 texts on main, 611 on ea6dbdaf, 321 on 242dfd66 and 321 on this head; withheld: 0, 375, 467 and 467 (main, ea6dbdaf, 242dfd66 and this head, in that order); errors raised: 0, 2, 0 and 0. This set was written before batch 12 and does not hold the shapes batch 12 fixed (a backslash-e inside a value, a gap character glued to a spaced run, a crash of the redactor), so it shows no change between the last two heads; those shapes are covered by the tests of batch 12 (a grid of 63 spellings of a handed-out value among them). No text is readable on this head that is not readable on main, on ea6dbdaf or on 242dfd66 (per-text comparison in `handover/evidence/PRH/b12/splitleak-diff.txt`). On the seeded 3,000 texts of the second fuzz set: strict withheld 161 on this head, 156 on 242dfd66, 155 on ea6dbdaf and 0 on main; readable windows 0, 0, 0 and 1,045. The 5 more withheld texts than on 242dfd66 come from the change that a key that is only a piece of a held identifier counts as new (issue 3 of round 11); a sample of the 6 texts that differ holds a key cut by an escape sequence or an invisible character; the cost is stated, not hidden. A secret written with a backslash-e spelling of ESC (`\e[0m`, `\e(B`) is read like `\x1b`. Backslash-e is read as ESC in exactly these places (batch 12 wording): directly before `[`, `]`, `(` or `)`, anywhere; glued inside a word, meaning a character that is no space and no backslash on each side (`qZ7k\eM3vR`, `Ab3+\edE6/`), unless a backslash follows within 12 characters or the word is a Windows path word (a drive letter, a colon and a backslash, then every character up to the next space: `C:\Users\err\x`, `C:\env\etc`), where the spelling is a folder name and is left as written; before 12 or more letters, digits, `_` or `-` in a row, with anything in front, and with 6 or more of them on each side; and one such character away from another backslash-e (`q\eZ\e7`). It is read before `P`, `X`, `^` or `_` only when one of those rules holds (for example 12 or more token characters follow), not because of the letter; at the end of the text it is left as written. A Windows path that is not written with a drive letter and has a long name after a backslash-e may still be read and then takes the heavier path: that only adds one reading of the text. Before batch 11 only the first place was read, and a secret with a literal backslash-e spelled into it (in the middle, in front, or between every character) stayed readable. Spaced-out runs: on the repository's own text (552 files, 95,967 lines) the reader finds 84 lines with a spaced run and changes 50 of them, all of them evidence files that quote the made-up example key spaced out, none outside `handover`; on the Python 3.13 standard library (4,695 files, 1,933,591 lines) it finds 75 and changes 0. A gap character (a variation selector, U+034F, a filler letter) glued in front of a spaced run no longer makes the run start two characters late (batch 12). A letter, digit or accent glued in front of a spaced run still makes the run part of a longer word (the rule of batch 11), so the run is read from one character later; seen in a probe, no count measured, not changed in this batch; whether to change that rule is the owner's decision. Crash rule (batch 12): a crash of the redactor (`RedactorCrash`) stops the run in every place that catches errors of redaction (the approval summary, the golden-input gate of the evals, the injection check, the tool-result and document screens, the approval request hook, and the tick step message, which shows a fixed note and still records the step as failed). It is never read as a limit and never swallowed. Forged-marker downgrade, stated plainly: a short message (an exception text, a validation error, a line of an approval card) that still holds a redaction marker or a placeholder the call did not issue is shown as a fixed note, not as its own text (`safe_head` turns the refusal into the note); the reader loses that message, nothing is shown that should be hidden. NOT fixed in this batch, each with its reason and next step: (a) the two halves of one value placed apart with ordinary words between them (the 261 split texts that stay readable on this head; 277 on main) each stay readable; masking every 8-character stretch of every known value would withhold many more ordinary texts and no figure for that cost has been measured, so the owner decides (question `q-prh-piece-masking`); (b) a spelled-out escape (`\x1b`, `\033`, `\e`) followed by a title string that a raw bell closes leaves the key readable (the same before this batch); next step: build the decoded readings also from the text with its hidden items intact; (c) a few texts, in which each lone ESC in one value must eat or keep its letter on its own; next step: a gap pattern that allows ESC and one optional letter between any two characters; (d) a known value (one the system already holds) written with a hyphen between its characters; an unknown value inside a run is read with a hyphen between its characters (see the spaced-out bullet above); (e) a stop of later reads once an earlier read found nothing (round 10 group 5) is not built in this batch and was wrongly filed under the owner's questions: it limits reads and is not piece masking; next step: measure how many reads a run takes and build the stop. Cost bound: a text that needs more than 24 reading passes is refused (nothing is shown); the time budget is 6 seconds of CPU time of the calling thread (batch 12; it was wall time, so a slow or busy machine could refuse an ordinary text). The share of texts that reach 24 passes was measured at batch 9 on code that has changed since and has not been measured again; no figure is stated.

Control that does not depend on these limits: a tool is not handed a secret it does not need (least privilege).

## Hidden characters and escape sequences (pull request H)

Redaction reads text after taking out the control characters and terminal escape sequences a reader does not see, so a secret that a colour code cuts is masked like the uncut secret. This does not imitate a terminal (a backspace overstrike or a carriage-return overwrite is not played), so `AKIA` + `X` + backspace + the rest of a key is not read as the whole key. A key or value with a tab, form feed, line separator or line break inside it is masked only up to that character; a word glued in front of a cut value is not split off; look-alike letters and base64, hex or quoted-printable spellings of pattern-shaped values are not masked. A value that main removed only because it stood after an escape string that main read as never ending (a string closed by the C1 string terminator U+009C, which main did not read) is now kept as text and is masked only if the plain value would be masked; a string that really never ends is still removed to the end of its line, or of the text, as before. A text that needs more than the counted number of passes (`defaults.MAX_REDACT_PASSES`), that cannot be read within the time budget, or whose two readings of a cut escape sequence cannot be merged, is refused, not shown. The pinned test rows are in `tests/fixtures/prh_regressions.json` (`NOT_PROMISED` in `tests/test_prh_regressions.py` names each one and its reason).
