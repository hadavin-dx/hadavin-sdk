# Changelog

## Unreleased

### Upgrade steps
- **Breaking: the first stage is now called `demo`; `environment: dev` is refused.** The stages are exactly `demo`, `pilot` and `prod`. A config that says `environment: dev` stops at start with "environment: dev was renamed to demo; write environment: demo (allowed values: demo, pilot, prod)" (shown beside any other problem found in the same file, and also for `Dev`, `DEV` and spellings with spaces, which are refused all the same); any other value (`Demo`, `staging`, `uat`, an empty value) is refused too, and values are never tidied or guessed. To upgrade: (1) change `environment:` in your config to `demo`; (2) if your code imports `backends.table.DEV_ONLY`, import `DEMO_ONLY` instead (same six kind pairs, no old name kept); (3) a project label such as `uat` is not a stage: map it to one stage in your own config. Also: the pilot and prod checks (`deferred.py`, `registry.py`, `app.py`) now ask one function, `hadavin_sdk.stages.is_live(environment)`, which treats anything that is not exactly `demo` as live; the prod-only rules (no local key file, a retention-agreed anchor) ask `hadavin_sdk.stages.is_prod(environment)`, which is true for `prod` and for any value that is not a stage. `STAGES`, `is_live` and `is_prod` live in the new leaf module `hadavin_sdk/stages.py`, not in `config.py`; the list `deferred.LIVE` is removed. The redactor no longer sweeps the words `demo` and `pilot` as a name (it already skipped `prod`), but a secret that reads `demo` is still swept. No stage is stored today; the first change that stores one must map an old `dev` value to `demo` on read, for display only and never for a guard decision, and add a test through that real read site.
- **Breaking for pilot and prod: `app.build` refuses the six keyword arguments that exist for tests, and `run_tick` refuses `now=` and `steps=`.** In short: a pilot or prod process can no longer be handed a made-up part, time or step list by accident. "Pilot and prod" below always means every stage value that is not exactly `demo`. These refusals stop a test object that arrives in a live process by accident. They do not stop hostile code that already runs inside the same process (see "What is not covered" below). The stage checks of these refusals (`app.py`, and `runtime/tick.py` for the two keywords of `run_tick`) ask `hadavin_sdk.stages.is_live`, as described under the stage rename below.
  - **The six keywords of `build`.** `secrets=`, `channel=`, `detector=`, `llm=`, `clock=` and `timeout_s=` hand `build` a ready-made object (or a value) in place of a part that is set up in the configuration. A build that is given one of them outside demo stops with a `ConfigError`: "channel= is for tests; configure backends.channel in pilot and prod" (the same sentence for `secrets`, `detector` and `llm`), or "clock= is for tests; it is refused in pilot and prod" (the same for `timeout_s`). With several given, only the first in the order secrets, channel, detector, llm, clock, timeout_s is named. "Given" means not None, so an object that is falsy is refused too. To upgrade: remove the keyword from your pilot and prod start-up code and configure the backend under `backends:` in the config (the executor timeout is `executor_timeout_s`; pilot and prod have no executor). `clock`'s default is now `None` (the real clock is still used when none is given; passing the real clock by hand, `clock=models.now`, is refused in pilot and prod like any other given clock). `hold_run_ids=` stays allowed everywhere: it is a production hook.
  - **The tick: `now=` and `steps=`.** `runtime.tick.run_tick(app, now=...)` is refused the same way ("now= is for tests; it is refused in pilot and prod"): the time it is handed drives the approval sweep, the stuck-run check and the evidence purge, so a time in the future would delete evidence early; outside demo the tick takes the time from the app's own clock. `run_tick(app, steps=...)` is refused outside demo as well ("steps= is for tests; it is refused in pilot and prod"; an empty list counts as given): a step list of the caller's choice lets a tick return exit code 0 with no approval sweep and no evidence purge, so nothing would alert. Both refusals RAISE a `ConfigError`; `run_tick` otherwise returns an exit code, so a caller that passes either keyword must catch the error (an uncaught one ends a Python process with exit code 1, which the tick's own list reads as "a step failed"). With both given, `now=` is the one named. The command line passes neither. To upgrade: call `run_tick(app)` without `now=` and without `steps=`.
  - **The list of steps.** A deployment that needs another step appends a `TickStep` to the list `runtime.tick.STEPS`; the appended step runs after the built-in ones. Outside demo a tick also refuses to run, with a `ConfigError`, in two cases: "a built-in tick step is missing: <names>" when one of the built-in steps (sweep, reconcile, stuck, checkpoint, purge_evidence, reprobe_sources) is no longer in that list by name, so a cut or emptied list cannot return exit code 0 with no sweep and no purge; and "a tick step name is used twice: <names>" (of the four refusals that raise instead of returning an exit code, these are the last two: `now=`, `steps=`, a missing built-in step, a repeated name; results are kept by name, so a second step with a built-in name would hide a failed built-in step). The tick takes ONE copy of the list at its start and uses it for both checks and for the run, so a list edited in place between the checks and the loop changes nothing. Demo runs the list as it is.
  - **The time inside a step: `TickContext`.** The same refusal sits where the time enters the steps: `runtime.tick.TickContext(app, <time>)` raises a `ConfigError` outside demo (the sentence "now= is for tests; it is refused in pilot and prod", followed by the advice to build the context as `TickContext(app)`, which takes the time from the app's clock, and a note that a copy made by `dataclasses.replace()` carries the old time as a given one and is refused too), so a step called by hand, for example `purge_evidence(TickContext(app, <time>))`, can no longer work with a time of the caller's choice (with a time 500 days ahead that call deleted every stored tool call and redaction map of a pilot app). `TickContext(app)` takes the time from the app's clock and is not refused. The context is frozen (its time cannot be changed afterwards by assignment), and outside demo a step refuses an object that only looks like a context. To upgrade: build the context as `TickContext(app)`; code that assigned to `ctx.now`, or copied a context with `replace()`, must build a new context. **Test code that subclasses `TickContext` now fails at import with a `TypeError`; build a plain `TickContext` instead.**
  - **`sources=` and `tools=` (already refused in pilot and prod) now count as given when they are not None.** An empty mapping (`sources={}`, `tools={}`) was let through in pilot and prod and is refused now, with the same two messages as before; pass nothing instead. A mapping that holds entries and is falsy is refused in pilot and prod, and used as given in demo (it was silently dropped). Both keywords take a mapping; a list of pairs happens to work in demo because the code copies the value with `dict()`, and that is not part of the contract.
  - **The demo executor's timeout has one rule on both routes: an int or float between 0.001 and 3600 (seconds).** The `timeout_s=` keyword of `build` and the config field `executor_timeout_s` are checked by one function (`config.executor_timeout_ok`). Anything else stops the build with "timeout_s= must be an int or float between 0.001 and 3600", and stops the config from loading with the same sentence under `executor_timeout_s`: `0`, a negative number, `true` or `false` (the config used to read `true` as 1.0), a text such as `'5'` (the config used to read it as 5.0), not-a-number, infinity (`.inf` was accepted by the config), a number over 3600 (3601 and 3600.0000001 were accepted by the config), a number under 0.001, and for the keyword a number of another type such as `Decimal` or `Fraction` (convert it with `float()` first). The bounds are `defaults.EXECUTOR_TIMEOUT_MIN_S` and `defaults.EXECUTOR_TIMEOUT_MAX_S`. Why a lower bound of one millisecond: no network call can finish in less, so a value such as `1e-9` behaves like 0 (every executor call fails at once), which is the failure the rule exists to stop. A `timeout_s=0` used to be replaced by the configured timeout without a word. This matters in demo only: pilot and prod build no executor, and there the keyword itself is refused, whatever its value; the config field is still checked at load in every stage. The config file is read with YAML 1.1 rules, so `0x10` means 16 and `1:30` means 90 (both are accepted as numbers inside the range, and `1:30` is 90 seconds). One difference remains between the routes: `Decimal('2.5')` given by keyword is refused (convert it with `float()` first), while the config file cannot carry a `Decimal` (YAML reads `2.5` as a float), so `executor_timeout_s: 2.5` is accepted; an int such as 3600 stays an int by keyword and becomes 3600.0 from the config field. A configuration error text names the problem and where it is, not the value that was refused. What `load_config` and `load_registry` raise (and what `app.build` raises for a source or a tool name) follows these rules, each tested: (1) the text of a validation error shows field names and item positions; a key the model does not know is shown as `<unknown key>` (with its parent path), never as written, because a pasted secret can be a key; (2) any other name taken from a file (a mapping key, an agent, action, chain, system, tool, operation or tool-module name, a `model_route`, a scope name, a schema keyword or property name, a tool host) is shown only when it is a plain identifier (lower-case letters, digits, `-`, `_` and `.`, 1 to 64 characters), otherwise as `<not shown>`; this is a filter on shape, not a secret detector, so a pasted secret made only of those characters would still be shown; (3) a `ValueError` that a library raised inside a check (not one of our own sentences) shows its type only; (4) a URL that cannot be read (for example a host that changes under Unicode NFKC into one holding `@` or `:`) gives the fixed sentence "not a valid URL" (`hadavin_sdk.safe_url.safe_urlsplit` is the one function that splits a URL; no other module calls `urlsplit`, and a test checks that); (5) every YAML file of the configuration folder (`config.yaml`, `egress.yaml`, `agents.yaml`, `principals.yaml`, `chains.yaml`, `actions/*.yaml` and `tools/<agent>.yaml`) is read through one reader (`config.load_yaml`) that gives "not valid YAML" with the line and column only (`tools/<agent>.yaml` used to be read outside it and quoted the broken line), and a file that is not UTF-8 text or cannot be opened gives its error type only; (6) a duplicate key or id is reported by line or entry number, a `base_url` that holds a login by the sentence `base_url must not contain a login` (the URL is not shown), and the lists of refused entries are counted; (7) the cause that Python would print under the error is dropped too. What this does not cover: the names of fields and of kinds (shown so the error can be found); the list of known kind names that an unknown-kind message prints; the text of errors raised later by `app.build` or a backend while it connects; and the refusals of a running tool call (`ToolRefused`: an operation, method or host that a caller handed in). The one sentence for a time given to a tick context was reworded: it no longer says that the context was copied by `replace()` when the caller did not copy anything. To upgrade: set `executor_timeout_s` to a number from 0.001 to 3600.
  - **An object that is falsy is used as given, not silently replaced.** In demo this holds for the keywords `secrets=`, `channel=`, `detector=`, `llm=` and `clock=` of `build`, and for `sources=` and `tools=` (a `timeout_s=` of 0 is refused, see above). It also holds, in every stage, for a secret provider handed to `backends.factory.make` (the command line's `gate`, `limits` and replay commands call `make`): a provider object that is falsy is no longer swapped for an empty one.
  - **What is not covered (limits, stated plainly).** First the plain sentence: these refusals stop a test object that reaches a pilot or prod process by accident, not hostile code that already runs inside the same process. Code inside the process can already do everything the process can do, so a check inside the process cannot stop it; the control for deletion is least privilege: the app deletes evidence only through the separate purge identity (test `test_the_app_deletes_evidence_only_through_the_purge_identity`).
    - **What the refusals cover.** The six keywords of `build`; `now=` and `steps=` of `run_tick`; a `runtime.tick.STEPS` that lacks a built-in step or holds one step name twice; and a time handed to a `TickContext` (so also a tick step called by hand with such a context). A tick step outside demo takes only an object whose type is exactly `TickContext`: a plain stand-in object (a made-up replacement that only has the same fields), a `Mock(spec=TickContext)` and a subclass are refused.
    - **Routes that do not pass through the refusals.** Constructing `App`, `Runtime` or `Approvals` directly (a hand-built `Approvals(clock=...)` among them), assigning attributes after build, a kind added to the table, a direct call of `backends.factory.make`, a leftover patch of `app.make` or `app.now`, a clock that tells the wrong time (`app.approvals.clock` replaced after build), and the time parameters of `Approvals.sweep(at=)` and `Approvals.resend_unsent(at=)` (`at=` is the tick's own parameter and is not refused; both now use a given time as given, where a time object that is falsy was swapped for the clock).
    - **Changes to the step list that keep every built-in name once.** Reordering; replacing a step's function under the same name (for example a `purge_evidence` that does nothing); giving a built-in name a huge `every_s` or `interval` (also a replacement); and a rebound `runtime.tick._BUILT_IN`.
    - **Same-process acts on a context (three probes, measured at ecd5dba1).** Changing the time of a real `TickContext` with `object.__setattr__` (frozen stops ordinary assignment only); building a context without its constructor (`TickContext.__new__` followed by filling in its fields, or a crafted pickle, which means a file that Python's pickle reader turns back into an object); and an `app` wrapper that reports `demo` and passes everything else to the real app. These are deliberate acts inside the same process.
    - **Direct store purge (measured at ecd5dba1, evidence `handover/evidence/Q8a-1/ecd5dba/RESULTS.md`).** The store's own methods that delete by a cut-off date handed to them (`purge_tool_calls(before)`, `purge_redaction_maps(before)`) know no stage. Called directly on a pilot or prod app with a time 500 days ahead, `purge_tool_calls` returned 3 and `purge_redaction_maps` returned 3: every row planted by the run was deleted without a refusal. The control is the separate purge identity named above, not a check at this layer.
    - **Not refused on purpose.** A tick step called by hand with `TickContext(app)` (the app's clock); it is not a supported entry point, and there is no supported way today to run only some steps outside demo.
- **Breaking for pilot and prod: a build refuses Vault `auth: token` (the default).** A config whose `vault` secrets kind or `vault_transit` signer (or any kind built on `backends.table.VaultConnection`, the new public name of the shared Vault sign-in settings) signs in with a static token, written as `auth: token` or with `auth` left out, makes `app.build` stop outside demo (in pilot, in prod and for any stage value that is not exactly `demo`), before any backend is built, with "environment pilot: refused: secrets: vault auth token (the default; set auth: kubernetes (recommended) or auth: approle)" (every such backend is named in the one message). A static token would sit in the environment of every process that calls `app.build`. To upgrade: set `auth: kubernetes` with its `role` (recommended: the sign-in uses the pod's own service-account token, so no Vault secret sits in the environment). `auth: approle` with its `role_id` is allowed; its secret id is also read from the environment, so set a short secret id lifetime on the Vault side; this code cannot check that. Demo is unchanged.
  - **What the refusal covers:** every process that calls `app.build`; of the commands that is only `hadavin-sdk tick`.
  - **What it does not cover:** the one-off commands that load the config without `build`: `limits stop` and `limits reset` (the kill switch), `audit verify`, `gate`, `migrate`, `replay` and `score`. The config itself still loads with `auth: token` in pilot and prod, so a person can run those commands with a short-lived Vault token of their own. Nothing checks how long that token lives, and a scheduled job that runs one of these commands with a static token in its environment is not refused either. A direct call of `backends.factory.make` is not covered either.
- **Configuration errors no longer show a value that came from a file (Q8a-1).** A config or registry file can hold a pasted secret in a place where a name or a URL belongs. The error text of a refused file now names the problem and its place (field names, list positions) and never the value. This is the exact list of what is covered:
  - **The one choke point is `config.config_error_text`.** A pydantic message is shown as written only for the problem types in `config._FIXED_SENTENCE_TYPES` (the rule or the bound, never the value). A bad choice of `kind` says "the kind is missing or not one of the known kinds" plus the list of allowed kinds. Any other type, including one that a later pydantic adds, says "a value was refused (<type>)". A `value_error` sentence is shown only when it was raised as `errors.ConfigValueError`, the one class that means "Hadavin wrote this sentence"; every other `ValueError` (a library's, or a plain one) shows its type only. This replaces the earlier test of the traceback's last frame, which could not tell a sentence written by us from the text of `int()`, `float()`, `Decimal()` or `bytes.fromhex()` called inside one of our validators. The validators of `config.py`, `backends/table.py` and `actions/contract.py` all raise `ConfigValueError`; a test fails if a plain `raise ValueError(` returns to those three files.
  - **Names from files go through `errors.shown_name`** (two tests, both must pass where a set of loaded ids exists: the text is word-like, meaning a letter first, at most 40 characters, only lower-case letters, digits, `_`, `.`, `:` and `-`, and no run of 20 or more digits or hex digits; AND it is the id of something that was loaded, which only `registry.load_registry` (two places in `registry.py`) sets with `errors.loaded_ids`. With no loaded set (a message printed before anything was loaded, at call time after the load, or by a unit called alone, for example in `secrets_*`, `tools.load_tool_module` and `config.py`) only the word-like test applies, and a plain-shaped name is shown. A name that fails either test is `<not shown>`; it hides what does not have that shape and what matched nothing, it does not find secrets: a secret typed as an id and written as a short lower-case word is the id of a loaded thing and is shown). Covered: the cross-checks in `registry.py`, every message of `deferred.py`, the source keys in `sources/__init__.py`, the model id in the alias refusal (it is no longer printed at all), the names and sources in `app.py`, and, in `tools.py`, the module name and the operation and method of a refused call (a host in `tools.py` is never printed: a manifest host is said by its position, "hosts entry 2", and a refused host by a fixed sentence; hosts are printed only in `guard/http.py`; a secret in `tools.py` is said by its position, never through `shown_name`). A name from a file that matched nothing (an unknown route, an action in `scope_allowed`, a tool in `tools_allowed`) is not quoted even when it looks like a plain name: it is named by its position ("scope_allowed entry 1 has no contract"). **Decision (default "hide" for references; whether ids that define a thing should be hidden too is an open question for the owner, and until it is answered they stay printed): ids that DEFINE a thing (agent, action, chain, principal) stay printed when they have the plain shape and were loaded, as listed above; every field that only REFERS to something (a secret name in any `*_secret_name` field, a secret listed by a tool or an action, an environment variable name, a path, a namespace of the Kubernetes source, said as "namespace entry 2") is never printed, not even when it looks like a plain word, because a password pasted there is a plain word too.** The secret providers (`secrets_aws`, `secrets_azure`, `secrets_gcp`, `secrets_file`, `secrets_env`, `secrets_cache`, `secrets_vault`) now say "the secret" without its name; `backends/platform_secrets.py` names the settings field that holds the name ("the secret set in PostgresSettings.dsn_secret_name") or the position among the action executor or read-tool secrets; a tool's short-secret refusal says "secret 2 of this tool's secret_names"; the golden-case gate says "golden case 3"; the Vault sign-in refusal names the sign-in method (approle or kubernetes), a fixed word. A tool manifest's own field names (`max_output_bytes`) are shown on the word-like test alone (`errors.error_where(..., field_names=True)`): they are written in code, not configured. **The guard (round 12, rewritten the other way round): a site is a finding unless every value put into it is proven to be written in code.** `test_no_config_derived_name_is_put_in_a_message_outside_the_one_filter` reads every module under `src/hadavin_sdk` (found by walking, apart from the exempt places listed in `tests/test_stage_names.py`, each with its reason, and a test checks that they read no configuration) and finds every message site: an f-string, `%`, `.format`, `+` and `+=`, `join`, `str()`, `repr()`, `json.dumps`, `raise X(value)` and an argument of a log call on any logger, and also a `raise ... from <value>` (the cause). A value is proven when it is a written text, a written constant (UPPER_CASE), a class name (`type(x).__name__`), a number (a `len`, an `int`, a loop counter, a value declared `int`, `float`, `bool` or a `Literal`, a number format), a call of the one filter (`shown_name`, `error_where`), a variable that is bound only to proven values (also across functions: a parameter is proven only when every call in the tree passes a proven value, and a function that is passed on as a value, such as a callback, has callers the scan cannot see, so its parameters are not proven), or text made only of proven parts. Anything else is a finding, unless the module and the site's text are in `tests/_guard_allowances.py` with a reason; an entry that matches no site any more fails the test. **What the scan cannot see, stated plainly:** (1) a configured value that passes through a call into another module and comes back as text (the scan proves a function's return only when every return is proven); (2) the text that a library formats itself (`f"{exc}"` of a library error is a finding, but the scan cannot know what a library quotes: that is why the library error is turned into its class name by `errors.call_class_only`, not by the scan); (3) a check made by an `if` or a type test that narrows a value (`type(seq) is int`): such a site is allowed by a reason that says so; (4) text that reaches a person by a path that is not a message (a file written, a record handed to an investigation). The closing of the whole class, a `ConfigName` type whose `str()` is "<not shown>", is the open owner question q-q8a1-hide-ids and was not built. **Every row has been read, and every reason is a claim that a test checks (updated in batch 15).** The reason `UNREAD` no longer exists. Each row of `tests/_guard_allowances.py` (and of the older table in `tests/test_stage_names.py`) carries a reason from `REASONS`, and `tests/test_guard_reasons.py` checks that claim against the source tree for 50 of the 52 reasons; the two it does not check (`CARD`, `REDACTED`) are pinned in `UNCHECKED`, which may only shrink (see the batch 15 entry). One planted fault per shape is checked alone by `test_the_guard_finds_each_planted_fault_alone`, the forms that must pass by `test_the_guard_passes_the_filtered_and_code_owned_forms`, and each branch of the guard has a mutant in `tests/stage_mutants.py` (the first ones are Z1 to Z5; every later batch added its own, and the count at this head is in the batch 16 entry). Line numbers in messages differ by design: the agent loop counts physical lines of a file, the golden-set gate counts non-empty lines (its message says so); an unknown agent id handed in by a caller is `<not shown>`, where earlier code printed it.
  - **URL fields.** Every settings field that holds a URL (`base_url`, `address`, `endpoint_url`, `account_url`, `vault_url`, `key_id` of the Azure key, `api_base`, `api_url`) now has the type `config_url.ConfigUrl`: a login (`user:secret@host`), a host with non-ASCII characters (full-width brackets, full-width percent) or a percent sign is refused with a fixed sentence. `openai_compat` `base_url` and Vault `address` used to accept a login. `systems.base_url` uses the same check (`safe_url.config_urlsplit`). A test fails if a field with one of those names is not a `ConfigUrl`.
  - **Tool calls at run time.** `tools.fetch` turns an unreadable URL (`:abc`, `:99999`, an open bracket) into `ToolRefused("the URL is not valid")` (it was a `ValueError` that quoted the port).
  - **New refusals at load, because a typo would silently disable a check:** an `egress.yaml` with a key other than `hosts`, or a host entry that is not a bare host name or IP address; a `rights` entry that names no action, an `approver_of` entry that names no chain, a chain `approver_ids` entry that is not a person in `principals.yaml`; a `tools_allowed` entry with no tool in that agent's manifest (when a manifest exists). A file that cannot be read (a folder, no permission, a loop of links, a name too long, not UTF-8) is reported as "<what>: cannot be read (<error type>)" and is never read as empty; this holds for every file or folder whose location comes from a configuration value (`config.yaml`, `egress.yaml`, the registry files, `actions/`, `tools/`, `prompt_file`, golden sets and their documents, `ca_file`, `jwt_path`, `private_key_path`, `sslrootcert`, `ca_cert`, `recorded_dir`, the audit index), through the one reader `errors.read_configured` and the one folder lister `errors.list_configured`, with these exceptions: the audit folder is read through it only for the audit index read at start-up (`local_dir._entries`); its later run-time reads and appends (the index append, the object files, the outbox, `qualified.jsonl`) open the files directly; `ca_cert` of the Vault kinds is checked by `ssl.create_default_context` behind a fixed sentence ("the CA file (ca_cert) cannot be used (<type>)"), not through the reader; the tool module pin (`tools.module_sha256`) reads files through the reader, while `tools.load_tool_module` reads a pinned module's files directly and its errors say the error type only ("cannot be loaded (OSError)"). A YAML key that is a list is a `ConfigError`. A `ca_file` that is not a file in the config folder is refused when the registry loads. `tool_module_hashes` must be 64 lower-case hex digits (a pasted credential there is refused by position), and the digest shown for a mismatching module is the real digest's first 12 characters. A library error out of a validator (such as a `Decimal` error) is a fixed-sentence `ConfigError`. A tool manifest that holds no tool no longer refuses `tools_allowed`. A chain's `approver_ids` are checked against `principals.yaml` only for a chain that a principal names in `approver_of`; a chain nobody names keeps channel-native ids such as a Slack user id. That person check is advisory: who may decide is settled by the decision path, which authorises by membership of the chain's approver list (`approvals/requests.py`); no right is widened. Vault `token_env`, `secret_id_env`, `role_id` and `field` must match a name pattern, and the Kubernetes source settings no longer echo a refused URL.
  - **Q8a-1 batch 12, what changes for you.** (1) A library error (a cloud, database, key or client library) is never passed on with its text, and it is no longer chained: the new error has no `__cause__` and no `__context__` (it is raised after the `except` block, in `errors.call_class_only` and in the places listed in `tests/test_q8a1_f_string_trace.py`), so a printed traceback, a log with `exc_info` and a debugger show the class name only. The other places that say `from None` hide the old error from every printed traceback but keep it in `__context__` in memory; this is stated, not fixed, because the old error is needed there for a person who reads the process with a debugger. (2) A backend kind (a block under `backends:`) with a key it does not know is refused with "unknown setting at position N (name not shown); the settings here are: ..." The layers are undone to a fixed point, at most 8 rounds (`defaults.SCRUB_MAX_LAYERS`; deeper is cut or replaced, see the next entry), so they may nest either way (`&#37;41`, a double-escaped entity). The redactor's second pass (`guard/runmap.py`) joins surrogate pairs and reads `\/` too.
  - **What it does not undo.** Hex of a percent-encoded value, ROT13 or any substitution cipher, reversed text, a character separator (`V-h-5`), one- and two-digit octal escapes, named escapes, a base32 token that wraps a secret, a base64 token shorter than 8 characters (`tools.B64_MIN_TOKEN`, the one bound), and any layer not listed: the text stays as it came and a cut inside such a spelling leaves its first characters next to the marker. This is a limit, not a guarantee: the control is that a tool is not handed a secret it does not need (least privilege). `tests/test_k5_fixes7.py` pins the unhandled layers so a change is seen.
  - **Settings.** The thresholds are validated configuration under `evidence.scrub` (`tail_window` 256, `min_redaction_window` 4096, `min_secret` 6, `fragment_scan` 4096, `fragment_min` 1, `partial_end` 10; ranges in `config.ScrubSettings`), one set of defaults in `hadavin_sdk/defaults.py`.
- **K5-core, layered encodings.** Every tool result, whether or not a secret was handed out, also gets a decode-to-fixed-point view (percent, entity, backslash escapes, NFKC) that is redacted too, so a pattern-shaped secret (`%41KIA...`, `password%3Dx`) is found; a text nested deeper than the cap is not shown. The scrub undoes any ordered stack of percent, HTML entity (decimal and hex), backslash-u, backslash-slash and NFKC full-width layers, and a base64 token front, to a fixed point: each round applies NFKC, JSON escapes, percent-decoding and entity-decoding ONE AT A TIME (a combined step turned the half entity `&#10`, which percent-decoding had just exposed, into a newline, so `percent(entity(secret))` cut inside the token left its front: 7 of 451 cut points). A half-written escape at the end is dropped before every decoder. The depth is capped at `defaults.SCRUB_MAX_LAYERS` (8); a text that still changes after the cap is not shown (the tail is cut back to its start; a whole result becomes `<SECRET_REDACTED>` + `[truncated]`): fail closed. Our own design (not a quoted standard): CWE-174 (double decoding) warns that decoding twice lets values past a check and says to reject non-conforming input; OWASP Input Validation Cheat Sheet says to decode before checking and to cap parser nesting depth (both pages fetched 2026-11-03); neither describes decoding to a fixed point, which is what finding a secret in any spelling needs. `error_reason` and every tool result go through the same `_scrub`. Pinned by `tests/test_k5_layers.py` (seeded fuzz of 20,000 orderings and depths at the default and a small window, the recorded failing cut points, a sensitivity control, a perf-marked 100 KB timing test).
